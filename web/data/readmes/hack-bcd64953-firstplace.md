# AI Sana Challenge Hub



Краткое описание

**AI Sana Challenge Hub** — платформа, которая помогает бизнесу превращать короткое и недостаточно проработанное описание задачи в понятную проектную заявку для студенческих команд.

# Link to our site: https://ai-sana-dusky.vercel.app/

Бизнес создаёт черновик задачи, система помогает уточнить требования с помощью ИИ, рассчитывает **готовность заявки**, после чего заявку можно опубликовать в каталоге. Студенческие команды находят подходящие проекты, проверяют соответствие своей команды требованиям и отправляют отклики. Бизнес просматривает отклики и выбирает команду для работы.

Целевая аудитория:

* компании и организации, которые хотят передавать реальные задачи студенческим командам;
* студенты и команды, которые ищут практические проекты;
* организаторы AI Sana / хакатона, которым нужен прозрачный процесс от постановки задачи до выбора исполнителя.

### Для бизнеса

* регистрация и авторизация;
* отдельный интерфейс для роли `business`;
* создание и редактирование заявок;
* пошаговая подготовка заявки;
* AI-анализ исходного описания;
* уточняющие вопросы;

* предпросмотр перед публикацией;
* публикация и закрытие заявки;
* просмотр откликов команд;
* просмотр профиля команды;
* принятие или отклонение отклика;
* уведомления;
* профиль и настройки.

* отдельный интерфейс для роли `student`;
* каталог опубликованных заявок;

* просмотр подробной информации о проекте;
* загрузка CSV-файла с данными команды;
* проверка соответствия команды требованиям проекта;
* расчёт процента соответствия;
* отправка отклика при достижении необходимого порога;
* просмотр статусов отправленных откликов;
* уведомления;
* профиль команды и настройки.

### Общие возможности

## Как работает решение

### Сценарий бизнеса

1. Пользователь регистрируется или входит как представитель бизнеса.
2. Создаёт новую заявку и вводит краткое описание задачи.
3. Backend передаёт описание в AI-сервис.
4. ИИ анализирует заявку, определяет недостающую информацию и формирует уточняющие вопросы.
5. Пользователь отвечает на вопросы.
6. Система рассчитывает **Readiness Score** — насколько полно задача подготовлена для публикации.
7. Бизнес просматривает итоговую карточку и публикует её.
8. Заявка становится доступна студенческим командам.
9. После получения откликов бизнес сравнивает команды и принимает или отклоняет кандидатов.

### Сценарий студента

1. Студент входит в систему как `student`.
2. Открывает каталог опубликованных заявок.
3. Находит интересующий проект.
4. Переходит на страницу проекта и начинает отправку отклика.
5. Загружает CSV с данными команды.
6. Backend анализирует данные и рассчитывает **Match Score**.
7. Если соответствие ниже установленного порога, система показывает причины и недостающие навыки.
8. Если соответствие достигает порога, студент может отправить отклик.
9. Статус отклика отображается в личном кабинете.


## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone <REPOSITORY_URL>
cd <PROJECT_FOLDER>
```

### 2. Запустить backend

```bash
cd backend
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install -e .
```

Создать `.env`:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Пример переменных:

```env
APP_ENV=development
APP_URL=http://localhost:8000
FRONTEND_URL=http://localhost:3000

SUPABASE_URL=
SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
SUPABASE_JWT_ISSUER=
SUPABASE_JWKS_URL=

AI_API_KEY=
AI_MODEL=
AI_BASE_URL=

MAX_CSV_SIZE_MB=5
MATCH_THRESHOLD=90
```

Запустить backend:

```bash
uvicorn app.main:app --reload
```

Backend:

```text
http://localhost:8000
```

Swagger:

```text
http://localhost:8000/docs
```

### 3. Запустить frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend:

```text
http://localhost:3000
```

## Как проверить решение

### Сценарий для жюри

1. Открыть `/login`.
2. Войти как пользователь с ролью `business`.
3. Перейти в `/business/applications/create`.
4. Создать короткое описание задачи.
5. Нажать **«Проанализировать с ИИ»**.
6. Ответить на уточняющие вопросы.
7. Проверить Readiness Score.
8. Опубликовать заявку.
9. Войти как `student`.
10. Открыть `/student/applications`.
11. Найти опубликованную заявку.
12. Загрузить CSV команды.
13. Проверить Match Score.
14. При достаточном соответствии отправить отклик.
15. Снова войти как бизнес.
16. Открыть отклики и принять или отклонить команду.

Пример описания:

> Нужно создать сервис, который поможет анализировать обратную связь студентов.

## Безопасность

* JWT передаётся через `Authorization: Bearer <token>`.
* Подпись проверяется через Supabase JWKS.
* Backend проверяет `exp`, `iss`, `aud` и пользователя.
* Роль определяется backend, а не frontend.
* Неверная роль возвращает `403`.
* Неверный или отсутствующий токен возвращает `401`.
* Секреты хранятся в `.env`.

## Ограничения

* качество AI-анализа зависит от используемой модели;
* для AI требуется внешний API;
* matching не гарантирует успешное выполнение проекта;
* результат CSV-анализа зависит от полноты данных;
* порог соответствия задаётся через `MATCH_THRESHOLD`;
* требуется настроенный проект Supabase;
* production deployment необходимо настраивать отдельно;
* deployed URL в предоставленных материалах не указан.
