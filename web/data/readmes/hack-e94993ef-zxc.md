# Smart Contractor

> Объяснимый сервис подбора event-подрядчиков по параметрам конкретного мероприятия.

## 1. Название проекта

**Smart Contractor** — сервис детерминированного подбора подрядчиков с объяснением результата и автоматическим **«Планом Б»** для слишком строгих запросов.

## 2. Краткое описание

Пользователю сложно вручную сравнивать подрядчиков одновременно по городу, дате, формату мероприятия, бюджету, языку и длительности работы. Smart Contractor принимает параметры заказа, исключает неподходящие профили и возвращает до трёх подходящих вариантов.

Сервис не ограничивается обычной фильтрацией: для каждого результата формируется конкретное объяснение, почему подрядчик подходит под запрос. Если подходящих кандидатов нет или их меньше трёх, модуль **«План Б»** анализирует ограничения и предлагает изменение параметров, которое может расширить выбор.

## 3. Что реализовано

- фильтрация подрядчиков по городу и категории;
- проверка занятости на выбранную дату;
- фильтрация по формату мероприятия;
- проверка бюджета;
- опциональная фильтрация по языку;
- опциональная фильтрация по длительности;
- дополнительные текстовые пожелания пользователя;
- TF-IDF и cosine similarity для сопоставления пожеланий с описаниями подрядчиков;
- детерминированное ранжирование кандидатов;
- выдача до трёх карточек подрядчиков;
- конкретные объяснения причин рекомендации;
- три различимых состояния результата:
  - `matched` — подходящие подрядчики найдены;
  - `category_absent` — выбранной категории нет в указанном городе;
  - `no_match` — категория существует, но никто не проходит заданные условия;
- диагностика причин, по которым кандидаты были отсеяны;
- **«План Б»** с альтернативами по дате, бюджету, языку, длительности, городу или комбинации даты и бюджета;
- применение предложенного варианта «Плана Б» прямо из интерфейса;
- отображение признаков `synthetic`, `city_imputed`, `price_imputed`;
- адаптивный web-интерфейс;
- REST API на FastAPI;
- API-тесты через pytest и FastAPI `TestClient`.

## 4. Как работает решение

1. Пользователь задаёт город, дату, формат мероприятия, категорию подрядчика и бюджет.
2. При необходимости добавляет длительность, язык и текстовые пожелания.
3. Backend выбирает подрядчиков нужной категории в указанном городе.
4. Последовательно проверяются обязательные ограничения: дата, формат, бюджет, язык и длительность.
5. Для текстовых пожеланий рассчитывается TF-IDF-сходство с описанием подрядчика.
6. Подходящие кандидаты ранжируются детерминированно.
7. Пользователь получает до трёх карточек с объяснением причин выбора.
8. Если подходящих вариантов недостаточно, модуль «План Б» проверяет альтернативные параметры и предлагает изменения, которые дают дополнительные результаты.

Одинаковый запрос возвращает одинаковый порядок рекомендаций.

### Назначение основных компонентов

- `backend/main.py` — создание FastAPI-приложения, API endpoints и раздача frontend;
- `backend/data_loader.py` — чтение и нормализация CSV-датасета;
- `backend/models.py` — Pydantic-модели запросов, результатов и «Плана Б»;
- `backend/recommender.py` — фильтрация, TF-IDF, ранжирование, объяснения и логика «Плана Б»;
- `frontend/index.html` — структура пользовательского интерфейса;
- `frontend/styles.css` — визуальное оформление и адаптивность;
- `frontend/app.js` — работа формы, обращения к API, вывод карточек и применение «Плана Б»;
- `data/contractors.csv` — локальный каталог подрядчиков;
- `tests/test_api.py` — проверка health/meta endpoints, обычной рекомендации и возврата «Плана Б».

### Взаимодействие компонентов

```text
Пользователь
    ↓
frontend/index.html + styles.css + app.js
    ↓ POST /api/recommend
backend/main.py
    ↓
RecommendationRequest
    ↓
ContractorRecommender
    ├── город / категория
    ├── занятость
    ├── формат
    ├── бюджет
    ├── язык
    ├── длительность
    ├── TF-IDF
    ├── детерминированное ранжирование
    └── Plan B analyzer
    ↓
Top-3 + explanations + plan_b
    ↓
JSON → frontend
```

Frontend обслуживается самим FastAPI-приложением, поэтому отдельный frontend-сервер для локального запуска не требуется.

## 7. Установка и запуск

### Требования

- Python 3.11+
- pip

### 1. Клонировать репозиторий

```bash
git clone https://github.com/BAITC-Hacks/hack-e94993ef-zxc.git
cd hack-e94993ef-zxc
```

### 2. Создать виртуальное окружение

Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

В текущей структуре `main` отдельный `requirements.txt` отсутствует, поэтому зависимости можно установить напрямую:

```bash
pip install fastapi uvicorn pandas scikit-learn pytest httpx
```

### 4. Запустить приложение

Windows:

```powershell
run.bat
```

Или напрямую:

```bash
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

### 5. Открыть приложение

```text
http://127.0.0.1:8000
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

### 6. Запустить тесты

Из корня проекта:

```bash
python -m pytest -q
```

`pytest.ini` добавляет корень проекта в Python path и указывает папку `tests` как каталог тестов.

## 8. Как проверить решение

### Сценарий 1 — плотная категория

```text
Город: Алматы
Дата: 15.10.2026
Тип мероприятия: корпоратив
Категория: Ведущий
Бюджет: 1 500 000 ₸
Длительность: 6 ч
Язык: русский
Пожелания: интеллигентный юмор импровизация современная подача
```

Ожидаемый результат: статус `matched` и от одной до трёх карточек. Повторный запуск с теми же параметрами должен возвращать тот же порядок.

### Сценарий 2 — редкая категория

```text
Город: Алматы
Дата: 15.10.2026
Тип мероприятия: свадьба
Категория: Флорист
Бюджет: 500 000 ₸
Язык: русский
Пожелания: авторское оформление цветы
```

Ожидаемый результат: подходящие профили отображаются вместе с конкретным объяснением.

### Сценарий 3 — строгий запрос и «План Б»

```text
Город: Астана
Дата: 31.12.2026
Тип мероприятия: свадьба
Категория: Ведущий
Бюджет: 300 000 ₸
Длительность: 10 ч
Язык: казахский
```

Ожидаемый результат: `no_match`. Интерфейс показывает причины отсутствия результата и возвращённые backend-варианты «Плана Б». Кнопка **«Применить»** переносит предложенные параметры в форму и выполняет новый поиск.

## 9. Данные и интеграции

Источник данных:

```text
data/contractors.csv
```

Backend использует следующие поля профиля подрядчика:

- `id`;
- `anon_name`;
- `categories`;
- `city`;
- `city_imputed`;
- `synthetic`;
- `price_from_kzt`;
- `price_imputed`;
- `event_formats`;
- `languages`;
- `max_hours`;
- `busy_dates`;
- `description`.

Датасет содержит 66 профилей подрядчиков. Все вычисления выполняются локально; внешняя база данных, LLM API и сторонние сервисы для работы рекомендательной логики не используются.

## 10. Ограничения

- каталог хранится в локальном CSV;
- календарь доступности ограничен датами, содержащимися в датасете;
- бронирование, заявки и уведомления подрядчикам не реализованы;
- нет авторизации и пользовательских аккаунтов;
- нет постоянной базы данных;
- нет административного интерфейса;
- TF-IDF основан на лексическом сходстве и не является полноценной embedding-моделью;
- стоимость берётся из `price_from_kzt`, индивидуальная смета не рассчитывается;
- доступность не синхронизируется с внешними календарями;
- «План Б» строит предложения только на основе текущего каталога и реализованных правил;
- в текущей структуре репозитория автоматические тесты находятся в одном файле `tests/test_api.py`.
