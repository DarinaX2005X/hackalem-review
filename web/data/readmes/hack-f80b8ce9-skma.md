# ИИ-консультант для ekt.kz

Прототип для кейса HackAlem AI: чат-консультант интернет-магазина электротехники
ТОО «Электрокомплект». Помогает покупателю найти товар по артикулу или описанию,
узнать цену и наличие, подобрать альтернативу и подготовить корзину.

## Что реализовано

- Поиск по артикулу, коду производителя и названию, включая нечёткие совпадения
  и отдельные синонимы: например, «автомат» → «АВ».
- Карточки товаров: цена в тенге, общий остаток и остатки по складам,
  характеристики, кратность, ссылка на товар.
- Подбор аналогов в наличии из той же серии или категории с объяснением
  совпавших характеристик и параметров названия.
- Ответы об оплате, доставке и минимальной партии из локального файла условий.
- Предложение добавить товар в корзину, подтверждение или отказ.
  Корзина меняется после кнопки «Да, добавить» либо короткого подтверждения
  в чате при наличии ожидающего предложения.
- Страница корзины `/cart/[id]` с количеством, стоимостью позиций и итогом.
- Адаптивный чат с карточками товаров, состояниями загрузки и повтором запроса
  при ошибке; на небольшом экране чат занимает весь экран.
  При недоступности карточек каталог возвращает 503 вместо пустой выдачи,
  а чат показывает «Каталог временно недоступен» с кнопкой повтора.
  На мобильном экране открытый чат блокирует прокрутку фоновой страницы.
- Два режима ассистента: LLM с вызовом инструментов и резервный режим правил.
  Для вопросов с характерными буквами казахского языка можно включить отдельную
  модель, которая переписывает готовый ответ на казахский.
- Загрузка спецификации `.csv`, `.xlsx` или `.docx` кнопкой 📎 (до 2 МБ, первые 50
  товарных строк): по каждой строке отображаются найденный товар, остаток и статус
  «В наличии», «Частично», «Нет в наличии» или «Не найдено». Для отсутствующего
  товара сервис пытается подобрать аналог; число таких проверок ограничено десятью.
  Содержание последней загруженной спецификации доступно LLM в следующих сообщениях
  этой сессии, поэтому можно попросить «добавь из файла автомат на 250А».

## Как работает решение

1. Покупатель открывает чат и вводит артикул или описание товара.
2. Backend ищет кандидатов в локальном списке каталога, получает подробные
   карточки через API ekt.kz или из кэша.
3. Ассистент формирует ответ, а интерфейс показывает структурированные карточки.
   Для отсутствующего товара предусмотрен подбор аналогов.
4. По просьбе «добавь 2 шт» создаётся ожидающее предложение. Само предложение
   ещё не добавляет позицию в корзину.
5. После подтверждения backend повторно запрашивает карточку, ограничивает
   количество доступным остатком с учётом уже добавленного и сохраняет корзину.
   При сбое API возможен возврат к кэшированным данным — см. ограничения ниже.
6. Покупатель может загрузить спецификацию: backend разбирает файл, сопоставляет
   строки с каталогом и показывает результат в чате. Загрузка сама по себе не
   добавляет товары в корзину.
7. Покупатель переходит на страницу корзины. Кнопка оформления открывает ekt.kz;
   автоматического переноса позиций на сайт партнёра пока нет.

LLM-режим построен на LangGraph ([agent_graph.py](backend/app/services/agent_graph.py)):

```text
START → guard ─┬─ confirm ─────────▶ END   короткое «да» на открытое предложение → корзина
               ├─ reject ──────────▶ END   «нет» → предложение отменено
               └─ agent ⇄ tools ───▶ END   ChatOpenAI + инструменты каталога
```

- `guard` — код, а не модель: корзину меняет только явное «да» на последнее предложение.
- `agent` — LangChain `ChatOpenAI` с инструментами `@tool`: `search_products`, `get_product`,
  `find_analogs`, `get_purchase_terms`, `propose_add_to_cart`. Инструменты выполняет
  `ToolNode`, лимит — около шести раундов «модель ⇄ инструменты».
- История диалога — в чекпойнтере LangGraph (поток = `session_id`). В модель уходят
  последние 30 сообщений.

При пустом ключе LLM или ошибке её API используется обработка по ключевым словам
и те же сервисы каталога и корзины. История LLM-диалога этой сессии при ошибке
сбрасывается.

## Технологии

- **Backend:** Python 3.10+, FastAPI, Uvicorn, Pydantic Settings.
- **Хранение:** PostgreSQL 17, SQLAlchemy AsyncIO и asyncpg; SQLite для кэша карточек.
- **Поиск и интеграции:** RapidFuzz, HTTPX.
- **AI:** LangGraph (граф диалога, чекпойнтер истории), LangChain (`ChatOpenAI`, `@tool`).
  По умолчанию — OpenAI `https://api.openai.com/v1`, модель `gpt-5.4-mini`. Подходит любой
  OpenAI-совместимый API с вызовом инструментов, например build.nvidia.com с моделью
  `qwen/qwen3-next-80b-a3b-instruct` или свой NIM на NVIDIA Brev.
- **Дополнительная модель для казахского:** при настроенном `KAZAKH_LLM_BASE_URL`
  сервис обнаруживает характерные казахские буквы в вопросе и отправляет готовый
  ответ на переписывание отдельной OpenAI-совместимой модели. В конфигурации
  указана `inception42/Llama-3.1-Sherkala-8B-Chat` для vLLM. При ошибке модели,
  пустом ответе или изменении набора числовых фрагментов возвращается исходный
  ответ. Основная модель для диалога может быть OpenAI, NVIDIA или другим
  совместимым сервисом. [Инструкция по NVIDIA API](docs/nvida-llm-instructions.md).
- **Frontend:** TypeScript, Next.js 16 App Router, React 19, Tailwind CSS 4.
- **Запуск и проверки:** Docker Compose, Make, pytest, Ruff, ESLint, TypeScript.
  Тесты backend используют SQLite в памяти через aiosqlite и подмены внешних API.

## Архитектура проекта

Браузер обращается к `/api/*` на Next.js, который проксирует запросы в FastAPI.
Маршруты backend передают работу сервисам:

- `agent_graph` — граф LangGraph: guard, агент с инструментами, чекпойнтер;
- `assistant_service` — инструменты для LLM, подтверждение корзины, резервные правила;
- `kazakh_service` — обнаружение казахских букв и необязательное переписывание ответа;
- `attachment_service` — разбор спецификаций и сопоставление строк с каталогом;
- `search_service` — поиск и ранжирование аналогов;
- `catalog_service` — локальный список товаров, API ekt.kz, кэш в памяти и SQLite;
- `cart_service` — корзины и ожидающие подтверждения в PostgreSQL.

История LLM-диалогов хранится в `InMemorySaver`, а контекст последней спецификации —
в памяти процесса backend. Идентификаторы сессии и корзины frontend сохраняет в
`localStorage`.

```text
backend/
  app/api/routes/    HTTP-маршруты chat, catalog, cart, health, items
  app/services/      ассистент, поиск, каталог, корзина, файлы и казахский ответ
  app/models/        таблицы carts, cart_items, pending_actions
  app/schemas/       модели запросов и ответов
  app/core/          настройки и подключение к БД
  data/              образец каталога, условия покупки, локальный каталог и кэш
  scripts/           синхронизация каталога, прогрев кэша, проверка LLM
  tests/             тесты и примеры ответов API
frontend/
  app/_components/   чат, карточки, таблица спецификации и подтверждение
  app/cart/[id]/     страница корзины
  public/guide/      иллюстрации пяти шагов на главной
  lib/api.ts         типизированный клиент backend
examples/            пример CSV-спецификации
docs/                отслеживаемый отчёт, скриншоты и требования безопасности
Makefile             команды установки, запуска и проверки
docker-compose.yml   PostgreSQL, backend и frontend
```

## Установка и запуск

Все команды выполняются из корня репозитория. Нужен доступ к партнёрскому API
для загрузки каталога и карточек. Ключ LLM необязателен.

### Настройка окружения

Создайте файл настроек, если его ещё нет:

```bash
cp backend/.env.example backend/.env
```

В `backend/.env` укажите:

- `EKT_API_USER`, `EKT_API_PASSWORD` — выданные партнёром учётные данные;
- `EKT_API_URL` — по умолчанию `https://ekt.kz/api`;
- `EKT_SYNC_PAGES` — число страниц для синхронизации, `0` означает все;
- `OPENAI_API_KEY` — ключ выбранного LLM-сервиса; оставьте пустым для режима правил;
- `OPENAI_BASE_URL`, `OPENAI_MODEL` — адрес сервиса и имя модели; по умолчанию
  `https://api.openai.com/v1` и `gpt-5.4-mini` в коде; пример `backend/.env.example`
  задаёт NVIDIA `https://integrate.api.nvidia.com/v1` и
  `qwen/qwen3-next-80b-a3b-instruct`;
- `OPENAI_REASONING_EFFORT` — для reasoning-моделей (`minimal` / `low` / `medium`),
  пусто — значение модели по умолчанию;
- `KAZAKH_LLM_BASE_URL`, `KAZAKH_LLM_API_KEY`, `KAZAKH_LLM_MODEL` — казахская модель для
  гибридного режима (vLLM на Brev); пустой адрес — режим выключен;
- `DATABASE_URL` — для локального backend по умолчанию
  `postgresql+asyncpg://app:app@localhost:5432/ekt`.

В Docker Compose адрес БД для backend задаётся автоматически. Параметры PostgreSQL
`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` можно задать в корневом `.env`;
при локальном запуске согласуйте с ними `DATABASE_URL`. Реальные ключи и пароли
не добавляйте в Git.

### Вариант 1: Docker

Требования: Docker с актуальным Compose v2 и поддержкой `env_file.required`, Make;
свободные порты 3000, 8000 и 5432.

```bash
make demo
```

Команда скачивает каталог, если `backend/data/catalog.json` отсутствует,
прогревает карточки демо-товаров и аналогов, затем собирает и запускает стек.
Отдельные шаги:

```bash
make docker-sync-catalog
make docker-warm-cache
make up
```

Для повторного запуска с подготовленными данными достаточно `make up`.
`make logs` показывает логи, `make down` останавливает стек.
PostgreSQL хранит данные в volume `pgdata`, каталог и кэш — в подключённой
папке `backend/data`.

### Вариант 2: локальная разработка

Требования: Python 3.10+ с модулем venv, Node.js 22 (как в Dockerfile), npm, Make
и Docker Compose для PostgreSQL. Настройте `backend/.env`, как описано выше.

```bash
make install
cp frontend/.env.example frontend/.env.local
make sync-catalog
make warm-cache
make dev
```

Не перезаписывайте существующий `frontend/.env.local`; проверьте в нём
`BACKEND_URL=http://localhost:8000`. `make dev` поднимает PostgreSQL в Docker,
backend и frontend локально. Если полный Docker-стек уже запущен, сначала
выполните `make down`, чтобы освободить порты.

### Адреса после запуска

- Интерфейс: [localhost:3000](http://localhost:3000).
- Swagger с маршрутами и схемами API: [localhost:8000/docs](http://localhost:8000/docs).
- Проверка backend: [localhost:8000/api/health](http://localhost:8000/api/health).
- Проверка БД: [localhost:8000/api/health/db](http://localhost:8000/api/health/db).

## Как проверить решение

### Сценарий для жюри

После загрузки каталога и прогрева кэша откройте интерфейс и нажмите «Консультант».
Для воспроизводимой проверки режима правил оставьте `OPENAI_API_KEY` пустым.
Внешний API ekt.kz с учётными данными всё равно нужен для карточек, остатков
и проверки товарных строк спецификации.

1. Введите `Есть в наличии 200300285_?` — проверьте карточку, цену, остаток и склады.
2. Введите `Есть в наличии 150100218_?` — если товар отсутствует, появятся аналоги
   с обоснованием. Остатки зависят от текущих данных API и кэша.
3. Спросите `Какие условия доставки и оплаты? Минимальная партия?` — получите
   ответ из локального файла условий.
4. Снова выберите товар в наличии, затем введите `добавь 2 шт` — появится
   предложение с кнопками подтверждения и отказа.
5. Нажмите «Нет» — позиция не должна добавиться. Повторите запрос и нажмите
   «Да, добавить» — откройте корзину и проверьте количество и итог.
6. Запросите количество больше остатка — предложенное количество должно быть
   ограничено наличием. Сам запрос ещё не подтверждает добавление.
7. Нажмите 📎 и загрузите [пример спецификации](examples/spec-example.csv) — появится
   таблица со статусом каждой позиции. Статусы и аналоги зависят от актуального каталога.
   Затем напишите `из файла добавь автомат на 250А — сколько есть` (нужен ключ LLM).
8. Если настроена вторая модель, задайте вопрос с казахскими буквами, например
   `Бұл автомат қоймада бар ма?`. При недоступности второй модели ответ останется
   от основного ассистента.

Формат файла: первая строка с колонками (можно после заголовка документа)
«Артикул» / «Код», «Наименование» и «Количество». Достаточно одной из первых двух.
Разделитель CSV — `;` или `,`, кодировка UTF-8 или Windows-1251. В Word берётся первая
таблица с такими колонками (таблица реквизитов пропускается); если таблиц нет —
строки текста с разделителем Tab, `;` или `|`. Файл без заголовка тоже читается:
первая колонка — товар, числовая — количество.

### Автоматические проверки

После `make install`:

```bash
make check       # Ruff, ESLint, TypeScript и pytest
make build       # production-сборка frontend
```

Отдельно доступны `make test`, `make lint` и `make typecheck`. Тесты не требуют
партнёрских ключей, работающей LLM или PostgreSQL: используются фикстуры,
подменённые HTTP-ответы и SQLite в памяти. Покрыты поиск, адаптация карточек,
аналоги, сценарии чата, подтверждение и отказ, ограничения количества,
разбор CSV/XLSX/DOCX, обработку сбоев каталога и казахское переписывание.

Для запущенного приложения:

```bash
curl -fsS http://localhost:8000/api/health
curl -fsS http://localhost:8000/api/health/db
curl -fsS http://localhost:3000/api/health
```

Все три запроса должны вернуть `{"status":"ok"}`. Последний также проверяет
проксирование через Next.js.

`make llm-smoke` прогоняет настоящий граф LangGraph с реальным каталогом и LLM на
демо-вопросах и печатает ответы, вызванные инструменты и время ответа. Для него
нужны ключ LLM, доступ к API партнёра и подготовленный каталог. Сравнение моделей:
`make llm-smoke MODELS="gpt-5.4-mini gpt-4.1-mini"`.

[Отчёт о проверке интерфейса и известных ограничениях](docs/testreport.md) содержит
скриншоты и результаты отдельного прогона проекта.

## Данные и интеграции

- **Партнёрский API ekt.kz с Basic Auth:** `/api/products?page=N` для списка
  товаров и `/api/products/detail?id=...` для подробностей, остатков и свойств.
- **Локальный каталог:** `make sync-catalog` сохраняет список в
  `backend/data/catalog.json`. Если файла нет, поиск использует
  `backend/data/catalog_sample.json`. Образец содержит список товаров,
  но не заменяет API подробных карточек и не обеспечивает автономное демо.
- **Кэш карточек:** память процесса и `backend/data/details_cache.sqlite`.
  Срок актуальности по умолчанию — 600 секунд; при ошибке API сервис может
  вернуть сохранённую карточку и после истечения этого срока.
- **Условия покупки:** [backend/data/terms.md](backend/data/terms.md).
  В файле указаны публичные страницы-источники; обновление условий вручную.
- **LLM:** получает историю диалога и результаты инструментов через настроенный
  OpenAI-совместимый сервис. Структурированные карточки формируются из данных
  каталога, а текст ответа в LLM-режиме генерирует модель.

Полный каталог, кэш и файлы `.env` исключены из Git. В `docs/` уже отслеживаются
отчёт, скриншоты и требования безопасности; новые локальные файлы в этой папке
игнорируются. Пример для загрузки хранится в `examples/`.

## Ограничения текущей версии

- Это прототип: оформление заказа и перенос корзины в систему партнёра
  не реализованы. Кнопка оформления открывает главную страницу ekt.kz.
- Корзина не резервирует товар на складе. При недоступности API даже повторная
  проверка перед подтверждением может использовать устаревший кэш.
- Одновременные подтверждения не защищены отдельной блокировкой строк БД;
  последовательный повтор проверяется тестами.
- Кратность выводится в карточке, но не применяется как обязательное ограничение
  количества при добавлении.
- Авторизации пользователей нет; доступ к корзине определяется её случайным
  идентификатором. История диалогов теряется при перезапуске backend и не
  разделяется между несколькими процессами.
- Аналоги выбираются эвристически по категории, названию и совпадению свойств;
  техническая взаимозаменяемость не гарантируется.
- Промпт требует от LLM использовать данные инструментов, однако отдельной
  проверки всех фактов в сгенерированном тексте нет. Проверка казахского
  переписывания сравнивает набор числовых фрагментов, но не проверяет сохранность
  названий и смысл каждого предложения.
- Определение казахского языка основано на наличии характерных букв; интерфейс
  и ответы режима правил преимущественно русскоязычные. Дополнительная модель
  выключена, пока не задан её адрес.
- Сертификаты не загружаются: `certificate_url` сейчас всегда пуст.
  Вложения поддерживаются только `.csv`, `.xlsx` (первый лист) и `.docx`. Старый `.doc`,
  PDF и распознавание фото не реализованы. Добавить все строки спецификации в корзину
  одним подтверждением нельзя: позиции добавляются по одной.
- Внешние API влияют на доступность и скорость ответа. Условия покупки в
  локальном файле необходимо подтвердить у партнёра перед рабочим запуском.
