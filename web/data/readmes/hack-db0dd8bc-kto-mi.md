# Qadam

[![CI](https://github.com/BAITC-Hacks/hack-db0dd8bc-kto-mi/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/BAITC-Hacks/hack-db0dd8bc-kto-mi/actions/workflows/ci.yml)

**Qadam** (каз. «шаг») — платформа бизнес-задач для студенческих команд: от сырой идеи к готовой задаче шаг за шагом.

Бизнес описывает задачу своими словами, ИИ задаёт уточняющие вопросы и собирает из черновика и ответов
карточку задачи — без выдуманных фактов: если сведений нет, поле остаётся пустым. Прозрачный рейтинг
(без ИИ) показывает, насколько карточка готова и что добавить. Бизнес вручную публикует задачу,
студенческие команды получают рекомендации и откликаются, бизнес сам принимает отклики и подтверждает
этапы работы (+10 баллов команде).

## Архитектура и стек

**Стек:** Java 21, Spring Boot 3.5 (Web, Validation, Data JPA), Maven Wrapper, H2 (in-memory), Lombok,
springdoc-openapi (Swagger UI), JUnit 5 + Spring Boot Test, JaCoCo. OpenAI Chat Completions вызывается
через `RestClient`, без SDK. CI — GitHub Actions, поставка — Docker / Docker Compose.

```
 Браузер / Swagger UI
         │  REST /api/**
         ▼
 controller ── TaskController, TeamController, ProposalController, GlobalExceptionHandler
         │  тонкий слой: @Valid, DTO, делегирование в сервисы
         ▼
 service ──── TaskService ──► TaskAiService ──► llm.LlmClient ─┬─ MockLlmClient (по умолчанию, офлайн)
         │         │                                            └─ OpenAiLlmClient (structured output)
         │         └────────► RatingService (детерминированный рейтинг, без ИИ)
         │    TeamService ──► TaskMatcher (рекомендации по совпадению слов)
         │    ProposalService (отклики, решения бизнеса, этапы и баллы)
         ▼
 repository ─ Spring Data JPA ──► H2 (Task, Team, Proposal)
```

| Пакет `com.qadam` | Назначение                                                                     |
|-------------------|--------------------------------------------------------------------------------|
| `config`          | конфигурация Spring, выбор LLM-клиента, OpenAPI, загрузка демо-данных          |
| `controller`      | REST-контроллеры, единый обработчик ошибок, примеры для Swagger                |
| `dto`             | записи запросов и ответов: `TaskCard`, `TaskAnalysis`, `Rating`, …             |
| `model`           | JPA-сущности `Task`, `Team`, `Proposal`; перечисления `CardField`, `Industry`, `RatingLevel`, статусы |
| `repository`      | репозитории Spring Data JPA                                                    |
| `service`         | бизнес-логика: задачи, ИИ, рейтинг, команды, рекомендации, отклики             |
| `llm`             | абстракция `LlmClient`, промпты; реализации `llm.mock` и `llm.openai`          |

Ключевые решения:

- **ИИ только готовит текст.** Рейтинг, каталог, рекомендации и выбор команды — детерминированный код без ИИ.
- **Вызов LLM идёт вне транзакции БД.** Если ИИ не справился, в базу ничего не сохраняется.
- **Статусы.** Задача: `DRAFT` → `PUBLISHED` (только вручную). Отклик: `PENDING` → `ACCEPTED` / `REJECTED`
  (только вручную).

## Запуск

По умолчанию приложение работает в mock-режиме: LLM не вызывается, ключ OpenAI не нужен.

**Вариант 1. Docker Compose** (нужен только Docker):

```bash
docker compose up --build
```

Контейнер считается здоровым, когда отвечает `GET /api/health`. Остановить: `docker compose down`.

**Вариант 2. Maven Wrapper** (нужен JDK 21 или новее):

```powershell
.\mvnw.cmd spring-boot:run      # Windows
```

```bash
./mvnw spring-boot:run          # Linux / macOS
```

После запуска:

- Health check: http://localhost:8080/api/health → `{"status":"ok"}`
- Swagger UI: http://localhost:8080/swagger-ui.html (в нём есть примеры запросов для всех методов)
- Консоль H2: http://localhost:8080/h2-console (JDBC URL `jdbc:h2:mem:qadam`)

**Переменные окружения** (см. `.env.example`):

| Переменная          | По умолчанию  | Назначение                                                        |
|---------------------|---------------|-------------------------------------------------------------------|
| `LLM_MODE`          | `mock`        | `mock` — офлайн без сети, `openai` — настоящий LLM                |
| `OPENAI_API_KEY`    | —             | обязателен при `LLM_MODE=openai`, иначе приложение не стартует    |
| `OPENAI_MODEL`      | `gpt-4o-mini` | модель OpenAI с поддержкой structured output                      |
| `DEMO_DATA_ENABLED` | `true`        | заполнить пустую базу демо-данными при старте                     |

**Режим OpenAI.** Скопируйте `.env.example` в `.env` и укажите:

```dotenv
LLM_MODE=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

`docker compose` читает `.env` автоматически. При запуске через Maven задайте те же переменные
в окружении (например, `$env:LLM_MODE="openai"; $env:OPENAI_API_KEY="sk-..."`). `.env` в git не коммитится.

**Демо-данные.** При старте в пустую базу добавляются синтетические данные: 5 черновиков разной полноты,
5 опубликованных задач всех четырёх уровней рейтинга, 5 команд и 5 откликов. ИИ при этом не вызывается,
персональных данных нет (контакты на `example.com`). Отключить: `DEMO_DATA_ENABLED=false`.

**Сборка и тесты:** `.\mvnw.cmd clean verify` (Linux / macOS: `./mvnw clean verify`). Тесты не ходят в сеть,
отчёт о покрытии — `target/site/jacoco/index.html`.

## Рейтинг карточки

Рейтинг считает `RatingService` — обычный код без ИИ, результат всегда одинаков для одной и той же карточки.
Максимум — 100 баллов.

| Критерий               | Вес | Правило начисления                                                          |
|------------------------|-----|-----------------------------------------------------------------------------|
| Контекст и потребность | 20  | поле «Контекст» — 10, поле «Потребность» — 10                               |
| Данные и материалы     | 20  | поле «Данные» заполнено — 20                                                |
| Ожидаемый результат    | 15  | поле «Ожидаемый результат» заполнено — 15                                   |
| Критерии успеха        | 15  | есть цифра или `%` — 15; заполнено без измеримого показателя — 7            |
| Ограничения            | 10  | поле «Ограничения» заполнено — 10                                           |
| Пользователи           | 10  | поле «Пользователи» заполнено — 10                                          |
| Связь с бизнесом       | 10  | поле «Контакт» — 5, поле «Формат взаимодействия» — 5                        |

**Когда поле засчитывается:** оно не пустое и содержит не меньше 15 символов (у контакта — не меньше 5).
Поле «Название» в рейтинге не участвует.

**Уровни готовности:**

| Уровень    | Баллы  | Название        | Что это значит                                                   |
|------------|--------|-----------------|------------------------------------------------------------------|
| `DRAFT`    | 0–39   | Черновик        | в каталоге с пометкой «требует уточнения», в рекомендации не попадает |
| `WORKING`  | 40–69  | Рабочая задача  | можно начинать, но часть сведений придётся уточнить              |
| `READY`    | 70–89  | Готова к работе | сведений достаточно для старта                                   |
| `PRIORITY` | 90–100 | Приоритетная    | карточка заполнена полностью                                     |

Рейтинг пересчитывается и сохраняется при каждом изменении карточки. Каждый ответ с задачей содержит
объяснение оценки: баллы по критериям с причиной (`breakdown`), коды незаполненных полей (`missing`)
и подсказки, сколько баллов даст каждое поле (`tips`):

```json
"rating": {
  "score": 75,
  "level": "READY",
  "levelName": "Готова к работе",
  "breakdown": [
    { "criterion": "Критерии успеха", "points": 15, "maxPoints": 15, "reason": "Заполнено, есть измеримый показатель" },
    { "criterion": "Связь с бизнесом", "points": 5, "maxPoints": 10,
      "reason": "Контакт: заполнено (+5); Формат взаимодействия: не заполнено (0 из 5)" }
  ],
  "missing": ["constraints", "users", "interactionFormat"],
  "tips": ["Заполните «Ограничения»: +10 баллов", "Заполните «Пользователи»: +10 баллов",
           "Заполните «Формат взаимодействия»: +5 баллов"]
}
```

## Каталог, рекомендации и отклики

**Каталог** (`GET /api/catalog`):

- показывает только опубликованные задачи (`PUBLISHED`); неопубликованные (`status=DRAFT`) в каталог
  не попадают, их можно открыть только по `GET /api/tasks/{id}`;
- сортировка — по убыванию рейтинга, при равном рейтинге — по возрастанию `id`;
- фильтры (оба необязательны, можно сочетать): `industry` — код отрасли из `GET /api/industries`,
  `level` — уровень рейтинга (`DRAFT`, `WORKING`, `READY`, `PRIORITY`);
- опубликованные задачи уровня `DRAFT` остаются в каталоге, но помечены `needsClarification=true`
  и `clarificationNote="требует уточнения"`.

**Публикация** — только вручную (`POST /api/tasks/{id}/publish`), без проверки на минимальный рейтинг:
бизнес сам решает, когда задача готова.

**Рекомендации для команды** (`GET /api/teams/{id}/recommendations`, `TaskMatcher`):

- берутся опубликованные задачи уровня не ниже `WORKING`;
- интересы, навыки и технологии команды сравниваются с текстом задачи (название отрасли и поля карточки,
  кроме контакта и формата взаимодействия);
- слова приводятся к нижнему регистру, стоп-слова отбрасываются, слова сравниваются по основе
  (первые 5 букв);
- задачи сортируются по числу совпадений (`matchScore`), в ответе видно, какие слова совпали
  (`matchedKeywords`).

**Отклики:**

- откликнуться можно только на опубликованную задачу (иначе 409);
- количество откликов не ограничено: одна команда может отправить несколько, на задачу может откликнуться
  сколько угодно команд;
- **выбор команды — только вручную.** Бизнес сам принимает или отклоняет каждый отклик
  (`accept` / `reject`, только из статуса `PENDING`). Можно принять несколько откликов или ни одного.
  Ни ИИ, ни рейтинг, ни рекомендации команду не выбирают;
- в списке откликов видны название команды и её баллы — они помогают бизнесу принять решение;
- этап работы подтверждает бизнес (`confirm-milestone`, только для принятого отклика): команда
  получает +10 баллов, счётчик этапов отклика растёт на 1.

## AI-функции

ИИ используется ровно в двух местах, оба — на стороне бизнеса до публикации:

| Функция          | Метод API                 | Что делает                                                        |
|------------------|---------------------------|-------------------------------------------------------------------|
| Анализ черновика | `POST /api/tasks/analyze` | находит незаполненные поля карточки и задаёт не меньше 3 вопросов |
| Сборка карточки  | `POST /api/tasks`         | собирает карточку строго из черновика и ответов                   |

**Промпты и схемы:**

- системные промпты: [`prompts/analyze-task.md`](src/main/resources/prompts/analyze-task.md),
  [`prompts/build-card.md`](src/main/resources/prompts/build-card.md);
- строгие JSON-схемы ответа: [`llm/task-analysis.schema.json`](src/main/resources/llm/task-analysis.schema.json),
  [`llm/task-card.schema.json`](src/main/resources/llm/task-card.schema.json).
  `TaskSchemaTest` проверяет, что схемы совпадают с DTO.

**Что ИИ не делает:**

- **не выдумывает факты.** Промпт запрещает добавлять цифры, имена, технологии, сроки, контакты и цели,
  которых нет в черновике и ответах. Нет сведений — поле остаётся пустой строкой. Пустое поле честно
  снижает рейтинг, и бизнес видит, что дописать;
- **не выбирает команду**, не публикует задачу и не ставит оценку: это делают бизнес и детерминированный код.

### Обработка некорректного ответа ИИ

1. `OpenAiLlmClient` запрашивает ответ в режиме `response_format: json_schema, strict: true`, таймаут — 60 с.
2. `TaskAiService` проверяет результат через Bean Validation: не меньше 3 вопросов, известные коды полей,
   допустимая длина полей карточки.
3. Невалидный JSON, отказ модели, обрезанный ответ или нарушение правил — **одна повторная попытка**.
4. Если и вторая попытка неудачна, либо LLM недоступен (сетевая ошибка, HTTP-ошибка — без повтора),
   API возвращает `502` с понятным сообщением, а в базу ничего не сохраняется:

```json
{
  "status": 502,
  "error": "Bad Gateway",
  "message": "Не удалось обработать задачу с помощью ИИ. Попробуйте ещё раз чуть позже",
  "timestamp": "2026-09-23T10:15:30Z"
}
```

### Mock-режим

`LLM_MODE=mock` (по умолчанию) включает `MockLlmClient` — детерминированный офлайн-клиент для демо, CI и тестов:

- делит черновик на предложения и раскладывает их по полям карточки по ключевым словам
  (без совпадений — в «Контекст»); название — первое предложение о потребности;
- ответы бизнеса дописывает в их поля;
- `analyze` спрашивает о незаполненных полях и добирает до 3 вопросов самыми слабыми полями;
- никогда не придумывает текст: в карточке только предложения из черновика и ответов.

## API

Полное описание с примерами — в Swagger UI (`/swagger-ui.html`).

| Метод и адрес                                 | Что делает                                                              |
|-----------------------------------------------|-------------------------------------------------------------------------|
| `POST /api/tasks/analyze`                     | `{draftText, industry}` → недостающие поля и не меньше 3 вопросов       |
| `POST /api/tasks`                             | `{draftText, industry, answers: [{field, answer}]}` → задача `DRAFT`   |
| `GET /api/tasks/{id}`                         | задача с полями карточки и рейтингом                                    |
| `PUT /api/tasks/{id}/card`                    | правка карточки (все поля заменяются), пересчёт рейтинга                |
| `POST /api/tasks/{id}/publish`                | ручная публикация (`PUBLISHED`)                                         |
| `GET /api/catalog?industry=&level=`           | опубликованные задачи по убыванию рейтинга                              |
| `GET /api/industries`                         | отрасли: код и название                                                 |
| `GET /api/teams`                              | команды с интересами, навыками, технологиями и баллами                  |
| `GET /api/teams/{id}/recommendations`         | задачи уровня от `WORKING` по совпадению навыков и интересов команды    |
| `POST /api/tasks/{id}/proposals`              | отклик `{teamId, idea, plan, duration, prototypeUrl}`, только на опубликованную задачу |
| `GET /api/tasks/{id}/proposals`               | отклики на задачу в порядке поступления                                 |
| `POST /api/proposals/{id}/accept`, `/reject`  | решение бизнеса по отклику                                              |
| `POST /api/proposals/{id}/confirm-milestone`  | подтверждение этапа, команда получает +10 баллов                        |

**Валидация:** черновик — 20–5000 символов, отрасль обязательна, не больше 20 ответов с известным полем;
поля карточки — до 3000 символов (название — до 200, контакт — до 300); отклик: идея — 10–2000 символов,
план — 10–4000, срок обязателен, ссылка на прототип необязательна и должна начинаться с `http(s)://`.

**Ошибки** возвращаются в едином формате с сообщением на русском:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Задача с id=42 не найдена",
  "timestamp": "2026-09-23T10:15:30Z"
}
```

Коды: 400 — ошибка валидации или некорректный JSON (с полем `fieldErrors`), 404 — не найдено,
409 — действие недоступно в текущем статусе (например, отклик на неопубликованную задачу),
502 — ИИ не смог обработать задачу, 500 — непредвиденная ошибка.

## Тестовые сценарии

### Демо-сценарий (Swagger UI, mock-режим, демо-данные включены)

1. Запустите приложение (`docker compose up --build`) и откройте http://localhost:8080/swagger-ui.html.
2. `GET /api/industries` — список отраслей; возьмите код `HORECA`.
3. `POST /api/tasks/analyze` с черновиком о кофейнях из примера выше — ИИ нашёл 6 незаполненных полей
   и задал 6 вопросов. В базе ничего не появилось.
4. `POST /api/tasks` с черновиком и ответами на 3 вопроса — создана задача `DRAFT` с рейтингом 75
   (`READY`). Пустые поля `users`, `constraints`, `interactionFormat` — ИИ их не выдумал; в `tips` видно,
   сколько баллов даст каждое.
5. `PUT /api/tasks/{id}/card` — допишите пользователей, ограничения и формат взаимодействия
   (готовое тело есть в примере Swagger) — рейтинг вырос до 100 (`PRIORITY`).
6. `POST /api/tasks/{id}/proposals` до публикации — `409`: откликнуться на черновик нельзя.
7. `POST /api/tasks/{id}/publish` — задача опубликована.
8. `GET /api/catalog` — задача в каталоге, сортировка по рейтингу. Демо-задача уровня `DRAFT` внизу
   с пометкой «требует уточнения». Проверьте фильтры `?industry=HORECA` и `?level=READY`.
9. `GET /api/teams`, затем `GET /api/teams/1/recommendations` — для команды Data Wizards первой идёт
   задача про пустые полки: совпали «розничная торговля» и «прогнозирование». Задач уровня `DRAFT`
   в рекомендациях нет.
10. Отправьте два отклика на новую задачу от разных команд (`teamId` 1 и 5) — ограничений на количество нет.
11. `GET /api/tasks/{id}/proposals` — бизнес видит оба отклика с названием и баллами команды.
12. `POST /api/proposals/{id}/accept` для одного отклика, `/reject` для другого. Повторное решение — `409`.
13. `POST /api/proposals/{id}/confirm-milestone` для принятого отклика — баллы команды выросли на 10
    (проверьте в `GET /api/teams`). Для отклонённого отклика — `409`.
