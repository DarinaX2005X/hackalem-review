**Для жюри доступны два равноправных способа проверки:** открыть работающий **[baqbaq.world](https://baqbaq.world)** без установки и пароля либо самостоятельно развернуть этот репозиторий по инструкции ниже. На домене используется серверный API-ключ; при локальном запуске нужен собственный ключ OpenAI.

## Суть за 30 секунд

При реорганизации обязанность может сменить номер, название подразделения или владельца. Текстовый diff покажет удаление — но не объяснит, куда ушла функция.

BaqBaq предлагает соответствия между обязанностями, отмечает возможные потери и дублирование и открывает **точные цитаты обеих редакций**. Сотрудник принимает решение отдельно от алгоритма и получает проверяемое заключение.

**Изменение → источник → граница вывода → решение сотрудника.** Это отличие подхода от одного ответа чат-бота, а не заявление об отсутствии конкурентов.

## Два способа проверки — один проект

| | Домен | Локально из этого GitHub |
|---|---|---|
| Начать | [baqbaq.world](https://baqbaq.world) | Команды ниже |
| Доступ | Без пароля, сразу рабочий Live | Тот же интерфейс и пайплайн |
| Документы | Собственные файлы двух редакций | Собственные файлы двух редакций |
| API | Серверный ключ и общие лимиты | Ваш ключ в локальном .env |
| Данные | Изолированы случайной HttpOnly cookie браузера | На вашем компьютере; Live передаёт текст в OpenAI |

В рабочем Live-интерфейсе нет предзаполненного демонстрационного результата и переключателя Offline. Каждый анализ запускается по загруженным файлам через OpenAI. Отдельный презентационный обзор показывает проверенный синтетический сценарий и не подменяет Live. Тестовые фикстуры в коде предназначены только для проверок. Прежние приватные сравнения не раскрываются при включении публичного режима.

Повторяемость проверяется при одинаковых документах, режиме модели, поиске и версии кода. На сервере для новых расчётов по умолчанию используется FastEmbed; результат может отличаться от lexical и от нового Live-запроса. Режимы явно указаны в интерфейсе и паспорте запуска.

## Проверка для жюри за 3 минуты

1. Загрузите положения и/или организационные структуры в «До изменений» и «После изменений».
2. Нажмите **«Запустить анализ»**. Дождитесь результата; длительность зависит от объёма документов и API.
3. Выберите изменение в таблице. Сверьте исходные цитаты, редакции, пункты и ограничение вывода.
4. Зафиксируйте решение с комментарием, скачайте HTML-отчёт. При необходимости задайте агенту вопрос по выбранному изменению.

Три минуты — маршрут объяснения результата, не гарантия времени расчёта или установки. Вход на сайт не требуется. Для приватного репозитория нужно приглашение организатора. Загружайте только документы, разрешённые к передаче в OpenAI.

## Быстрый запуск

Python **3.12**, Windows:

```powershell
git clone https://github.com/BAITC-Hacks/hack-22e532a4-ai-solo.git
cd hack-22e532a4-ai-solo
Copy-Item .env.example .env
# Укажите OPENAI_API_KEY в .env
.\run.ps1
```

Linux / macOS:

```bash
git clone https://github.com/BAITC-Hacks/hack-22e532a4-ai-solo.git
cd hack-22e532a4-ai-solo
cp .env.example .env
# Укажите OPENAI_API_KEY в .env
bash run.sh
```

Откройте **http://127.0.0.1:8000/** — рабочее пространство открывается сразу. API-ключ нужен для анализа; без ключа интерфейс объясняет, что необходимо настроить. Уже существующий .env не перезаписывайте.

По умолчанию поиск использует FastEmbed: при первом расчёте нужны интернет и загрузка весов multilingual MiniLM. Для быстрого расчёта **без загрузки весов** до запуска задайте:

```powershell
$env:BAQBAQ_SEARCH_MODE='lexical'  # Windows PowerShell
```

```bash
export BAQBAQ_SEARCH_MODE=lexical  # Linux / macOS
```

Lexical — отдельный лексический режим, не embeddings. Интернет всё равно нужен для первоначальной установки зависимостей. Ручной эквивалент запуска: создать venv, `pip install -r requirements.txt`, `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.

### Live / OpenAI

Скопируйте .env.example в **новый** .env, только если файла ещё нет. Не перезаписывайте существующие ключи.

```dotenv
OPENAI_API_KEY=ваш_ключ_только_локально
OPENAI_MODEL=gpt-4.1-mini
BAQBAQ_MODEL_MODE=live
BAQBAQ_PUBLIC_LIVE=1
BAQBAQ_DAILY_API_REQUESTS=200
BAQBAQ_JOB_API_REQUESTS=80
```

Перезапустите приложение и создайте сравнение в Live. Ключ обрабатывает только backend; не вводите его в интерфейс и не коммитьте. 200 запросов/день UTC и 80/задание — сохраняемые **лимиты числа вызовов, не долларов**. Неудачные вызовы учитываются, автоматические повторы SDK отключены. Задание хранит фактические input/output tokens, если провайдер их вернул. Контроль списаний остаётся в кабинете провайдера.

## Что реализовано

| Требование трека | Реализация | Граница |
|---|---|---|
| Организационная структура | Сохранение, добавление, отсутствие, явное преобразование | Не юридический факт создания/ликвидации |
| Судьба функций | Сохранение, изменение, перенос; кандидаты разделения/объединения | Интерпретацию проверяет специалист |
| Потери и дублирование | Покрытие, кандидаты, область и полномочия, отрицание и периодичность | Неполный комплект не доказывает потерю |
| Доказательства | SHA-256, редакция, пункт/локатор, исходная цитата, контекст перечня | Наличие цитаты не гарантирует истинность интерпретации |
| Решение и заключение | Отдельная история решений, HTML/Markdown, приоритет рисков | Анонимная сессия не удостоверяет личность сотрудника |
| Агент | Responses API, поиск/чтение/сравнение/покрытие, журнал инструментов | Максимум 6 шагов, 6 инструментов за шаг |

## Архитектура и точные данные

```text
DOCX / PDF / XLSX → парсер → SQLite: документы и точные SourceSpan
                                ↓
                   реестр функций → кандидаты → риски
                                ↓               ↑
                 FastEmbed / lexical       OpenAI Live
                                ↓
                    снимок запуска → проверка человеком → отчёт
```

Exact-слой хранит байтовые хеши, исходные фрагменты и снимок состава документов/функций каждого запуска. Исторический поиск фильтрует документы **до** выбора top-k; новые загрузки не вытесняют старые источники. Снимок фиксирует версию алгоритма, хеш Python-кода, зависимости, режим поиска/модели, входной хеш с разделением «до/после» и API usage.

Семантическое решение модели **не называется детерминированным**. Версия весов embeddings не закреплена commit-хешем. Экспорт конкретного запуска использует неизменный машинный результат и **текущие** решения сотрудника с датами — сохраните файл, если нужен неизменный экземпляр заключения.

## Проверка кода

```powershell

```

```bash
.venv/bin/python scripts/verify.py
node tests/frontend_jury.cjs
```

Тесты используют временные БД. Workflow настроен на проверку Offline/lexical без секретов. [Запуск GitHub Actions для коммита 84d0024](https://github.com/BAITC-Hacks/hack-22e532a4-ai-solo/actions/runs/35860805012) не начал выполнение тестов из-за блокировки биллинга аккаунта владельца репозитория; успешный CI не заявляется. [Фактически выполненные локальные и серверные проверки](results/RELEASE_VERIFICATION.md).

Есть unit/API-регрессии, 24 синтетических документных сценария и проверка трёх опорных связей реальных редакций. Это **не независимая экспертная разметка и не доказательство промышленной точности**. Исходники контрольного набора: [app/fixtures.py](app/fixtures.py).

Для реальной пары укажите локальные BAQBAQ_DEMO_BEFORE / BAQBAQ_DEMO_AFTER и выполните `python scripts/verify_real_pair.py`. Организаторские документы в Git не публикуются. Их можно загрузить вручную в локальном интерфейсе.

## Безопасность и масштабирование

Домен: открытый Live. Случайная 256-битная HttpOnly Secure SameSite cookie отделяет документы и результаты одного браузера от другого; API проверяет владельца сравнения, включая источники, отчёты и решения. Cross-site запись запрещена. Это не учётная запись: после потери cookie доступ не восстанавливается через интерфейс. Скачайте отчёт. Не загружайте конфиденциальные документы на открытый хакатонный стенд.

Платный API открыт всем посетителям по решению владельца проекта. Общие лимиты числа запросов ограничивают расход, но не гарантируют доступность бюджета для жюри. Это не денежный лимит и не защита от целевого злоупотребления.

Отдельный systemd-сервис, пользователь, venv и данные; приложение слушает loopback. Развёртывание затрагивает только BaqBaq, проверяет хеши других Nginx-конфигов. [Развёртывание](deploy/README.md).

SQLite, один worker, атомарный запрет параллельных анализов одного сравнения и маркировка прерванных запусков после рестарта подходят для MVP. **Это не enterprise multi-tenant сервис.** Для пилота нужны отдельные роли/организации, очередь worker-задач, квоты хранилища, политика удаления, резервные копии с проверкой восстановления и нагрузочное тестирование.

## Честные ограничения и следующий этап

OCR и старые DOC/XLS не поддержаны; DOCX/PDF-экспорт, MCP, внешние нормативы и сложный граф подчинённости ещё не реализованы. Формулы XLSX не вычисляются; неполное извлечение видно как partial. Offline-эвристики могут пропускать обязанности и ошибаться в совпадениях. [Подробности](docs/LIMITATIONS.md).

Для внедрения: независимая разметка реальной пары экспертом → precision/recall по каждому виду риска → измерение времени ручной проверки → пилот на нескольких подразделениях. Нельзя заменять эти результаты процентом прошедших разработческих тестов.
