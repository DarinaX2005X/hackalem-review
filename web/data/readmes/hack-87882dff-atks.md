# Qoyma 

![](/qoyma.jpeg)
Система анализа запасов, рекомендаций по закупкам и мобильных складских операций. Веб-панель и приложение на русском языке. Qoyma используется как название и визуальный бренд, SupplyMind AI как название хакатонного проекта.

**Инструкция предназначена для запуска на новом компьютере.** Для первой проверки достаточно браузера: телефон, OpenAI-ключ и обучение модели не обязательны.

## 1. Что работает сейчас

В проекте два разных источника данных. Их важно не путать при проверке.

| Часть | Источник | Возможности |
| --- | --- | --- |
| Рабочий склад | MySQL | Товары, склады, продажи, поставщики, операции, история и подтверждённые заказы |
| План Systeme Electric | Python, Excel и CSV | Каталог, прогнозы, объяснения, фильтры, экспорт CSV; пока только просмотр |
| Ассистент | Проверенные результаты Python | Локальный разбор без ключа или выбор инструментов через OpenAI; не изменяет остатки и не утверждает заказы |
| Демо закупочного процесса | Mock на товарах MySQL, включается отдельно | Расчёт, группировка по поставщикам, изменение количества, подтверждение менеджером и приёмка |

Мобильные вкладки: **Операции, Склад, Прогнозы, История, Профиль**. Поддерживаются приёмка, выдача, перемещение, списание и инвентаризация, Barcode/QR и ручной ввод кода.

Веб-разделы: **Обзор, Остатки, Товары, Продажи, Поставщики, Прогноз, Закупки, Заказы поставщикам, AI-агент**.

**Заказы не отправляются поставщикам автоматически.** В операционном деморежиме только подтверждение менеджера создаёт заказ и ожидаемую поставку. Фактический остаток меняется при складской операции, не при расчёте закупки.

### Ограничения текущей версии

- Исторические остатки Systeme Electric пока не синхронизированы с текущими остатками MySQL.
- У внешних рекомендаций нет согласованной привязки к складам, поставщикам и срокам поставки. Их подтверждение отключено, отображается «Поставщик не указан».
- Нет полной интеграции категорий и отдельного внешнего прогноза роста. В прогнозе используется история спроса, включая сезонный метод с годовым ростом.
- Месячные всплески определяются автоматически, но без `client_id` нельзя подтвердить разовую крупную покупку конкретного клиента.
- Месячные снимки остатков не дают точного числа дней stockout. Неизвестные данные не подменяются нулями.
- Jetson/hardware, Figma и публикация в магазинах приложений не входят в текущую поставку.

Подробный аудит: [docs/HACKATHON-READINESS.md](docs/HACKATHON-READINESS.md).

```text
Веб-панель / React Native (Expo)
                |
                v
          PHP REST API :8000 <----> MySQL :3306
                |
                v
        Python FastAPI :8004 <---- Excel / CSV / модель
                |
                +---- OpenAI (необязательно, по запросу ассистента)
```

PHP проверяет авторизацию. Python слушает только `127.0.0.1`; телефон и браузер получают его результаты через PHP, не обращаются к FastAPI напрямую.

## 2. Что установить заранее

| Программа | Версия / требование | Назначение |

Ссылки: [Node.js](https://nodejs.org/en/download), [Python](https://www.python.org/downloads/), [Composer](https://getcomposer.org/download/), [MySQL Community Server](https://dev.mysql.com/downloads/mysql/), [PHP для Windows](https://windows.php.net/download/).

Проект использует Expo SDK 57, React Native 0.86 и React 19.2.3. Минимальная версия Node 22.13.x указана в [документации SDK 57](https://docs.expo.dev/versions/v57.0.0/). Не устанавливайте глобальный старый `expo-cli` и не обновляйте SDK при первоначальном запуске.

Если используете OSPanel или другой серверный комплект, запустите в нём MySQL и используйте его PHP. PHP, Composer, Node и Python должны быть доступны через `PATH`. После установки программ откройте новый терминал.

Проверка в PowerShell:

```powershell
php -v
php --ini
php -m
composer --version
node --version
npm.cmd --version
python --version
mysql --version
```

В `php -m` должны быть `PDO`, `pdo_mysql`, `curl`, `openssl`. Если расширение выключено, включите его в `php.ini`, который показывает `php --ini`, и перезапустите PHP.

Если `mysql` не найден в `PATH`, SQL ниже можно выполнить в MySQL Workbench или SQL-консоли серверного комплекта. Сам MySQL-сервис должен быть запущен.

## 3. Первоначальная установка на Windows

Команды выполняются в **PowerShell**. Не вводите префиксы `PS ...>`, `>>` и текст сообщений терминала.

### 3.1. Получить проект

Скачайте архив от команды или клонируйте переданный командой репозиторий. Распакуйте в отдельную папку. Одной папки `smartstock-mobile` недостаточно.

Далее используется пример `D:\Projects\smartstock-hackathon`. Если путь другой, замените его во всех командах.

```powershell
cd D:\Projects\smartstock-hackathon
Get-ChildItem
```

В корне должны быть `README.md`, `composer.json`, `composer.lock`, `config.php`, `router.php`, `setup.php`, папки `src`, `api`, `web`, `smartstock-mobile`, `intelligence`, `tests`.

Для демонстрации нужны `intelligence/data/raw` и `intelligence/data/processed`. Если их нет в репозитории, получите у команды комплект данных отдельно. Не переименовывайте Excel: имена заданы в `intelligence/loader.py`.

### 3.2. Создать пустую базу

Запустите MySQL и подключитесь с вашей локальной административной учётной записью:

```powershell
mysql -u root -p
```

Введите пароль MySQL. В появившейся **SQL-консоли**, не в PowerShell:

```sql
CREATE DATABASE IF NOT EXISTS smartstock
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
SHOW DATABASES LIKE 'smartstock';
EXIT;
```

Пароль MySQL не является паролем менеджера приложения. База не создаётся командой `setup.php`: сначала выполните SQL выше.

Для локального демо можно использовать локального администратора. Для общего сервера нужен отдельный пользователь с правами на выделенную базу. Не подключайте демонстрацию к производственной БД.

### 3.3. Настроить PHP `.env`

В корне проекта:

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
notepad .env
```

Пример содержимого для основного режима с Python:

```dotenv
DB_HOST=127.0.0.1
DB_NAME=smartstock
DB_USER=root
DB_PASSWORD=ваш_пароль_MySQL
INTELLIGENCE_API_URL=http://127.0.0.1:8004
ML_API_URL=
ML_API_KEY=
```

Укажите свои host/user/password. Если у локального MySQL действительно нет пароля, оставьте `DB_PASSWORD=`. Не используйте пример `ваш_пароль_MySQL` как настоящий пароль. Сохраните файл как `.env`, не `.env.txt`, в UTF-8 без BOM.

`INTELLIGENCE_API_URL` указывает на новый FastAPI. **Не записывайте его в `ML_API_URL`: это старый, другой контракт.** `DB_PORT` в текущем конфиге не используется; инструкция рассчитана на MySQL 3306.

### 3.4. Установить зависимости

В корне проекта:

```powershell
composer install
npm.cmd ci --prefix web
npm.cmd ci --prefix smartstock-mobile
python -m venv .venv-intelligence
.\.venv-intelligence\Scripts\python.exe -m pip install --disable-pip-version-check -r intelligence/requirements.txt
```

Дождитесь завершения каждой команды. При ошибке сначала устраните её, затем продолжайте.

- `composer install` создаёт `vendor/` по `composer.lock`.
- `npm ci` использует `package-lock.json`; lock-файлы обоих Node-проектов должны быть в архиве.
- Python-окружение создаётся на вашем компьютере. Чужую `.venv` с Windows/Linux переносить нельзя.
- Активировать окружение не нужно: команды используют полный путь к его Python.
- Если `python` открывает Microsoft Store, установите Python и настройте `PATH`. При наличии Windows Launcher можно использовать `py -3.13 -m venv .venv-intelligence`.

## 4. Запуск: три отдельных терминала

MySQL должен оставаться включённым. Каждый сервер работает в своём окне. Пока сервер работает, приглашение ввода не возвращается. Это нормально.

### Терминал 1: PHP и веб-панель

```powershell
cd D:\Projects\smartstock-hackathon
php -S 0.0.0.0:8000 router.php
```

Ожидается `PHP ... Development Server ... started`.

Откройте [http://localhost:8000/manager](http://localhost:8000/manager). Отдельный `npm run dev` для веб-панели не нужен: её обслуживает PHP.

### Терминал 2: Python ML API

```powershell
cd D:\Projects\smartstock-hackathon
.\.venv-intelligence\Scripts\python.exe -m uvicorn intelligence.api.main:app --host 127.0.0.1 --port 8004
```

Ожидаются `Application startup complete` и `Uvicorn running on http://127.0.0.1:8004`.

Эквивалентный вариант через скрипт, вместо команды выше:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-intelligence.ps1
```

Не запускайте оба варианта одновременно.

Проверьте [http://127.0.0.1:8004/health](http://127.0.0.1:8004/health): ожидается `status: "ok"`, `metadata.pipeline_ready: true`. Swagger: [http://127.0.0.1:8004/docs](http://127.0.0.1:8004/docs).

Для первого запуска подготовлены готовые прогнозы. Обучение при старте API не запускается.

### Терминал 3: мобильная веб-версия

```powershell
cd D:\Projects\smartstock-hackathon\smartstock-mobile
npx.cmd expo start --web --port 8081
```

Откройте [http://localhost:8081](http://localhost:8081). Это мобильное приложение в браузере; для проверки форм и операций телефон не нужен.

**Expo запускается из `smartstock-mobile`, не из корня PHP-проекта.** Если интерфейс не обновился, остановите Expo через `Ctrl+C` и повторите команду с `--clear`.

Если 8081 занят, сначала проверьте, не запущен ли уже ваш Expo. Для второй копии можно выбрать 8082:

```powershell
npx.cmd expo start --web --port 8082
```

Тогда откройте `http://localhost:8082`. PHP остаётся на 8000, Python на 8004. Смена порта Expo не меняет адрес backend.

### Остановка и повторный запуск

`Ctrl+C` останавливает сервер в его терминале. Не закрывайте PHP/Python во время демонстрации. При следующем запуске достаточно включить MySQL и повторить три команды серверов; установка зависимостей и создание учебного товара повторно не нужны.

## 6. Проверка через интерфейс

### 6.1. Каталог и прогнозы

1. Войдите менеджером в веб-панель и нажмите «Обновить результаты».
2. В «Товары» выберите источник «Systeme Electric».
3. Проверьте поиск по названию, коду и артикулу, например `IMT35180`.
4. Откройте «Закупки», фильтр «К закупке» и подробный разбор товара.
5. Нажмите значок скачивания: CSV должен содержать текущий поиск/фильтр, объяснение и статус данных.
6. В мобильном приложении откройте «Прогнозы»: используется тот же PHP API.

Для поставляемого снимка от 23.09.2026 ожидаются:

| Показатель | Значение |
| --- | --- |
| Общий каталог | 724 SKU |
| Готовые прогнозы | 422 |
| Без прогноза | 302 |
| К пополнению | 21 позиция |
| С неполными входами | 25 позиций |
| Период прогноза | Октябрь 2026 |

Проверка арифметики `IMT35180`, код `030200203_`:

```text
Остаток по файлу: 4668
В пути:          0
Прогноз спроса:  4928
Не хватает:     260
Кратность:      900
К закупке:      900
```

Количество округляется вверх до кратности. Дата остатка взята из файла, не означает текущее состояние склада. После изменения данных/модели эти контрольные числа могут измениться.

### 6.2. Ассистент

В «AI-агент» задайте один из вопросов:

```text
Какие товары нужно закупить?
Почему IMT35180 нужно закупить?
Какие товары требуют проверки данных?
Как товары в пути влияют на закупки?
```

Без ключа отображается **«Локальный разбор, без OpenAI»**. Это ограниченный поиск фактов по коду/артикулу и типу запроса, не языковая модель. Ответ и этапы проверки показываются на русском. От вопроса заказы не создаются.

### 6.3. Складские операции

Эти проверки действительно изменяют данные. Выполняйте их только в своей тестовой БД. Нужен учебный товар MySQL, не внешний Python-каталог.

1. В мобильной веб-версии войдите сотрудником склада.
2. В «Операции» выберите Алматы и найдите `SM-DEMO-OAT-06` ручным вводом.
3. Запишите исходный остаток `Q`. В свежей базе после `demo-demand.php` он равен 12.
4. «Приёмка» на 5 без привязки к заказу: остаток `Q + 5`.
5. «Выдача» на 2: остаток `Q + 3`.
6. «Перемещение» на 1 в Астану: на исходном складе `Q + 2`, на складе назначения прибавится 1.
7. «Списание» на 1 с причиной `Учебная проверка`: остаток исходного склада `Q + 1`.
8. «Инвентаризация» с фактическим количеством 10 и причиной `Учебный пересчёт`: остаток ровно 10, не увеличение на 10.
9. Обновите «История», «Склад» и веб-раздел «Остатки». Операции должны быть видны в общей MySQL-базе.
10. Попробуйте выдать больше доступного остатка. Ожидается ошибка без изменения остатка.

Для приёмки ожидаемого заказа явно выберите его в форме. Обычная приёмка не закрывает поставку. Для списания и инвентаризации обязательна причина.

## 7. Проверка REST API

В новом PowerShell, из корня:

```powershell
Invoke-RestMethod -Uri 'http://localhost:8000/'
Invoke-RestMethod -Uri 'http://127.0.0.1:8004/health'
php tools/check-intelligence.php
```

Последняя команда должна показать `reachable: true`, `healthy: true` и маршруты. Она не вызывает OpenAI и не меняет остатки.

Проверка авторизованного запроса через PHP:

```powershell
$base = 'http://localhost:8000/api/v1'
$loginBody = @{ email = 'manager@supplymind.local'; password = 'SupplyMind2026!' } | ConvertTo-Json
$session = Invoke-RestMethod -Method Post -Uri "$base/login" -ContentType 'application/json' -Body $loginBody
$headers = @{ Authorization = "Bearer $($session.token)" }

$snapshot = (Invoke-RestMethod -Uri "$base/intelligence/results?refresh=1" -Headers $headers).data
$snapshot.results.total
$snapshot.results.catalog.Count
$snapshot.stale

$null = Invoke-RestMethod -Method Post -Uri "$base/logout" -Headers $headers -ContentType 'application/json' -Body '{}'
```

Ожидается `422`, `724`, `False` для комплектного снимка. Не публикуйте `$session.token`: это токен доступа. После `logout` он больше не действует.

### Основные маршруты PHP

Префикс `/api/v1/`. Кроме `login`, нужен `Authorization: Bearer <token>`.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | `login`, `logout` | Вход / выход |
| GET | `session`, `catalog`, `inventory` | Сессия, справочники, текущий склад |
| GET | `lookup?code=SM-DEMO-OAT-06` | Поиск товара MySQL по SKU / штрихкоду |
| GET, POST | `movements` | История / проведение операции |
| GET | `purchase-orders` | Подтверждённые и полученные заказы |
| GET | `intelligence/results?refresh=1` | Сотрудник и менеджер: снимок Python |
| GET | `workspace`, `recommendations` | Менеджер: операционные данные |
| GET | `intelligence/health`, `intelligence/schema` | Менеджер: состояние / схема Python |
| GET | `intelligence/forecast?sku=030200203_` | Менеджер: прогноз SKU |
| GET | `intelligence/recommendation?sku=030200203_` | Менеджер: рекомендация SKU |
| POST | `intelligence/agent/run` | Менеджер: разбор, тело `{"message":"..."}` |
| POST | `procurement/run`, `procurement/approve` | Операционный расчёт / подтверждение; не импорт Python-снимка |
| POST | `products`, `suppliers`, `sales` | Менеджер: товар, поставщик, продажи за день |

Операции: `receive`, `issue`, `transfer`, `writeoff`, `count`. Используются `product_id`, `warehouse_id`, `quantity`, уникальный `request_id`; для перемещения также `destination_id`, для инвентаризации `expected_version`, для списания/инвентаризации `note`. ID получайте из API, не копируйте из чужой базы.

Повтор после потери ответа отправляйте с тем же `request_id` и телом: это предотвращает дублирование. История продаж редактируется отдельно и не проводит физическую выдачу.

Контракты: [Python-интеграция](contracts/intelligence-integration.md), [старый контракт расчёта](contracts/README.md).

## 8. Запуск на телефоне

Сначала проверьте работу в браузере компьютера.

### Одна локальная сеть

1. Установите Expo Go, совместимый с SDK 57. Не создавайте новый Expo-проект вместо существующего.
2. Подключите телефон к Wi-Fi сети компьютера. ПК может использовать кабель, если маршрутизатор разрешает обмен между устройствами.
3. Выполните `ipconfig`, найдите IPv4 активного адаптера. Не используйте адрес Docker, VPN или `127.0.0.1`.
4. На телефоне откройте `http://IP-КОМПЬЮТЕРА:8000/`. Ожидается JSON PHP backend.
5. При необходимости разрешите входящие подключения PHP/Node в Windows Firewall только для доверенной частной сети. Не отключайте весь firewall.
6. В `smartstock-mobile/.env.local` укажите реальный адрес ПК, например:

```dotenv
EXPO_PUBLIC_API_URL=http://192.168.1.50:8000
```

IP здесь только пример. Адрес без `/api/v1` в конце и без секретных ключей.

Остановите предыдущий Expo и запустите:

```powershell
cd D:\Projects\smartstock-hackathon\smartstock-mobile
npx.cmd expo start --lan --clear --port 8081
```

Откройте QR в Expo Go, войдите сотрудником склада и разрешите камеру. Для проверки нужен QR с точным SKU `SM-DEMO-OAT-06` или штрихкод товара `200000000006`. Сканируется товар MySQL, не произвольный внешний артикул.

Если Expo Go несовместим с SDK, не меняйте зависимости наугад: сначала используйте Expo Web, затем согласуйте совместимый клиент. Проверка форм в браузере не заменяет проверку камеры на телефоне.

### Телефон на мобильном интернете

Локальный `192.168.*` / `10.*` обычно недоступен из другой сети. Проще использовать общую Wi-Fi-сеть либо мобильную веб-версию на ПК.

Для разных сетей нужны отдельно доступный **HTTPS backend** и доступный Expo/сборка. Expo `--tunnel` относится к Metro и не открывает PHP на 8000. `EXPO_PUBLIC_API_URL` должен указывать на доступный HTTPS-адрес PHP, не Swagger и не туннель Metro. Публичную публикацию development-серверов с демопаролями эта инструкция не предусматривает.

<a id="openai"></a>
## 9. OpenAI: необязательное подключение

Прогнозы, каталог, склад и локальный разбор работают без OpenAI. Ключ нужен только для выбора инструментов языковой моделью при отправке вопроса менеджером.

В корне проекта:

```powershell
if (-not (Test-Path -LiteralPath 'intelligence/.env')) {
    Copy-Item -LiteralPath 'intelligence/.env.example' -Destination 'intelligence/.env'
}
notepad intelligence/.env
```

Содержимое:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini
```

После `OPENAI_API_KEY=` укажите новый ключ с доступом к выбранной модели. Не отправляйте его в чат. Ранее опубликованные в сообщениях или архиве ключи отзовите.

- Файл `intelligence/.env` читается при каждом запросе. После изменения обновите результаты в панели; перезапуск Python для замены ключа не требуется.
- Корневой PHP `.env`, мобильный `.env.local` и унаследованные переменные сторонних процессов для OpenAI не используются.
- Отправка вопроса с настроенным ключом может вызвать платный запрос; сообщение и выбранные данные инструментов передаются OpenAI.
- Health, просмотр прогнозов и обновление результатов OpenAI не вызывают.
- `metadata.agent_mode: "openai"` означает наличие ключа, не гарантирует его действительность, доступ к модели или наличие средств.
- При отказе провайдера интерфейс явно показывает локальный разбор. Модель не меняет числовые результаты.

Режим виден в `/health`, без вывода ключа. Официальная справка: [OpenAI API quickstart](https://developers.openai.com/api/docs/quickstart).

## 10. Отдельный деморежим подтверждения заказов

Нужен для проверки полного процесса на учебных товарах MySQL. **Это mock, не прогноз Systeme Electric.** Для основной демонстрации Python включать его не требуется.

1. Остановите PHP через `Ctrl+C`.
2. Запомните текущее значение `INTELLIGENCE_API_URL` в корневом `.env`.
3. Временно оставьте пустыми оба адреса:

5. Запустите PHP и обновите панель. Источник должен быть явно обозначен как mock.
6. Нажмите «Рассчитать закупки», откройте «Закупки» и разбор `SM-DEMO-OAT-06`.
7. Проверьте поставщика, измените количество с учётом минимальной партии, выберите позиции, откройте проверку заказа и подтвердите в отдельном диалоге.

10. Восстановите `INTELLIGENCE_API_URL=http://127.0.0.1:8004`, оставьте `ML_API_URL=` пустым, перезапустите PHP и обновите панель.

Изменение входных данных между расчётом и подтверждением может сделать рекомендацию устаревшей. Сервер отклонит её: пересчитайте закупки. В деморежиме мобильная вкладка внешних прогнозов может сообщать об отключённом Intelligence Service; складские операции продолжают работать.

## 12. Пересчёт модели из исходных Excel

Для первого просмотра не нужен. Используйте при изменении данных или для воспроизводимости.

Остановите Python API, чтобы он не загрузил частично обновлённые CSV. При необходимости сохраните копию `intelligence/data/processed` и `intelligence/models`: команды перезаписывают производные результаты и модель, но не исходные Excel и не MySQL.

Из корня, последовательно; при ошибке остановитесь:

```powershell
.\.venv-intelligence\Scripts\python.exe -m intelligence
.\.venv-intelligence\Scripts\python.exe -m intelligence.demand
.\.venv-intelligence\Scripts\python.exe -m intelligence.forecast
```

1. `intelligence` нормализует Excel в CSV и формирует отчёты качества.
2. `intelligence.demand` обрабатывает месячные выбросы, проверяет stockout и оценивает поддержанную историей потерю спроса.
3. `intelligence.forecast` использует скорректированный спрос, проводит хронологическую проверку методов, выбирает метод по SKU и рассчитывает закупку по остатку, транзиту и кратности.

Результаты: `intelligence/data/processed/forecasts.csv`, `procurement_recommendations.csv`, `forecast_metrics.json`. Модель и схема признаков: `intelligence/models/`.

Перезапустите Python API и нажмите «Обновить результаты» в вебе/мобилке. Обновление интерфейса не обучает модель. FastAPI держит снимок в памяти: изменения CSV без перезапуска не подхватятся.

Проверка методов на шести хронологических месяцах не является независимым финальным тестом или гарантией точности. Методология: [intelligence/README.md](intelligence/README.md).

<a id="troubleshooting"></a>
## 14. Частые ошибки

| Ошибка / симптом | Что проверить |
| --- | --- |
| `Unable to find expo in this project` | Перейдите в `smartstock-mobile`, выполните `npm.cmd ci`, запускайте локальный `npx.cmd expo start --web` |
| Legacy `expo-cli` | Не используйте глобальный `expo`. Установите локальные зависимости и запускайте `npx.cmd expo` из мобильной папки |
| `npm.ps1 cannot be loaded` | Используйте `npm.cmd` / `npx.cmd`; глобально отключать политику безопасности не нужно |
| `No module named uvicorn` / `dotenv` / `catboost` | Установите requirements через `.venv-intelligence` и запускайте Python именно из неё |
| Нет `vendor/autoload.php` | `composer install` в корне |
| Пропали иконки веба | `npm.cmd ci --prefix web`; проверьте `/manager/icons.js` на PHP-сервере |
| `could not find driver` | Включите `pdo_mysql` в PHP, путь показывает `php --ini` |
| Не найдена `curl_init()` | Включите PHP cURL, перезапустите PHP |
| `Unknown database` | Создайте БД SQL-командой, сверьте `DB_NAME` |
| MySQL `Access denied` | Проверьте MySQL-логин/пароль, права и адрес в корневом `.env` |
| MySQL `Connection refused` | Запустите MySQL на `127.0.0.1:3306` |
| Таблица не найдена | `php setup.php` для выбранной базы; не `seed.php` |
| «Неверная почта или пароль» | Регистр и `!`, правильная БД, выполнен ли `setup.php`. Он не сбрасывает пароль существующего аккаунта |
| Python `/health` недоступен | Оставьте Uvicorn открытым, проверьте порт 8004 и traceback в его терминале |
| Python `degraded` / нет pipeline data | Проверьте комплект `intelligence/data/processed`; восстановите файлы или выполните раздел 12 |
| «Сохранённая копия» | Кэш устарел или PHP не получил новый снимок. Проверьте Python и обновите результаты |
| Ассистент локальный после добавления ключа | Нужен `intelligence/.env`, точное `OPENAI_API_KEY`, UTF-8, не `.env.txt`. Обновите результаты |
| OpenAI настроен, но ответ локальный | Проверьте доступ к модели, ключ, лимиты и соединение. Интерфейс показывает предупреждение провайдера |
| На складе нет 724 товаров | «Склад» показывает MySQL, «Прогнозы» и внешний каталог показывают файлы. Автоимпорт отключён |
| Нельзя подтвердить внешнюю рекомендацию | Не согласованы поставщик, склад и текущий остаток. Approval проверяется в отдельном деморежиме |
| Телефон не видит backend | Проверьте `http://IP-ПК:8000/`, сеть, firewall, `EXPO_PUBLIC_API_URL`. `localhost` на телефоне означает телефон |
| UI не обновляется | Жёсткое обновление страницы или перезапуск Expo с `--clear`. После `.env.local` перезапустите Metro |
| Инвентаризация возвращает 409 | Остаток изменился после загрузки формы; обновите товар и повторите |
| Workflow-тест не создаёт БД | Нужны права CREATE/DROP DATABASE для тестовой БД |

### Занят порт

Посмотреть слушающие порты:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000,8004,8081,8082 -ErrorAction SilentlyContinue
```

Не завершайте неизвестные процессы наугад. Свой предыдущий сервер можно использовать или остановить из его терминала. Если меняете порт:

- PHP: обновите URL веб-панели и `EXPO_PUBLIC_API_URL` в мобилке.
- Python: обновите `INTELLIGENCE_API_URL` в корневом `.env`, перезапустите PHP.
- Expo: открывайте URL, выданный Expo; адрес PHP не меняется.

**PHP и Python не могут занимать один и тот же адрес/порт.** Поэтому здесь используются 8000 и 8004.
