# EKT Assistant — ИИ-консультант для покупателей ekt.kz

Проект для HackAlem AI, кейс ТОО «Электрокомплект»: единое окно чата помогает частным покупателям и закупщикам разобраться в задаче, найти электротехническую продукцию, проверить наличие и параметры, посмотреть фотографии, сравнить аналоги и подготовить корзину после явного согласия.

Решение предназначено для сокращения ожидания консультации и повторяющихся вопросов менеджерам. Изменение конверсии, оттока и нагрузки менеджеров пока не измерялось.

**Статус: работающий локальный прототип с реальным каталогом EKT и отдельным демо-режимом. Корзина сохраняется в проекте, но не подключена к покупательской корзине ekt.kz. Оформления заказа и оплаты нет. Публичная версия не опубликована.**

Документация сверена с кодом и тремя предоставленными PDF 23 сентября 2026 года. Повторная автоматическая проверка: **47 тестов, все прошли**.

## Возможности и пользовательский сценарий

Ассистент поддерживает обычный разговор: объясняет понятия, задаёт уточняющие вопросы, учитывает контекст и помогает сформулировать задачу клиента. Поиск товаров вызывается для товарных запросов; благодарность или вопрос «чем отличается автомат от УЗО?» не должны превращаться в бессмысленный поиск по каталогу.

Основной путь пользователя:

1. Открыть чат и написать вопрос, артикул, название либо загрузить спецификацию или фото маркировки.
2. Получить ответ и карточки: фотография, название, артикул, цена, общий остаток, характеристики, склады, сертификаты и ссылка на товар — если эти данные есть в источнике. Фото открывается крупнее по нажатию; при отсутствии или ошибке загрузки отображается заглушка.
3. При нулевом остатке посмотреть найденные аналоги с объяснением совпадения параметров. При неоднозначности уточнить выбор.
4. Выбрать товар и количество. На этом этапе корзина ещё не меняется.
5. Подтвердить предложение кнопкой или точным сообщением `да, добавь` / `иә, қос`. Сервер повторно получает карточку и проверяет цену, остаток, суммарное количество, минимум и кратность.
6. Перейти по ссылке `/cart` и увидеть локальную корзину своей сессии. Заказ на ekt.kz при этом не создаётся.

Дополнительно доступны русский и казахский интерфейсы, условия покупки со ссылкой на источник, локальные аккаунты, сохранение/очистка истории, удаление аккаунта, контакты менеджера и скачивание текста запроса с контекстом разговора и корзиной. Гостевая сессия и корзина переживают перезапуск сервера в пределах срока действия сессии.

## Технологии и архитектура

- **Backend:** Python, FastAPI, Uvicorn, Pydantic/Pydantic Settings, httpx.
- **Frontend:** HTML, CSS, JavaScript без сборщика; находится в `ekt-ai-assistant/backend/app/static/`. Отдельный frontend-сервер, Node.js и `npm install` для запуска сайта не нужны.
- **AI:** OpenAI Python SDK, Responses API, структурированный JSON и обработка изображений. Модель задаётся `OPENAI_MODEL`; значение по умолчанию в коде — `gpt-5.6-luna`. Доступ к модели с нужными возможностями зависит от API-проекта.
- **Файлы:** pypdf и PyMuPDF для PDF, python-docx, openpyxl, xlrd, Pillow; OCR через модель с поддержкой изображений.
- **Хранение:** SQLite для аккаунтов/истории и сессий/корзин; JSON-снимок каталога.
- **Проверки:** unittest, FastAPI TestClient, заглушки API; GitHub Actions.
- **Размещение:** Dockerfile, Docker Compose, Caddy для HTTPS — подготовлены, сборка здесь не проверена.

```text
Браузер: чат / карточки / фото / локальная корзина
  → FastAPI: сессия + CSRF + валидация + ограничения запросов
    → Dialogue: контекст → намерение → разговор / поиск / условия / менеджер
      → CatalogService → EKT API (Basic Auth) или DemoClient
      → OpenAI: разбор запроса, документа, фото; объяснение фактов
      → Recommendations: сравнение параметров / заданные связи товаров
    → Cart: предложение → согласие → свежий detail → сохранение корзины
    → Accounts / SessionStore → SQLite
  ↔ Фоновая загрузка каталога → var/catalog.json
```

## Установка и локальный запуск

Рекомендуется **Python 3.12**. Нужен интернет для установки зависимостей и внешних API; для синтетического поиска/корзины после установки ключи не обязательны. Команды ниже выполняются из корня репозитория.

### Windows / PowerShell

```powershell
# Создать конфигурацию, не перезаписывая существующую:
if (-not (Test-Path ekt-ai-assistant/backend/.env)) {
    Copy-Item ekt-ai-assistant/backend/.env.example ekt-ai-assistant/backend/.env
}

# Демо-каталог, порт 8000:
.\start.ps1 -Demo
```

Открыть [http://127.0.0.1:8000](http://127.0.0.1:8000). Скрипт создаёт `.runtime`, проверяет доступность основных библиотек и при необходимости устанавливает зависимости. Для воспроизводимой установки всех закреплённых версий используйте ручной вариант ниже.

```powershell
# Запуск с настройками .env:
.\start.ps1

# Если порт занят:
.\start.ps1 -Port 8010
```

Во втором случае сайт доступен по [http://127.0.0.1:8010](http://127.0.0.1:8010). Остановить сервер: `Ctrl+C`. После изменения `.env` перезапустить; после изменения frontend при необходимости обновить страницу через `Ctrl+F5`.

Ручная установка и запуск:

```powershell
python -m venv .runtime
.\.runtime\Scripts\python.exe -m pip install -r ekt-ai-assistant/backend/requirements.lock.txt
cd ekt-ai-assistant/backend
..\..\.runtime\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Если политика PowerShell запрещает запуск скрипта, используйте ручные команды. Старую `.venv`, перенесённую с другого компьютера, не используйте.

### Linux / macOS

```sh
python3 -m venv .runtime
.runtime/bin/python -m pip install -r ekt-ai-assistant/backend/requirements.lock.txt
test -f ekt-ai-assistant/backend/.env || cp ekt-ai-assistant/backend/.env.example ekt-ai-assistant/backend/.env
cd ekt-ai-assistant/backend
../../.runtime/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Этот путь предусмотрен структурой проекта; текущие локальные проверки выполнялись на Windows.

### Реальный каталог и AI

В `ekt-ai-assistant/backend/.env` установить `DEMO_MODE=false`, заполнить `EKT_API_USER` и `EKT_API_PASSWORD` доступами партнёра, `OPENAI_API_KEY` — своим ключом. Выбрать доступную модель в `OPENAI_MODEL`. Секреты не вставлять в код, README или frontend.

Демо-режим заменяет источник товаров и условия, но сам по себе **не отключает платные AI-запросы** при наличии ключа. Для проверки без AI задайте `AI_DIALOGUE=false` и оставьте `OPENAI_API_KEY` пустым. Разбор спецификаций в чате и распознавание изображений требуют OpenAI даже в демо.

## Данные и внешние сервисы

### Каталог EKT

В документе с данными предоставлены только Basic Auth и методы чтения:

- `GET https://ekt.kz/api/products` — первая страница;
- `GET https://ekt.kz/api/products?page=2` — последующие страницы;
- `GET https://ekt.kz/api/products/detail?id=515291` — детальная карточка.

Логин и пароль хранятся только в серверной конфигурации. Доступы каталога не дают методов изменения корзины, авторизации покупателя или CRM.

Live-каталог загружается порциями с параллелизмом до четырёх страниц. Снимок и курсор сохраняются в `var/catalog.json`; фон делает паузу 60 секунд между проходами. Полный снимок обновляется по TTL. Незавершённый обход возобновляется; после суток начинается заново. При сбое сохраняются доступные данные, при повторении страниц полнота не объявляется. Статус доступен в `/api/health`: `products`, `complete`, `next_page`, `stale`, `limit_reached`.

Количество товаров меняется во время обхода. Даже `complete=true` означает завершение пагинации, а не транзакционно согласованную выгрузку склада. Перед показом выбранной карточки и добавлением товара используется detail. Нулевой результат по неполной выборке не доказывает отсутствие товара во всём магазине.

Фотографии загружаются браузером по ссылкам каталога. Реальный товар `027228` / ID `515291` проверен: фото загружается; карточка имеет расхождение тока в названии и свойствах — 160 А и 250 А. Интерфейс показывает предупреждение, автоматический подбор аналога по такой карточке блокируется.

### Демо и условия покупки

`app/services/demo_catalog.py` содержит четыре синтетических товара: отсутствующий `DEMO-001`, аналог `DEMO-002` с остатком 12, кабель `DEMO-003`, аксессуар `DEMO-004`. Демо-цены, остатки, склады и условия не относятся к реальным предложениям EKT. `demo-certificate.txt` — образец для демонстрации.

Встроенная live-справка хранится в `app/services/terms.py`, основана на [странице оплаты и доставки EKT](https://ekt.kz/checkout-delivery/); дата проверки в коде — 2026-09-23. Это сохранённая справка, не автоматическое ежедневное обновление. На странице были противоречивые пороги бесплатной доставки; окончательный тариф должен подтвердить менеджер. Согласованный текст можно внести в `PURCHASE_TERMS`.

Сопутствующие товары задаются в `data/related_products.json`: ключ — ID товара, значение — список объектов с `product_id`, `reason` и необязательным `reason_kk`. В live-файле сейчас `{}`; совместимость не генерируется без подтверждённых связей.

### AI и передаваемые данные

OpenAI используется для определения намерения, ответа клиенту, структурирования спецификаций и распознавания маркировки/сканов. Для ответа передаются сообщение, ограниченный контекст истории и необходимые факты каталога; для файлов — извлечённый текст или изображение. Запросы используют `store=False`; это не обещание отсутствия обработки или любых журналов у внешнего провайдера.

Текст документов, карточек и истории обрабатывается как данные. Промпты запрещают выполнять встроенные команды и выдумывать цену/остаток. Модель не получает инструмента изменения корзины. NVIDIA в текущем приложении не используется; AI-агент Codex применялся при разработке.

## Проверка для жюри

### Сквозной обязательный сценарий без внешних ключей

1. Запустить `start.ps1 -Demo`; для полностью детерминированной проверки отключить `AI_DIALOGUE` и оставить OpenAI-ключ пустым.
2. Ввести `DEMO-001`: проверить нулевой остаток, технические характеристики, ссылку на demo-сертификат и аналог `DEMO-002` с объяснением.
3. У аналога указать количество **2** и нажать «Выбрать». Открытие `/cart` до подтверждения должно показать пустую корзину.
4. Вернуться в чат, подтвердить добавление. Корзина должна содержать 2 единицы. Повторное подтверждение не добавляет товар повторно.
5. Попробовать добавить ещё **11**: суммарно получилось бы 13 при остатке 12, поэтому сервер отказывает. Проверить и отказ от нового предложения.
6. Спросить «Оплата и доставка»: получить содержательный ответ с явной пометкой демонстрационных условий.
7. Открыть приложение в приватном окне: чужая корзина недоступна. Перезапустить сервер в том же режиме и вернуться в прежнем браузере: корзина сохраняется, если часовая сессия ещё действует.

### Дополнительные сценарии

- **AI-диалог:** при настроенном ключе написать «Я делаю ремонт и не понимаю, с чего начать», затем уточнить вопрос. Ожидается разговор по задаче, без самовольного добавления товара.

- **Фото/скан:** загрузить чёткую маркировку JPEG/PNG или PDF со сканом. Нечитаемые символы нужно уточнить, результат проверить вручную.
- **Live-карточка:** включить live, дождаться загрузки нужной части каталога и найти `027228`. Проверить фото, цену/остаток из текущего API и предупреждение о противоречии. Конкретные цена и остаток не фиксируются в сценарии, поскольку меняются.

- **Сопутствующий товар:** отдельный поиск `DEMO-002` показывает заданный demo-аксессуар.

## API

Документация: `/docs`, схема: `/openapi.json`. Swagger загружает ресурсы jsDelivr. Все URL ниже относятся к локальному приложению, а не к API сайта EKT.

| Метод и маршрут | Назначение |
|---|---|
| `GET /`, `GET /cart` | Чат и локальная корзина |
| `GET /api/session` | Создать/восстановить cookie-сессию, получить CSRF-токен и настройки UI |
| `DELETE /api/session` | Отозвать сессию и удалить её корзину/гостевой диалог |
| `POST /api/chat` | JSON: `message`, `language` (`ru` / `kk`) |
| `POST /api/chat/attachment` | Multipart-поле `file`: распознавание и поиск |
| `GET /api/cart` | Позиции текущей сессии |
| `POST /api/cart/propose` | `product_id`, `quantity`: предложение, без добавления |
| `POST /api/cart/confirm` | `proposal_id`, `confirmed`: подтверждение или отказ |
| `POST /api/language` | Смена языка сессии |
| `POST /api/account/register`, `POST /api/account/login` | Локальная регистрация/вход: `username`, `password` |
| `DELETE /api/account` | Удаление аккаунта, истории и отзыв его сессий |
| `GET /api/history`, `DELETE /api/history` | Чтение/очистка истории |
| `GET /api/handoff` | Текстовый файл для передачи менеджеру вручную |
| `GET /api/health` | Режим, состояние каталога, признаки настройки сервисов без значений секретов |
| `GET /api/ekt/products?page=N`, `GET /api/ekt/products/{id}` | Чтение реального API через backend |
| `POST /api/attachments/extract` | Извлечение содержимого файла |
| `POST /api/attachments/parse-specification` | Структурированный разбор через AI |
| `POST /api/attachments/match-products` | Сопоставление файла с **реальным EKT**, независимо от demo-режима |

Защищённые маршруты требуют cookie `ekt_session`; изменяющие запросы и все три API вложений — заголовок `X-CSRF-Token` из `/api/session`. При входе токен меняется. Ошибки: `400` — некорректный файл/запрос, `401` — нет действующей сессии, `403` — CSRF, `409` — конфликт подтверждения/цены/количества, `413` — размер, `422` — валидация, `429` — лимит, `502` — ошибка внешней интеграции. Точный контракт доступен в OpenAPI.

На Linux/macOS заменить путь интерпретатора на `../../.runtime/bin/python`. Последний прогон при подготовке README: **47 тестов — OK**.

Тесты используют заглушки API и временные базы, поэтому не доказывают качество всех ответов настоящей модели. ## Безопасность и хранение данных

- Cookie: HttpOnly, SameSite=Strict; Secure включается настройкой для HTTPS. Токен CSRF проверяется сервером. Секреты API не передаются frontend.
- Подтверждение корзины одноразовое, TTL 120 секунд. Изменение цены или недостаточный остаток требуют нового предложения. Серверная блокировка сериализует операции корзины внутри одного процесса.
- Сессия действует **1 час с создания**. Гостевой диалог, язык, корзина и ожидающее подтверждение сохраняются в `var/sessions.sqlite3`; идентификатор сессии хранится в виде хеша. Фоновая очистка удаляет истёкшие записи. Удалённая сессия не восстанавливается последующим сохранением старого запроса.
- `var/accounts.sqlite3` хранит локальные аккаунты и историю до 100 сообщений. Пароль хешируется scrypt с солью. Вход меняет идентификатор и CSRF и создаёт пустую корзину. Выход удаляет сессию, но сохраняет аккаунтную историю до очистки/удаления аккаунта.
- AI получает ограниченный контекст, обычно последние 8 записей; история не считается источником текущих цен/остатков.
- CSP, защита от MIME-sniffing, политика referrer, запрет кэширования ответов. Товарные тексты вставляются как текст, URL проверяются по протоколу.
- Лимиты: 30 запросов через защищённую mutation-зависимость в минуту на сессию, 120 API-запросов в минуту на адрес клиента. Это не защита от всех видов злоупотреблений.
- Полей оплаты нет. Сообщения, распознанные фильтром как платёжные данные или ключи, не передаются модели и не входят в историю. Фильтр не покрывает все формы персональных/платёжных данных, особенно внутри вложений.
- Приложение не создаёт постоянный архив загруженных файлов; multipart-обработка фреймворка может использовать временные файлы. Изображения перекодируются без EXIF перед отправкой AI. Пользователю показано уведомление о передаче данных провайдеру.
- Фото товара загружается с внешнего адреса каталога, поэтому браузер обращается к серверу изображения. Для фото установлен `no-referrer`.
- `.env`, `.runtime`, `var`, временные файлы исключены из Git. Ранее отслеживаемая `.venv` остаётся в индексе: `.gitignore` не удаляет уже отслеживаемые файлы и историю. Перед публикацией нужна проверка индекса и истории на секреты; раскрытые ключи следует отозвать и заменить.

## Развёртывание

**Публичная deployed-версия отсутствует.** Адреса `127.0.0.1` доступны только на компьютере, где запущен сервер, и не являются публичной ссылкой для жюри.

Подготовлены [Dockerfile](ekt-ai-assistant/backend/Dockerfile), [compose.yaml](compose.yaml), [Caddyfile](deploy/Caddyfile) и [инструкция размещения](docs/DEPLOYMENT.md). Нужны сервер с Docker Compose, домен, DNS и доступные порты 80/443.

На сервере из корня проекта, после заполнения backend `.env`:

```sh
export DOMAIN=assistant.example.com  # заменить своим доменом
docker compose up -d --build
docker compose ps
```

Compose включает Secure-cookie и постоянный том `assistant_data`; приложение запускается без root, его порт не публикуется наружу. Caddy обслуживает HTTPS. Docker в текущей среде отсутствует: сборка, сертификат и доступность домена не проверены.

Приложение не доверяет forwarded-заголовкам. За текущим proxy IP-лимит приложения общий для посетителей; перед публичной нагрузкой нужны ограничения на ingress и согласованная настройка доверенного proxy. Подробности резервного копирования и восстановления — в `docs/DEPLOYMENT.md`. Не удалять тома с данными командой `docker compose down -v`.
