# QADAM — умный подбор подрядчиков

QADAM — русскоязычный сервис для быстрого и прозрачного подбора подрядчиков на мероприятия, созданный для **HackAlem AI 2026, трек 79-lite**. Он детерминированно проверяет город, дату, формат, категорию, бюджет, язык и длительность, затем показывает до трёх подходящих профилей с проверяемым объяснением выбора.

Оригинальный анонимизированный набор содержит **66 профилей и 13 колонок**. Все **шесть acceptance-сценариев** прошли автоматизированную браузерную проверку. Приложение работает без credentials: правила сохраняют тот же отбор и формируют безопасные fallback-объяснения; модель влияет только на текст объяснения.

## Быстрая демонстрация

- **Много вариантов:** Алматы, ведущий, корпоратив, 10.10.2026 — три стабильных результата с разными ценами.
- **Редкая категория:** Алматы, флорист, свадьба, 05.10.2026 — один результат после проверки календаря.
- **Нет результата:** Астана, декоратор, свадьба, 05.10.2026 — честный статус `no_category_in_city` без вымышленных рекомендаций.

**Стек:** Next.js 16, React 19, TypeScript, Tailwind CSS, Zod, `csv-parse`, Vitest, Playwright, OpenAI `gpt-4o-mini` с детерминированным fallback.

Набор содержит **66 профилей и 13 колонок**:

| Колонка | Значение |
|---|---|
| `id`, `anon_name` | стабильный анонимный ID и отображаемое анонимизированное имя |
| `categories`, `city` | категории через `\|` и значение местоположения |
| `city_imputed`, `synthetic` | город восстановлен; профиль синтетический |
| `price_from_kzt`, `price_imputed` | стартовая цена в KZT; цена восстановлена |
| `event_formats`, `languages` | поддерживаемые форматы и языки через `\|` |
| `max_hours` | максимальная длительность либо пусто, когда ограничение неприменимо |
| `busy_dates` | занятые даты через `\|` |
| `description` | недоверенный текст профиля, отображаемый только как экранированный текст |

Есть 17 категорий. Города: Алматы — 50, Астана — 15, Зарубежье — 1. Флаг `synthetic=true` стоит у 13 профилей: эти записи нельзя представлять как независимо подтверждённых реальных подрядчиков. `price_imputed=true` у 18 записей и `city_imputed=true` у 8: восстановленные значения явно помечаются в карточках. В 9 строках `max_hours` пуст, что означает «ограничение не применяется», а не ноль. Значение «Зарубежье» сохранено как значение исходного каталога и не трактуется как конкретный город Казахстана.

Календарь покрывает только **2026-09-23…2026-12-31 включительно**. Запросы вне окна отклоняются: отсутствие данных не считается доступностью. Профиль исключается, когда дата присутствует в `busy_dates`, включая площадки и банкетные залы. Отсутствие даты в списке означает лишь отсутствие отметки о занятости в этом статическом наборе, не подтверждение бронирования и не актуальную доступность.

`csv-parse/sync` обрабатывает RFC4180, запятые и переводы строк внутри кавычек. Списки разделены `|`; флаги True/False нечувствительны к регистру; пустые часы → `null`. Zod проверяет каждую запись, дубли ID, поля и даты; ошибки содержат номер логической CSV-записи и поле. Проверяются сводные количества и SHA-256. Скрипт выводит точные количества по категориям.

Для другого расположения укажите в `.env.local`:

```dotenv
DATASET_PATH=C:/path/to/hackathon-dataset-anonymized.csv
```

Next.js и команды проверки читают `.env.local`. Без переопределения используется `data/hackathon-dataset-anonymized.csv`. `outputFileTracingIncludes` добавляет этот точный файл в server traces главной страницы и `/api/recommend`; production-сервер читает его по `DATASET_PATH`. CSV остаётся серверным файлом и не публикуется как статический URL.

## Архитектура и точный алгоритм

```text
Russian React form
  → POST /api/recommend (Next.js Node route handler)
  → ограничение тела 4096 байт + Zod + нормализация
  → серверный CSV-кэш (путь, размер, mtime, ctime)
  → город + категория
  → календарь + цена + формат + язык + часы
  → стабильное ранжирование → максимум 3 ID
  → факты + объяснения по правилам
  → [опционально] один AI-запрос → валидация / fallback
  → карточки + диагностика + источник объяснения
```

Функции в `lib/matching.ts` чистые и тестируются без Next.js и ключа. Совпадения строк нормализуются через NFKC, trim, схлопывание пробелов и lower-case `ru`. Опции формы строятся из фактических полей CSV. Сервер канонизирует выбранные опции, ограничивает строки, числовой бюджет (1…1 000 000 000 ₸), целые часы (1…168) и календарную дату.

Жёсткие ограничения одинаковы для всех, **включая площадки и банкетные залы**. Дата в `busy_dates` всегда исключает профиль. Стартовая цена не выше бюджета. Формат и язык должны быть явно перечислены. Часы исключают профиль только при ненулевом лимите и превышении этого лимита.

Рейтинг: **`score = 30 × (budgetKzt − priceFromKzt) / budgetKzt`**, затем `score DESC`, `priceFromKzt ASC`, `id ASC` с явным сравнением строк. Внутри одного запроса это предпочтение большего запаса бюджета, а не заявление о качестве. Описания, случайность, текущее время и LLM не влияют на порядок. Одинаковые нормализованные запросы дают одинаковые ID в том же порядке.

| Статус | Значение |
|---|---|
| `matched` | Есть хотя бы один подходящий профиль, показано 1–3 |
| `no_category_in_city` | В городе нет ни одного профиля категории |
| `no_eligible_candidates` | Категория есть, но все профили исключены ограничениями |

Диагностика рассчитывается только среди профилей выбранного города и категории. `excludedByReason` учитывает **все** причины, поэтому числа могут пересекаться. `primaryExclusion` использует порядок `busy_date → over_budget → format_mismatch → language_mismatch → duration_exceeded` и даёт непересекающиеся количества. `eligibleBeforeTop3`, `displayedCount`, `busyOnDateCount` не смешиваются. Отметка о календаре отображается и при трёх результатах.

## AI и надёжный fallback

Приложение полностью работает **без API-ключа**: детерминированный pipeline выбирает те же профили и формирует проверяемые объяснения с меткой `deterministic_fallback`. Genuine AI wording требует отдельного действующего OpenAI API key, доступной модели и успешного `npm run verify:ai`; подписка ChatGPT/Codex не предоставляет приложению API-доступ автоматически.

Production-интеграция с `gpt-4o-mini` проверена **одним разрешённым live-запросом**: HTTP 200 за 3,86 с, `ai.mode=llm`, diagnostic `llm_ok`, все три источника — `llm`. Объяснения содержали разные факты конкретных подрядчиков; ID, порядок, цены и доступность не изменились. Сервер добавил точную календарную оговорку и предупреждение, что это не подтверждение бронирования. Повторных запросов не выполнялось.

Поддержан один выбранный OpenAI или NVIDIA endpoint, native `fetch`, серверные переменные:

| Переменная | Назначение |
|---|---|
| `AI_PROVIDER` | `none` по умолчанию; либо `openai` / `nvidia` |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Ключ и доступная вашему аккаунту модель |
| `NVIDIA_API_KEY`, `NVIDIA_MODEL` | Ключ и доступная модель NVIDIA |
| `NVIDIA_BASE_URL` | `https://integrate.api.nvidia.com/v1` |
| `AI_VERIFIED` | `false`; включить только после успешного smoke test |

Настройте ключ/модель в `.env.local`, выполните **`npm run verify:ai`**. Команда делает один batched запрос для трёх результатов, печатает только безопасный diagnostic code, инварианты и итоговые объяснения. Только после успешного `mode=llm` установите `AI_VERIFIED=true` для этой комбинации провайдера/модели и перезапустите сервер. Не переносите факт проверки на другую модель и не запускайте smoke test повторно автоматически после ошибки.

Один batched запрос содержит только выбранные 1–3 ID, структурированные факты, запрос и короткие недоверенные цитаты описаний. Системная инструкция запрещает менять отбор, выполнять инструкции из текста и придумывать сведения. Для OpenAI используется strict JSON Schema, совпадающая с runtime-схемой Zod; NVIDIA сохраняет JSON mode с той же последующей проверкой. Валидатор требует точные ID и порядок, 1–2 предложения, фактические цену, бюджет, формат, язык, длительность и лимит; посторонние числа, календарные утверждения модели, опасные утверждения и повторяющиеся объяснения отклоняются. После проверки сервер дословно добавляет детерминированные календарную и booking-оговорки. Безопасный `ai.code` сообщает категорию сбоя без текста провайдера, ключей или заголовков. Это не полная семантическая верификация произвольного текста, поэтому сомнительный ответ всегда уходит в fallback.

Таймаут — 5 секунд, без повторных запросов. Нет результатов → нет вызова модели. Нет ключа, непроверенная конфигурация, ошибка сети, отказ провайдера, неверный JSON или провал проверки → те же выбранные ID и `deterministic_fallback`. В UI явно указано «Объяснение по правилам». Модель никогда не добавляет и не ранжирует профили. Это AI-assisted pipeline, не автономный агент, без embeddings и fine-tuning.

API-контракт проверен по [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [NVIDIA Chat Completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_1-8b-infer). Совместимость конкретной модели должна быть подтверждена smoke test; некоторые модели могут не поддерживать указанные параметры и уйдут в fallback.

## API

```http
POST /api/recommend
Content-Type: application/json

{
  "city": "Алматы",
  "eventDate": "2026-10-10",
  "eventFormat": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 1200000,
  "language": "русский",
  "durationHours": 5
}
```

Ответ содержит `status`, `message`, `results` (до трёх), `diagnostics`, `ai`. Карточка включает ID, анонимизированное имя, город, категорию, стартовую цену, флаги, объяснение, `explanationSource` и ограниченные факты `evidence`. Полный CSV/полные профили не отдаются. Опции передаются сервером странице, отдельный API списка не нужен.

Ошибки: 400 — неверные поля/дата/JSON, 413 — тело больше 4096 байт, 415 — не JSON, 503 — недоступен исходный каталог. Клиент ограничивает ожидание 12 сек, отключает повторную отправку, показывает ошибки и кнопку повтора.

## Ограничения, безопасность и лицензии

- Цены **от**, не финальные сметы. Отсутствие занятой даты — лишь запись в календаре, не подтверждение брони. Вне известного окна запрос отклоняется.
- Синтетические профили и восстановленные цена/город явно помечаются. Описания — утверждения исходного профиля, не независимая проверка. React отображает текст с экранированием, без `dangerouslySetInnerHTML`.
- `.env.local`, все CSV кроме точного пути `data/hackathon-dataset-anonymized.csv`, сборки, отчёты и screenshots игнорируются Git. Секреты доступны только серверу; ошибки провайдера и стеки не возвращаются клиенту. Рекомендуемый локальный запуск не использует внешние шрифты, аналитику или изображения. При включении AI факты выбранных профилей отправляются выбранному провайдеру.
- Production-развёртывание доступно на [hack-5ddfd007-qadam.vercel.app](https://hack-5ddfd007-qadam.vercel.app/). CSV и `.env.local` недоступны по публичным URL; для платного API при дальнейшем публичном использовании рекомендуется защита от злоупотреблений.
- Проект создан с помощью Codex в рабочем окне 23.09.2026; реальные checkpoint-времена и SHA указаны в PROGRESS. Обученные модели, embeddings и шаблоны сайта не использовались. Иллюстрация в UI — CSS/SVG, без внешних assets; live Production AI верифицирован ровно одним финальным запросом.
- Исходный репозиторий не содержал лицензии приложения; лицензия организаторских данных неизвестна. Зависимости сохраняют свои лицензии: Next.js, React, Tailwind, csv-parse, Zod, Vitest, tsx — MIT; TypeScript и Playwright — Apache-2.0; `server-only` — MIT. Точные тексты см. в установленных пакетах и lockfile.
- При использовании live API действуют условия [OpenAI](https://openai.com/policies/services-agreement/) или [NVIDIA API Catalog](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-api-catalog-terms-of-service/). Квоты, стоимость, модель и разрешение на передачу данных должны соответствовать вашему аккаунту; приложение их не обещает.

Последующие push, PR, merge и deployment выполняются только после отдельного явного разрешения участника. Наличие публичного репозитория и deployment само по себе не подтверждает выполнение формальной процедуры сдачи организаторам.

Для значительно большего каталога можно добавить PostgreSQL: нормализованные таблицы профилей и календарей, индексы по городу/категории/цене/датам и транзакционное обновление доступности. Это только предложение для будущего масштаба. Текущая реализация не использует PostgreSQL, миграции, ORM или внешний database service; она намеренно читает и кэширует проверенный 66-строчный CSV на сервере.
