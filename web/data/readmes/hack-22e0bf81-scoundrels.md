# RouteMap — голосовой AI-маршрутизатор

Проект команды **Scoundrels** для HackAlem AI, трек «Коммуникации», кейс
Voice Router от Halyk Bank. RouteMap помогает клиентам вымышленной страховой
компании Saqta задать вопрос голосом или текстом и попасть в нужный сценарий.

LLM выбирает один или несколько из **40 бизнес-сценариев и 3 системных намерений**.
Система сохраняет темы разговора при переключении, использует данные Saqta
для ответа и озвучивает его. Панель супервизора показывает маршрут, альтернативы,
слоты и задержки. Поддерживаются RU, KK, EN и смешанная речь; интерфейс — RU/KK.

## Запуск

Нужны Python 3.11+ и ключ OpenAI. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Скопируйте `.env.example` в `.env`, если его ещё нет. Впишите свой
`OPENAI_API_KEY`, поставьте `APP_MODE=live` и сохраните модели из примера:
`gpt-6-luna`, `gpt-transcribe`, `gpt-4o-mini-tts`. Ключ хранится только на сервере.

```powershell
.\.venv\Scripts\python.exe run.py
```

Откройте [localhost:8000](http://127.0.0.1:8000), отправьте текст или удерживайте
кнопку микрофона во время речи. [API-документация](http://127.0.0.1:8000/docs).
На Linux/macOS используйте `.venv/bin/python`.
По умолчанию `APP_MODE=scaffold`: интерфейс работает без платных LLM/STT/TTS-вызовов.

## Технологии

Python, FastAPI, Pydantic, OpenAI Responses API со Structured Outputs;
HTML/CSS/JavaScript и MediaRecorder. Голосовой путь: **STT → LLM-маршрутизатор →
ответ по данным Saqta → TTS**. База знаний и тестовые клиенты — из официального
набора `case_2/voice_router_dataset/`. Node.js и отдельная БД для запуска не нужны.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
# Дополнительно, если установлен Node.js 22.7+:
node --test frontend/tests/*.test.mjs
```

**85 Python-тестов и 13 JS-тестов** проходят без API-ключа и расходов. Для ручной проверки
отправьте «Действует ли мой полис?» — ожидается `SC25` и запрос данных для проверки.
Голосовой ввод должен вернуть транскрипт, маршрут и озвученный ответ.

На доступном dev-наборе после настройки промпта: **104/104** реплики и
**40/40** маршрутов в 10 диалогах. Это результаты на известных данных.
Подробнее: [оценка маршрутизации](backend/router/evals/README.md),
[голосовые проверки](backend/voice/evals/README.md).
Потоковая озвучка начинает воспроизведение до окончания загрузки;
[замеры и повторение эксперимента](docs/PERFORMANCE.md).

## Ограничения

Это симулятор: реализованы справочные ответы, проверка тестового полиса и обращения;
остальные сценарии используют подсказки из каталога. Изменение данных, SMS и передача
оператору не выполняются реально. Сессии ограничены 10 репликами и хранятся в памяти.
В четырёх браузерных A/B-пробах поток уменьшил медиану ожидания озвучки
с **1,91 до 1,18 с**. Это только TTS, не вся цепочка: LLM остаётся основной
задержкой, цель ≤1,5 с от конца речи до звука пока не достигнута.

Live-вызовы расходуют OpenAI-бюджет. `SESSION_BUDGET_USD` и `RUN_BUDGET_USD`
ограничивают локальные резервы запросов; это не точный счёт провайдера.
