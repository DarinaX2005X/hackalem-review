# SanaLab

**`hack-b2505c12-sanalab` — репозиторий команды SanaLab для хакатона.**

По техническому заданию проект предназначен для описания задач бизнеса: пользователь формулирует потребность, сохраняет редактируемую карточку, подтверждает сведения и видит оценку полноты задачи. В обсуждённой структуре предусмотрены аккаунты представителей бизнеса и студентов.

> **О версии документа.** Зависимости и точка запуска проверены по переданным корневым файлам; структура данных — по схемам двух резервных баз SQLite. Разделы о функциях и маршрутах основаны на ТЗ и коде из обсуждения проекта. Актуальные папки `accounts`, `backend`, `frontend`, `config` и рабочая база `db.sqlite3` в последнюю загрузку не вошли, поэтому наличие всех функций в текущем репозитории и успешный запуск не подтверждены.

## Функциональность по ТЗ

| Направление | Требование |
| --- | --- |
| Аккаунты | Регистрация, вход и личный кабинет для ролей «Представитель бизнеса» и «Студент». |
| Создание задачи | Свободный ввод названия, описания, потребности, ожидаемого результата, контакта и формата взаимодействия. |
| Карточка задачи | Просмотр сохранённых сведений и редактирование существующей записи. |
| Ручное подтверждение | Отдельное действие подтверждения после проверки введённых данных. |
| Оценивание | Рейтинг полноты от 0 до 100, расшифровка баллов и список недостающих сведений. |
| Пересчёт | Обновление оценки после редактирования и сохранения задачи. |

В ранее обсуждённом сценарии подтверждение выполняет **автор задачи**, а не модератор. Сохранение изменений возвращает карточку в черновик и требует повторного подтверждения. Реализацию этих переходов необходимо сверять с текущими обработчиками.

### Данные задачи

| Поле | Имя в модели из обсуждения | Содержание |
| --- | --- | --- |
| Название | `title` | Краткое название задачи. |
| Описание | `description` | Текущая ситуация и контекст проблемы. |
| Потребность | `need` | Что необходимо для решения задачи. |
| Ожидаемый результат | `expected_result` | Желаемые изменения и признаки достижения результата. |
| Контакт | `contact` | Удобный способ связи, указанный свободным текстом. |
| Формат взаимодействия | `interaction_format` | Предпочтительный способ совместной работы. |

Все шесть столбцов присутствуют в таблице `backend_businessrequest` резервной базы `db.before_request_features.sqlite3`. Это подтверждает структуру снимка, но не правила проверки формы и не состояние рабочей базы.

### Рейтинг полноты

ТЗ предусматривает общую оценку **0–100**, пояснение начисленных баллов и рекомендации, какие сведения повысят рейтинг. После сохранения изменений пользователь должен видеть актуальную оценку.

Конкретные веса и пороги исходным ТЗ не заданы. В подготовленном ранее дополнении расчёт был вынесен в `backend/task_rating.py`, а вывод — в шаблоны карточки и списка. В последнюю загрузку этот модуль не вошёл: действующие критерии необходимо проверять в коде репозитория.

Рейтинг полноты не следует представлять как оценку достоверности, коммерческой ценности или выполнимости задачи. Он также не заменяет ручное подтверждение.

## Локальный запуск

Инструкция рассчитана на **полный репозиторий** с приложениями, настройками и миграциями. Одних приложенных корневых файлов недостаточно: отсутствие `config/settings.py` или кода приложений нельзя исправить установкой зависимостей.

Перед обновлением существующего проекта сохраните копию кода и рабочей базы. Не подменяйте `db.sqlite3` одним из резервных снимков для обычного запуска.

### 1. Открыть корень проекта

Перейдите в уже скачанный или клонированный репозиторий:

```bash
cd hack-b2505c12-sanalab
python --version
```

Адрес репозитория в переданных файлах не указан, поэтому команда клонирования с предполагаемым URL здесь не приводится.

### 2. Создать и активировать окружение

При первом запуске:

```bash
python -m venv venv
```

Если рабочее окружение уже создано, достаточно его активировать. Выберите команду для своего терминала.

**Windows — Git Bash:**

```bash
source venv/Scripts/activate
```

**Windows — CMD:**

```bat
venv\Scripts\activate.bat
```

**Windows — PowerShell:**

```powershell
.\venv\Scripts\Activate.ps1
```

**Linux / macOS — Bash или Zsh:**

```bash
source venv/bin/activate
```

На Linux/macOS при отсутствии команды `python` для создания окружения используйте `python3 -m venv venv`.

### 3. Установить зависимости

В активированном окружении:

```bash
python -m pip install -r requirements.txt
python -m django --version
```

После установки из приложенного файла ожидаемая версия Django — `6.0.6`. Если установщик не находит одну из закреплённых версий, сначала проверьте версию Python, доступ к индексу пакетов и корректность командного окружения; не заменяйте зависимости произвольными версиями без согласования с командой.

### 4. Проверить проект и применить миграции

```bash
python manage.py check
python manage.py migrate
```

Выполняйте команды по очереди и исправляйте ошибку предыдущей до запуска следующей. При обычном развёртывании применяются миграции из репозитория. `makemigrations` нужен для изменений моделей, а не вместо отсутствующих исходников.

### 5. Запустить сервер разработки

```bash
python manage.py runserver
```

Откройте в браузере:

```text
http://127.0.0.1:8000/
```

Остановка сервера — `Ctrl + C`. `runserver` предназначен для локальной разработки, а не для публичного размещения.

## Страницы и маршруты

Адреса приведены по маршрутам из обсуждения. Они предполагают подключение `frontend.urls` к корню сайта и `accounts.urls` под префиксом `accounts/`; актуальный `config/urls.py` необходимо сверить с репозиторием.

| Адрес | Назначение |
| --- | --- |
| `/` | Главная страница. |
| `/request/` | Создание задачи. |
| `/requests/` | Список «Мои заявки» из дополнения к карточкам. |
| `/accounts/` | Выбор типа аккаунта. |
| `/accounts/business/register/` | Регистрация представителя бизнеса. |
| `/accounts/business/login/` | Вход представителя бизнеса. |
| `/accounts/business/` | Личный кабинет представителя бизнеса. |
| `/accounts/student/register/` | Регистрация студента. |
| `/accounts/student/login/` | Вход студента. |
| `/accounts/student/` | Личный кабинет студента. |
| `/accounts/logout/` | Выход; в присланной реализации используется POST-форма. |

В показанном `accounts/urls.py` личный кабинет имеет имя `accounts:dashboard` и принимает параметр `role` со значением `business` или `student`. Страницы входа и регистрации используют имена `accounts:login` и `accounts:register`.

Точные адреса отдельных карточек и их редактирования следует брать из текущего `frontend/urls.py`; в корневых файлах они не определены.

## База данных и резервные копии

| Файл | Что подтверждает схема снимка |
| --- | --- |
| `db.before_form_tz.sqlite3` | Таблица `backend_businessrequest` содержит первоначальные поля: компанию, email, тип обращения, название, описание, ожидаемый результат и дату создания. |
| `db.before_request_features.sqlite3` | В таблице задач дополнительно присутствуют `need`, `contact`, `interaction_format`, `status`, `confirmed_at`, `updated_at`, `owner_key` и `revision`. Также присутствует `accounts_accountprofile` со столбцами `role` и `user_id`. |

Наличие столбцов статуса и подтверждения само по себе не доказывает работу соответствующих действий в интерфейсе. Снимки нельзя считать достоверным описанием последней версии моделей.

При подготовке документа проверялась структура таблиц, а не содержимое пользовательских записей. Для запуска проекта используйте актуальные миграции и выбранную рабочую базу; не удаляйте историю миграций для устранения ошибки формы или шаблона.

### Что исключено из Git

В приложенном `.gitignore` указано:

```gitignore
__pycache__/
*.py[cod]
db.sqlite3
venv/
.venv/
```

В этом файле нет правила для `db.before_*.sqlite3`. Перед публикацией проекта проверьте, не попадут ли резервные базы в репозиторий.

Возможное дополнение, которое **не применено автоматически**:

```gitignore
*.sqlite3
*.sqlite3-*
.env
```

Правила `.gitignore` не прекращают отслеживание файлов, уже добавленных в Git. Изменения состава репозитория нужно проверять отдельно; публикация резервной базы может раскрыть содержащиеся в ней данные.

## Проверка изменений

После внесения правок в полный проект:

```bash
python manage.py check
python manage.py test
```

Если установлен ранее подготовленный модуль оценки и существует `backend/test_task_rating.py`, отдельно доступны его тесты:

```bash
python -m unittest backend.test_task_rating -v
```

Присутствие этого тестового файла и результаты тестов в текущей версии не проверены по последней загрузке. Успешная системная проверка не заменяет проверку пользовательского сценария.

### Проверка сценария по ТЗ

1. Зарегистрировать тестовый аккаунт, выйти и повторно войти; проверить переход в кабинет своей роли.
2. Создать задачу с шестью полями и убедиться, что после открытия карточки данные сохранены.
3. Отредактировать карточку и проверить, что изменяется та же запись, а не создаётся новая.
4. Проверить расшифровку рейтинга и рекомендации, затем изменить сведения и сравнить оценку после сохранения.
5. Выполнить ручное подтверждение и отдельно проверить поведение статуса после редактирования.

Дополнительно следует проверить доступ к карточкам из другого аккаунта и другой сессии. В ранее подготовленном дополнении использовалась привязка к сессии; её нельзя автоматически считать привязкой к учётной записи после добавления авторизации.
