# TASKER

Платформа бизнес-задач для студенческих команд на HackAlem. Бизнес формулирует потребность, команды изучают условия в паспорте задачи. В одной сборке объединены актуальный backend и исходный интерфейс 3600d55^ с именем TASKER и увеличенными шрифтами. В браузере работают открытый каталог, серверный рейтинг, фильтры, команды, избранное и паспорт задачи. Формы создания, AI, подтверждения, публикации, отправки откликов и решений бизнеса в восстановленном интерфейсе отсутствуют; серверные реализации сохранены.

## Запуск

Node.js 20 или новее. Сторонние зависимости не нужны.

```sh
node --version
npm start
```

Открыть http://127.0.0.1:3000/ без `?preview=1`. Данные загружаются через API; в шапке отображается «API подключён». Сервер слушает только локальный адрес. Это демонстрационный проект с синтетическими примерами и переключателем ролей, без настоящей аутентификации.

```sh
npm test
```

135 тестов проверяют рейтинг, фильтры, HTTP API v1, хранение, AI и fallback, отклики и принятые этапы, внутренние сервисы v2 и транспорт интерфейса. POST не повторяется автоматически при неопределённом сетевом результате; preview не отправляет записи. Объединённая сборка проверена на Node 20.9.0; серверный автор также проверял Node 24.19.0.

Переменные окружения:

| Имя | По умолчанию | Назначение |
| --- | --- | --- |
| PORT | 3000 | Локальный порт, целое число 1–65535 |
| DATA_FILE | data/state.json | JSON-база; относительный путь считается от рабочей папки процесса |

При первом запуске база создаётся из seed. На один DATA_FILE запускается только один сервер. База и секреты не входят в Git. PORT и DATA_FILE задаются окружением запуска. Настройки серверного AI описаны в src/ai/README.md; ключи и локальные .env не публикуются.

Для самостоятельного предпросмотра интерфейса: `npm run preview`, адрес http://127.0.0.1:4173/?preview=1. Этот явный режим читает статическую фикстуру и не используется вместо API при ошибках.

## Архитектура

- public/ — интерфейс и транспорт API; официальный рейтинг не рассчитывается в браузере.
- server.mjs — стандартный HTTP-сервер Node и раздача public/.
- src/domain.mjs — поля, шкала, валидация и каталог.
- src/store.mjs — последовательная запись JSON через временный файл и rename.
- src/state.mjs — выдача состояния и расчёт баллов команд из подтверждённых этапов.
- src/seed.mjs — по пять синтетических черновиков, задач, команд и откликов.
- tests/ — серверные, интеграционные и транспортные тесты.

Backend 725948c сохранён целиком: реализованы все endpoints API v1 из docs/API_CONTRACT.md. Исходный app.js вызывает только GET /api/state и GET /api/catalog; createTask сохранён в транспорте для последующего подключения формы. Сервисы v2 пока не подключены к HTTP и экранам, живой Google-вход отложен. Актуальные границы готовности — docs/FRONTEND_STATUS.md и docs/BACKEND_STATUS.md.

Айдентика и продуктовые решения: [docs/BRAND_DIRECTION.md](docs/BRAND_DIRECTION.md). Исходная карточка показывает серверный балл, в паспорте раскрывается серверная расшифровка по семи группам. Баллы браузер не пересчитывает. Прежняя витрина /tasker-system.html сохранена для истории и больше не определяет рабочий дизайн.

## Рейтинг

Баллы начисляются только за непустые подтверждённые поля. Контекст и потребность — по 10; данные — 20; результат и критерии успеха — по 15; ограничения и пользователи — по 10; контакт — 3, формат взаимодействия — 3, обратная связь — 4. Максимум 100. Название нужно для публикации, баллов не даёт.

0–39 — требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Каталог включает все опубликованные задачи, даже с нулевым рейтингом, и сортирует их по баллам. При равенстве раньше показана задача с более ранней публикацией. Поиск работает по полям, компании, отрасли и тегам. Неопубликованный черновик в каталог не попадает.

## Проверка первого этапа вручную

1. Открыть приложение без preview: пять задач с рейтингами 100, 90, 65, 45, 20.
2. Найти «Карты»: остаётся туристическая задача. Сбросить фильтры: вернутся все пять.
3. Открыть задачу студии с 20 баллами: увидеть заполненные и отсутствующие поля и причины рейтинга.
4. Проверить фильтры отрасли и готовности, избранное и список команд.
5. Повторно запустить сервер: существующая база читается без пересоздания seed.
6. Проверить ширины 1440/664/390: каталог обоими видами, команды и диалог задачи, без горизонтального переполнения.

## Работа команды

Правила и владельцы: AGENTS.md и docs/COORDINATION.md. Перед небольшим этапом выполнить `npm run team:sync -- frontend` или `npm run team:sync -- backend`. Команда получает опубликованные изменения и читает статус коллеги; рабочие файлы не меняет.
