### Өнім қандай мәселені шешеді

HACKALEM AI / «Электрокомплект» ЖШС кейсі бойынша жеткізушілерге берілетін тапсырыстарды есептеуге арналған қолданба. Сату тарихын, қойма қалдықтарын, жолдағы тауарларды, маусымдылықты, сұраныстың өсуін, тауардың болмаған кезеңдерін және бір реттік ірі сатылымдарды өңдейді. Нәтижесінде түсіндірмесі бар, менеджер тексере алатын және файлға экспортталатын ұсыныстар қалыптасады.

Екі нұсқа да **бір репозиторийде** орналасқан, бірдей есептеулерді қолданады және **қазақша, русский және English** тілдерін қолдайды.

Негізгі пайдаланушы — сатып алу бөлімінің менеджері. ProcureFlow сату мен қалдықтар туралы деректерді бір есепке біріктіруге, қорды толықтыру қажеттілігін анықтауға және тапсырысты рәсімдеу алдында оны тексеруге көмектеседі. Маусымдылық, тұрақты өсу және тауар болмаған кездегі қанағаттандырылмаған сұраныс бөлек ескеріледі; бір реттік ірі сатып алулар, оның ішінде бір клиенттің ірі сатып алуы, тұрақты сұранысты бағалаудан алынып тасталады.

**Кіріс деректері:** сату тарихы, клиенттердің иесіздендірілген идентификаторлары, қоймалар бойынша қалдықтар, тауар болмаған кезеңдер (stockout), жолдағы тауарлар, санаттар, жеткізушілердің жеткізу мерзімдері және 1С жүйесінен алынған материалдық ведомость. **Нәтиже:** жеткізушілер бойынша топтастырылған, әр артикул үшін саны, тапшылық қаупі және негіздемесі көрсетілген ұсыныстар. Менеджер тапсырысты түзетіп, бекітеді, содан кейін файлды өзі экспорттайды.

Өнімнің мақсаты — артық қорды, тапшылықты және Excel-де қолмен есептеуге кететін уақытты азайту. Нақты экономикалық әсерді компанияның тарихи деректері мен пилоттық қолдану нәтижелері бойынша бағалау қажет.

### Іске қосу жолы

Кестеден қажетті нұсқаны таңдаңыз. Қадамдық командалар төменде берілген: [Web нұсқасын компьютерде іске қосу](#kk-web), [Windows нұсқасын бастапқы кодтан іске қосу](#kk-windows), [Windows EXE құрастыру](#kk-build). Дайын Portable EXE файлы Node.js орнатпай-ақ екі рет шерту арқылы іске қосылады.

#### Қай нұсқаны таңдау керек

| Міндет | Нені таңдау керек | Қалай ашылады |
| --- | --- | --- |
| Қолданбаны сілтеме арқылы жылдам ашу, әртүрлі операциялық жүйеде жұмыс істеу | **Web — main-web** | GitHub Pages сайтында жарияланған нұсқа |
| Web нұсқасын өз компьютерінде жергілікті іске қосу | **Web — main-web** | START-WEB.cmd немесе npm start |
| Сайтқа кірмей, бөлек Windows терезесінде жұмыс істеу | **Windows — main-windows** | Portable EXE немесе Setup орнатқышы |
| Кодты өзгерту немесе Windows қолданбасын құрастыру | **main-windows** | Node.js 24, npm ci, npm start |

Есептеу және жүктелген кестелерді өңдеу пайдаланушының құрылғысында орындалады. Web нұсқасында серверлік дерекқор мен пайдаланушы тіркелгісі жоқ. Жарияланған сайтты ашу үшін интернет қажет; интернетсіз тұрақты жұмыс істеу үшін жергілікті веб-серверді немесе дайын Windows қолданбасын пайдаланыңыз.

**.pfproject** жобалары екі нұсқа арасында үйлесімді. Жұмысты ауыстыру үшін жоба файлын бір нұсқада сақтап, екіншісінде ашыңыз. Автоматты синхрондау жоқ. Жобаны ашқаннан кейін тапсырыстарды қайта бекіту қажет.

**main-web және main-windows — Git тармақтары емес, қалталар.** Репозиторийде ортақ main немесе master тармағы қолданылады. GitHub Actions баптаулары түбірлік .github қалтасында орналасады: GitHub ішкі main-web/.github немесе main-windows/.github қалталарындағы workflow файлдарын іске қоспайды.

Әр нұсқаның жеке package.json файлы және өз тәуелділіктері бар. npm командалары таңдалған қалтаның ішінде орындалады. Бастапқы код, жұмыс деректері және құрастыру нәтижелері араластырылмайды: Web нұсқасы main-web/_site қалтасына, Windows нұсқасы main-windows/dist қалтасына құрастырылады.

### Тілді таңдау

Қолданбаның тіл тізімінен **Қазақша**, **Русский** немесе **English** таңдаңыз. Тілді ауыстыру бетті қайта жүктемейді; ағымдағы деректер, қолмен енгізілген мөлшерлер және тапсырыстардың бекітілу күйі сақталады. Таңдалған тіл құрылғыда жұмыс жобасынан бөлек сақталады.

Қолданбаның интерфейсі аударылады. Тауарлар, жеткізушілер, қоймалар атаулары және файлдарыңыздағы басқа мәндер бастапқы күйінде қалады. Экспортталатын есептердегі стандартты тақырыптар мен негіздемелер таңдалған тілде беріледі. Кіріс шаблондарының құрылымы мен 1С жүйесімен алмасуға арналған бапталатын баған атаулары тіл ауысқанда өзгермейді.

<a id="kk-web"></a>

### Web нұсқасын компьютерде іске қосу

**Node.js 24** және онымен бірге npm орнатыңыз. Жүктеп алынған репозиторийдің түбірінде PowerShell ашыңыз:

~~~powershell
cd main-web
npm.cmd start
~~~

**http://127.0.0.1:8000/** мекенжайын ашыңыз. Сервер терезесін ашық ұстаңыз; жұмысты аяқтау үшін Ctrl+C басыңыз. Командалардың орнына **main-web/START-WEB.cmd** файлын екі рет шертуге болады.

macOS/Linux жүйелерінде npm.cmd орнына npm қолданыңыз. Web нұсқасын іске қосу үшін сыртқы npm тәуелділіктері қажет емес. Фондық есептеулер мен браузердің қорғаныс тетіктері жұмыс істеуі үшін оны жергілікті HTTP-сервер арқылы ашыңыз.

<a id="kk-windows"></a>

### Windows нұсқасын бастапқы кодтан іске қосу

**Windows x64 және Node.js 24** қажет. Репозиторий түбірінен жаңа PowerShell терезесін ашып, орындаңыз:

~~~powershell
cd main-windows
npm.cmd ci
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm.cmd start
~~~

Тәуелділіктерді алғаш орнатқанда және бірінші рет іске қосқанда Electron жүктеу үшін интернет қажет. Қайта іске қосу үшін npm.cmd start жеткілікті. package-lock.json өзгергеннен кейін npm.cmd ci командасын қайта орындаңыз.

Баламасы — **main-windows/START-WINDOWS.cmd** файлын екі рет шерту. Ол тәуелділіктер жоқ болса, оларды орнатып, қолданбаны ашады.

<a id="kk-build"></a>

### Windows EXE құрастыру

**main-windows** қалтасында орындаңыз:

~~~powershell
npm.cmd ci
npm.cmd test
npm.cmd run check:offline
npm.cmd run dist:win
~~~

Немесе **BUILD-WINDOWS.cmd** файлын іске қосыңыз. main-windows/dist қалтасында мына файлдар пайда болады:

- **ProcureFlow-Portable-…-x64.exe** — орнатусыз іске қосылады.
- **ProcureFlow-Setup-…-x64.exe** — ағымдағы пайдаланушыға арналған орнатқыш.

Дайын EXE үшін Node.js қажет емес. Қолданба интернетсіз, жергілікті жұмыс істейді. Бұл репозиторийде Windows кодына қол қою сертификаты бапталмаған; құрастырылған файлдарда шығарушының цифрлық қолтаңбасы болмайды.

### Бір репозиторийді GitHub-қа жүктеу

Мысалы, **procureflow** атты бос репозиторий жасаңыз. Дайындалған бастапқы код архивін ашып, жасырын .github қалтасын қоса алғанда, **оның ішіндегісін** жүктеңіз. Репозиторийдің басты бетінде README.md, LICENSE, main-web және main-windows көрінуі керек.

Git қолдансаңыз, жоба түбірінде терминал ашыңыз:

~~~powershell
git init
git branch -M main
git add .
git status
git commit -m "Add ProcureFlow Web and Windows"
git remote add origin https://github.com/YOUR_LOGIN/procureflow.git
git push -u origin main
~~~

YOUR_LOGIN орнына GitHub пайдаланушы атыңызды жазыңыз. git status нәтижесіндегі тізімді тексеріңіз: коммерциялық деректер файлдары, .pfproject, node_modules, _site және dist коммитке кірмеуі керек. .gitignore оларды алдын ала алып тастайды.

#### Web нұсқасын жариялау

1. **Settings → Pages → Build and deployment → Source: GitHub Actions** бөлімін ашыңыз.
2. **Actions → Web checks and GitHub Pages → Run workflow** бөлімін ашып, негізгі main немесе master тармағын таңдаңыз.
3. Процестің сәтті аяқталуын күтіңіз. Сайт сілтемесі **Settings → Pages** бөлімінде және **github-pages** ортасында пайда болады.

Workflow main-web нұсқасын тексереді, main-web/_site қалтасын жасайды және тек оның ішіндегісін жариялайды. Сайттағы қолданба **https://YOUR_LOGIN.github.io/procureflow/** түріндегі мекенжайда ашылады; соңына /main-web/ қосылмайды. Windows бастапқы коды, тесттер және жұмыс файлдары сайтқа кірмейді.

Кейінгі өзгерістер кезінде жариялау репозиторийдің негізгі тармағынан орындалады. Pull request кезінде жариялаусыз тексерулер іске қосылады. Pages қолжетімділігі GitHub баптаулары мен тарифіне байланысты. [GitHub Pages ресми нұсқаулығы](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

#### Windows EXE файлын GitHub арқылы алу

1. **Actions → Build Windows EXE** бөлімін ашыңыз.
2. Сәтті аяқталған іске қосуды таңдаңыз немесе **Run workflow** басыңыз.
3. Аяқталған іске қосуда **Artifacts → ProcureFlow-Windows-x64** бөлімін ашыңыз.
4. Жүктелген архивті ашып, Portable немесе Setup таңдаңыз.

Workflow main/master тармақтарындағы Windows нұсқасы өзгергенде, pull request кезінде және қолмен іске қосылады. Ол main-windows қалтасында бекітілген тәуелділіктерді орнатады, тексерулерді орындайды, EXE құрастырады және оралған қолданбаны тексереді. Артефакт құрамында Portable, Setup, SHA256SUMS.txt, тексеру есебі және тәуелділіктердің lock-файлы бар. Сақтау мерзімі — 14 күн; содан кейін құрастыруды қайталауға болады. GitHub Release автоматты түрде жасалатындай бапталмаған.

### Алғашқы есептеу және экспорт

1. Демоны ашыңыз немесе деректерді жүктеу бетінде XLSX/CSV/ZIP файлдарын жүктеңіз. Коммерциялық тест файлдары репозиторийге кірмейді.
2. Танылған дереккөздерді, есептеу күнін және деректер қателерін тексеріңіз. Параметрлерде жеткізушілердің мерзімдерін, қойманы, тапсырыс циклін, қорды және жоспарлы өсімді көрсетіңіз.
3. Ұсыныстарды және тауар карточкасын ашыңыз: онда формула, маусымдылық, тренд, алынып тасталған сатылымдар және тауар болмаған кезеңдегі сұранысты өтеуге арналған түзету көрсетіледі.
4. Белгісіз қалдықтарды нақтылап, қажет болса, ең аз партия мен еселікті ескере отырып, мөлшерді өзгертіңіз.
5. Жеткізушілер бөлімінде тапсырысты тексеріп, жауапты тұлғаны көрсетіңіз және тексеруді растаңыз. Экспорт пайдаланушының әрекетімен орындалады; қолданба тапсырысты жеткізушіге өзі жібермейді.
6. Кейін жалғастыру үшін жобаны қолмен сақтаңыз. Жұмыс жобасы автоматты түрде сақталмайды.

**1С** жүйесінің әмбебап конфигурациясы үшін бекітілген, нөлден үлкен мөлшерлерді XLSX/CSV пішімінде экспорттау қарастырылған. Ұйымды, қойманы көрсетіп, баған атауларын өз дерекқорыңыздың жүктеу өңдегішімен сәйкестендіріңіз. CSV UTF-8 кодтауын BOM белгісімен және «;» бөлгішімен қолданады; XLSX кодтарды мәтін, мөлшерлерді сан ретінде сақтайды.

Әмбебап алмасу пішімі кез келген 1С дерекқорымен дайын интеграция бар дегенді білдірмейді. Жұмыста қолданар алдында тестілік базаға жүктеуді тексеріңіз. [Есептеу әдістемесі, ауытқуларды алып тастау және кіріс шаблоны](main-web/docs/METHODOLOGY.md).

### Деректер және шектеулер

Импорт келісілген, иесіздендірілген деректер жиынынан алынуы тиіс. Танылған клиент өрістері есептеуге дейін жергілікті HMAC-SHA256 идентификаторларымен ауыстырылады; белгісіз мәтіндік өрістерде сезімтал ақпарат болуы мүмкін. Жұмыс жобалары мен экспорт коммерциялық көрсеткіштерді қамтиды және қолданба арқылы шифрланбайды.

.pfproject файлдары бастапқы парақтарсыз қалыпқа келтірілген деректер мен журналды сақтайды. Журнал — жергілікті әрекеттер тарихы; ол электрондық қолтаңба да, қолжетімділікті шектеу жүйесі де емес. Жұмыс жобалары мен деректер файлдарын GitHub-қа жүктемеңіз.

Белгісіз қалдық нөлге тең емес. Ұсыныстардың дәлдігі қалдықтар, жеткізу мерзімдері, клиент идентификаторлары және stockout кезеңдері туралы деректердің толықтығына байланысты. Экономикалық әсер мен болжам сапасын компанияның тарихи деректері бойынша тексеру қажет. Бір файлдың/ZIP көлемінің шегі — 25 МБ, жобаның шегі — 80 МБ; XLS, XLSB және шифрланған кітаптар қолдау таппайды.

<a id="ru-problem"></a>

### Что решает продукт

Приложение для расчёта заказов поставщикам по кейсу HACKALEM AI / ТОО «Электрокомплект». Обрабатывает историю продаж, остатки, товары в пути, сезонность, рост спроса, периоды отсутствия товара и разовые крупные продажи. Результат — рекомендации с объяснениями, проверкой менеджером и экспортом.

Обе версии находятся в **одном репозитории**, используют одинаковые расчёты и поддерживают **қазақша, русский и English**.

Основной пользователь — менеджер отдела закупа. ProcureFlow помогает свести выгрузки продаж и остатков в один расчёт, определить потребность в пополнении и проверить её до оформления заказа. Сезонность, устойчивый рост и упущенный спрос при отсутствии товара учитываются отдельно; разовые крупные покупки, в том числе одного клиента, исключаются из оценки регулярного спроса.

**Вход:** история продаж, обезличенные клиентские идентификаторы, остатки по складам, периоды stockout, товары в пути, категории, сроки поставщиков и материальная ведомость из 1С. **Выход:** рекомендации по артикулам, сгруппированные по поставщикам, с количеством, риском дефицита и обоснованием. Менеджер корректирует и утверждает заказ, затем явно выгружает файл.

Цель продукта — уменьшить избыток запасов, дефицит и время ручного расчёта в Excel. Фактический экономический эффект нужно оценить на истории и в пилоте компании.

Выберите вариант в таблице. Пошаговые команды приведены ниже: [Web на компьютере](#ru-web), [Windows из исходников](#ru-windows), [сборка Windows EXE](#ru-build). Готовый Portable EXE запускается двойным щелчком без установки Node.js.

<a id="ru-web"></a>

### Запуск Web на компьютере

Установите **Node.js 24** вместе с npm. Откройте PowerShell в корне скачанного репозитория:

~~~powershell
cd main-web
npm.cmd start
~~~

Откройте адрес **http://127.0.0.1:8000/**. Держите окно сервера открытым; для завершения нажмите Ctrl+C. Можно вместо команд дважды щёлкнуть **main-web/START-WEB.cmd**.

На macOS/Linux используйте npm вместо npm.cmd. У веб-версии нет внешних npm-зависимостей для запуска. Открывайте её через локальный HTTP-сервер, чтобы работали фоновые вычисления и браузерные механизмы защиты.

<a id="ru-windows"></a>

### Запуск Windows из исходников

Нужны **Windows x64 и Node.js 24**. В новом окне PowerShell из корня репозитория:

~~~powershell
cd main-windows
npm.cmd ci
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm.cmd start
~~~

При первой установке зависимостей и первом запуске нужен интернет для скачивания Electron. Для повторного запуска достаточно npm.cmd start. После изменения package-lock.json снова выполните npm.cmd ci.

Альтернатива — двойной щелчок по **main-windows/START-WINDOWS.cmd**. Он устанавливает зависимости при их отсутствии и открывает приложение.

<a id="ru-build"></a>

### Сборка Windows EXE

В папке **main-windows** выполните:

~~~powershell
npm.cmd ci
npm.cmd test
npm.cmd run check:offline
npm.cmd run dist:win
~~~

Или запустите **BUILD-WINDOWS.cmd**. В main-windows/dist появятся:

- **ProcureFlow-Portable-…-x64.exe** — запуск без установки.
- **ProcureFlow-Setup-…-x64.exe** — установщик для текущего пользователя.

Для готового EXE Node.js не нужен. Приложение работает локально без интернета. Сертификат подписи Windows в этом репозитории не настроен; сборки будут без цифровой подписи издателя.

Экономический эффект и качество прогноза требуют проверки на истории компании. Лимит одного файла/ZIP — 25 МБ, проекта — 80 МБ; XLS, XLSB и зашифрованные книги не поддерживаются.

### What the product solves

An application for calculating supplier orders for the HACKALEM AI / Elektrokomplekt LLP (ТОО «Электрокомплект») case. It processes sales history, stock balances, goods in transit, seasonality, demand growth, stockout periods, and one-off large sales. The result is a set of recommendations with explanations, manager review, and export.

Both versions are located in **one repository**, use the same calculations, and support **қазақша, русский, and English**.

The primary user is a procurement manager. ProcureFlow helps consolidate sales and inventory exports into a single calculation, determine replenishment needs, and review them before placing an order. Seasonality, sustained growth, and unmet demand during stockouts are accounted for separately; one-off large purchases, including those made by a single customer, are excluded from the estimate of regular demand.

**Input:** sales history, anonymized customer identifiers, stock balances by warehouse, stockout periods, goods in transit, categories, supplier lead times, and a materials statement from 1C. **Output:** recommendations by SKU, grouped by supplier, with quantities, shortage risk, and explanations. The manager adjusts and approves the order, then explicitly exports the file.

The product aims to reduce excess inventory, shortages, and time spent on manual Excel calculations. Its actual economic impact must be evaluated using the company's historical data and a pilot deployment.

#### Verifying the mandatory requirements

The manual scenario checks the manager's workflow. Algorithm behavior is verified using reproducible synthetic datasets in the [calculation tests](main-web/tests/engine.test.cjs) and [acceptance tests](main-web/tests/acceptance.test.cjs); the same datasets are available in main-windows.

| Requirement | What must be confirmed |
| --- | --- |
| All sources contribute to the baseline requirement | Changes to history, stock balances, on-time deliveries, category, and planned growth affect the result in control scenarios |
| Seasonality and sustained growth | A seasonal peak is reflected in the forecast; a sustained trend changes the forecast relative to constant demand |
| Unmet demand during stockouts | Compensation increases the demand estimate compared with calculations based on actual sales |
| One-off large orders | An added purchase of 10,000 units by a single customer does not cause a comparable increase in regular replenishment needs |
| Supplier-grouped orders with explanations | Recommendations include explanations; the interface groups orders and allows review before approval |

### Data and limitations

Imports must come from an agreed, anonymized export. Recognized customer fields are replaced with local HMAC-SHA256 identifiers before calculation; unknown text fields may contain sensitive information. Working projects and exports contain commercial metrics and are not encrypted by the application.

.pfproject files store normalized data and the log, without the original worksheets. The log is a local action history, not an electronic signature or an access-control system. Do not upload working projects or data exports to GitHub.

An unknown stock balance is not zero. Recommendation accuracy depends on the completeness of stock balances, lead times, customer identifiers, and stockout periods. Economic impact and forecast quality require validation against the company's historical data. The limit is 25 MB per file/ZIP and 80 MB per project; XLS, XLSB, and encrypted workbooks are not supported.
