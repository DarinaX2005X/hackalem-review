## Қазақша

### Бізге берілген тапсырма

Хакатон тапсырмасы — «мердігерлерді ақылды іріктеу» сервисін жасау. Клиент іс-шараның қаласын, күнін, түрін, мердігер санатын және теңгемен бюджетін енгізеді. Қажет болса, ұзақтығын және мердігердің жұмыс тілін көрсетеді. Сервис осы шарттарға сай **ең көбі 3 карточка** қайтарады.

Негізгі мақсат — каталогты жай көрсету емес, **«неге осы мердігер менің іс-шарама сәйкес?»** деген сұраққа жауап беру. Әр карточкада атау, санат, қала, «бастап» бағасы және профиль фактілеріне сүйенген 1–2 сөйлемдік түсіндірме болуы керек. Жалпылама мақтау, жұлдызша, ойдан шығарылған рейтинг немесе сәйкестік пайызы қолданылмайды. Сирек санат пен бос нәтиже де адал түсіндірілуі тиіс.

### Тапсырманы қалай орындадық

Жобаны екі адамнан тұратын команда болып әзірледік. Жұмысты frontend және backend бағыттарына бөліп, ортақ TypeScript контракт арқылы біріктірдік.

| Бағыт | Орындалған жұмыс |
|---|---|
| Frontend | Іздеу формасы, карточкалар, үш нәтиже күйі, сұраныс қорытындысы, күн мен бюджетті жылдам өзгерту, сүзгілерді алып тастау, қазақша/орысша/ағылшынша интерфейс, қателерді көрсету және қайта іздеу |
| Backend | CSV каталогын оқу және тексеру, API, бос күн/бюджет/формат/тіл/ұзақтық сүзгілері, тұрақты сұрыптау, фактілік түсіндірмелер, AI провайдерлері мен резервтік жауап, автоматты тесттер |
| Бірлескен жұмыс | `shared/types.ts` және `shared/api.md` келісімі, моктардан нақты API-ге өту, интеграцияны тексеру, күн ауыстыру және бос нәтиже демосын дайындау |

Алдымен толық MVP жолын жасадық: **форма → сұраныс → іріктеу → түсіндірмесі бар нәтиже**. Backend дайын болғанға дейін frontend синтетикалық моктармен жұмыс істеді. Кейін нақты каталогқа қостық, үш тілдегі мәтіндерді, күн мен баға пішімдерін түзеттік және интерфейсті жаңарттық. Әзірлеу мен тексеруде Codex көмекшісі пайдаланылды.

### Қазір не жұмыс істейді

- Міндетті өрістер: қала, іс-шара күні, формат, мердігер санаты, бюджет. Қосымша өрістер: сағат саны және жұмыс тілі.
- Каталог мәндері backend-тен алынады. Экрандағы аударма API-ге жіберілетін бастапқы мәнді өзгертпейді.
- Карточкаларда нақты профиль үзіндісі, баға мен бюджет арақатынасы, күннің бос болуы және берілген қосымша шарттар көрсетіледі.
- Нәтиже үстінде сұраныс қорытындысы бар: күнді немесе бюджетті өзгертіп, қайта іздеуге болады.
- Карточкаға кірмеген мердігерлердің себептері бөлек ашылатын тізімде көрсетіледі: бос емес, бюджеттен жоғары, формат/тіл/ұзақтық сәйкес емес немесе алғашқы үштікке кірмеді.
- Интерфейс пен түсіндірмелер қазақша, орысша және ағылшынша. Тіл таңдауы браузерде сақталады; профильден алынған үзінді орысша түпнұсқада қалады.
- `dataFlags` бар карточкада синтетикалық профиль, толықтырылған қала немесе толықтырылған баға белгісі көрінеді.

| API күйі | Пайдаланушы не көреді |
|---|---|
| `found` | Шарттардан өткен 1–3 карточка және нәтиже туралы түсіндірме |
| `no_category` | Таңдалған қалада осы санаттағы профиль жоқ деген хабар |
| `no_match` | Қала мен санатта профильдер бар, бірақ шарттарға сәйкес келмегені және себептері туралы хабар |

`candidatesBeforeCut` — барлық сүзгіден өткен, алғашқы үштікке дейінгі кандидаттар саны. Бұл қаладағы барлық мердігер саны емес. `no_match` кезінде ол 0 болса, интерфейс артық нөлдік жолды көрсетпейді. Бір профиль бірнеше себеппен өтпеуі мүмкін, сондықтан себептердегі сандарды қосып, адам саны деп есептеуге болмайды.

### Іріктеу және AI қалай жұмыс істейді

```text
React интерфейсі :5173
        │ /api сұранысы, Vite proxy
        ▼
Express API :8787
        │
        ├─ CSV каталогы → сұранысты тексеру
        ├─ Қала + санат → күн, бюджет, формат, тіл, ұзақтық сүзгілері
        ├─ Сипаттаманың форматқа қатыстылығы → тең болса ID → ең көбі 3 карточка
        └─ Профиль үзіндісі + тексерілген фактілер → түсіндірме → нәтиже
```

Қатаң сүзгілерді **код** орындайды. Баға тек шек ретінде қолданылады: `priceFromKzt <= budgetKzt`; арзан не қымбат болуы сапа бағасы емес. Өткен профильдер сипаттамадағы форматқа қатысты сөз топтары бойынша реттеледі, тең болса ID шешеді. Бірдей сұраныс бірдей карточкаларды бірдей ретпен береді. Интерфейс тілі іріктеуге әсер етпейді.

AI қосылса, таңдалған карточкалардың бәріне бір batch-сұраныс жіберіледі. Модель тек алдын ала дайындалған профиль үзіндісі мен факті сөйлемінің индексін таңдайды. Сервер ID мен индекстерді тексеріп, мәтінді өзі құрастырады: модель жаңа баға, бос күн немесе тәжірибе қоса алмайды.

Тізбек: **OpenAI → NVIDIA → фактілік шаблон**. Әр провайдерге 1,8 секундқа дейін, жалпы AI бөлігіне 3,6 секунд уақыт шегі берілген. Жарамды AI таңдаулары жергілікті кэшке сақталады. Кілт жоқ болса немесе провайдер істемесе, іріктеу мен түсіндірме шаблон арқылы жұмысын жалғастырады. **Қазылар демосына API кілті міндетті емес.**

### Қазыларға: жобаны іске қосу

**Керек:** Node.js 24, npm және репозиторий көшірмесі. Тексерілген орта: Node.js `24.21.0`, npm `11.19.0`. Алғашқы `npm ci` үшін интернет керек. Тәуелділіктер орнатылғаннан кейін кілтсіз негізгі демо жергілікті жұмыс істейді.

**1. Репозиторийді алу** — терминалда:

```bash
git clone https://github.com/BAITC-Hacks/hack-96ac4fd9-7-s-ai.git
cd hack-96ac4fd9-7-s-ai
```

ZIP жүктелсе, оны ашып, терминалды `frontend/`, `backend/`, `shared/` орналасқан түбірлік папкадан бастаңыз. Келесі екі терминал да осы түбірден басталады. Түбірде `package.json` жоқ: тәуелділіктер әр бөлікте бөлек орнатылады.

**2. Бірінші терминал — backend:**

```bash
cd backend
npm ci
npm start
```

Терминалды ашық қалдырыңыз. Backend: [http://localhost:8787/api/health](http://localhost:8787/api/health). Дұрыс жауап:

```json
{"ok":true,"data":{"status":"up"}}
```

**3. Екінші терминал — frontend, Windows PowerShell:**

```powershell
cd frontend
npm ci
$env:VITE_USE_MOCKS = 'false'
npm run dev
```

macOS/Linux үшін сол қадам:

```bash
cd frontend
npm ci
VITE_USE_MOCKS=false npm run dev
```

**4. Браузерде [http://localhost:5173](http://localhost:5173) ашыңыз.** `index.html` файлын екі рет басып ашудың қажеті жоқ: интерфейс Vite сервері арқылы жұмыс істейді. Екі сервер де бір компьютерде іске қосылуы керек. Тоқтату үшін әр терминалда `Ctrl+C` басыңыз.

`VITE_USE_MOCKS=false` нақты backend пен CSV каталогын қосады. Бұл мән берілмесе, dev режимі әдепкіде синтетикалық моктарды қолданады; бетте демо белгісі көрінеді. Режимді өзгерткеннен кейін Vite-ті қайта іске қосыңыз. Кілттер мен `.env` жасау негізгі іске қосуға қажет емес.

### Қазыларға: 3 минуттық демо

Төмендегі сценарийлер **нақты backend және репозиторийдегі CSV** үшін, моктарға арналмаған. Негізгі сұраныс: **Алматы · 2026-10-06 · Корпоратив · Жүргізуші (`Ведущий`) · 1 000 000 ₸ · 5 сағат · жұмыс тілі Орысша (`ru`)**. Интерфейс тілін Қазақша етіп қалдыруға болады.

| Қадам | Әрекет | Күтілетін нәтиже |
|---|---|---|
| 1 | Негізгі сұранысты жіберу | `found`: 6 кандидат өтті, 3 карточка көрсетілді: `HK-44733`, `HK-88430`, `HK-35215` |
| 2 | Қорытындыда тек күнді **2026-10-01** ету | 2 карточка: `HK-88430`, `HK-44923`; хабарда сол күні бос емес 6 профиль көрсетіледі |
| 3 | Қазақша → Русский → English ауыстыру | Карточкалардың ID-і мен реті сақталады; интерфейс пен түсіндірме тілі өзгереді |
| 4 | Алматы · 2026-10-04 · Корпоратив · Флорист · 300 000 ₸ · 24 сағат; жұмыс тілін бос қалдыру | Сирек нәтиже: 1 карточка, `HK-39372` |
| 5 | Негізгі сұранысқа оралып, Астана + Безендіруші (`Декоратор`) таңдау | `no_category`: осы қалада бұл санат жоқ |
| 6 | Негізгі сұранысқа оралып, тек бюджетті **1 000 ₸** ету | `no_match`: қала мен санатта 10 профиль бар, бірақ ешқайсысы бюджетке сай емес |

Басты сәт — **1 → 2**: күн өзгергенде карточкалардың құрамы өзгереді, ал хабар мен ашылатын тізім кімнің неге көрсетілмегенін түсіндіреді. Тек жоғалған карточкаға қарап себеп болжамаймыз — себеп backend-тен келеді.

### API қысқаша

| Әдіс және жол | Мақсаты |
|---|---|
| `GET /api/health` | Сервердің жұмысын тексеру |
| `GET /api/catalog-options` | Қала, санат, формат және жұмыс тілі нұсқалары |
| `POST /api/match` | Мердігерлерді іріктеу |

Негізгі демоға арналған JSON body:

```json
{
  "city": "Алматы",
  "eventDate": "2026-10-06",
  "eventType": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 1000000,
  "durationHours": 5,
  "language": "ru",
  "locale": "kz"
}
```

`language` — мердігердің жұмыс тіліне сүзгі; `locale` — жауап мәтінінің тілі. API қазақша үшін `kz`, ал frontend ішкі локалі `kk` қолданады. Күн `YYYY-MM-DD`, бюджет оң бүтін сан болуы керек. Сәтті жауап `{ok:true,data:...}`, қате `{ok:false,error:{code,message}}` түрінде беріледі. Бос іріктеу — HTTP 200; жарамсыз сұраныс — HTTP 400. Толық келісім: [shared/api.md](shared/api.md), типтер: [shared/types.ts](shared/types.ts).

Нақты backend 8787 портында жұмыс істеп тұрғанда, түбірден бөлек терминалда:

Backend-тің **21 автоматты тесті** сүзгілерді, тұрақты ретті, күн ауысуын, бос нәтижелерді, валидацияны, тілдерді және AI қатесі кезіндегі резервтік жауапты қамтиды. Frontend тексерістері моктарды, React SSR нәтижелерін, клиент келісімін және аудармаларды тексереді. `checkLiveBackend.mjs` нақты Vite `/api` проксиі арқылы API-ге қосылады; есебі `frontend/.status/t14-backend-check.json` файлына жазылады. Бұл тексеріс браузердегі басу/енгізу әрекеттерін алмастырмайды.

Соңғы тексеруде typecheck, frontend check/build, backend-тің 21 тесті және нақты API интеграциясы өтті. Жинақтау кезінде ірі JS-чанк туралы ескерту бар, build сәтті аяқталады. Қазіргі README-дегі бес негізгі API сценарийі қайта тексерілді.

Production файлдары `frontend/dist/` ішіне жиналады. Серверге орналастырғанда `/api` маршрутын backend-ке бағыттау қажет; бір `dist` папкасын жариялау API-ді іске қоспайды. Хакатон демосы үшін жоғарыдағы екі терминалды тәсіл жеткілікті.

### Deploy: қысқаша нұсқаулық

Бір Linux VPS-та, бір доменмен орналастыру жоспары:

1. Серверге Node.js 24 және Nginx орнатып, репозиторийді толық көшіріңіз. `shared/` және `backend/data/contractors.csv` файлдары да қажет.
2. `backend/` ішінде `npm ci --include=dev` орындап, `npm start` процесін systemd қызметі арқылы тұрақты іске қосыңыз. `tsx` dev dependency болғандықтан, оны орнатудан алып тастамаңыз. Backend осы сервердің `127.0.0.1:8787` адресінде жұмыс істейді.
3. `frontend/` ішінде `npm ci --include=dev`, содан кейін `VITE_USE_MOCKS=false npm run build` орындаңыз. Жарияланатын файлдар — `frontend/dist/`.
4. Nginx-тің `root` мәнін `frontend/dist/` абсолют жолына бағыттаңыз; `/` үшін `try_files $uri $uri/ /index.html;`, `/api/` үшін `proxy_pass http://127.0.0.1:8787;` қолданыңыз. `proxy_pass` адресінің соңына `/` қоспаңыз: backend-ке `/api/...` жолы толық жетуі керек. Vite dev proxy production-да жұмыс істемейді.
5. Доменді сервер IP-іне бағыттап, HTTPS сертификатын қосыңыз. Сыртқа 80/443 порттарын ашу жеткілікті; 8787 ішкі болып қалады. AI кілттері қажет болса, оларды тек backend ортасында сақтаңыз.

## Русский

### Какую задачу мы получили

Задание хакатона — создать сервис «умного подбора подрядчиков». Клиент указывает город, дату, тип мероприятия, категорию подрядчика и бюджет в тенге. Дополнительно можно задать длительность и рабочий язык подрядчика. Сервис возвращает **не более 3 карточек**.

Главная ценность — объяснить **«почему этот подрядчик подходит именно для моего мероприятия?»**. Карточка должна содержать название, категорию, город, цену «от» и 1–2 предложения на основе фактов профиля. Общая похвала, звёзды, выдуманный рейтинг и процент совпадения не используются. Редкие категории и отсутствие результатов должны обрабатываться честно и понятно.

### Как мы выполнили задачу

Мы разработали проект командой из двух человек, разделив работу на frontend и backend и объединив их через общий TypeScript-контракт.

| Направление | Что реализовано |
|---|---|
| Frontend | Форма поиска, карточки, три состояния результата, сводка запроса, быстрое изменение даты и бюджета, удаление фильтров, интерфейс на трёх языках, ошибки и повтор поиска |
| Backend | Чтение и проверка CSV, API, фильтры доступности/бюджета/формата/языка/длительности, стабильная сортировка, фактические объяснения, AI-провайдеры и резервный ответ, автоматические тесты |
| Совместная работа | Контракт `shared/types.ts` и `shared/api.md`, переход от моков к реальному API, проверка интеграции, подготовка демо со сменой даты и пустыми результатами |

Сначала собрали полный MVP-путь: **форма → запрос → подбор → результат с объяснениями**. Пока backend разрабатывался, frontend работал на синтетических моках. Затем подключили реальный каталог, исправили локализацию, даты и суммы, обновили интерфейс. При разработке и проверке использовали помощника Codex.

### Что умеет приложение

- Принимает обязательные параметры: город, дату, формат, категорию и бюджет; дополнительные — количество часов и рабочий язык.
- Получает варианты формы из backend. Перевод подписи на экране не меняет исходное значение, отправляемое в API.
- Показывает выдержку из профиля и проверенные факты: свободную дату по данным каталога, отношение цены к бюджету и дополнительные условия запроса.
- Позволяет менять дату и бюджет прямо в сводке над результатами и повторять поиск.
- В раскрываемом списке объясняет, почему остальные кандидаты не показаны: заняты, дороже бюджета, не подходят по формату/языку/длительности или не вошли в первые три.
- Поддерживает казахский, русский и английский языки интерфейса и объяснений. Выбор языка сохраняется в браузере; цитата из профиля остаётся на русском языке оригинала.
- Показывает `dataFlags`: синтетический профиль, восстановленный город или восстановленная цена.

| Статус API | Что видит пользователь |
|---|---|
| `found` | От 1 до 3 подходящих карточек и пояснение результата |
| `no_category` | В выбранном городе нет профилей этой категории |
| `no_match` | Профили в городе и категории есть, но условия не прошёл никто; указаны причины |

`candidatesBeforeCut` — число прошедших все фильтры до ограничения первыми тремя, а не общее число подрядчиков города. При `no_match` нулевой счётчик отдельно не показывается: остаётся сообщение с причинами. Один профиль может не пройти несколько условий, поэтому суммы причин нельзя считать числом уникальных людей.

### Алгоритм и роль AI

```text
React :5173 → /api через Vite proxy → Express :8787
                                          │
                         CSV → валидация → строгие фильтры
                                          │
                         релевантность описания → ID → до 3 карточек
                                          │
                         выдержка из профиля + факты → объяснение
```

Строгие фильтры выполняет **код**: город, категория, занятость на дату, формат, `priceFromKzt <= budgetKzt`, а при наличии — рабочий язык и длительность. Цена является порогом, а не оценкой качества. Прошедшие профили сортируются по группам слов в описании, связанным с форматом, при равенстве — по ID. Одинаковый запрос даёт одинаковые карточки в одинаковом порядке; язык интерфейса на отбор не влияет.

Если AI подключён, все выбранные профили отправляются одним batch-запросом. Модель выбирает только индексы готовой выдержки и предложения с проверенными фактами. Сервер проверяет ID и индексы, затем собирает текст сам. Новую цену, доступность или опыт модель добавить не может.

Цепочка: **OpenAI → NVIDIA → фактический шаблон**. Лимит каждого провайдера — до 1,8 секунды, всей AI-части — 3,6 секунды. Валидные выборы сохраняются в локальном кэше. Без ключей или при ошибке провайдера подбор продолжает работать с шаблонным объяснением. **Для демонстрации жюри API-ключи не обязательны.**

### Кратко об API

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | Проверка сервера |
| `GET /api/catalog-options` | Города, категории, форматы и рабочие языки |
| `POST /api/match` | Подбор подрядчиков |

JSON body базового демо:

```json
{
  "city": "Алматы",
  "eventDate": "2026-10-06",
  "eventType": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 1000000,
  "durationHours": 5,
  "language": "ru",
  "locale": "ru"
}
```

`language` фильтрует по рабочему языку подрядчика, `locale` задаёт язык текста ответа. Казахский язык в API обозначается `kz`, внутренний locale frontend — `kk`. Дата передаётся как `YYYY-MM-DD`, бюджет — положительным целым числом. Ответ: `{ok:true,data:...}` или `{ok:false,error:{code,message}}`. Пустой подбор возвращает HTTP 200, невалидный запрос — HTTP 400. Полный контракт: [shared/api.md](shared/api.md), типы: [shared/types.ts](shared/types.ts).

### Deploy: краткая инструкция

Схема размещения на одном Linux VPS с одним доменом:

1. Установите Node.js 24 и Nginx, скопируйте весь репозиторий. Сохраните `shared/` и `backend/data/contractors.csv`.
2. В `backend/` выполните `npm ci --include=dev`, затем настройте постоянный запуск `npm start` через службу systemd. Не исключайте dev dependencies: для запуска нужен `tsx`. Backend слушает `127.0.0.1:8787` на этом же сервере.
3. В `frontend/` выполните `npm ci --include=dev`, затем `VITE_USE_MOCKS=false npm run build`. Публикуемый каталог — `frontend/dist/`.
4. В Nginx укажите абсолютный путь к `frontend/dist/` как `root`; для `/` задайте `try_files $uri $uri/ /index.html;`, для `/api/` — `proxy_pass http://127.0.0.1:8787;`. Не добавляйте `/` в конце адреса `proxy_pass`: backend должен получить полный путь `/api/...`. Dev proxy Vite в production не работает.
5. Направьте домен на IP сервера и подключите HTTPS-сертификат. Снаружи достаточно портов 80/443; 8787 остаётся внутренним. Если нужны AI-ключи, храните их только в окружении backend.
6. После размещения проверьте `https://<домен>/api/health`, главную страницу и демо со сменой даты. При обновлении пересоберите frontend и перезапустите службу backend.

Это инструкция по размещению, а не адрес уже опубликованного приложения.

### Необязательное подключение AI

Шаблон переменных: [.env.example](.env.example). Backend читает `backend/.env`, затем корневой `.env`; переменные процесса имеют приоритет. Не добавляйте ключи во frontend или Git.

### Ограничения

Это хакатонный прототип на предоставленном CSV. Календарь не обновляется в реальном времени; свободная дата в датасете не гарантирует реальную бронь. При `maxHours=null` фильтр длительности не применяется: это не обещание неограниченного времени работы. Описание — утверждение из профиля, а не независимо проверенный факт.

Отображаемые имена и иллюстрационные аватары вымышлены. Имена стабильно заменяются по ID; портреты не являются фотографиями реальных людей. Сортировка использует словарную эвристику и не понимает смысл полностью. Бронирование, оплата, личный кабинет и отправка сообщений подрядчику не реализованы.
