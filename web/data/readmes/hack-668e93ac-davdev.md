Что делает проект?

Что реализовано?

- Полноценное клиент-серверное приложение: отдельные React-клиент и TypeScript/Express-сервер, объединённые REST API и WebSocket-каналом.
- Современная интерактивная landing-страница с плавной прокруткой, прогрессом просмотра, кастомным курсором и выразительными 2D/3D-визуальными эффектами.
- Авторизация по электронной почте и паролю с обязательным подтверждением email, восстановлением пароля и автоматической отправкой локализованных писем.
- OAuth-вход через Google, Facebook и GitHub, а также авторизация и привязка аккаунта через Telegram.
- Безопасная аутентификация без пароля через passkeys/WebAuthn с управлением зарегистрированными ключами.
- Двухфакторная аутентификация TOTP: подключение через QR-код, ручной секрет, проверка кода и генерация резервных кодов восстановления.
- Управление активными сессиями и связанными OAuth-аккаунтами из профиля пользователя.
- Защита регистрации и входа: Cloudflare Turnstile, проверка скомпрометированных паролей через Have I Been Pwned, rate limiting, замедление подозрительных запросов, Helmet, CORS и серверная валидация Zod.
- Ролевая модель с пользовательским и супер-административным доступом; защищённые маршруты и отдельная панель управления для супер-администратора.
- Чаты реального времени с сохранением сообщений в PostgreSQL, списком диалогов, счётчиками непрочитанных сообщений, статусами online/offline, индикатором набора текста, прочтением сообщений и URL-навигацией к диалогу.
- Умная доставка сообщений: если получатель не подключён, сообщение дополнительно отправляется через Firebase Push и Telegram при наличии привязанного Telegram-аккаунта.
- Push-уведомления для веб-приложения и Android: запрос разрешений, регистрация устройств, Service Worker для Web Push и нативный мост Tauri/FCM.
- Панель супер-администратора для отправки адресных push-уведомлений конкретному пользователю.
- Профиль пользователя с изменением имени и аватара, автоматической оптимизацией изображений в WebP, а также выбором языка и часового пояса с мгновенным сохранением изменений в базе данных.
- Приложение полностью локализовано на три языка — русский, английский и казахский — с автоматическим определением языка браузера; локализованы также системные письма и уведомления.
- Встроенный Monaco Editor с подсветкой синтаксиса и переключением JavaScript, TypeScript, Python, JSON, HTML и CSS; поддерживаются светлая и тёмная темы.
- Адаптивный интерфейс для мобильных и настольных экранов, единая система уведомлений и обработка ошибок на клиенте.
- Установка как PWA с автообновлением и offline-ready инфраструктурой Workbox.
- Нативная оболочка на Tauri 2 для desktop и Android, включая нативный вход через Google и системные push-уведомления.
- Серверная работа с PostgreSQL через Sequelize: автоматическая проверка и создание базы данных, типизированные модели пользователей, аккаунтов, сессий, passkeys, 2FA, сообщений и push-установок.
- Модульная серверная архитектура с отдельными доменами авторизации, пользователей, чатов, уведомлений, email и Telegram; статика аватаров и API защищены middleware.
- Локализованные email-шаблоны для подтверждения адреса, сброса пароля, регистрации администратора и других системных сценариев.
- Начальное создание root-супер-администратора и поддержка безопасной cookie-сессии между клиентом, REST API и WebSocket.

Используемые технологии и архитектура

- Клиент: TypeScript, React 19, React Router, Vite Plus/Vite и Node.js 24+.
- Интерфейс: MUI, Emotion, Tailwind CSS, Roboto, GSAP и Motion; для визуализаций используются Three.js, React Three Fiber и Rapier.
- Управление состоянием и данными: TanStack React Query; HTTP-запросы выполняются через Axios, обмен сообщениями в реальном времени — через Socket.IO Client.
- Интернационализация: i18next с определением языка в браузере; поддерживаются русская, английская и казахская локали.
- Клиент собирается как веб-приложение и PWA с Vite PWA/Workbox. Для нативных сборок используется Tauri 2 с Rust, включая Android.
- Сервер: TypeScript, Node.js 24+, Express 5 и Socket.IO. Код разделён на модули авторизации, пользователей, чатов, уведомлений, электронной почты и Telegram-бота.
- Авторизация: Better Auth с поддержкой входа по почте и паролю, OAuth-интеграций, двухфакторной аутентификации и passkeys; сервер дополнительно использует Helmet, CORS, ограничение частоты запросов и валидацию через Zod.
- Данные: PostgreSQL, Sequelize и sequelize-typescript. Модели пользователей, аккаунтов, сессий, passkeys, двухфакторной аутентификации, подтверждений, сообщений и push-установок хранятся в базе данных.
- Взаимодействие между слоями: клиент обращается к серверу по REST API с cookie-сессией и по WebSocket через Socket.IO; сервер отдаёт статические ресурсы и обрабатывает фоновые задачи через node-cron.
- Внешние интеграции: Firebase для push-уведомлений, Telegram Bot API через Grammy, отправка почты через Nodemailer и работа с изображениями через Sharp.
- Репозиторий разделён на независимые приложения `oqucat-client` и `oqucat-server`; для установки и сборки используется pnpm 12.

Среда разработки и инструменты

- Разработка ведётся в VSCodium на Node.js 24+ с использованием pnpm 12. Для проекта используются TypeScript 7, `tsc` для строгой проверки типов и сборки, `tsx` для запуска TypeScript в разработке, Vite Plus/Vite для dev-сервера и сборки, а также esbuild для production-сборки сервера.
- Инструменты качества кода из экосистемы OXC: `oxlint` и `oxlint-tsgolint` для быстрого статического анализа TypeScript/JavaScript, `oxfmt` для форматирования, `@oxc-node/cli` и единые команды `lint`, `fmt`, `typecheck` и `fix` в обоих приложениях.
- Полезные расширения VSCodium: OXC, Tailwind CSS IntelliSense, Tauri, ES7 React/Redux/GraphQL snippets, GitLens, Error Lens, I18n Ally, DB Client, Draw.io с поддержкой Mermaid, Material Icon и Material Product Icons.
- Настроены кастомные сниппеты под стек проекта, ускоряющие разработку компонентов и типовых модулей на React, UI-элементов MUI и моделей/связей Sequelize.
- MUI Icons Lookup — собственное расширение, разработанное автором проекта для быстрого поиска и подбора иконок MUI.
- В репозитории предусмотрены Git-хуки: `prepare-commit-msg` проверяет формат Conventional Commits (`feat`, `fix`, `refactor`, `docs`, `test`, `build`, `ci`, `chore`, `perf`, `revert`), а `pre-commit` для изменённого приложения запускает форматирование, `lint:fix` и проверку типов. После успешной проверки версия пакета автоматически увеличивается: для `feat` — minor-релиз, для остальных типов — patch-релиз, после чего изменённый `package.json` добавляется в commit.

Порядок установки и запуска

Требования: Node.js 24+, pnpm 12 и доступный экземпляр PostgreSQL. Команды выполняются из соответствующего каталога приложения.

1. Установить зависимости клиента и сервера:

   ```bash
   cd oqucat-client
   pnpm install

   cd ../oqucat-server
   pnpm install
   ```

2. Создать файлы окружения в каждом приложении на основе `.env.example`:

   ```bash
   pnpm generate-envs
   ```

   Заполнить `.env` и `.env.local` необходимыми значениями: параметры PostgreSQL, адреса клиента и сервера, ключи Better Auth, OAuth, Firebase, Telegram, Cloudflare и LLM. Файл `.env` предназначен для разработки через прокси-туннель, `.env.local` — для полностью локального запуска.
3. Для разработки через `dev.oqucat.dav-dev.kz`:

   - настроить в PuTTY SSH-туннель, который проксирует локальные порты приложений на домен `dev.oqucat.dav-dev.kz`;
   - в одном терминале запустить сервер:

     ```bash
     cd oqucat-server
     pnpm dev
     ```
   - в другом терминале запустить клиент:

     ```bash
     cd oqucat-client
     pnpm dev
     ```

   Скрипт `dev` использует `.env` и рассчитан на доступ к приложению через `dev.oqucat.dav-dev.kz`.
4. Для полностью локальной разработки на `localhost` запустить оба приложения с профилем `local`:

   В одном терминале:

   ```bash
   cd oqucat-server
   pnpm dev:local
   ```

   В другом терминале:

   ```bash
   cd oqucat-client
   pnpm dev:local
   ```

   Скрипт `dev:local` использует `.env.local`; прокси-туннель и домен `dev.oqucat.dav-dev.kz` не требуются.
5. Для проверки production-сборки выполнить в каждом приложении:

   ```bash
   cd oqucat-server
   pnpm build

   cd ../oqucat-client
   pnpm build
   ```

   Клиент после сборки можно предварительно просмотреть командой `pnpm preview`. Для публикации предусмотрены команды `pnpm sync`: клиент передаёт сборку на сервер, а сервер загружает собранный файл и перезапускает приложение через PM2.
6. Установка и запуск Android-версии:

   - установить JVM 21;
   - установить зависимости Tauri для Android по [официальному руководству](https://tauri.app/start/prerequisites/);
   - из каталога `oqucat-client` инициализировать Android-проект:

     ```bash
     pnpm tauri:android:init
     ```
   - добавить `src-tauri/gen/android/keystore.properties` с параметрами ключа подписи:

     ```toml
     password=xxxxxx
     keyAlias=upload
     storeFile=C:\\upload-keystore.jks
     ```
   - добавить Firebase-файл `src-tauri/gen/android/app/google-services.json`;
   - добавить GitHub Packages credentials в `%USERPROFILE%\.gradle\gradle.properties`:

     ```toml
     gpr.user=github_username
     gpr.key=ghp_xxxxxxxxxxx
     ```

   Для запуска Android-версии в режиме разработки использовать `pnpm tauri:android:dev`, а для production-сборки — `pnpm tauri:android:build`. Дополнительные сведения также приведены в [README клиента](oqucat-client/README.md).
