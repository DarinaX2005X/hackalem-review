# HackAlem AI — ИИ-помощник Электрокомплекта

Прототип консультанта для ekt.kz: поиск товара и характеристик, наличие, аналоги с объяснением, условия покупки и добавление в корзину только после отдельного подтверждения. Помощник работает поверх подготовленного мокапа сайта и собирается отдельно для встраивания.

**По умолчанию используются синтетический каталог и собственная корзина прототипа. Ключи и доступ к ekt.kz для демонстрации не нужны. Это не подключение к реальной корзине ekt.kz.**

## Быстрый запуск из чистого клона

Нужны доступ к приватному репозиторию, Git, Node.js 22.12+ и npm. Команды ниже рассчитаны на macOS/Linux. Запускать `npm ci` из указанных каталогов.

```bash
git clone git@github.com:BAITC-Hacks/hack-0571bab2-any.git
cd hack-0571bab2-any
```

Терминал 1 — backend, из корня клона:

```bash
cd apps/api
npm ci
CATALOG_MODE=demo AI_PROVIDER=none EXTERNAL_AI_ALLOWED=false WEB_ORIGIN=http://localhost:5173 npm run dev
```

Терминал 2 — frontend, из корня того же клона:

```bash
cd apps/web
npm ci
npm run dev -- --host localhost --port 5173 --strictPort
```

Открыть **http://localhost:5173/** в браузере и нажать кнопку помощника справа внизу. API работает на `http://127.0.0.1:3001`; Vite проксирует `/api/*`. Файл `.env` для этого запуска не нужен. В прототипе поиск по артикулу, корзина, условия и разбор документов работают без внешней модели.

Если порт занят, остановить старый dev-процесс или согласованно изменить порт frontend и `WEB_ORIGIN` backend. `localhost` и `127.0.0.1` — разные origin: адрес страницы должен точно совпадать с `WEB_ORIGIN`. Для другого порта API задать `PORT` и `API_ORIGIN` на сервере, а у frontend — `VITE_API_PROXY_TARGET`, например `http://127.0.0.1:3002`.

## Демонстрация пяти must-have

Начать в новой сессии браузера; в этом каталоге все товары синтетические.

| Действие | Ожидаемый результат |
| --- | --- |
| `Есть ABC-123?` | 4 единицы, артикул и технические характеристики; явная метка демо. Цена и сертификат в стандартных данных отсутствуют — интерфейс это сообщает. Если API передаёт сертификат, карточка показывает безопасную ссылку. |
| `Есть ABC-000?` | Нулевой остаток, доступный аналог `ABC-124` и причина совместимости по известным характеристикам. |
| `Какие оплата, доставка и минимальная партия?` | Ответ по публичным условиям, ссылка на источник; минимальная партия и спорный порог бесплатной доставки не выдаются за подтверждённые факты. |
| `Добавь 2 шт. ABC-123` | Предложение с количеством; корзина ещё пуста. Только отдельная кнопка «Подтвердить и добавить» меняет её. Сервер повторно проверяет остаток. Повтор подтверждения с тем же ключом не дублирует товар. |
| Перейти по ссылке на корзину | `/cart` показывает ту же сессию, товар `ABC-123` и количество 2. Попытка добавить ещё 3 при остатке 4 отклоняется. |

Сертификат присутствует в контракте и интерфейсе, но ни стандартный синтетический набор, ни подтверждённые сейчас поля live-каталога не дают реальную ссылку. Проверка с настоящим сертификатом остаётся зависимостью от данных партнёра.

Дополнительно проверить: режимы quick chat → половина экрана → полный экран без потери диалога; мобильный вид; переключение РУС/ҚАЗ; повтор запроса после ошибки сети; загрузку небольшого синтетического PDF/DOCX/XLSX/JPEG/PNG. Артикул и количество из документа необходимо проверить вручную; вложение само не меняет корзину.

## Архитектура

```text
Страница мокапа / сайт партнёра
  └─ React-виджет в Shadow DOM
       └─ same-origin /api/* proxy
            └─ Fastify API
                 ├─ каталог: синтетические данные / разрешённый live API
                 ├─ проверенные публичные условия покупки
                 ├─ ограниченный локальный разбор PDF/DOCX/XLSX
                 ├─ опциональный OpenAI gateway
                 └─ сессия → предложение → явное подтверждение → корзина прототипа
```

- `apps/web`: React/TypeScript/Vite, адаптивный виджет, RU/KZ, клиент API, ручная проверка вложений, подтверждение и страница корзины. Статические карточки мокапа служат оформлением и не являются актуальными фактами ассистента.
- `apps/api`: Fastify/TypeScript, каталог, проверка источников, сессии, CSRF, предложения и идемпотентное подтверждение. Модель не записывает в корзину напрямую.
- Ввод, результаты и выбранные позиции сохраняются при смене режима виджета. Последние 40 сообщений могут восстанавливаться из `sessionStorage` вкладки в течение 30 минут; действующие предложения и содержимое файлов там не сохраняются. Сервер удерживает ограниченный контекст товаров для уточняющих вопросов.
- Для изменения корзины клиент сначала получает сессию и CSRF-токен через `GET /api/cart`. Затем отдельные POST готовят предложение и подтверждают его. Сервер проверяет origin, CSRF, срок предложения, количество, актуальные товары и остатки.

Подробности: [контракт API](docs/03_КОНТРАКТ_API.md), [backend](apps/api/README.md), [frontend и вставка виджета](apps/web/README.md).

## Данные и AI

Синтетические позиции `ABC-123`, `ABC-000`, `ABC-124` покрывают наличие, отсутствие и аналог. В серверном каталоге есть дополнительные вымышленные кабель, розетка, светильник и выключатель для поиска по задаче. Они не являются готовым электротехническим проектом. Неизвестные цены, единицы измерения, сертификаты и остатки не дополняются догадками.

Условия оплаты и доставки основаны на [публичных источниках](docs/BUYING_TERMS_SOURCES.md). Условия без подтверждения помечаются как неизвестные.

Live-каталог и OpenAI включаются **только локально на backend** по [его инструкции](apps/api/README.md), после получения необходимых разрешений. API-ключи и Basic Auth не попадают во frontend. При разрешённом включении OpenAI помогает с неоднозначными запросами и фото; факты товара всё равно берутся из каталога. Есть ограничения числа вызовов и параллельности, при сбое работает детерминированный fallback. NVIDIA для запуска не требуется.

PDF с текстовым слоем и таблицы DOCX/XLSX разбираются локально с ограничениями размера, страниц, строк и распаковки. Допускается один файл до 2 МиБ. Распознанные позиции требуют проверки человеком. Для внешнего анализа JPEG/PNG требуется отдельное согласие клиента и разрешение в конфигурации сервера; без них используется ручной сценарий. Документы не отправляются внешней модели. Старые `.doc`/`.xls` и OCR сканированных PDF в текущую реализацию не входят.

## Сборка и проверки

Backend, из `apps/api`:

```bash
npm run build
npm test
```

Frontend, из `apps/web`:

```bash
npm run build
npm run test:e2e
```

Браузерные тесты используют установленный Google Chrome на macOS; на другой машине предварительно установить тестовый браузер командой `npx playwright install chromium` из `apps/web`. `npm run build` создаёт `dist/` для демонстрационной страницы и `dist-widget/ekt-assistant.js` для встраивания. Тесты интерфейса с подставленными ответами API не заменяют ручной совместный сценарий с настоящим сервером.

Совместная браузерная проверка с настоящим API, из `apps/web` после `npm ci` в **обоих** приложениях:

```bash
npx playwright test --config playwright.integration.config.ts
```

Конфигурация сама запускает изолированный API на порту 3010 и frontend на 5180, использует синтетический каталог и отключает внешние AI-вызовы. Порты должны быть свободны; ключи не нужны. Проверяются факты/аналог/условия, явное подтверждение и актуальная корзина, казахский мобильный сценарий с ограничением остатка, изменение количества нескольких позиций, PNG без согласия и ручная проверка PDF перед добавлением.

В интеграционном прогоне 23.09.2026 прошли 96 backend-тестов, 10 браузерных тестов frontend с подставленным API и 4 браузерных сценария с настоящим API. Обе сборки прошли. Тот же результат повторён из чистого общего клона коммита `158f8c9`: `npm ci` в обоих приложениях, обе сборки и все 96 + 10 + 4 проверки прошли; подробности в [листе приёмки](docs/ACCEPTANCE_CHECK_2026-09-23.md). Этот прогон использовал синтетические данные без внешних OpenAI-вызовов.

Отдельная проверка с локальным ключом OpenAI прошла на двух синтетических запросах RU/KZ: HTTP 200, успешный ответ модели, 483 входных и 106 выходных токенов суммарно. Корзина не менялась. Учётные данные не сохранены в репозитории.

API-тесты проверяют серверные правила без реальных учётных данных. Отдельно проверены небольшие синтетические PDF/DOCX/XLSX/JPEG на настоящем API: документы вернули кандидатов для ручной проверки, фото без согласия — честный ручной fallback; корзина не изменялась. Итоговую интеграционную проверку выполнять по таблице выше с обеими частями из одного клона.

## Встраивание и ограничения прототипа

```html
<script src="/assets/ekt-assistant.js"></script>
<script>
  EktAssistant.mount({ apiBase: '/api', locale: 'ru' });
</script>
```

Разместить после загрузки `body`. Для реального сайта требуется same-origin reverse proxy, HTTPS, корректные публичные origin и защищённые cookie; Vite proxy относится только к разработке. Подключение одного JS-файла даёт интерфейс, но не создаёт интеграцию с сессией и корзиной партнёра.

- API реальной корзины ekt.kz пока не подключён. Нет оплаты и оформления заказа; платёжные данные не запрашиваются.
- Сессии, корзины и бюджеты модели находятся в памяти процесса и сбрасываются при перезапуске. Для публичного использования нужны постоянное хранилище, согласование экземпляров сервера и ограничения на внешнем proxy.
- Live-поиск ограничен доступными полями, локальным индексом и лимитом запросов. Неполный поиск не означает, что товара точно нет. Неподтверждённые данные цены/сертификата остаются неизвестными.
- Изображение товара не включено в текущий контракт ассистента; используется нейтральная иконка. Скриншоты дизайна не служат источником технических фактов.
- Это демонстрационный прототип, а не завершённое внедрение в production ekt.kz.
