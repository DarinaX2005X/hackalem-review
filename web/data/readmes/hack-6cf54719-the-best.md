# AI Sana

Платформа, где компании публикуют реальные учебные задачи, а студенческие команды предлагают решения и прототипы. Компания просматривает отклики и сама выбирает исполнителя.

Каталог включает три карточки, перенесённые из публичного раздела технологических задач Astana Hub, и задачи, которые компании публикуют сами. Внешние карточки снабжены ссылкой на источник и пометкой о локальных откликах.

## Основной сценарий

1. Компания регистрируется, создаёт карточку задачи и при необходимости сохраняет её как черновик.
2. Компания уточняет описание, указывает аудиторию, доступные данные или ресурсы, критерии успеха и срок, затем публикует задачу.
3. Студенты создают команду или вступают в неё по коду приглашения.
4. Команда отправляет отклик с описанием своего подхода и необязательной ссылкой на прототип.
5. Компания рассматривает отклики, отклоняет неподходящие и вручную выбирает исполнителя. После выбора задача закрывается.

Для трёх импортированных карточек отклики и решения доступны только внутри AI Sana на локальном аккаунте куратора. Они не отправляются iDerek, Xena Soft или PROMAT-SYSTEMS, и эти компании не выбирают исполнителя в AI Sana. Чтобы запустить настоящий цикл с компанией-партнёром, она должна зарегистрировать свой аккаунт и разместить/подтвердить собственную задачу.

AI-помощник может отредактировать заполненный текст. Он не заполняет пустые поля; компания проверяет и вручную применяет каждое предложение. Без API-ключа AI выключен, остальные функции доступны.

## Стек

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2, Pydantic.
- **База данных:** PostgreSQL 17.
- **Интерфейс MVP:** Streamlit.
- **Запуск:** Docker Compose.
- **Документация API:** OpenAPI/Swagger через FastAPI.

## Запуск на Windows

Нужен установленный и запущенный Docker Desktop.

1. В PowerShell из корня репозитория создайте локальный файл настроек:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Запустите приложение и базу данных:

   ```powershell
   docker compose up --build
   ```

3. Откройте интерфейс и документацию API:

   - Сайт: <http://localhost:8502> (значение по умолчанию; если порт свободен, установите `FRONTEND_PORT=8501` в `.env`)
   - Swagger API: <http://localhost:8000/docs>
   - Проверка API и PostgreSQL: <http://localhost:8000/health>

Остановить сервисы можно сочетанием `Ctrl+C` в терминале. PostgreSQL хранит данные в Docker volume, поэтому они сохраняются после обычной остановки.

### AI-помощник

AI — необязательная функция. Чтобы включить её, добавьте свой `OPENAI_API_KEY` в `.env` и перезапустите Compose. Ключ хранится только на backend и не передаётся интерфейсу. Модель можно указать в `OPENAI_MODEL`. Помощник редактирует только уже заполненные поля; пустые поля остаются пустыми, чтобы AI не дополнял карточку выдуманными фактами.

### Локальный запуск без Docker

Если PostgreSQL уже установлен и доступен, создайте виртуальное окружение и установите зависимости в двух терминалах PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
py -m pip install -r backend/requirements.txt
py -m pip install -r frontend/requirements.txt
```

Задайте `DATABASE_URL` для своей PostgreSQL и `JWT_SECRET_KEY`, затем запустите API из корня:

```powershell
py -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Во втором терминале запустите Streamlit:

```powershell
py -m streamlit run frontend/app.py
```

При локальном запуске сайт откроется по адресу <http://localhost:8501>.

## Основные возможности

- Регистрация, вход и серверная проверка ролей «Компания» и «Студент».
- Команды студентов: создание, код приглашения и вступление.
- Черновики задач, публикация и рейтинг полноты карточки с перечнем недостающих полей.
- Пояснение баллов готовности по каждому полю и подсказки по уточнению карточки; редактирование опубликованных задач.
- Открытый каталог с поиском, отраслевыми фильтрами и сортировкой по готовности.
- Отклики команд с сообщением и ссылкой на прототип.
- Кабинет компании: просмотр откликов, перевод на рассмотрение, отклонение и ручной выбор исполнителя.
- Права доступа на сервере: компании управляют только своими задачами и откликами, студенты откликаются только от своих команд.

## Импортированные карточки Astana Hub

При первом запуске backend добавляет три снимка публичных карточек в локальный каталог. Источник каждой карточки открыт из её подробного описания. Внешние данные не синхронизируются автоматически: перед демонстрацией проверьте исходную страницу и сроки. Даты в импортированных карточках — сроки принятия решений, указанные на Astana Hub, а не обещанный срок выполнения проекта.

Локальный кураторский аккаунт для просмотра и выбора внутренних откликов:

- Email: `catalog@aisana.example.com`
- Пароль: `local-demo-change-me`

Эти учётные данные нужны только для локальной демонстрации. Задайте собственные `ASTANAHUB_REVIEW_EMAIL` и `ASTANAHUB_REVIEW_PASSWORD` в `.env` перед запуском и не публикуйте приложение с локальным паролем.

Исходные публикации: [iDerek: OCR на хостинге](https://astanahub.com/en/tech_task/ocr-na-khostinge), [Xena Soft: AI-агент для E2E-тестов](https://astanahub.com/en/tech_task/ii-agent-dlia-soprovozhdeniia-skvoznykh-avtotestov-v-ci-razbor-padenii-ispravlenie-testov-i-rasshirenie), [PROMAT-SYSTEMS: ночное распознавание госномеров](https://astanahub.com/en/tech_task/ustoichivoe-nochnoe-raspoznavanie-gosnomerov-rk-na-vezde-parkovki-ik-podsvetka-zasvetka-farami-raz).

## Статус и ограничения MVP

Приложение рассчитано на локальную демонстрацию и проверку основного сценария. Таблицы базы создаются при первом запуске; для развития production-схемы следует добавить управляемые миграции. Регистрация не подтверждает юридическую принадлежность к компании. Учетные записи не используют подтверждение email или восстановление пароля. Перед публичным развёртыванием замените локальные значения пароля PostgreSQL и `JWT_SECRET_KEY`, настройте HTTPS и добавьте проверку компаний.
