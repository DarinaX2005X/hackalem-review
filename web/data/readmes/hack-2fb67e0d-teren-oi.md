# Teren Oi

**Сравнение редакций организационных документов с проверяемыми источниками.** Приложение сопоставляет пункты, показывает изменения подразделений по текстовым признакам и помогает проверить возможную потерю функций или дублирование ответственности. Каждый показанный вывод сопровождается цитатой из конкретной редакции.

Проект команды Teren Oi для HackAlem AI. Основной сценарий: **демо в один клик → карта изменений → выводы и источники → заключение PDF/Word**. Демо синтетическое; оно не является официальными документами АО «Казахтелеком».

## Быстрый запуск для жюри

Скачайте репозиторий (Code → Download ZIP) и **распакуйте архив**. API-ключ для демонстрации не нужен.

### Windows: двойной клик

Нужны установленные **Python 3.11+** и **Node.js 22.12+** (npm входит в Node.js). Запустите **`START.bat`** в корне проекта. Скрипт автоматически:

1. Создаст отдельное окружение `.venv-run`, сохранив существующие окружения команды.
2. Установит Python- и JavaScript-библиотеки.
3. Соберёт интерфейс и запустит его вместе с API.
4. Откроет **[Teren Oi](http://127.0.0.1:8765/)** в браузере.

Держите окно запуска открытым. Для остановки нажмите `Ctrl+C`. При повторном запуске установка/сборка пропускаются, если соответствующие файлы проекта не изменились. Для воспроизводимости версии Python-библиотек закреплены в `constraints.txt`, JavaScript — в `frontend/package-lock.json`. Сборка автозапуска изолирована в `.venv-run/frontend` и не затрагивает рабочий Vite. При первом запуске нужен интернет для загрузки зависимостей; подготовленное локальное сравнение работает без интернета. OpenAI требует интернет и собственный ключ.

На macOS/Linux с Python и Node.js выполните `python3 launch.py`. Если порт занят: `python launch.py --port 8766`. Для подготовки заранее без запуска: `python launch.py --prepare-only`. Параметр `--no-browser` отключает автоматическое открытие браузера.

### Docker: одна команда

Если установлен и запущен Docker с Compose, Python/Node.js на компьютере не нужны:

~~~bash
docker compose up --build
~~~

Откройте **[http://127.0.0.1:8765/](http://127.0.0.1:8765/)**. Образ сам устанавливает библиотеки и кириллические шрифты. Первое построение требует интернет. Для остановки: `docker compose down` в другом терминале. Для подготовки до демонстрации можно заранее выполнить `docker compose build`.

Локальный `.env` необязателен. Compose передаёт `OPENAI_API_KEY`/`OPENAI_MODEL` только серверу; `.env` исключён из контекста сборки образа. После изменения настроек перезапустите контейнер через `docker compose up --force-recreate`. Порт доступен только на вашем компьютере.

### Проверка за минуту

1. Нажмите **«Загрузить контрольный демо-комплект Казахтелеком»** с выключенным ИИ.
2. Откройте цитату удалённого пункта и карту изменений.
3. Скачайте PDF или Word. Показатели смысловой проверки без ключа честно показывают «не проверено».
4. Для проверки ИИ настройте локальный `.env`, перезапустите приложение и включите переключатель **«AI-анализ»**.

Если окно сообщает об отсутствии Python/Node.js, установите эти два компонента или выберите Docker-вариант. Ручная установка отдельных библиотек не требуется. При проблемах скачивания проверьте интернет и повторите запуск; сообщение об ошибке останется в окне.

## Запуск для разработки

Нужны Python 3.11+, Node.js 22.12+ и npm. Все команды Python выполняйте одним интерпретатором. Рекомендуется отдельное виртуальное окружение.

**Терминал 1, корень репозитория, PowerShell:**

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn teren_oi.web:app --host 127.0.0.1 --port 8000 --reload
~~~

На macOS/Linux вместо пути к Windows-интерпретатору используйте `.venv/bin/python` (для создания окружения обычно `python3 -m venv .venv`). В уже активированном окружении достаточно `python -m pip install -e ".[dev]"` и `python -m uvicorn teren_oi.web:app --reload`.

**Терминал 2, корень репозитория:**

~~~bash
cd frontend
npm ci
npm run dev
~~~

Откройте [интерфейс](http://127.0.0.1:5173/). Vite передаёт `/api` на `http://127.0.0.1:8000`. [Описание HTTP API](http://127.0.0.1:8000/docs) доступно у запущенного FastAPI. Эти адреса работают локально и не означают публичный деплой.

Для PDF нужен TrueType-шрифт с кириллицей. Поддерживаются системные Arial, DejaVu Sans, Liberation Sans; при их отсутствии положите DejaVuSans.ttf и, по возможности, DejaVuSans-Bold.ttf в src/teren_oi/fonts/. Word создаётся через python-docx.

### Настройка ИИ

Без ключа доступны локальное сравнение, цитаты удалённых пунктов, карта изменений и экспорт. Чтобы добавить смысловую проверку:

1. Создайте локальный `.env` по образцу `.env.example`, не перезаписывая существующий файл с настройками.
2. Укажите `OPENAI_API_KEY`; модель по умолчанию — `gpt-5.6-terra`, её можно изменить через `OPENAI_MODEL`.
3. Перезапустите API, обновите состояние подключения в интерфейсе и включите **«AI-анализ»** рядом с кнопкой запуска. Выбранный режим применяется и к демо.

`.env` исключён из Git. Ключ используется только Python-сервером: не помещайте его в React, переменные `VITE_*`, коммиты или скриншоты. Статус «ключ подключён» означает наличие настройки; действительность ключа, доступ к модели и квота проверяются реальным запросом. Баланс API не определяется этим статусом.

При включённом ИИ сервер передаёт выбранные фрагменты документов в OpenAI API, включая часть сохранённых пунктов для поиска возможных дублей. Для проверки подключения используйте синтетическое демо. Запрос ограничен по объёму, без автоматических повторов; ошибка ИИ сохраняет результат локального сравнения.

## Сценарий для жюри

1. Откройте приложение с выключенным **«AI-анализ»** и нажмите **«Загрузить контрольный демо-комплект Казахтелеком»**. Файлы с диска не нужны; выбранные пользователем документы в этот запрос не попадают.
2. Дождитесь результата. Статус — **«ИИ выключен»**; карта содержит пять сопоставлений. Ожидаемые детерминированные значения:

   | Категория | Количество | Что проверить |
   | --- | ---: | --- |
   | Добавлено | 1 | Новый пункт 2.4 про департамент клиентского опыта |
   | Удалено | 1 | Исходный пункт 2.2 про контроль качества |
   | Изменено | 1 | Пункт 2.3 про закрытие заявки |
   | Без изменений текста | 2 | 2.1 и перенумерация 2.4 → 2.5 |

3. Отфильтруйте удалённые пункты, откройте источник 2.2 и проверьте цитату. Локальная находка помечена «Удалённый пункт»: проверьте, перенесена ли функция. Это не вывод ИИ о потере функции. Без ИИ отсутствие найденных дублей не означает, что дублирование проверено.
4. Откройте сохранённый текст 2.4 → 2.5: исходный и новый номера должны быть доступны. Это совпадение текста, а не доказательство сохранения полномочий подразделения.
5. Скачайте PDF и Word. Сверьте числа, цитату 2.2, обе редакции и состояние AI-проверки с экраном; проверьте читаемость кириллицы.
6. Для проверки ИИ вернитесь к документам, включите **«AI-анализ»** и повторите демо один раз. При успешном запросе появится **«Ответ ИИ»**, статус **«AI-проверка выполнена»**, модель и охват. Нажатие на замечание открывает его источники. Число смысловых выводов зависит от ответа модели; фиксированного ожидаемого числа нет.
7. При отсутствии ключа или ошибке сервиса результат должен объяснять состояние ИИ, сохраняя локальные числа и экспорт. Не считайте отсутствие ai_error самостоятельным признаком успешного вызова.

Дополнительно проверьте светлую/тёмную тему, управление клавиатурой и ширины 320, 390, 768, 1280 и 1440 px. В таблице допустима собственная прокрутка; содержимое страницы и кнопки должны оставаться доступны.

## Что считается результатом

### Работа с заключением

- **Направление:** «Поменять редакции местами» меняет файлы и текст; слева старая редакция, справа новая.
- **Поиск:** текст, цитаты и номера в замечаниях и точной карте; сочетается с фильтрами статуса пункта и подразделения. Смысловая таблица ИИ остаётся полной.
- **История:** внизу результата задайте название и нажмите «Сохранить в историю». Сохраняется исходное заключение с цитатами, без загруженных файлов. Есть поиск, просмотр, скачивание и отмена последнего удаления до перезагрузки.
- **Хранение:** только в этом браузере и по этому адресу, до 8 записей и 1,5 млн символов JSON. Автосохранения и командной синхронизации нет. При переполнении скачайте Markdown. Старые сохранённые заключения остаются неизменными.
- **Экспорт:** PDF/Word — исходное серверное заключение; Markdown — тот же текст без обращения к серверу. CSV содержит всю точную карту независимо от фильтров. PDF/Word из истории форматируются сервером из сохранённого текста без повторного вызова ИИ.

### Соответствие обязательным сценариям ТЗ

| Требование | Где смотреть |
| --- | --- |
| Созданные, сохранённые, преобразованные подразделения | «Подразделения и функции · ИИ», цитаты; при выключенном ИИ только текстовые признаки |
| Сопоставление функций до/после | Смысловая карта функций с подразделениями и источниками |
| Возможные потери, дублирование, конфликты интересов | Замечания ИИ с проверенными цитатами; отсутствие замечаний не гарантирует отсутствия рисков |
| Проверяемые выводы | Раскрываемые источники: редакция, пункт, цитата, файл и позиция при наличии |
| Итоговое заключение | PDF, Word, Markdown с результатами и ограничениями |
| Word / PDF / Excel | DOCX, PDF с текстовым слоем, XLSX; дополнительно TXT и вставка текста |
| Рекомендательный характер | Ограничения на экране и в отчёте; решения требуют проверки ответственным сотрудником |

**Границы текущей реализации:** OCR, сравнение с внешней нормативной базой и бенчмаркинг других операторов не реализованы. Смысловая проверка требует работающего OpenAI API и ограничена указанным охватом. Наличие цитаты подтверждает источник, но не истинность интерпретации модели. Демонстрационный комплект синтетический; приёмку по контрольным документам организаторов необходимо проводить отдельно.

**Локальное сопоставление** нормализует регистр и пробелы. Сначала резервируются непустые тексты, встречающиеся ровно один раз в каждой редакции, даже если изменился номер. Затем сопоставляются одинаковые тексты внутри одного номера; оставшиеся пункты с одинаковым номером — по порядку появления. Каждое вхождение сохраняется. Удалённый пункт означает отсутствие найденной пары, а не доказанную потерю функции.

Если текст повторяется, совпадения между разными номерами не выводятся автоматически: определить единственный перенос нельзя. После частичного сопоставления повторяющийся текст тоже не объявляется уникальным. Перенумерация одновременно с переформулировкой, слияния и разделение функций требуют ручной проверки. Нечёткого смыслового сопоставления в локальном алгоритме нет.

**Выводы ИИ** проходят проверку источников: цитата должна дословно присутствовать в указанной редакции, указанном пункте и отправленном модели фрагменте; повторный номер должен однозначно разрешаться по цитате. Выводы могут быть скрыты из-за неоднозначной цитаты, отсутствия нужной редакции или недостаточной полноты контекста; число отклонённых находок сообщается. Для сигналов о дублировании и конфликте нужны два разных подтверждённых вхождения новой редакции; две цитаты из одного пункта не образуют два источника. Такая проверка подтверждает происхождение цитаты, но не истинность интерпретации, уровня риска или оценки уверенности модели.

**«Ответ ИИ»** включает формулировки модели с проверенными цитатами. Короткая сводка создаётся сервером из допустимых находок и явно помечается summary_origin: verified_findings. Свободное поле summary исходного ответа модели не публикуется: его утверждения не связаны с доказательствами. Пустая сводка находок не гарантирует отсутствия рисков.

### Статусы и охват ИИ

| `ai.status` | Значение |
| --- | --- |
| `disabled` | Пользователь выбрал локальное сравнение; вызова ИИ не было |
| `unavailable` | ИИ запрошен, но ключ отсутствует на сервере |
| `succeeded` | Вызов модели завершён и структурированный ответ обработан; допустимых выводов может быть ноль |
| `failed` | AI-проверка завершилась ошибкой; локальное сравнение сохранено |
| `skipped` | Вызов не потребовался, например нет изменений для проверки |

Пока HTTP-запрос выполняется, интерфейс показывает ожидание результата. API не передаёт поток этапов или процент выполнения; анимация ожидания не измеряет прогресс сервера.

coverage.before/after показывает извлечённые пункты, ненумерованные блоки и применение временных номеров. ai.coverage считает **фрагменты-кандидаты**, а не уникальные номера или все абзацы файла: изменённый пункт учитывается дважды, по одному разу для каждой редакции; сохранённый одинаковый текст — один раз из новой редакции; добавленный и удалённый — по одному разу. Поэтому в демо кандидатов **6**, хотя в каждом исходном документе по четыре пункта.

Если сохранённый текст совпадает дословно, модель получает явную дополнительную ссылку на его исходный номер в редакции «до». Например, текст нового 2.5 также имеет ссылку на старый 2.4. Тело текста передаётся один раз, поэтому такая ссылка не увеличивает счётчик фрагментов. Совпадение только после нормализации регистра/пробелов не создаёт эту ссылку и не доказывает полный охват старой редакции.

Флаги `ai.coverage.before_complete` и `after_complete` отдельно указывают, передан ли полный извлечённый контекст каждой редакции. Интерфейс и отчёт показывают **«Полный контекст для ИИ: до / после»**. Даже «6 из 6 фрагментов» не означает полноту обеих редакций: при совпадении только после нормализации исходная формулировка «до» не отправляется, `before_complete=false`, а ссылка на неё входит в `ai.omitted_refs`. Списки `omitted_refs` и `truncated_refs` содержат до 50 обозначений пропущенных и сокращённых источников каждый; это пояснения к ограничению, а не полный текст документов.

Поля total_clauses, included_clauses, omitted_clauses, truncated_clauses отражают общий объём кандидатов, включённые, пропущенные и сокращённые фрагменты. Текущий бюджет запроса — не более 32 000 символов сериализованного JSON с учётом экранирования и ссылок на обе редакции (системная инструкция и схема ответа считаются отдельно); один пункт ограничен 1 600 символами. Для сохранённых пунктов резервируется часть бюджета. В состояниях без успешного ответа число включённых фрагментов не следует трактовать как подтверждённый сервером OpenAI охват проверки.

## Архитектура и API

~~~mermaid
flowchart LR
    UI[React / TypeScript / Framer Motion] --> API[FastAPI web.py]
    API --> READ[readers.py / parsers.py]
    READ --> DIFF[diff.py: точный текст и номера]
    DIFF --> LOCAL[Локальные сигналы]
    DIFF --> AI[analyzer.py: OpenAI, опционально]
    AI --> CHECK[evidence.py: проверка цитат]
    LOCAL --> CHECK
    CHECK --> REPORT[report.py: единое заключение]
    REPORT --> UI
    REPORT --> STORE[report_store.py: временный снимок]
    STORE --> EXPORT[export_formats.py: PDF / Word]
~~~

Основные контракты находятся в `src/teren_oi/models.py` и `frontend/src/types.ts`. Клиентские запросы — `frontend/src/api.ts`, экраны — `frontend/src/components/`, стили — `frontend/src/index.css`.

### Структурированный анализ для команды

`analyzer.analyze_structure(comparison, model)` возвращает общий `AnalysisResponse`: `department_changes`, `function_mappings` и `findings`. Он использует тот же ограниченный запрос, что и `analyze_with_metadata`; отдельный дополнительный вызов модели внутри него не выполняется. `analyze_changes` остаётся совместимым адаптером для старых клиентов и возвращает список находок. Streamlit использует `analyze_with_metadata`, чтобы сохранять статус и охват конкретного запуска.

`diff.validate_analysis_response` проверяет цитаты и достаточность сторон/охвата для этих структур. Создание подразделения требует полного переданного контекста «до», удаление подразделения и статус функции `lost` — полного контекста «после». Для остальных сопоставлений нужны источники обеих редакций; для переназначения функции — также обе подписи подразделений. Сигнал `possible_loss` требует цитаты «до» и либо цитаты «после», либо полного нового контекста. Дублирование/конфликт требуют двух разных однозначных источников «после». Полнота означает передачу всех извлечённых вхождений целиком с учётом явных ссылок и отсутствие пропущенных ненумерованных блоков; она не доказывает истинность смыслового вывода.

Веб-интерфейс использует `analyze_with_metadata(...).structured`: это структурированный результат того же ядра, доступного через `analyze_structure`, вместе со статусом вызова и охватом. Второго запроса к модели нет. API дополнительно возвращает `department_changes`, `function_mappings` и `ai_summary`; при выключенном/недоступном ИИ списки пусты, сводка равна `null`.

В результатах появился раздел «Подразделения и функции · ИИ»: исходная и новая функции, подразделения, статус и раскрываемые цитаты с позициями. Эти же оценки и цитаты включаются в PDF/Word. `ai_summary` собирается сервером из валидированных результатов, а не из свободного резюме модели.

Карточки `units` используют оценку ИИ при однозначном соответствии имён (регистр и пробелы нормализуются); `origin` показывает `ai` или `local`. Противоречивые оценки одного подразделения не переопределяют локальный статус. При отсутствии оценки сохраняется эвристика по упоминаниям. Валидированное сопоставление функции со статусом `retained`, `changed` или `reassigned` скрывает соответствующий локальный сигнал «Удалённый пункт» только для того же однозначно разрешённого пункта «до»; одинаковых номеров пунктов для этого недостаточно. Например, функция ДНМ из 3.4.а может соответствовать 3.4.в: ИИ оценивает подразделение как сохранённое, а точная карта `changes` продолжает показывать исходный текстовый diff без изменений.

KPI «Потери функций · ИИ» и «Возможные дубли · ИИ» используют `summary.ai_loss_count` и `ai_duplicate_count`: только валидированные находки модели; `null` означает «не проверено». Удалённые пункты считаются отдельно (`summary.removed`) и в отчёте вынесены в «Локальные сигналы точного сравнения», отдельно от потерь, оценённых ИИ. Для старых клиентов числовой `loss_count` сохранён: при успешном ИИ он содержит число AI-сигналов потери, иначе число локальных сигналов; новый UI использует явное nullable-поле.

### HTTP-контракт

| Метод | Запрос | Результат |
| --- | --- | --- |
| GET /api/health | Без параметров | Наличие ключа, модель, форматы; без платного вызова |
| POST /api/analyze | multipart/form-data: before_file / before_text, after_file / after_text; use_ai, demo | analysis_id, summary, changes, units, department_changes, function_mappings, findings, ai_summary, ai, coverage, warnings, report_markdown |
| POST /api/export | JSON: analysis_id, format: pdf или docx | Файл из сохранённого сервером заключения |

Для каждой редакции передаётся либо файл, либо текст. При demo=true входные файлы и тексты должны отсутствовать. Лимиты: 12 МиБ на файл, 500 000 символов для вставленного текста. Ошибки API содержат HTTP-статус и error.code / error.message; например 400 для неверного ввода, 413 для превышения объёма. ai_error сохранён для совместимости; актуальное состояние определяется по ai.status.

Находки содержат id, origin: local | ai, объяснение и цитаты с файлом/позицией. Числа рисков считаются по тем же находкам, которые передаются в UI и заключение; это количество замечаний, а не вероятность события.

### Жизненный цикл отчёта

React скачивает отчёт через непрогнозируемый analysis_id: сервер преобразует тот же Markdown, который сформировал при анализе. Клиент не пересобирает заключение. Размер итогового Markdown ограничен 4 млн символов; при превышении сравните документы по разделам. Для старых клиентов API также принимает report_markdown вместо analysis_id; этот режим форматирует переданный текст и не подтверждает его связь с ранее выполненным анализом. Оба поля одновременно запрещены.

Снимки хранятся **в памяти одного процесса**, максимум час: до 32 отчётов и суммарно до 8 000 000 символов. Старые записи могут удаляться раньше по лимиту ёмкости. Перезапуск API, включая --reload, очищает память. Если снимок истёк или удалён, экспорт вернёт **410 REPORT_EXPIRED** — повторите анализ. Скачанные файлы сохраняются у пользователя независимо от памяти сервера.

## Комплекты документов

В каждой колонке можно выбрать или перетащить до **8 файлов** DOCX/PDF/XLSX/TXT. Повторный выбор добавляет файлы; крестик удаляет конкретный файл. До 12 МиБ на файл, до 500 000 символов извлечённого текста на комплект. Текст и файлы в одной редакции не смешиваются.

Для соответствующих документов используйте одинаковые имена в комплектах «до» и «после». Имена внутри одной стороны должны быть уникальны. В режиме комплекта ссылка на пункт включает имя файла, исходный номер остаётся в позиции источника. Это защищает от смешения одинаковых номеров разных документов. Порядок загрузки не определяет пары. При разных именах автоматически сопоставляется однозначно совпадающий текст; переформулировки могут выглядеть как удаление/добавление. Смысловое сопоставление выполняет ИИ в пределах доступного контекста. Лимит AI-контекста не увеличивается с числом файлов.

API принимает повторяемые multipart-поля `before_files` и `after_files`. Старые одиночные `before_file` / `after_file` продолжают работать; смешивание одиночного и множественного поля одной стороны отклоняется.

## Ограничения входных данных

- До 12 МиБ на файл и 500 000 символов извлечённого текста. Office-архив: до 64 МиБ после распаковки и 4096 частей; XLSX: до 500 000 просматриваемых ячеек; PDF: до 500 страниц. Пустые форматированные области XLSX тоже входят в лимит: удалите лишние строки/столбцы или разделите файл. Защищённые паролем документы и недопустимые управляющие символы отклоняются с объяснением.
- Поддерживаются составные номера `3.4.а` и отдельные подпункты `а)` под родительским пунктом. Строки вроде `100% заявок` не считаются номерами пунктов.
- Принимаются DOCX, PDF с текстовым слоем, XLSX и TXT. Сканы требуют внешнего OCR; внутри приложения OCR нет. Пустые или повреждённые файлы возвращают объяснение ошибки.
- Для PDF доступны страница и блок, XLSX — лист и ячейка, TXT — строка, DOCX — абзац/таблица. Это положение извлечённого текста, а не гарантированная страница визуальной вёрстки Word.
- Полностью ненумерованный текст получает временные номера блоков. Из файлов точная исходная позиция таких блоков может быть недоступна. При смешанной структуре ненумерованные блоки не входят в точное сравнение и AI-выборку; их количество показано в предупреждениях.
- Повторяющиеся номера не теряются. Остаточное сопоставление одинаковых номеров по порядку требует проверки экспертом; одинаковая цитата в нескольких вхождениях не даёт однозначного источника для находки.
- Статусы подразделений определяются по названиям и изменениям текста. Они не устанавливают фактическое создание, ликвидацию или реорганизацию отдела.
- Большие документы могут проверяться ИИ частично; усечённые хвосты и пропущенные фрагменты не проверяются моделью. Даже полный охват извлечённых пунктов не включает содержание, которое парсер не прочитал.

## План публикации

Текущий запуск рассчитан на локальную демонстрацию. Для публикации соберите frontend/dist/, разместите его за HTTPS и настройте обратный прокси /api на FastAPI либо задайте публичный адрес API через VITE_API_BASE_URL при сборке. Корневой .env предназначен для Python; настройки Vite размещаются в окружении сборки или в frontend/.env.local.

Храните OPENAI_API_KEY только в секретах сервера. Разрешите в CORS только адреса своего интерфейса; сейчас разрешены два локальных адреса на порту 5173. Для текущих снимков используйте один worker FastAPI без --reload; для нескольких процессов/реплик потребуется общее ограниченное хранилище с TTL. Перед публичным доступом добавьте авторизацию, лимиты запросов/расходов и ограничения загрузок на прокси; в локальном MVP этих механизмов нет. Установите кириллические шрифты и повторите сценарий жюри уже на адресе публикации.
