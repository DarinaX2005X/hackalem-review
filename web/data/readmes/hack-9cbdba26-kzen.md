# KZen — рекомендации заказов поставщикам

KZen помогает менеджеру закупок ТОО «Электрокомплект» превратить выгрузки 1С в
понятный заказ поставщикам. Сервис рассчитывает количество по каждому товару,
показывает причины рекомендации и даёт человеку проверить заказ перед выгрузкой.

## Что умеет сервис

- Загружает Excel-выгрузки ИЭК и Systeme Electric; без файлов запускается на
  демонстрационных данных.
- Учитывает продажи, остатки, товар в пути, сезонность, тренд и условия отгрузки.
  Показывает рекомендации по поставщикам, срочность и расчёт по шагам.
- Позволяет искать товары, менять параметры расчёта и вручную исправлять
  количество с указанием причины.
- Даёт менеджеру отправить заказ на согласование, руководителю — утвердить его,
  а затем скачать XLSX или CSV для 1С.
- Показывает пять проверок требований технического задания на отдельном экране.

## Как получается рекомендация

Сервис связывает отчёты по коду 1С и собирает историю товара по месяцам. Разовая
накладная становится кандидатом на исключение, если она не менее чем в 10 раз
больше медианной накладной товара и составляет не менее 50% доступной истории
накладных. Месячный всплеск свыше трёх ожидаемых уровней заменяется ожидаемым
спросом; повторяющийся сезонный пик сохраняется.

Расчёт оценивает спрос за месяцы с нулевым или пустым начальным остатком, затем
учитывает тренд и сезонность. Из потребности на срок поставки и период пересмотра
вычитаются свободный остаток и поступления, которые успеют прийти; заказ
округляется по минимуму и кратности отгрузки. Оценки отсутствия товара нужно
сверять с исходными остатками.

ИИ может только сформулировать текст объяснения: рекомендуемое количество считает
расчётное ядро. Без ключа OpenAI показывается локальный шаблон.

## Технологии и архитектура

- Интерфейс: React 19, TypeScript, Vite.
- Сервер и расчёт: Python 3.11, FastAPI, Pydantic, openpyxl. Redis используется для кэша в Docker.
- Необязательное текстовое объяснение: OpenAI-совместимый API, по умолчанию модель
  `gpt-4o-mini`.

Интерфейс обращается к REST API. В сервере маршруты `api` вызывают сценарии
`application`, расчётные правила находятся в `domain`, а чтение Excel, кэш,
экспорт и вызов ИИ — в `infrastructure`. Обучать модель для запуска не нужно.

## Запуск

Понадобятся Git и Docker с Docker Compose. На Windows сначала запустите Docker
Desktop. В терминале:

```bash
git clone https://github.com/BAITC-Hacks/hack-9cbdba26-kzen.git
cd hack-9cbdba26-kzen
docker compose up --build -d
```

Откройте [интерфейс](http://localhost:3000). Документация API доступна по адресу
[localhost:3000/docs](http://localhost:3000/docs). Первый запуск может занять
несколько минут из-за сборки образов. Для остановки выполните
`docker compose down`.

Файлы партнёра не входят в репозиторий, поэтому чистый клон работает на
синтетическом демо-наборе. Для реальных расчётов загрузите Excel-файлы на экране
«Данные»: первый импорт поставщика требует все шесть отчётов 1С с именами и
колонками партнёра, дальше можно загружать любой поднабор. После импорта версии
расчёта и ручные правки сбрасываются, потому что считались по старым данным.

Для необязательного текста ИИ создайте в корне `.env` по образцу `.env.example`,
укажите `NARRATOR_BACKEND=openai` и свой `OPENAI_API_KEY`, затем снова выполните
`docker compose up -d`. Файл `.env` исключён из Git.

## Как проверить

1. Откройте [localhost:3000](http://localhost:3000). На экране «Данные» нажмите
   **«Рассчитать рекомендации»**. Для проверки достаточно демо-данных.
2. Перейдите в **«Рекомендации»**, откройте товар и посмотрите историю, прогноз
   и шаги расчёта.
3. В карточке товара измените количество, укажите причину и сохраните правку.
4. На экране **«Согласование»** отправьте версию на согласование. Переключите
   демонстрационную роль на «Руководитель», утвердите версию и скачайте файл для 1С.
5. На экране **«Проверки»** убедитесь, что пять сценариев ТЗ пройдены.

## Данные и ограничения

Источники — Excel-отчёты 1С двух поставщиков: продажи, остатки, детализация
продаж, товар в пути, условия отгрузки и сезонность. Результат выгружается в
XLSX или CSV; прямого подключения к 1С и автоматической отправки поставщикам нет.

- Нулевой или пустой начальный остаток служит признаком возможного отсутствия
  товара, но не подтверждает его. У ИЭК нет отдельного текущего снимка свободного
  остатка: используется начальный остаток последнего месяца. Эти оценки нужно
  проверить до утверждения заказа.
- Импорт понимает текущие форматы отчётов партнёров; ручного сопоставления колонок нет.
- Роли демонстрационные, полноценной авторизации нет. Версии заказа и журнал
  хранятся в памяти процесса и пропадают после перезапуска.
- Хронологический бэктест ещё не реализован.
