# ИИ-ассистент для ekt.kz

Проект команды «Метрологи» — `hack-3c5e22be-team`.

Ассистент будет консультировать по электротехнической продукции и добавлять выбранные позиции в корзину только после явного подтверждения клиента.

## Текущее состояние

Готов инфраструктурный каркас: Node.js 24, страница состояния, HTTP healthcheck, Docker Compose и GitHub Actions CI. Внешний хостинг пока не подключается. CI проверяет временное развёртывание контейнера на runner, но не публикует постоянный стенд.

ИИ, каталог, остатки, условия покупки, загрузка вложений и корзина **ещё не реализованы**. Реальные клиентские данные не используются. Healthcheck подтверждает работу процесса, а не готовность бизнес-функций.

## Быстрый запуск

Нужен Node.js 24.x. Внешних npm-зависимостей на этом этапе нет; установка пакетов не требуется. При добавлении зависимостей нужно коммитить `package-lock.json` и использовать `npm ci` в CI и Docker.

```sh
git clone https://github.com/BAITC-Hacks/hack-3c5e22be-team.git
cd hack-3c5e22be-team
# До слияния PR переключитесь на ветку каркаса:
git switch chore/bootstrap-environment
npm start
```

Откройте http://127.0.0.1:3000. Для перезапуска при изменениях: `npm run dev`.

При необходимости скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в shell). Файл `.env` исключён из Git и Docker-контекста.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Интерфейс локального сервера; в контейнере `0.0.0.0` |
| `PORT` | `3000` | Порт локального сервера; в Compose — порт хоста, внутренний порт всегда 3000 |

Ключи модели и API пока не нужны. Не коммитьте секреты, платёжные данные, диалоги или клиентские вложения.

## Проверки

```sh
npm run check
```

Команда проверяет синтаксис и запускает HTTP smoke-тест: главная страница, healthcheck, статус интеграций, запрет мутаций, 404 и HEAD. Это проверка инфраструктуры; пять бизнес-сценариев пока не реализованы и описаны в [матрице приёмки](docs/acceptance.md).

## Раннее развёртывание через Docker

Нужны Docker Engine/Docker Desktop и Docker Compose v2 с поддержкой `--wait`.

```sh
docker compose up --build -d --wait --wait-timeout 90
docker compose ps
curl --fail http://127.0.0.1:3000/healthz
docker compose logs --tail=100 app
docker compose down
```

В Windows PowerShell используйте `curl.exe` вместо `curl`, если команда является псевдонимом. Порт публикуется только на loopback. Контейнер запускается непривилегированным пользователем с файловой системой только для чтения. Данные не сохраняются, томов и БД пока нет.

Для изменения порта хоста задайте `PORT` в `.env`, затем повторите `docker compose up`. Dockerfile использует обновляемый тег Node.js 24; перед постоянным стендом следует закрепить одобренный digest образа.

### CI

Workflow `.github/workflows/ci.yml` запускается при push, pull request и вручную. Он выполняет проверки Node.js, собирает образ, запускает Compose, ждёт успешного healthcheck, проверяет HTTP и удаляет контейнер. Секреты и платный внешний хостинг не требуются; действуют лимиты GitHub Actions организации.

Если workflow не стартует, владелец репозитория должен проверить доступность Actions и разрешение используемых actions в настройках организации. Успех локального теста не заменяет зелёный CI.

Для будущего внешнего стенда: выбрать провайдера, настроить HTTPS и доступ, секреты через хранилище провайдера, CI/CD, журналирование без персональных данных, readiness зависимостей и откат на предыдущий образ. Подробности: [развёртывание](docs/deployment.md).

## Архитектура

Сейчас: браузер → HTTP-сервис Node.js → страница состояния и служебные маршруты.

Планируемая схема: чат сайта → сервер диалогов → поиск в каталоге и утверждённых условиях → ответ со ссылками на источники. Отдельный серверный адаптер корзины принимает подтверждённое предложение и проверяет сессию, цену, количество и остаток перед записью. Модель не получает прямого доступа к записи в корзину.

| Маршрут | Сейчас |
| --- | --- |
| `GET /` | Страница состояния стенда |
| `GET /healthz` | Проверка работоспособности процесса |
| `GET /api/status` | Флаги неподключённых интеграций |
| Мутации и прочие маршруты | 405 / 404; бизнес-API не реализовано |

```text
src/server.js          HTTP-сервис и корректное завершение
public/index.html      Страница состояния
test/server.test.js    Проверка HTTP
docs/                 Приёмка, правила и развёртывание
Dockerfile            Образ сервиса
compose.yaml          Локальный стенд
.github/workflows/    CI
```

## Данные и источники

Каталог пока не загружен. Для прототипа допустима синтетическая или анонимизированная выборка, явно помеченная как демонстрационная.

Ожидаемые поля: артикул, наименование, категория, характеристики с единицами измерения, сертификаты, цена и валюта, остаток по складам, статус наличия, единица продажи, кратность упаковки, минимальная партия, время обновления.

Реальные цена и остатки — из согласованного API/выгрузки ekt.kz; характеристики и сертификаты — из утверждённых карточек и документов. Оплата, доставка и самовывоз — из согласованных страниц или базы правил партнёра. Условия минимальной партии должны учитывать исключения для артикула. Конкретные URL, приоритет источников, срок актуальности и ответственный пока **не согласованы**. Недоступные сведения нельзя заменять догадками.

## Правила корзины и открытые решения

До записи показать артикул, количество, единицу продажи, цену и сумму; получить однозначное подтверждение именно этого предложения. На сервере повторно проверить доступ, актуальную цену и итоговое количество с учётом уже лежащего в корзине. Повтор одного подтверждения не должен дублировать запись. Изменение цены, количества или состава требует нового подтверждения.

Предлагаемая политика для нескольких позиций — добавление всего набора целиком. Резервирование остатков, срок действия предложения и поведение при конкурентной покупке необходимо согласовать с партнёром. Замена, удаление и оформление заказа не входят в текущий каркас. Нельзя запрашивать или сохранять платёжные данные.

Открытые вопросы: платформа сайта и API корзины; гостевая и авторизованная сессии; доступность по складам; критерии аналогов по категориям; источники условий; срок хранения диалогов и вложений; допустимые размеры файлов; точный SLA. Обработка Excel, Word, PDF и JPEG — следующий этап, без текущего приёма файлов.
