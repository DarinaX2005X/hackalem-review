# SIL

Локальное рабочее пространство аудитора для сравнения организационной структуры и функций до и после реорганизации. Кейс: «Анализ организационной структуры и функционала», Казахтелеком.

## Запуск в Windows / PowerShell

Нужен Node.js 20.12+ (для загрузки `.env`; рекомендуется Node.js 22+).

```powershell
git switch main
git pull --ff-only origin main
npm.cmd ci
npm.cmd test
npm.cmd start
```

Откройте `http://localhost:3000`. Если сервер уже запущен, сначала остановите его сочетанием **Ctrl+C**. После обновления файлов обновите страницу с **Ctrl+F5**.

Другой порт:

```powershell
$env:PORT = "3001"
npm.cmd start
```

Для Linux/macOS: `npm ci`, `npm test`, `npm start`. Сервер слушает только `127.0.0.1`.

## Интерфейс

| Раздел | Возможности |
| --- | --- |
| Обзор | Статистика текущего анализа, переход к изменениям и наблюдениям |
| Документы | Два комплекта, перетаскивание и выбор файлов, удаление из очереди, проверка формата/размера, просмотр извлечённого текста |
| Сравнение | Функции, изменения пунктов, подразделения, извлечённые факты; поиск, фильтры и страницы |
| Наблюдения | Доказательства, нормативное основание, риск, рекомендация, подтверждение/отклонение и комментарий |
| Заключение | Предпросмотр, скачивание Markdown, печать/сохранение в PDF через браузер |
| Подразделения | Карточки структуры, руководителей, функций, полномочий, ответственности и процессов |
| Сотрудники | Синтетические ФИО, должности, образование, стаж, сертификаты и компетенции |
| Карта функций | Учебная AS-IS: подразделение → сотрудник → функция → полномочие → ответственность |
| База знаний | Поиск исходных фрагментов, применимые контрольные требования и каталог источников |
| Настройки ИИ | Состояние OpenAI/NVIDIA, дополнительная проверка функций, результаты и расхождения провайдеров |

Подразделения, сотрудники и карта AS-IS — отдельная учебная модель для просмотра; загруженные документы не подменяются этой моделью. Факты именно из документов доступны в **Сравнение → Извлечение**.

## Проверка ваших двух положений

1. В **Документы** добавьте редакцию 8 в «До», редакцию 9 — в «После».
2. Оставьте объект пустым для всего комплекта или укажите «Внутренний аудит».
3. Нажмите **Запустить анализ**. Для локального режима API-ключ не нужен.
4. Откройте **Сравнение → Пункты**. В поиске укажите, например, `3.6`.
5. Откройте источник: отображаются имя исходного файла, пункт, цитата и определённая парсером страница/ячейка.
6. В **Наблюдения** проверьте доказательства, выберите решение, добавьте комментарий и нажмите **Сохранить решение**.
7. В **Заключение** нажмите **Сформировать заключение**, затем скачайте `.md` или выберите **Печать / PDF**.

В отчёт включаются только подтверждённые наблюдения. Отклонённые и ожидающие проверки учитываются отдельно. Ноль подтверждений не означает отсутствие рисков.

Пункты сопоставляются внутри одноимённых документов с учётом обозначения редакции в названии; одинаковый номер пункта разных положений не объединяется. Изменения текста не равнозначны нарушениям. Для положения о внутреннем аудите автоматически формируются кандидаты по изменённым пунктам разделов 3, 5 и 7 (до 30 наблюдений); полный список текстовых изменений доступен во вкладке «Пункты».

Предоставленные пользователем положения не публикуются в репозитории. Их нужно выбрать из своих локальных файлов.

## Демо без собственных документов

- **Открыть учебный сценарий**: разделение Департамента ИБ на Security Operations и Risk Department, одна функция не передана.
- **Документы → Проверить 12 документов**: реальные учебные DOCX/XLSX из `company_before/` и `company_after/`.

Оба сценария создают полноценную сессию с источниками, решениями и отчётом.

## ИИ

Создайте `.env` в корне проекта и задайте нужные переменные:

```dotenv
OPENAI_API_KEY=org-3JiWhuYoI5HYoorO3370MGACJvy
OPENAI_MODEL=gpt-4.1-mini
NVIDIA_API_KEY=ваш_ключ
NVIDIA_MODEL=meta/llama-3.3-70b-instruct
```

Перезапустите сервер и откройте **Настройки ИИ → Обновить статус**. Не добавляйте `.env` в Git.

- При загрузке флажок ИИ по умолчанию выключен; для него нужен OpenAI. В этом режиме используются существующие модули сопоставления и извлечения с `gpt-4o-mini`.
- Дополнительная проверка в настройках поддерживает OpenAI, NVIDIA или оба провайдера. Для неё используются `OPENAI_MODEL` / `NVIDIA_MODEL`.
- Запросы внешним моделям запускаются только действиями пользователя. Тексты отправляются провайдеру; запросы могут тарифицироваться.
- Дополнительная проверка ограничена 60 функциями и 60 000 символами контекста. Результаты показываются отдельно; они автоматически не заменяют утверждённые наблюдения.
- Источники восстанавливаются сервером из исходного комплекта. Придуманные моделью ID отклоняются. Интерпретацию подтверждает аудитор.
- API-ключи хранятся на сервере. OpenAI вызывается с `store:false`.

## Сессии и хранение

По умолчанию сервер держит в памяти до 20 анализов. Браузер запоминает только ID текущей сессии. После обновления страницы анализ и **сохранённые** решения восстанавливаются, пока работает тот же сервер. При перезапуске сервера сессии в памяти исчезают; интерфейс объясняет необходимость повторной загрузки. Несохранённые изменения защищены предупреждением при закрытии страницы.

Для PostgreSQL/pgvector задайте `DATABASE_URL` и используйте `compose.yaml`. Схема находится в `db/schema.sql`; настройка описана в [STAGE712.md](STAGE712.md). В этом режиме анализы, фрагменты и решения записываются в базу. Поле статуса показывает наличие конфигурации, а не проверку доступности базы.

## Форматы и ограничения

- DOCX, PDF с текстовым слоем, XLSX, TXT и MD.
- Не более 30 файлов / 30 МБ в комплекте; не более 15 МБ на файл.
- PDF-сканы требуют отдельного OCR. Графические схемы не распознаются.
- Для DOCX сохраняются номер пункта и текст; номер страницы не выдумывается.
- Локальное сопоставление функций использует правила и текстовое сходство. «Не найдено» означает отсутствие совпадения в представленном комплекте.
- Внешние законы/стандарты в каталоге представлены ссылками; автоматическая юридическая оценка по полным текстам не выполняется. Требования из загруженных ВНД — кандидаты для экспертной проверки.
- Поиск фрагментов использует простые хеш-векторы. Это не семантическая модель embeddings.
- Приложение предназначено для локальной демонстрации с доверенными документами. Авторизация и промышленная изоляция парсеров не реализованы.

## Тестирование

```powershell
npm.cmd ci
npm.cmd test
```

Запускаются только тесты из папки `test/` текущего проекта: вложенные старые копии репозитория игнорируются.

Проверяются парсеры DOCX/PDF/XLSX, сопоставление функций, валидация ответов ИИ, источники, требования, сохранение решений, восстановление сессии и фильтрация заключения. Интеграционные DOM-тесты на jsdom подключаются к реальному локальному API и проходят основные действия интерфейса: загрузка, карточки, поиск, пагинация, источники, подтверждение и отчёт. Они не заменяют визуальную проверку в браузере. Реальные платные API в тестах не вызываются.

## Основные файлы

- `public/index.html`, `public/style.css`, `public/workspace-ui.js` — интерфейс без сборки и фреймворков.
- `server.js` — HTTP, документы, аудит и сессии.
- `lib/document-parser.js` — извлечение текста и метаданных источников.
- `lib/analyzer.js`, `lib/agent.js`, `lib/ai.js` — локальное и ИИ-сопоставление.
- `lib/audit.js`, `lib/clause-diff.js`, `lib/document-requirements.js` — наблюдения, сравнение пунктов, требования и заключение.
- `lib/knowledge.js`, `lib/storage.js` — поиск и необязательное хранение в PostgreSQL.
- `test/workspace.test.js` — интеграционные проверки нового интерфейса.
