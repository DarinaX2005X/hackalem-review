# EventMatch AI

Рабочий репозиторий команды Nebula для трека 06 HackAlem AI: «Умный подбор подрядчиков».

## Простая идея

Пользователь выбирает город, дату, формат мероприятия, категорию подрядчика и бюджет.

Сервис показывает до трёх подходящих подрядчиков из выданного каталога и объясняет каждый выбор конкретными фактами:

- подрядчик работает в нужном городе;
- берёт нужный формат мероприятия;
- свободен в выбранную дату;
- его цена «от» укладывается в бюджет;
- при запросе проверяются язык и длительность.

Если подходящих нет, сервис объясняет причину: такой категории нет в городе или кандидаты не проходят условия.

## Границы задачи

В проект не входят бронирование, заявки подрядчикам, платежи и уведомления.

Цена в каталоге является ценой «от». Сервис не обещает окончательную стоимость услуги.

Данные каталога анонимизированы. Поля `synthetic`, `city_imputed` и `price_imputed` должны быть видны в карточке, когда они равны `true`.

## Роли команды

### Участник 1 — данные и алгоритм

- Добавляет исходный CSV в `data/`.
- Создаёт загрузчик и проверку структуры данных.
- Реализует фильтры: город, категория, формат, бюджет, дата, язык и длительность.
- Создаёт детерминированное ранжирование и объяснение причин пустой выдачи.
- Готовит тестовые сценарии из ТЗ.

### Участник 2 — AI Agent и NVIDIA Brev

- Поднимает на Brev HTTP-сервис агента и модельный endpoint.
- Реализует поток: понять запрос на обычном языке → уточнить обязательное поле при необходимости → вызвать инструмент `search_contractors` → проверить структурированный ответ → объяснить результат.
- Агент вызывает единый API поиска `/api/match`; он не придумывает подрядчиков и не меняет порядок ранжирования.
- Возвращает подтверждённые причины для карточек и причину пустого результата.
- Настраивает защищённый HTTPS-вызов Brev со стороны Vercel; секреты не попадают в браузер и GitHub.

### Участник 3 — generalist, интерфейс и Vercel

- Доводит форму и карточки до демо-сценария с текстовым запросом.
- Соединяет интерфейс с API агента и API поиска.
- Разворачивает приложение в Vercel из GitHub, проверяет Preview и Production URL.
- Обновляет README, фиксирует демо-запросы и готовит показ жюри.

## Архитектура

Текущий работающий путь:

```text
Форма сайта → Vercel /api/match → официальный CSV
                              → строгие фильтры
                              → детерминированная сортировка
                              → до 3 карточек или причина пустой выдачи
```

Целевой путь после подключения агента:

```text
Текстовый запрос → Vercel /api/agent → AI Agent + модель на NVIDIA Brev
                                               ↓ search_contractors
Сайт ← объяснение по результатам ← Vercel /api/match ← CSV и правила
```

Результаты и их порядок принадлежат `/api/match`. Агент работает с запросом и объяснением, а не заменяет правила доступности.

## AI Agent: граница ответственности

Состояние на сейчас: API детерминированного подбора реализован в `api/match.js`; агентный endpoint на Brev и его подключение к сайту — следующий этап. Пока Brev не подключён, проект следует показывать как работающий matcher с интерфейсом, а не как завершённый агент.

Целевой поток:

```text
Браузер
  → Vercel: сайт и серверный gateway /api/agent
  → Brev: агент и модель
  → инструмент search_contractors
  → Vercel /api/match
  → data/contractors.csv и детерминированные правила
  → карточки и подтверждённое объяснение
```

Агент может извлечь параметры из текста и задать уточняющий вопрос. Отбор по городу, категории, формату, бюджету, занятости, языку и длительности выполняет matcher. Агент не создаёт карточки, не меняет порядок результатов и не снимает ограничения молча. При пустом результате он показывает фактическую причину и предлагает варианты для следующего запроса.

Секрет доступа к Brev задаётся только в серверных переменных проекта Vercel, например `BREV_AGENT_URL` и `BREV_AGENT_TOKEN`. Не добавляйте секрет в `app.js`, HTML, публичные переменные окружения или коммиты. Для текущего rule-based приложения переменные не требуются.

## Деплой в Vercel

GitHub остаётся главным источником кода, Vercel размещает сайт и API. Репозиторий проекта: `BAITC-Hacks/hack-86169f09-nebula`.

### Настройки проекта

- Root Directory: корень репозитория.
- Framework Preset: Other (`framework: null` в `vercel.json`).
- Build Command: пустая команда; сайт состоит из HTML/CSS/JS без сборщика.
- Output Directory: корень репозитория.
- Vercel Functions: `/api/match.js` с CSV-каталогом из `data/contractors.csv`.
- Переменные окружения: rule-based поиск в `/api/match` не требует ключей.

`server.js` нужен для локального запуска. `vercel build --yes --target preview` локально собирает корректный Build Output: статический интерфейс, Node.js Function `/api/match` и CSV-каталог.

## Как запустить локально

Нужен Node.js 20 или новее.

```powershell
node server.js
```

Откройте `http://localhost:3000`. Сервер отдаёт интерфейс, CSV и API `/api/match` без установки библиотек и без личного аккаунта.

## Текущая архитектура

- `data/contractors.csv` — официальный каталог из 66 профилей.
- `api/match.js` — серверный подбор по правилам ТЗ.
- `app.js` — интерфейс, который обращается к API; при загрузке своего CSV использует локальный безопасный fallback.
- `server.js` — локальный запуск сайта и API одной командой.
- `index.html` и `styles.css` — пользовательский интерфейс.

## Технологии

- Node.js без внешних зависимостей для локального запуска;
- CSV как единственный источник фактов о подрядчиках;
- HTML/CSS/JavaScript для интерфейса;
- NVIDIA Brev — планируемое место запуска AI Agent и модельного сервиса;
- Vercel — веб-интерфейс, публичный endpoint и серверный gateway к Brev;
- детерминированный matcher остаётся единственным источником результатов и порядка карточек;
- если Brev временно недоступен, интерфейс сохраняет обычный поиск по правилам.
