# AIZAK — объяснимый подбор подрядчиков для мероприятий

Конкурсный проект команды AIZAK для HackAlem, задача «Умный подбор подрядчиков (#79-lite)».
Официальный репозиторий: [BAITC-Hacks/hack-b82ccf3d-aizak](https://github.com/BAITC-Hacks/hack-b82ccf3d-aizak).
`main` — ветка сдачи; `integration/mvp-hour2` — ветка интеграции и проверки.
Проект рассчитан на **локальный запуск**. Публичный деплой и облачный хостинг не нужны и не настроены.

## Назначение и сценарий

Частным заказчикам и организаторам мероприятий в Казахстане нужно выбрать исполнителя
из каталога с учётом города, даты, категории, бюджета и формата, а затем понять причины выбора.

1. Выберите город, категорию, дату, формат мероприятия и бюджет в тенге.
2. При необходимости укажите язык и длительность; 0 часов в форме означает отсутствие ограничения.
3. Нажмите «Подобрать»: получите до трёх реальных записей из предоставленного CSV.
4. Карточки показывают цену «от», место и балл, индивидуальные факты, объяснение и предупреждения о данных.
5. В блоке «Как мы подобрали» видна последовательная воронка фильтров. При неполной/пустой
   выдаче могут появиться подтверждённые каталогом подсказки по дате, бюджету или другому городу.
   Подсказки не меняют запрос автоматически: внесите изменения в форму и повторите поиск.

| Статус | Значение |
| --- | --- |
| `found` | Есть 1–3 подходящие карточки |
| `no_category` | В выбранном городе нет категории; другой город предлагается при наличии категории там |
| `none_match` | Категория есть, но кандидаты исключены по условиям |

Бронирование, отправка заявок и уведомления подрядчикам не входят в MVP.

## Запуск с чистого клона

Нужны доступ к приватному репозиторию, Git и Python 3.12 (проверена версия 3.12.14).
Зависимость интерфейса — `streamlit==1.55.0` в `ui/requirements.txt`.
Backend использует стандартную библиотеку Python. База данных, GPU, отдельный HTTP-backend
и API-ключ для базового локального сценария не требуются.

Windows PowerShell:

```powershell
git clone https://github.com/BAITC-Hacks/hack-b82ccf3d-aizak.git
cd hack-b82ccf3d-aizak
git switch main
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ui/requirements.txt
.\.venv\Scripts\python.exe -m streamlit run ui/app.py --server.address 127.0.0.1
```

Откройте `http://127.0.0.1:8501`. Если порт занят, добавьте `--server.port 8502`.
Используйте интерпретатор вашего виртуального окружения; активация окружения необязательна.
Для проверки интеграционной ветки замените `git switch main` на `git switch integration/mvp-hour2`.

macOS/Linux, после клонирования и выбора ветки:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r ui/requirements.txt
.venv/bin/python -m streamlit run ui/app.py --server.address 127.0.0.1
```

## Данные и фильтрация

Используется неизменённый официальный `data/hackathon-dataset-anonymized.csv`:
**66 профилей, 13 synthetic**. Рабочий интерфейс не подменяет его mock-профилями.
Loader поддерживает CSV и JSONL, списки через `|`, числа, boolean, уникальность ID и проверку дат.
Пустой `busy_dates` допустим и означает отсутствие занятых дат в предоставленном календаре.

Подтверждённые поля: `id`, `anon_name`, `categories`, `city`, `price_from_kzt`, `event_formats`,
`languages`, `max_hours`, `busy_dates`, `description`, `synthetic`, `city_imputed`, `price_imputed`.
Фильтры проверяют город, категорию, дату, стартовую цену не выше бюджета, формат,
а также язык и часы, если они заданы. Для исполнителей и площадок занятость проверяется одинаково.
`max_hours=null` означает работу без привязки к присутствию на площадке.

Окно календаря: **23.09.2026–31.12.2026**. Вне него доступность неизвестна;
UI не принимает такую дату, backend исключает кандидатов с отдельной причиной.
Путь к CSV определяется от репозитория, а не от текущей папки терминала.
При необходимости задайте `AIZAK_DATASET` в окружении для другого официального CSV/JSONL;
при отсутствии/ошибке файла показывается ошибка, а не вымышленные карточки.

## Архитектура и контракт

```text
Streamlit ui/app.py
  → ui/service.py: проверка запроса
  → backend.load_profiles(): официальный CSV
  → backend.find_contractors(): фильтры → ранжирование → топ-3 → facts, шаблоны, suggestions, trace
  → backend.explanations.add_explanations(): один OpenAI-запрос на выдачу либо резерв
  → ui/contracts.py: проверка результата → карточки, подсказки, воронка
```

Исходный backend вызывается без сетевых функций. OpenAI подключён отдельным этапом
после готового подбора, а не как три отдельных вызова на каждую карточку.
API-контракт: [backend/CONTRACT.md](backend/CONTRACT.md).
Подключение UI: [ui/INTEGRATION.md](ui/INTEGRATION.md).

```python
from backend import find_contractors, load_profiles
result = find_contractors({
    "city": "Алматы", "category": "Ведущий", "date": "2026-10-15",
    "event_type": "свадьба", "budget": 1500000, "hours": None, "language": None,
}, load_profiles())
```

Ответ содержит `status`, `message`, `matches`, `excluded`, `more_available`, `funnel`,
`suggestions`, `trace`. Карточки содержат `profile`, `match_reasons`, `warnings`,
`facts`, `explanation`, `explanation_source`, `explanation_check`.
AI-адаптер может менять только текст и источник объяснения и добавлять `explanation_status`;
ID, порядок, оценки, профили, фильтры, причины и подсказки сохраняются.

## Ранжирование и индивидуальные факты

Прошедшие фильтры сортируются по **баллу убыванию, цене возрастанию, затем ID**.
Это версия Алибека `cb757a7`; прежний MVP сортировал только по цене и ID.
В `facts.ranking` доступны балл, компоненты, место и причины преимущества над следующим кандидатом.

| Компонента | Вес | Основание |
| --- | --- | --- |
| Соответствие описания формату | 0.35 | Ключевые слова формата в описании |
| Запас бюджета | 0.25 | `1 − цена / бюджет` |
| Семантическое сходство | 0.15 | Не подключено в рабочем UI, равно 0; есть необязательный backend-hook |
| Гибкость | 0.15 | Число языков и максимальная длительность, ограниченные шкалой |
| Признаки опыта | 0.10 | Упоминания опыта/объёмов в описании |

Вес отключённой семантики не перераспределяется. Балл — объяснимая эвристика,
а не рейтинг качества или проверка квалификации. Одинаковые входные данные дают одинаковый порядок;
некорректное значение необязательного semantic-hook заменяется нулём.

`facts` включает цену, дату, формат, языки, часы, происхождение данных,
короткие дословные фрагменты описания и отличия от других выбранных карточек.
Описание — заявление из датасета, а не независимо проверенная характеристика.
Подсказки по дате/бюджету вычисляются повторной проверкой условий, без ослабления текущего запроса.
Один исключённый профиль может иметь несколько причин; их количества нельзя складывать как число людей.

## OpenAI и настройка `.env`

Провайдер — **OpenAI Responses API**, модель по умолчанию `gpt-4.1-mini-2025-04-14`.
NVIDIA не подключён. Дополнительные Python-зависимости для OpenAI не нужны.
Схема ответа основана на [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

В папке запускаемой версии проекта скопируйте `backend/.env.example` в `backend/.env`,
если `.env` ещё не существует. Не перезаписывайте существующие настройки.
Вставьте ключ **локально** после `OPENAI_API_KEY=`:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini-2025-04-14
AIZAK_AI_ENABLED=true
AIZAK_AI_TIMEOUT_SECONDS=8
```

Переменные окружения имеют приоритет над `.env`, в том числе пустой ключ и
`AIZAK_AI_ENABLED=false`. Файл ищется относительно `backend/ai_config.py`.
Поддерживаются однострочные `KEY=value`, кавычки и комментарии; без интерполяции или запуска shell.
Для проверки без сети в PowerShell задайте `$env:AIZAK_AI_ENABLED = "false"` перед запуском.
`.env` и `.env.*` исключены из Git, кроме безопасного `.env.example`; ключ не следует присылать в чат.

Модель получает только факты выбранных 1–3 карточек, предупреждения и запрос:
без имён, полного каталога, полных описаний, календарей и исключённых кандидатов.
Ответ — `{"explanations": [{"id": "…", "explanation": "…"}]}`.
Текст связывается с карточкой по ID; перестановка объектов API не меняет выдачу.
Проверяются ID, полнота, длина/уникальность текста, числа и цитаты по `facts`.
Если ответ неполный, неподтверждённый или API недоступен, показываются шаблоны Алибека из тех же фактов.
Проверка чисел/цитат — ограниченная эвристика, не доказательство истинности каждого утверждения модели.

Одна попытка на поиск, без автоповторов; таймаут сетевой операции 8 секунд (настройка 0.1–8),
ограничены токены и размер ответа. Пустые результаты и перерисовка UI не вызывают API.
С ключом новый поиск может расходовать кредиты. Используется `store=false`, редиректы запрещены;
ключ и тела ошибок API не выводятся в интерфейс или логи.

**Статус живого AI (23.09.2026):** первая попытка с таймаутом 5 с не дождалась ответа (5.4 с).
После увеличения таймаута до 8 с выполнено три живых запроса на официальном CSV (Алматы / Ведущий /
свадьба / 1 500 000 ₸): ответ приходит за 5.6–6.3 с (около 1 700 токенов на запрос).
Два ответа прошли проверку и показаны как `openai` с уникальными текстами и неизменным порядком;
один отклонён проверкой фактов (`invalid_response`), и карточки корректно получили резервные тексты.

## Ограничения

- Данные анонимизированы, часть профилей синтетическая, цены и города могут быть восстановлены;
  соответствующие предупреждения сохранены в карточках.
- Цена «от» не равна окончательной стоимости. Отсутствие даты в календаре не гарантирует бронирование.
- Эвристическое ранжирование и факты из описания не подтверждают качество услуг.
- AI необязателен: локальная работоспособность обеспечивается резервными объяснениями.
  Ответ OpenAI занимает около 6 с; часть ответов отклоняется эвристической проверкой фактов.
- Новые данные за пределами календаря, обучение моделей, платежи и облачный хостинг не реализованы.
