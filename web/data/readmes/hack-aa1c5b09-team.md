# Ясно — от потребности к решению

MVP команды «А да нууууу». React-фронтенд подключён к Java/Spring backend через единый HTTP-адаптер.

Потребитель описывает идею → отвечает на уточняющие вопросы → проверяет и публикует карточку. Исполнитель находит её в каталоге → отправляет решение → обсуждает его с заказчиком. Заказчик выбирает исполнителя; в «Моих предложениях» обновляется статус. В текущем MVP уточняющий диалог работает по сценарию; подключение модели ИИ — следующий этап.

## Возможности MVP

- Регистрация, вход, личный и публичный профиль исполнителя.
- Создание и дополнение карточки потребности, общий каталог с поиском и фильтрами.
- Предложения решений, переписка заказчика с исполнителем и выбор одного решения.
- Рейтинг готовности задачи: семь критериев, до 100 баллов, явное подтверждение владельцем.

## Архитектура

Веб-клиент React + TypeScript + Vite обращается к REST API Java 21 / Spring Boot. Бэкенд организован как модульный монолит: пользователи, потребности, предложения и переписка. Данные хранятся в PostgreSQL, миграции применяются Flyway. Авторизация — серверная cookie-сессия с CSRF-защитой. В режиме разработки Vite перенаправляет `/api` на порт `8080`.

| Каталог | Содержимое |
|---|---|
| `frontend/` | Интерфейс, HTTP-адаптер и автономный деморежим |
| `backend/` | Java API, миграции и тесты |
| `scripts/` | Совместный запуск приложения |
| `demo/` | Ранний JavaFX-пример, не используется веб-приложением |

## Полный запуск с backend

Нужны Docker Desktop, Java 21+ и Node.js 22.12+. Сначала запустите Docker Desktop, затем из корня проекта:

```sh
./scripts/start-dev.sh
```

Откройте http://127.0.0.1:5173. Скрипт запускает PostgreSQL на `5433`, backend на `8080` и frontend на `5173`. Остановка — `Ctrl+C`; контейнер базы сохраняет данные между запусками.

Если файл `backend/.env` отсутствует, для локальной базы используется пароль `needboard-local-dev`. Свой пароль можно задать в `backend/.env` по примеру `backend/.env.example`.

На Windows этот скрипт запускается в Git Bash. Альтернатива без Docker — установленный PostgreSQL 18 и два окна PowerShell из корня проекта.

Первое окно — база и бэкенд:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backend\scripts\Start-Dev.ps1
```

Второе окно — фронтенд с настоящим API:

```powershell
cd frontend
npm.cmd ci
$env:VITE_API_MODE = 'http'
$env:VITE_API_BASE_URL = '/api'
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Путь к PostgreSQL при необходимости передаётся в `Start-Dev.ps1` параметром `-PostgresBin`. Используйте один способ запуска базы; оба занимают порт `5433`.

## Рейтинг готовности

| Критерий | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Баллы начисляются за заполненные и подтверждённые владельцем сведения. После изменения сведений подтверждение соответствующего критерия снимается. Уровни: 0–39 — требует уточнения, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик. По умолчанию каталог поднимает готовые и приоритетные задачи выше; приоритетные также выделяются визуально.

Сервер возвращает итог и разбивку по критериям. [Контракт рейтинга](backend/docs/api/READINESS.md), [REST API](backend/docs/api/README.md).

## Сценарий демонстрации

1. Зарегистрировать заказчика, создать потребность и ответить на вопросы.
2. В редакторе указать ожидаемый результат и критерии успеха, сохранить карточку. Подтвердить заполненные критерии рейтинга и опубликовать задачу.
3. В другом профиле браузера зарегистрировать исполнителя, найти задачу в каталоге и отправить предложение решения.
4. Обменяться сообщениями и выбрать предложение со стороны заказчика.

## Сборка

```sh
cd frontend
npm ci
npm run build
cd ../backend
./mvnw -DskipTests package
```

В PowerShell используйте `npm.cmd` и `.\mvnw.cmd`. Эти команды собирают приложение без запуска тестов. Инструкции проверки с отдельной тестовой базой приведены в `backend/README.md`.

## Только frontend-демо

Нужен Node.js 22.12+ (проверено на Node.js 24).

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173 и нажать **«Открыть демо»**. Этот режим не требует Docker и Java.

По умолчанию используется `mock` без сервера. Данные сохраняются в браузере. ИИ и подготовленные демоисполнители отвечают по сценарию; между локальными аккаунтами можно отправлять свои предложения и сообщения. Кнопка «Демо исполнителя» открывает вторую сторону сценария. На опубликованную заявку также добавляются три демонстрационных предложения.

В серверном режиме регистрация автоматически выполняет вход, карточки и предложения хранятся в PostgreSQL, а сообщения передаются через backend. Уточняющий диалог пока использует локальный сценарий вопросов в браузере; итоговая карточка сохраняется на сервере.
