# Career Quest

Career Quest — MVP внутренней платформы развития сотрудников. Она помогает сотруднику связать карьерную цель и дефициты навыков с подходящей развивающей активностью, а руководителю и HR — сопровождать подтверждение результата.

Проект рассчитан на команды, которым нужно сделать развитие сотрудников наблюдаемым и практическим: от выбора активности до проверки evidence и обновления прогресса. Это не ATS, не сервис найма и не инструмент автоматических кадровых решений.

## Что реализовано

- Ролевой контур для Employee, Manager, HR и Admin с локальной demo-аутентификацией.
- Профили сотрудников, целевые грейды, навыки, skill gaps и показатель readiness.
- Каталог развивающих активностей, сессии с расписанием, вместимостью и листом ожидания.
- Запись на сессию, отмена до дедлайна, продвижение из листа ожидания и экспорт события в формате `.ics` для активной записи.
- Отправка evidence сотрудником и проверка результата руководителем, HR или администратором.
- Неизменяемые progress events и пересчёт прогресса после подтверждения результата.
- Telegram-напоминания: одноразовая ссылка подключения со строгим сроком действия, синхронизацией с актуальной сессией, подтверждением/отменой участия и напоминаниями.
- Отдельные интерфейсы: публичная landing-страница, вход, рабочее пространство и страница подключения Telegram.

## Как это работает

1. Сотрудник входит в demo-контур и открывает персональный маршрут: профиль, навыки и доступные активности.
2. Он выбирает подходящую сессию. Сервер проверяет права, eligibility, дедлайны и наличие мест.
3. После записи сотрудник отдельно и явно соглашается на Telegram-напоминания, выпускает одноразовую ссылку подключения и получает напоминания о сессии.
4. После прохождения активности сотрудник добавляет evidence.
5. Руководитель, HR или администратор проверяет evidence. При подтверждении сервис сохраняет progress event и обновляет связанный навык и readiness в рамках MVP-логики.

## Технологии

- JavaScript и Node.js.
- Встроенные модули Node.js: `http`, `fs`, `path`, `crypto` — без npm-зависимостей.
- Статический HTML/CSS/JavaScript-интерфейс в `dist/`.
- JSON-файлы как локальное persisted-хранилище MVP.
- Telegram Bot API через HTTPS; поддерживаются режимы polling и webhook.
- Формат iCalendar (`.ics`) для добавления записей в календарь.

В репозитории нет подключённых AI-моделей или внешнего recommendation API: рекомендации и данные MVP реализованы локально и объяснимо.

## Архитектура

```text
Browser UI (dist/)
       │ HTTP + JSON
       ▼
Node.js server (server.js)
       ├── Career store (lib/career-store.js) ── data/career-store.json
       ├── Telegram links (lib/telegram-links.js) ── data/reminder-store.json
       └── Telegram reminder bot (lib/telegram-reminder-bot.js)
                         │ HTTPS
                         ▼
                   Telegram Bot API
```

- `server.js` раздаёт интерфейс, API и календарные файлы, применяет development RBAC и связывает домен Career Quest с напоминаниями.
- `lib/career-store.js` хранит сотрудников, активности, сессии, записи, evidence и progress events.
- `lib/telegram-links.js` выпускает и валидирует одноразовые ссылки подключения.
- `lib/telegram-reminder-bot.js` обрабатывает команды и callback-кнопки Telegram.
- `CareerQuestRemindBot.js` — отдельный процесс для локального polling-режима.

## Установка и запуск

### Требования

- Node.js с поддержкой встроенного `node:test`.
- Для Telegram-уведомлений — токен, созданный через BotFather.

### Локальный запуск

1. Перейдите в каталог проекта:

   ```powershell
   cd career-quest
   ```

2. Создайте локальную конфигурацию:

   ```powershell
   Copy-Item .env.example .env
   ```

3. Для demo API укажите в `.env`:

   ```text
   CAREER_QUEST_DEV_AUTH=true
   TELEGRAM_TRANSPORT=polling
   ```

4. Если Telegram пока не нужен, задайте `TELEGRAM_TRANSPORT=disabled`. Для polling укажите настоящий `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`; не добавляйте `.env` в Git.

5. Запустите сервер:

   ```powershell
   node server.js
   ```

6. Откройте `http://localhost:4173/`. Доступны также:

   - `/sign-in` — вход в demo-контур;
   - `/app/home` — пространство сотрудника;
   - `/manager/team` — пространство руководителя;
   - `/hr/overview` — пространство HR;
   - `/admin/overview` — пространство администратора;
   - `/telegram.html` — подключение Telegram.

7. Для polling-напоминаний запустите второй процесс:

   ```powershell
   node CareerQuestRemindBot.js
   ```

Не запускайте polling-процесс одновременно с webhook-режимом сервера.

## Как проверить решение

1. Запустите сервер в development-режиме из инструкции выше.
2. Откройте `/sign-in` и выберите демо-сотрудника.
3. Откройте доступную activity, выберите сессию и выполните запись.
4. В личных записях проверьте календарный файл или выпустите одноразовую ссылку Telegram.
5. Добавьте evidence к записи, затем переключитесь на роль Manager или HR и подтвердите либо верните evidence на доработку.
6. Убедитесь, что статус записи, skill и readiness изменились после подтверждения.
7. Запустите автоматические проверки:

   ```powershell
   node --test test\*.test.js
   ```

## Данные и интеграции

- В демо используются синтетические сотрудники, роли, навыки, активности и сессии, которые создаются в локальном JSON-хранилище.
- Telegram Bot API используется только при настройке токена и выбранном transport.
- Для календаря сервис создаёт файл `.ics`; внешние календарные API не требуются.
- В production предполагаются корпоративный SSO и постоянная база данных, но они не реализованы в этом MVP.

## Ограничения

- Аутентификация — development-механизм через заголовок `x-career-quest-actor`, а не корпоративный SSO.
- JSON-хранилище подходит только для локального MVP; конкурентный production-доступ и миграции БД не реализованы.
- Рекомендации, пересчёт readiness и данные являются MVP-логикой, а не полноценной корпоративной моделью компетенций.
- Telegram требует ручной настройки токенов; для production webhook нужны дополнительные секреты и инфраструктура.
- Нет ATS, вакансий, откликов, публичных рейтингов, платежей и автоматических кадровых решений.

## Deployed-версия

В репозитории есть конфигурация статического хостинга (`.openai/hosting.json`), однако подтверждённая публичная ссылка на развёрнутую версию в текущих файлах не указана.
