# Däneker — задачи бизнеса и решения студенческих команд

> MVP-платформа, на которой бизнес формулирует проектную задачу, а студенческие команды находят подходящие кейсы, предлагают решения и поэтапно сдают результат.

## О проекте

Бизнес-задачи часто приходят к студентам в виде короткого сообщения без контекста, критериев приёмки, доступных данных и ограничений. Из-за этого команде сложно оценить задачу и понять, какой результат нужен заказчику. В то же время бизнесу неудобно собирать и сравнивать предложения, а затем фиксировать прогресс проекта.

**Däneker** связывает две аудитории:

- **бизнес** — помогает превратить исходное описание в структурированную карточку, опубликовать её, сравнить предложения и принять результаты;
- **студенческие команды** — даёт каталог задач, профиль компетенций, объяснимую оценку соответствия и рабочий процесс по этапам.

Текущая версия является локальным MVP и учебной демонстрацией. Репозиторий не содержит подтверждений реального внедрения, реальных бронирований или измеренного бизнес-эффекта.

## Что реализовано

### Для бизнеса

- регистрация и вход с ролью бизнеса;
- создание черновика задачи и автосохранение изменений;
- AI-интервью из 3–5 уточнений и генерация структурированной карточки через OpenAI;
- явно обозначенный шаблонный режим уточнений в автономной демонстрации без API-ключа;
- ручное редактирование и подтверждение карточки перед публикацией;
- единый рейтинг полноты **0–100** с расшифровкой недостающих сведений;
- отдельная AI-проверка качества текста, не изменяющая детерминированный рейтинг;
- настройка 2–3 этапов проекта, критериев приёмки и распределения 100 баллов;
- просмотр и сравнение откликов, ручной выбор одной, нескольких или ни одной команды;
- приёмка результатов этапов либо возврат на доработку с комментарием.

### Для студенческой команды

- регистрация и вход с ролью команды;
- профиль участников: роли, навыки, уровень, доступность, проекты и интересы;
- каталог опубликованных задач с поиском, фильтрами, сортировкой, пагинацией и закладками;
- детерминированная оценка соответствия профиля задаче и, при доступном OpenAI, текстовое пояснение;
- неограниченное число предложений с идеей, планом, сроком и необязательной ссылкой на прототип;
- снимок профиля и оценки соответствия на момент отклика;
- согласование плана, последовательная отправка этапов и просмотр обратной связи;
- добавление проекта в подтверждённый опыт после приёмки всех его этапов.

### Безопасность и целостность данных

- серверная проверка ролей, владельца задачи и назначенной команды;
- пароли в виде salted `scrypt`-хешей;
- сессии в `HttpOnly`, `SameSite=Strict` cookie на 12 часов;
- ограничение попыток входа и запрет изменяющих запросов с другого origin;
- проверка входного JSON, размера запроса, ссылок и переходов между состояниями проекта.

## Как работает решение

Основной пользовательский сценарий выглядит так:

1. Представитель бизнеса регистрируется и вводит исходное описание проблемы.
2. AI-интервью задаёт минимум три уточняющих вопроса. После ответов формируется черновик карточки; AI не публикует её автоматически.
3. Пользователь проверяет и редактирует название, контекст, цель, ожидаемый результат, критерии успеха, данные, ограничения, аудиторию, контакт и формат взаимодействия. Рейтинг полноты пересчитывается общим детерминированным алгоритмом.
4. Бизнес задаёт этапы и публикует карточку в каталоге.
5. Команда заполняет профиль, находит задачу через поиск или фильтры, изучает оценку соответствия и отправляет предложение.
6. Бизнес сравнивает предложения и подтверждает выбор. Для каждой выбранной команды создаётся отдельный набор этапов.
7. Команда согласует план и по очереди прикладывает описание и ссылку на результат. Бизнес принимает этап или возвращает его на доработку.
8. Баллы этапа считаются начисленными только после подтверждения бизнеса; следующий этап открывается после приёмки предыдущего.

## Технологии

| Область | Используется в проекте |
|---|---|
| Backend | JavaScript, Node.js `>=22.9`, встроенные модули `node:http`, `node:fs`, `node:crypto` |
| Frontend | HTML5, CSS, Vanilla JavaScript, hash-навигация без frontend-фреймворка |
| Хранилище | JSON-файл `data/db.json` с атомарной заменой через временный файл |
| AI | OpenAI Responses API, Structured Outputs с JSON Schema; модель задаётся через `OPENAI_MODEL`, по умолчанию `gpt-4o-mini` |
| Авторизация | Собственная cookie-сессия, `scrypt`, `randomUUID` / `randomBytes` |
| Тестирование | Встроенный `node:test`, `node:assert`, интеграционные HTTP-тесты |
| Зависимости | Внешних npm-пакетов нет |

OpenAI используется только сервером: ключ не передаётся в браузер. Запросы к модели нужны для интервью, проверки качества карточки и пояснения оценки соответствия. Сам рейтинг полноты и числовой Match рассчитываются локальными детерминированными алгоритмами и не требуют AI.

## Архитектура проекта

```text
Браузер (public/)
  ├─ интерфейс каталога, карточек, профиля, откликов и этапов
  ├─ API-клиент основного приложения
  └─ автономный demo.html с локальными учебными данными
                    │ HTTP / JSON
                    ▼
Node.js HTTP-сервер (src/server.js)
  ├─ маршрутизация и раздача статических файлов
  ├─ авторизация и проверка прав (src/auth.js)
  ├─ бизнес-правила и персистентность (src/store.js)
  ├─ рейтинг полноты (src/rating.js + public/readiness-engine.cjs)
  ├─ Match команды и задачи (src/match.js + public/match-engine.cjs)
  └─ AI-адаптер (src/ai.js) ───────────────► OpenAI Responses API
                    │
                    ▼
             data/db.json
```

Основные каталоги и файлы:

| Путь | Назначение |
|---|---|
| `src/server.js` | HTTP-сервер, API-маршруты, статические файлы и проверки доступа |
| `src/store.js` | операции с задачами, профилями, откликами, этапами и JSON-хранилищем |
| `src/auth.js` | аккаунты, хеширование паролей и сессии |
| `src/ai.js` | валидация AI-ввода/вывода и интеграция с OpenAI |
| `src/rating.js`, `src/presentation.js` | расчёт и представление полноты карточки |
| `src/match.js` | серверный адаптер алгоритма соответствия |
| `public/` | интерфейс, стили и переиспользуемые браузерные движки |
| `test/` | модульные и интеграционные тесты |
| `docs/` | контракт API и подробности отдельных подсистем |

Одни и те же CommonJS-совместимые движки из `public/` переиспользуются сервером и браузером, поэтому рейтинг, этапы, каталог и Match следуют одинаковым правилам в интерфейсе и API.

## Установка и запуск

### Требования

- Node.js **22.9 или новее**;
- современный браузер;
- опционально — ключ OpenAI API для живого AI-интервью и AI-подсказок.

### Локальный запуск

1. Клонируйте репозиторий и перейдите в него:

   ```bash
   git clone <URL-РЕПОЗИТОРИЯ>
   cd hack-ba77eedd-aliskander
   ```

2. Проверьте версию Node.js:

   ```bash
   node --version
   ```

3. Если нужен живой OpenAI, создайте локальный файл настроек:

   ```bash
   cp .env.example .env
   ```

   Затем заполните `OPENAI_API_KEY` в `.env`. При необходимости измените `OPENAI_MODEL` и `PORT`. Файл `.env` исключён из Git. Не добавляйте API-ключ в клиентский код или коммиты.

4. Запустите приложение:

   ```bash
   npm start
   ```

   Установка пакетов не требуется: в проекте нет внешних npm-зависимостей.

5. Откройте [http://localhost:3000](http://localhost:3000). Сервер слушает loopback-интерфейс `127.0.0.1`; порт по умолчанию — `3000`.

При первом запуске `data/db.json` создаётся автоматически и получает две учебные задачи и три предложения. Можно указать другой путь переменной `DATA_FILE`. После изменения `.env` перезапустите сервер.

### Полезные страницы

| URL | Назначение |
|---|---|
| `http://localhost:3000/` | основное приложение с реальными серверными аккаунтами и данными |
| `http://localhost:3000/demo.html` | автономная демонстрация с переключением ролей и локальными данными |
| `http://localhost:3000/case.html` | повторяемый сценарий защиты на учебном кейсе |
| `http://localhost:3000/prototype.html?variant=grid` | учебный прототип записи, вариант «сетка» |
| `http://localhost:3000/prototype.html?variant=list` | тот же прототип, вариант «список» |

## Как проверить решение

### Быстрый сценарий для жюри

Этот сценарий не требует API-ключа и не изменяет серверное хранилище:

1. Запустите `npm start`.
2. Откройте `http://localhost:3000/case.html` и ознакомьтесь с учебным кейсом студии «Форма».
3. Нажмите **«Открыть кейс»**: откроется отдельная демонстрация полного потока с локальными данными.
4. Переключайтесь между ролями бизнеса и команды и пройдите цепочку: карточка задачи → предложения → выбор команды → этапы → отправка и приёмка результата.
5. На странице кейса откройте учебный прототип и проверьте запись на свободный сеанс, недоступность занятого сеанса, отмену и сохранение состояния после обновления страницы. Прототип использует только `localStorage` и не бронирует реальные услуги.

### Проверка основного защищённого потока

1. Откройте `/` и зарегистрируйте аккаунт с ролью **«Бизнес»**.
2. Создайте задачу, ответьте минимум на три уточнения, проверьте карточку и опубликуйте её. Без ключа OpenAI для гарантированного показа интервью используйте `/demo.html`; основной AI endpoint сообщит, что провайдер не настроен.
3. Выйдите и зарегистрируйте второй аккаунт с ролью **студенческой команды**.
4. Заполните профиль, найдите опубликованную задачу, добавьте её в закладки и отправьте предложение.
5. Вернитесь в аккаунт бизнеса, выберите предложение.
6. В аккаунте команды согласуйте этапы и отправьте первый результат с корректной ссылкой `http://` или `https://`.
7. В аккаунте бизнеса примите этап либо верните его на доработку и убедитесь, что следующий этап нельзя сдать раньше предыдущего.

### Автоматические проверки

```bash
npm test
npm run lint
```

Тесты OpenAI используют подменённые ответы и не расходуют API. Проверить настоящий ключ и доступность выбранной модели можно отдельно:

```bash
npm run verify:openai
```

Команда `verify:openai` требует заполненного `.env` и выполняет реальный запрос к OpenAI.

## Данные и интеграции

### Локальные данные

- Основные аккаунты, задачи, профили, закладки, предложения и этапы сохраняются в `data/db.json` или в файле из `DATA_FILE`.
- Каталог при первом запуске получает учебные данные из `src/sample-data.js`.
- `demo.html` работает отдельно от защищённого API и хранит демонстрационное состояние в браузере.
- Учебный прототип записи хранит записи в `localStorage`; персональные данные ему не нужны.

### Внешние сервисы

Единственная внешняя интеграция в репозитории — **OpenAI Responses API** (`https://api.openai.com/v1/responses`). Она опциональна: каталог, аккаунты, публикация, отклики, этапы, рейтинг полноты и числовой Match работают без неё. Репозиторий не содержит интеграций с CRM, мессенджерами, OAuth, платёжными системами или внешними базами данных.

## Ограничения текущей версии

- Сервер и файловое хранилище рассчитаны на **один процесс**; конкурентный многопроцессный доступ к JSON-файлу не поддерживается.
- Сессии находятся в памяти: после перезапуска сервера нужно войти снова, хотя аккаунты и проектные данные сохраняются.
- Нет восстановления пароля, подтверждения email, OAuth и приглашений отдельных участников команды.
- Нет push/email/мессенджер-уведомлений и интеграций с внешними бизнес-системами.
- Рейтинг 0–100 оценивает заполненность карточки по фиксированным правилам, а не достоверность или бизнес-ценность текста.
- Match является рекомендательным: он использует заявленные в профиле сведения, не проверяет владение навыками и не выбирает команду вместо бизнеса.
- OpenAI-функции требуют серверного `OPENAI_API_KEY`, доступа в интернет и доступности указанной модели. Ошибка провайдера не подменяется успешным AI-ответом.
- Старые задачи без владельца сохраняются, но не назначаются новому аккаунту; для управляемого показа следует создать новую задачу или использовать автономное демо.
- Учебный прототип записи не является production-сервисом и не выполняет реальные бронирования.
