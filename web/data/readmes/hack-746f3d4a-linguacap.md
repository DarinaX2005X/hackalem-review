# Tuyin — локальное автопротоколирование совещаний

Tuyin превращает аудиозапись совещания в структурированный протокол на
компьютере пользователя. Система распознаёт русскую, казахскую и смешанную
речь, выделяет спикеров, формирует саммари и поручения, позволяет отредактировать
результат и выгрузить его в DOCX или PDF.

Аудио, транскрипт и протокол не передаются в облачный AI-сервис: рабочие
компоненты взаимодействуют только через `127.0.0.1`.

## Возможности

- Загрузка MP3, WAV, M4A и MP4 до 1 GiB.
- Локальная подготовка аудио: нормализация, VAD и нарезка речевых фрагментов.
- Распознавание русско-казахской речи моделью `asr/rukk`.
- Локальная диаризация `pyannote/speaker-diarization-community-1`.
- Саммари и поручения через локальный `qwen3:4b` в Ollama.
- Редактирование реплик, спикеров, поручений, ответственных и сроков.
- Предупреждения о поручениях без ответственного или срока.
- Сохранение транскриптов и протоколов в локальной SQLite-базе.
- Экспорт текущего протокола в DOCX и PDF.

## Архитектура

```text
Браузер
  ↓ 127.0.0.1:3000
Next.js
  ↓ 127.0.0.1:8000
FastAPI ASR-сервис
  ↓
FFmpeg → VAD → rukk ASR → pyannote → Ollama qwen3:4b
  ↓
SQLite / DOCX / PDF
```

## Требования

- macOS на Apple Silicon;
- Node.js 20+;
- Python 3.13 для базового ASR-сервиса;
- Python 3.12 для полного окружения с NeMo и pyannote;
- FFmpeg 9+;
- Ollama с `qwen3:4b` — для саммари и поручений.

Установите FFmpeg, если он ещё недоступен в `PATH`:

```bash
brew install ffmpeg
```

## Быстрый запуск

### 1. Интерфейс

В корне репозитория:

```bash
npm install
cp .env.example .env.local
```

### 2. Базовый ASR-сервис

```bash
cd services/asr
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
set -a; source .env; set +a
python -m app.model_download
cd ../..
```

Команда скачивает веса `asr/rukk` в `services/asr/models/asr/rukk/`. Загрузка
выполняется один раз; после неё распознавание может работать без интернета.

### 3. Локальная LLM для саммари и поручений

Установите и запустите Ollama, затем загрузите модель:

```bash
ollama pull qwen3:4b
```

В `services/asr/.env` задайте:

```dotenv
ASR_LOCAL_LLM_PROVIDER=ollama
ASR_LOCAL_LLM_BASE_URL=http://127.0.0.1:11434
ASR_LOCAL_LLM_MODEL=qwen3:4b
ASR_LOCAL_LLM_TIMEOUT_SECONDS=180
```

Перед запуском ASR в этом же терминале заново экспортируйте значения из файла:

```bash
cd services/asr
set -a; source .env; set +a
cd ../..
```

## Более мощные и специализированные модели

Текущая конфигурация выбрана для локальной работы на текущем устройстве:
`qwen3:4b` для протокола и `asr/rukk` для распознавания. Модели крупнее или
специализированнее не проверялись на этом устройстве из-за ограничений памяти и
вычислительной мощности. Их следует считать кандидатами для отдельного
сравнения, а не гарантированным улучшением качества.

### Модель для саммари и поручений

LLM меняется без кода: укажите её тег в `ASR_LOCAL_LLM_MODEL`, перезапустите
ASR-сервис и заново сформируйте протокол. [Qwen3 в Ollama](https://ollama.com/library/qwen3)
поддерживает многоязычные инструкции, в том числе русский и казахский, поэтому
это наиболее прямой путь к повышению качества структуры протокола.

| Модель Ollama | Размер загружаемых весов | Когда пробовать |
| --- | ---: | --- |
| `qwen3:4b` | около 2.5 GB | Текущая экономичная конфигурация. |
| `qwen3:8b` | около 5.2 GB | Первый кандидат для более точного саммари и извлечения поручений. |
| `qwen3:14b` | около 9.3 GB | Подходит для компьютера с заметным запасом объединённой памяти. |
| `qwen3:30b` | около 19 GB | Практичнее запускать на более мощном Mac или GPU-сервере. |

Например, для проверки `qwen3:8b`:

```bash
ollama pull qwen3:8b
# в services/asr/.env
ASR_LOCAL_LLM_MODEL=qwen3:8b
```

Размер файла модели не равен точному потреблению памяти во время работы:
контекст транскрипта, Ollama и ASR также занимают память. При нехватке памяти
начинайте с `qwen3:8b`, сокращайте параллельность до одного задания и проверяйте
время обработки на короткой записи.

### Модели для казахской, русской и смешанной речи

`asr/rukk` — удобный локальный выбор для code-switching: его model card
заявляет одну модель для казахской, русской и смешанной речи. Для совещаний,
где почти вся речь на одном языке, у того же набора есть отдельные модели
`asr/kk` и `asr/ru`; они меньше, но обучены на одном языке и могут быть полезны
как базовая линия сравнения.

Следующие варианты требуют нового ASR-адаптера в проекте: интерфейс должен
сохранить контракт `WAV 16 kHz → текст сегмента`, временные метки и локальное
выполнение. Они не переключаются одной переменной окружения.

| Кандидат | Для чего | Особенности |
| --- | --- | --- |
| [`KRASR/kazakh-russian-asr-whisper-small-full-ft`](https://huggingface.co/KRASR/kazakh-russian-asr-whisper-small-full-ft) | Казахская речь с русскими словами и короткими фразами | Полностью дообученный Whisper Small для KK/RU и mixed speech; доступен через `transformers`. |
| [`KRASR/kazakh-russian-asr-whisper-large-v3-lora`](https://huggingface.co/KRASR/kazakh-russian-asr-whisper-large-v3-lora) | Более сильный вариант для KK/RU code-switching | Крупная база Whisper Large-v3 с LoRA; ожидать существенно более высокие требования к памяти. |
| [`KRASR/kazakh-russian-asr-xls-r-1b-ctc`](https://huggingface.co/KRASR/kazakh-russian-asr-xls-r-1b-ctc) | Альтернатива Whisper для KK/RU и смешанной речи | Модель класса XLS-R 1B; целесообразна для GPU или мощного Mac. |
| [`openai/whisper-large-v3-turbo`](https://huggingface.co/openai/whisper-large-v3-turbo) | Широкая многоязычная базовая линия | 0.8B-параметровая модель для 99 языков; не специализирована именно под казахско-русский микс, поэтому нужна проверка на собственных записях. |

У ISSAI есть также [`Persona-ASR`](https://huggingface.co/issai/Persona-ASR):
модель целевого спикера для перекрывающейся казахско-английской речи. Она
требует короткую enrollment-реплику нужного человека и не является заменой
обычному KK/RU распознаванию совещания. Её стоит рассматривать для отдельного
сценария «выделить одного известного спикера», а не для текущего конвейера.

Для обучения или дообучения на казахской речи полезен
[`ISSAI Kazakh Speech Corpus 2`](https://huggingface.co/datasets/issai/Kazakh_Speech_Corpus_2).
Это датасет, а не готовая модель: его нельзя подключить к сервису без обучения
и отдельной оценки лицензии, согласий и распределения речи.

Под «шала-казахским» здесь понимается разговорная казахская речь с частыми
переходами на русский, заимствованиями и нестандартной лексикой. Открытая
модель не даёт гарантии качества на таком материале. Наиболее надёжный путь —
собрать согласованный локальный набор аудио и эталонных расшифровок именно с
такой речью, сравнить кандидаты тем же скриптом и при необходимости дообучить
выбранную базовую модель на этих данных.

Для любого кандидата сохраняйте закрытый контур: скачать веса один раз, затем
запускать inference локально; не передавать аудио внешнему API. Перед заменой
основной модели проверьте RU, KK, смешанную речь, имена, даты и поручения на
размеченном эталоне.

## Как работать с записью

1. Откройте приложение и выберите аудиофайл.
2. Подтвердите уведомление участников и запустите обработку.
3. В «Транскрипте» исправьте реплики и при необходимости переименуйте спикеров.
4. На вкладке «Саммари» или «Поручения» запустите локальный анализ.
5. Уточните поручения, ответственных и сроки; предупреждения отмечают пустые
   обязательные поля.
6. Скачайте DOCX или PDF на вкладке «Экспорт».

Изменение реплики сбрасывает саммари и поручения: сформируйте их повторно,
чтобы ссылки на исходные сегменты оставались корректными.

## Результаты проверки на записях проекта

Локальное сравнение с эталонными DOCX дало следующие результаты:

| Запись | Эталонных слов | Точное покрытие | RU-покрытие | Сопоставлено поручений |
| --- | ---: | ---: | ---: | ---: |
| Совещание №1 | 685 | 72.5% | 73.1% | 4 из 10 |
| Совещание №2 | 541 | 85.2% | 86.2% | 2 из 6 |

Полная сводка без текста записей — в
[отчёте качества](./docs/quality/quality-comparison-2026-09-23.md). Оба
эталонных документа не содержат слов с уникальными казахскими буквами, поэтому
они не являются валидной проверкой качества чистой казахской или смешанной речи.
Для такой оценки нужен отдельный размеченный KK/RU эталон.

Запустить сравнение для своих сохранённых результатов можно локально:

```bash
services/asr/.venv-nemo/bin/python services/asr/scripts/compare_protocols.py \
  --store services/asr/runtime/protocols.sqlite3 \
  --case 'Совещание №1::<job-id>::ТЗ/Протокол_совещания№1.docx' \
  --case 'Совещание №2::<job-id>::ТЗ/Протокол_совещания№2.docx' \
  --public-report docs/quality/quality-comparison-YYYY-MM-DD.md \
  --private-report services/asr/runtime/quality/quality-comparison-YYYY-MM-DD.json
```

Markdown-отчёт содержит только агрегаты. Ограниченный список пар
«ожидалось/распознано» с временными метками остаётся в локальном runtime-каталоге
и исключён из Git.

## Приватность

- Next.js, FastAPI и Ollama принимают только loopback-подключения.
- Внешние AI-маршруты отключены; телеметрия Next.js выключена.
- В технических журналах нет аудио, имени файла, транскрипта или протокола.
- Исходный файл, WAV и фрагменты удаляются после обработки.
- Транскрипт и протокол хранятся локально в `services/asr/runtime/protocols.sqlite3`.
- `DELETE /jobs/<id>` очищает запись из SQLite и временную рабочую папку.
- DOCX/PDF создаются в памяти сервиса; скачанный браузером файл контролируется
  пользователем.

Ограничения: SQLite не шифруется сама по себе, а удаление не очищает резервные
копии или snapshots файловой системы. Полный разбор модели угроз — в
[аудите приватности](./docs/audits/privacy-audit-2026-09-23.md).
