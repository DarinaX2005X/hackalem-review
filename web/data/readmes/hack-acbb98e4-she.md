# She++ Campaign Lab — агент тарифных кампаний

Решение кейса **Beeline Tariff Marketing Campaigns** для маркетингового аналитика.
Агент исследует возможности смены тарифа, проводит пилоты и формирует план кампаний
при ограниченных бюджете и числе контактов. Цель — увеличить ARPU с учётом затрат
на коммуникацию и риска убыточных переходов.

Все данные кейса синтетические. Результаты не описывают реальный бизнес Beeline.
Условия задачи: [ТЗ организаторов](PARTICIPANT_GUIDE.md).

## Что реализовано

- Автономный интерфейс `Agent.act(env) -> list[dict]`, работающий без сети и внешних API.
- Сегментация по текущему тарифу и ARPU; дополнительные фильтры потребления для ограничения размера аудитории.
- Ранжирование гипотез по публичной истории переходов и адаптация решений по результатам текущих пилотов.
- Выбор пилотов, повторных проверок и каналов с учётом ресурсов и неопределённости наблюдений.
- Формирование непересекающихся финальных сегментов с учётом остатков после пилотов.
- Независимый аудит схемы, фильтров, контактов и расходов; тесты агента и валидатора.
- Сравнение с шаблоном организаторов на одинаковых seed, журнал решений и локальный HTML-отчёт.
- Задачи VS Code для запуска проверок, подготовки CSV и демонстрации.

Ограничения задачи: 1–10 финальных кампаний, до 5000 абонентов на кампанию,
до 15 000 контактов и 100 000 у.е. вместе с пилотами; до 20 пилотов по 10–200 абонентов.

## Как работает решение

1. Среда передаёт агенту профиль аудитории, доступные тарифы, каналы и остатки ресурсов.
2. Агент формирует сегменты и ранжирует переходы по `data/change_tariff.csv`.
   История относится к другой выборке и используется как источник гипотез.
3. Через `env.run_pilot` агент проверяет гипотезы на небольших выборках.
   Наблюдаемый эффект влияет на следующие действия; пилоты расходуют общий бюджет и контакты.
4. По собранным свидетельствам агент выбирает финальные кампании. Для каждой указывает
   фильтры аудитории, целевой тариф и канал. Причины решений доступны в `Agent.last_report`.
5. Официальный оценщик рассчитывает эффект и расходы, включая пилоты.
   Скрипт `make_submission.py` создаёт файл сдачи; отдельный инструмент строит отчёт для аналитика.

## Технологии

**Python**, **pandas 2.3.3**, **NumPy 2.0.2**; `unittest` для тестов.
HTML/CSS и небольшой JavaScript используются для локального отчёта с поиском по кампаниям.
Среда проверена на **Python 3.9.6**; версии зависимостей зафиксированы в
[requirements.txt](requirements.txt), полный состав проверенного окружения — в
[requirements-lock.txt](requirements-lock.txt).

LLM, облачные AI-модели, платные API и реальные сервисы рассылки не подключены.
Агентность реализована программным циклом «наблюдение → выбор эксперимента → обновление решения».

## Установка и запуск

Нужны Git, Python и доступ к закрытому командному репозиторию.
В VS Code откройте **Terminal → New Terminal / Терминал → Создать терминал**:

```bash
git clone https://github.com/BAITC-Hacks/hack-acbb98e4-she.git
cd hack-acbb98e4-she
```

Если репозиторий уже открыт, повторное клонирование не требуется.

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

**Windows, PowerShell:**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию, вместо `python` используйте
`.\.venv\Scripts\python.exe`; менять системную политику для запуска не требуется.
Для воспроизведения полного набора зависимостей замените `requirements.txt` на `requirements-lock.txt`.
Установка зависимостей требует доступа к индексу пакетов; последующая работа агента — офлайн.

В VS Code выберите **File → Open Folder / Файл → Открыть папку** и папку репозитория.
Через палитру команд выберите **Python: Select Interpreter → .venv**.
Откройте **Terminal → Run Task / Терминал → Запустить задачу**: доступны пронумерованные
проверки комплекта, агента, устойчивости, тестов, сравнения, генерации CSV и HTML.
Задачи используют интерпретатор `.venv` напрямую и не требуют активированной оболочки.

## Как проверить решение

Из корня проекта с установленными зависимостями выполните:

```bash
python tools/check_package.py
python -m unittest discover -s tests -v
python local_eval.py
python local_eval.py --runs 10
python tools/benchmark.py --runs 10
python make_submission.py
python tools/build_report.py
```

Воспроизводимый сценарий для жюри:

1. Убедитесь, что комплект найден, тесты завершились с `OK`, а оценщик не сообщает об ошибках агента или отброшенных кампаниях.
2. Откройте созданный `submission.csv`: проверьте целевой тариф, канал и фильтры каждой кампании.
3. Откройте `reports/campaign_report.html` в браузере. Найдите кампанию по тарифу,
   сравните её аудиторию и расходы, затем раскройте журнал решений и соответствующие пилоты.
4. В `reports/plan_audit.json` проверьте `audit.valid`, бюджет и контакты вместе с пилотами.
   Повторный контакт расходует лимит повторно; уникальный охват указан отдельно.
5. Для сдачи используйте `agent.py`, сгенерированный официальным скриптом `submission.csv`
   и зависимости согласно процедуре организаторов. CSV не заполняется вручную.

## Данные и интеграции

Оригинальный синтетический пакет включён в закрытый репозиторий команды.
`customer_profile.csv` содержит целевую аудиторию; `data/change_tariff.csv` — историю переходов;
`data/dict_tariff.csv`, `tariff_dictionary.csv` и `feature_dictionary.csv` описывают тарифы и поля.
`data/traffic.csv` и `data/arpu_monthly.csv` входят в пакет; агент не обучает на них отдельную модель.
Доступ к среде осуществляется через публичные поля `env` и метод `env.run_pilot`.
Сетевые интеграции, ключи API и реальные персональные данные для запуска не нужны.

## Ограничения

- Исторические переходы не являются причинной оценкой эффекта для новой аудитории.
- Интервалы строятся на рабочей модели шума: это не гарантия статистического покрытия,
  доходности или победы. Пилоты и финальные кампании могут дать отрицательный результат.
- Идентификаторы участников пилотов недоступны агенту. Точное пересечение пилотов
  с финальным планом не определяется; дедупликацию эффекта выполняет официальный оценщик.
- При отсутствии убедительного прибыльного плана возможна резервная кампания с малой
  экспозицией. Она явно помечается в журнале и тоже может оказаться убыточной.
- Аудит консервативно отклоняет пустые аудитории, сегменты больше 5000 и превышение
  остатков после пилотов. Он проверяет корректность, но не рассчитывает истинный финансовый эффект.
- Нет рабочей интеграции с биллингом, CRM и отправкой сообщений. Оценка на реальных данных не проводилась.

## Развёрнутая версия

Публичного развёртывания нет. Решение запускается локально через `Agent.act(env)`;
созданный HTML-отчёт открывается в браузере без сервера.
