# StockPilot — заказы поставщикам

Приложение закупщика для HackAlem AI. Нурасыл: данные. Гапар: engine. Рамазан: интерфейс и интеграция.

## Запуск

Python **3.12**. Команды из корня репозитория:

Основная ветка запуска — **`main`**. PR №1, №3 и №4 объединены. Получите обновления через `git fetch origin`, переключитесь командой `git switch main`, выполните `git pull --ff-only origin main` и перезапустите Streamlit из обновлённой папки. Обновление Git само по себе не перезапускает сервер.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте напечатанный адрес, обычно `http://127.0.0.1:8501`. Сервер слушает только локальный компьютер. Остановка: Ctrl+C.

Для macOS/Linux после создания окружения используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.

## Работа с приложением

1. При запуске открывается **«Демонстрация»**: 8 вымышленных товаров двух поставщиков. Расчёт выполняет настоящий `engine.py`.
2. Для реальных данных выберите **«Мои файлы»** и загрузите `Systeme electric.zip`, `IEK.zip` или XLSX. Для отдельного XLSX без поставщика в имени выберите **IEK / Systeme Electric** под загрузчиком. Выбор сохраняется в идентификаторе входов и передаётся loader через безопасную временную папку поставщика. Изменение выбора требует пересчёта и отменяет старое утверждение/AI-пояснение. ZIP с исходной структурой работает без такого выбора. Временные копии удаляются после чтения.
3. Укажите дату снимка, сроки поставки, период пересчёта и страховой запас. Нажмите **«Рассчитать заказ»**.
4. Во вкладке **«Заказы»** используйте поиск и фильтры. Колонка «Расчёт» содержит рекомендацию, «К заказу» — редактируемое количество. Подробности доступны по горизонтальной прокрутке или в полноэкранном режиме таблицы.
5. Выберите строки. **«Выбрать»** выбирает доступные положительные рекомендации только среди видимых строк. Ранее выбранные строки сохраняются при смене фильтра; весь состав виден в раскрывающемся списке перед утверждением.
6. Проверьте количество, единицы, ограничения и предупреждения; отметьте подтверждение и нажмите **«Утвердить выбранные позиции»**.
7. Скачайте CSV. Он содержит именно утверждённый снимок, сгруппирован по поставщику, включает дату расчёта и отметку источника. Нулевые количества означают отказ от закупки и в CSV не попадают.

Изменение параметров или файлов делает предыдущий расчёт устаревшим. Ручные правки и изменение выбранного состава отменяют утверждение. Для нового экспорта нужно утвердить заказ заново. Состояние хранится в текущей браузерной сессии; перезагрузка страницы/сервера может его сбросить, поэтому скачайте готовый файл.

Вкладка **«Объяснение SKU»** показывает слагаемые формулы, месячную историю, отдельный дневной прогноз и ограничения. Вкладка **«Данные»** содержит источники, размеры таблиц и диагностику.

Во вкладке **«Данные»** блок **«Что мешает расчёту и что проверить»** показывает сводку по типам проблем, фильтры поставщика/товара и разбор отдельного замечания: источник, период, исходное сообщение и необходимую проверку. Для расхождений продаж доступны месячный отчёт, сумма операций и разница из сверки loader; неизвестные значения остаются пропусками.

- **Блокирует расчёт** — engine явно назвал это замечание причиной недостаточных данных.
- **Требует проверки** — замечание есть, но отдельная блокирующая роль не подтверждена; engine мог остановиться раньше.
- **Вне выбранного периода** — engine выдал точное исключение для этого поставщика, SKU и текста ошибки. Исходный `severity=error` сохраняется; это не исправление источника и не разрешение заказа.
- **Информация** — пояснение расчёта, которое само по себе не определяет допуск заказа.

Повторы одного замечания из loader и engine объединяются с сохранением источников. Общие замечания поставщика относятся только к его товарам. В сводке считаются уникальные пары поставщик + код 1С; один товар может попасть в несколько типов проблем, поэтому строки сводки нельзя суммировать. Несвязанные записи не исчезают и не увеличивают число товаров. Исходные таблицы и полная диагностика доступны ниже.

**«Скачать полный список проблем (CSV)»** выгружает все замечания выполненного расчёта, независимо от фильтров, с датой и отметкой демонстрационных/реальных данных. Это отчёт для проверки, не заказ поставщику. После изменения файлов или параметров скачивание блокируется до пересчёта. Просмотр отчёта не меняет количества, исходные ошибки или утверждение. Даже полный список найденных замечаний не доказывает, что проверены все возможные проблемы: расчёт может остановиться на первой причине.

В боковой панели есть **«Подтверждённые условия поставщиков»**: единый складской контур и недостающие минимум/кратность. Настройки включаются только явным подтверждением менеджера и должны соответствовать проверенным условиям. Условия из файлов имеют приоритет; ошибки продаж, неизвестные единицы и отсутствие остатков этим не исправляются. Проверка ручных количеств использует те же условия, что и расчёт.

## Контракт и границы ответственности

```python
dataset = load_data(paths)                  # Нурасыл
result = calculate_orders(dataset, settings)  # Гапар
```

Схемы перечислены в [TEAM_PLAN.md](TEAM_PLAN.md).

Файлы `data_loader.py`, `engine.py`, тесты и документы их авторов сохранены без правок. Наша граница интеграции — `ui_integration.py`:

- переводит явный маркер общего контура `*all*` в `__all__` в копиях таблиц;
- для SKU с текущим снимком передаёт engine текущие снимки, оставляя исторические таблицы в исходном dataset для просмотра;
- блокирует использование снимка на другую дату без подтверждённого обновления;
- сохраняет неизвестные склады, пропуски, ограничения MOQ и все ошибки loader; значения не выдумывает.

`order_review.py` отвечает за привязку правок к `(supplier, sku)`, проверку выбора и количества. `export.py` создаёт CSV только после проверки снимка утверждения; текстовые поля защищены от интерпретации как формул. CSV в UTF-8 с BOM и разделителем `;`. При импорте в Excel задайте колонкам кодов текстовый формат для сохранения ведущих нулей. Совместимость с конкретным импортом 1С не заявляется без проверки шаблона.

## Ограничения текущих модулей

Подключён engine Гапара `cc15fe0`: устойчивый тренд, аномалии и восстановление подтверждённых stockout. UI читает `ENGINE_CAPABILITIES` и передаёт реальные настройки: тренд по умолчанию включён, исключение аномалий и восстановление stockout выключены до выбора пользователя. Карточка SKU показывает таблицу аномалий. Пустая таблица не доказывает отсутствие аномалий; отсутствие stockout/customer_id в источниках остаётся ограничением.

`recommended_qty=NaN` или `data_quality=insufficient` блокируют утверждение даже после ручного ввода количества. Недостающие минимум/кратность не подставляются автоматически. Общая сумма количества для разных единиц не вычисляется; закупочная стоимость без подтверждённых цен не показывается.

На предоставленных архивах проверка 23.09.2026 обработала **3 909 товаров**; все рекомендации заблокированы исходными ошибками качества/нехваткой данных. Это не подменяется деморезультатом. [Отчёт интеграции](docs/integration_review.md) содержит детали и задачи владельцам данных/алгоритма.

## AI-пояснения OpenAI

**На защите AI оставляем выключенным:** переключатель экспериментальных пояснений по умолчанию выключен. Известное ограничение: при сокращении до 24 issues пояснение неприменимости исторической ошибки может потеряться. Поэтому AI пока нельзя использовать как надёжное объяснение статуса при большом числе замечаний. Расчёт и утверждение от него не зависят. Живой запрос не проверен.

Во вкладке SKU доступны **«Объяснить простыми словами»** для готовой рекомендации и **«Что нужно уточнить»** для insufficient. Первая причина блокировки и все конкретные замечания товара/поставщика видны без AI. Чтение пояснения не изменяет черновик и утверждённый CSV.

Настройте `OPENAI_API_KEY` и `OPENAI_MODEL` в окружении процесса Streamlit либо в локальном `.streamlit/secrets.toml` по образцу `.streamlit/secrets.toml.example`. Реальный файл уже исключён из Git. Не отправляйте ключ в чат и не записывайте в документацию. При изменении окружения перезапустите сервер; secrets читаются при следующем действии в приложении. Модель также можно явно изменить в боковой панели. Без настройки доступны исходные формула и диагностика.

При первом нажатии кнопки проверяется доступ аккаунта к выбранной модели через `models.retrieve`, затем вызывается официальный SDK / Responses API со строгой JSON Schema и `store=False`. Успех запроса подтверждает совместимость конкретной модели; приложение не подменяет её другой. [Responses API](https://developers.openai.com/api/docs/guides/text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [проверка модели](https://developers.openai.com/api/reference/python/resources/models/methods/retrieve).

Это ограниченный AI-помощник: модель выбирает приоритет и порядок проверенных тезисов и вопросов. Текст и числа собираются локально из этих тезисов и фактов расчёта, а произвольный текст модели не отображается. Проверяются структура, разрешённые тезисы, evidence_id и согласованность фактов. Для insufficient нет тезиса с рекомендуемым количеством. При невалидном ответе, отказе API или таймауте остаются обычные пояснения. Контракт для Гапара: [docs/ai_contract.md](docs/ai_contract.md).

В OpenAI отправляется сводка одного SKU: числовые факты, обезличенный ID, классифицированные проблемы. Названия товаров, сырые сообщения, архивы, клиенты, документы, пути и ключи не входят в запрос. Только кнопка вызывает сеть; не более одного запроса одновременно, общий таймаут около 15 секунд и максимум один повтор временной ошибки. Кэш ограничен текущей сессией и включает расчёт, поставщика, SKU, вопрос, модель, провайдера и версию prompt. Смена входов очищает AI-кэш; смена модели сохраняет числовой заказ и утверждение.

Первый live smoke-test проводится только в **«Демонстрации»** на синтетическом SKU с ответом 72. Unit-тесты используют mock SDK и не делают платных вызовов. Наличие ключа не означает успешного подключения: готовность подтверждается ответом `status=ok`.

**NVIDIA:** в текущей сборке NVIDIA inference не подключён. Brev Billing относится к вычислительным ресурсам и общему балансу организации; он не подтверждает наличие hosted inference endpoint. Баланс и купон не проверялись, пользовательские coupon-ссылки не сохраняются. Отдельный Brev-эксперимент можно показывать только с фактическим результатом и подписью «офлайн-эксперимент». [Документация Brev](https://docs.nvidia.com/brev/guides/console-reference).

## Демо за 3 минуты

В режиме **«Демонстрация»** выберите **«Сценарий демонстрации»**:

- **Обзор · 8 товаров** — прежний сценарий расчёта, правки, утверждения и CSV.
- **Разовый крупный заказ** — исключение аномалии: **5232 → 72**.
- **Отсутствие товара (stockout)** — восстановление упущенного спроса: **0 → 72**.
- **Устойчивый рост спроса** — учёт тренда: **192 → 336**.

При смене сценария устанавливаются его синтетические данные, дата и начальные параметры; старое утверждение отменяется. Нажмите **«Рассчитать заказ»**: под общими показателями появятся два результата с выключенной и включённой коррекцией. Оба рассчитываются настоящим engine при одинаковых остальных параметрах. Чтобы применить коррекцию к таблице заказа, включите соответствующий флажок в **«Возможностях прогноза»** и пересчитайте. Изменение параметров скрывает устаревшее сравнение до пересчёта. Числа выше относятся к исходным настройкам примеров; при изменении срока или страховки они пересчитываются. Примеры используют `engine_examples.py`, работают без API и не подтверждают пригодность реальных выгрузок.

Контроль алгоритмов: `python engine_examples.py` — восемь проверок, включая 72, аномалии 5232 → 72, stockout 0 → 72, тренд 192 → 336 и неизвестный остаток. Примеры синтетические; они не разрешают сокращать реальную историю. Подробности: [docs/engine_handoff.md](docs/engine_handoff.md).
