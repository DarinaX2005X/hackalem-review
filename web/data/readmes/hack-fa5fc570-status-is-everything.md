# WindMind AI

Система почасового прогноза мощности двух ветроустановок на горизонте 24 или 48 часов.

Проект включает подготовку SCADA-данных, обучение отдельных моделей для двух турбин, историческую проверку, работу с архивной прогнозной погодой и интерфейс на Streamlit.

## Что реализовано

В проекте есть два режима работы с погодой:

1. **Интерактивный режим** — использует Open-Meteo Previous Runs и выводит почасовой расчёт в Streamlit.
2. **Режим архивных выпусков** — принимает прогнозы с известными `issued_at` и `available_at`, проверяет источник, полноту горизонта и время доступности данных.

Основной результат модели — `predicted_power`, нормализованная мощность каждой турбины. Физическая шкала подключается через коэффициенты `normalization_to_mw` в конфигурации.

## Данные

Исходные CSV находятся в каталоге `ВЭС/data/raw/`.

Период наблюдений:

- начало: `2023-03-11 00:00`;
- конец: `2026-01-31 23:50`;
- турбина 1: 142 360 строк;
- турбина 2: 149 499 строк;
- шаг измерений: 10 минут.

Используемые поля:

- время измерения;
- средняя скорость ветра;
- средняя температура воздуха;
- нормализованная активная мощность.

Названия некоторых старых файлов содержат слово `february`, хотя фактические SCADA-данные заканчиваются 31 января 2026 года.

## Подготовка данных

Модуль `src/data.py`:

- определяет UTF-8, CP1251 или UTF-16;
- определяет разделитель CSV;
- проверяет обязательные поля;
- сохраняет точные нулевые значения мощности;
- исключает конфликтующие временные метки;
- не заполняет пропущенные часы вымышленными значениями;
- агрегирует 10-минутные измерения в почасовые интервалы;
- помечает часы, пригодные для обучения.

По умолчанию час допускается к обучению, только если содержит шесть корректных 10-минутных измерений.

Настройки находятся в `config/settings.json`. Смысл временной метки, задержка поступления SCADA и шкала мощности вынесены в конфигурацию и не зашиты в код обработки данных.

## Модель

Для каждой турбины обучается отдельный `HistGradientBoostingRegressor`.

Признаки модели:

- `wind_speed`;
- `temperature`.

Базовая модель рассчитывает среднюю мощность по диапазонам скорости ветра шириной 0,5 м/с.

Для исторического расчёта используется point-in-time обучение:

- берутся только завершённые почасовые интервалы;
- учитывается настроенная задержка поступления SCADA;
- данные после момента расчёта не используются;
- февральские целевые значения в обучение не попадают;
- модель и базовый метод обучаются на одном и том же доступном срезе.

Прогноз по умолчанию ограничивается диапазоном мощности обучающей выборки. Неограниченный результат сохраняется отдельно в поле `raw_predicted_power`.

## Результаты проверки

### Проверка на измеренной погоде

Модель обучается на данных до января 2026 года и проверяется на 744 часах января.

| Турбина | MAE модели | RMSE модели | MAE baseline | RMSE baseline |
|---|---:|---:|---:|---:|
| 1 | 0.024855 | 0.048331 | 0.035322 | 0.058432 |
| 2 | 0.027006 | 0.064151 | 0.039181 | 0.072893 |

Эта проверка отдельно измеряет качество преобразования фактической погоды в мощность. Проверка на прогнозной погоде приведена ниже.

### Проверка на архивной прогнозной погоде

Для дополнительной проверки используются фиксированные срезы Open-Meteo Previous Runs за 24 и 48 часов до целевого времени.

| Турбина | Срез погоды | MAE модели | MAE baseline |
|---|---:|---:|---:|
| 1 | 24 ч | 0.3162 | 0.3090 |
| 1 | 48 ч | 0.3477 | 0.3388 |
| 2 | 24 ч | 0.3111 | 0.3109 |
| 2 | 48 ч | 0.3423 | 0.3411 |

Средняя абсолютная ошибка прогнозного ветра относительно SCADA составляет примерно 3,24–3,56 м/с. Сравнение с baseline сохранено в отчёте и используется как ориентир для следующей версии модели.

Open-Meteo Previous Runs используется для fixed-lead проверки. Для точного воспроизведения полного выпуска в проекте предусмотрен отдельный формат с полями `issued_at` и `available_at`.

## Установка

Требуется Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Полный набор закреплённых зависимостей находится в `requirements-lock.txt`.

## Подготовка данных и обучение

```powershell
.\.venv\Scripts\python.exe -m src.train
```

Команда:

- проверяет исходные CSV;
- создаёт `data/processed/hourly.csv`;
- сохраняет отчёт `reports/data_quality.json`;
- выполняет январскую валидацию;
- сохраняет модели в `models/validated/`;
- записывает метрики в `reports/metrics.json`.

После изменения версии `scikit-learn`, исходных данных или настроек модели необходимо переобучить модели и удалить старый кэш `models/point_in_time/`.

## Запуск интерфейса

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Или:

```powershell
.\run.bat
```

В интерфейсе можно выбрать:

- дату и час расчёта;
- горизонт 24 или 48 часов;
- таблицу почасовых результатов;
- графики мощности и погоды;
- исследовательский сценарный расчёт;
- отчёт январской валидации.

Streamlit объединяет выбор временного среза, графики, таблицу прогноза, сценарный расчёт и отчёты в одном интерфейсе. Расчётное ядро сохраняет нормализованную мощность и сведения о выбранном погодном срезе.

## Исследовательский replay

Загрузка или обновление архива Previous Runs:

```powershell
.\.venv\Scripts\python.exe -m src.previous_runs
```

Расчёт за февральский период:

```powershell
.\.venv\Scripts\python.exe -m src.evaluation
```

Проверка на январских фактических значениях мощности:

```powershell
.\.venv\Scripts\python.exe -m src.evaluation --january
```

Диагностический архив хранится в `data/weather/diagnostics/`. Его SHA-256, период, погодная модель и координаты проверяются перед использованием.

## Строгий погодный контракт

Рабочий файл `data/weather/forecasts.csv` должен содержать:

```text
turbine_id
issued_at
available_at
valid_time
wind_speed
temperature
```

Все временные поля должны содержать UTC-смещение. Для каждого выпуска требуется `data/weather/source.json` с источником, единицами измерения, высотой ветра, подтверждением совместимости со SCADA и SHA-256 файла.

Полное описание формата находится в `config/WEATHER_INPUT.md`.

После подключения архива расчёт запускается командой:

```powershell
.\.venv\Scripts\python.exe -m src.agent --origin "2026-02-01T00:00:00+05:00" --horizon 48
```

Режим наблюдения за обновлением файла:

```powershell
.\.venv\Scripts\python.exe -m src.agent --watch --interval 60
```

Строгий replay за период:

```powershell
.\.venv\Scripts\python.exe -m src.backtest
```

Входной контроль отклоняет неполные выпуски и предотвращает расчёт по данным, которые ещё не были доступны в выбранный момент времени.

## Загрузка NOAA GFS

Скрипт `fetch_gfs_archive.py` загружает отдельные прогнозные поля NOAA GFS через Herbie и формирует `forecasts.csv` и `source.json`.

Пример короткой проверки:

```powershell
.\.venv\Scripts\python.exe fetch_gfs_archive.py --start 2026-01-30 --end 2026-01-30 --max-fxx 6 --cycles 18
```

Пример архива на 48 часов:

```powershell
.\.venv\Scripts\python.exe fetch_gfs_archive.py --start 2026-01-30 --end 2026-02-28 --max-fxx 48 --cycles 00,06,12,18
```

Перед использованием полученного архива необходимо проверить координаты, время доступности выпусков, способ приведения ветра к высоте турбины и совместимость со SCADA.

## Развитие проекта

Следующие задачи относятся к подключению проекта к данным конкретной ВЭС:

- настройка физической шкалы мощности по паспортам турбин;
- привязка высоты прогнозного ветра к высоте SCADA-измерений;
- загрузка фактической мощности за февраль для проверки полного периода;
- добавление статусов работы, остановок и curtailment;
- калибровка вероятностного интервала прогноза;
- обновление модели по результатам fixed-lead проверки.

Текущая версия закрывает полный воспроизводимый цикл: исходные SCADA-данные → почасовая агрегация → обучение → историческая проверка → прогноз на 24/48 часов → интерфейс и CSV-выгрузка.
