# Аким на 5 часов · Ascension

**«Аким на 5 часов» — тренажёр для выбора городских решений.** Вы собираете план из пяти инициатив в пределах бюджета и видите, как он меняет качество жизни районов. Проект помогает сравнить варианты, понять, какие районы получают пользу, и подготовить записку для обсуждения решения. Это работа команды Ascension по кейсу №12 HackAlem AI.

В основе — учебный набор пяти районов Астаны, 14 мероприятий и бюджет 100 условных единиц. Карта показывает реальную географию, а показатели и эффекты мероприятий взяты из синтетической модели кейса. Результат позволяет проверить логику решения; он не является прогнозом для реального города.

**[Открыть публичное демо](https://ascension-city-map.azamatbreach.workers.dev)** — главная страница показывает обзор города и переходы к рабочим разделам. Для симулятора не нужны регистрация, личный API-ключ или подписка. **[3D-карта и Ascension AI](https://ascension-city-map.azamatbreach.workers.dev/command-center.html)** открываются в отдельном центре управления. Для последовательной проверки ниже используйте **[компактный симулятор](https://ascension-city-map.azamatbreach.workers.dev/classic.html)** и кнопку **«Попробовать на примере»**.

**[Рабочее пространство акима](https://ascension-city-map.azamatbreach.workers.dev/mayor-overview.html)** объединяет девять разделов: обзор, карту, конструктор, аналитику, районы, сценарии, обращения, поручения и паспорта данных. Они используют те же серверные расчёты и существующие модули. [Устройство и проверка кабинета](docs/design/mayor-workspace.md).

**[Учебный маршрут за 90 секунд](https://ascension-city-map.azamatbreach.workers.dev/demo.html)** проводит через пример решения и его последствия. Обращение и поручение в этом маршруте — демонстрационные записи в памяти страницы; для настоящей проверки реестра используйте формы жителя и акимата. В компактном симуляторе после расчёта также доступно объяснение распределения бюджета.

**[Презентация, речь и ответы жюри](docs/presentation/2026-09-23/README.md)** доступны в PowerPoint, PDF и Markdown. Это отдельный выпуск на 23 сентября, 16:48 GMT+5: исторические статусы внутри презентации не заменяют проверку текущего приложения.

API обращений подключён к публичному Cloudflare Worker. Локальная версия сохраняет обращения в JSON-файле, публичная — в постоянном хранилище Durable Object. Публичная панель защищена: HTTP 401 без служебного токена — ожидаемое поведение. Весь маршрут «житель → сотрудник → решение» жюри может проверить локально без аккаунтов и ключей команды.

## Как запустить

Нужны **Node.js 24 или новее**, npm из его поставки и современный браузер. Для клонирования нужен Git; также можно скачать ZIP репозитория и открыть терминал в распакованной папке. Доступ к закрытому репозиторию выдаётся организаторами; самому приложению аккаунт не нужен.

После распаковки на Windows достаточно дважды нажать **`START-WINDOWS.cmd`**. На macOS/Linux выполните **`sh start-local.sh`**. Скрипт проверит Node.js, запустит локальный сервер и откроет страницу; оставьте окно терминала открытым. [Запуск для организаторов и собственный хостинг](docs/organizer-hosting.md).

```sh
git clone --branch v1.1.0 https://github.com/BAITC-Hacks/hack-0c0b9665-ascension.git
cd hack-0c0b9665-ascension
node --version
npm start
```

Откройте **[обзор города — http://127.0.0.1:3000](http://127.0.0.1:3000)**. В текущей версии установка npm-пакетов и сборка для запуска не нужны: MapLibre уже включён в `public/vendor/`. Файл `.env.local` необязателен; сообщение о его отсутствии при первом запуске нормально. Остановка сервера — **Ctrl+C**.

Главная `/` — обзор. **[Центр управления `/command-center.html`](http://127.0.0.1:3000/command-center.html)** содержит полноэкранную 3D-карту, панели и AI; **[рабочее пространство `/mayor-overview.html`](http://127.0.0.1:3000/mayor-overview.html)** — девять разделов кабинета. **[Компактный `/classic.html`](http://127.0.0.1:3000/classic.html)** использует то же расчётное ядро; на нём выполняется контрольный сценарий ниже.

Расчёты, сравнение сценариев и локальные обращения работают без ключей внешних сервисов. Для подложки карты и поиска нужен интернет, для 3D — поддержка WebGL. Если карта не загрузилась, расчёт и таблица показателей остаются доступны. Без ключа модели показывается **«Без AI · расчётное объяснение»**.

Если порт 3000 занят, создайте в корне `.env.local` со строкой `PORT=3001`, перезапустите сервер и откройте `http://127.0.0.1:3001`. Остальные необязательные настройки перечислены в [.env.example](.env.example). По умолчанию сервер слушает только `127.0.0.1`.

[Подробная инструкция самостоятельного запуска](docs/self-hosting.md) включает чистую проверку, постоянный сервер Linux с systemd, Docker Compose, HTTPS и резервную копию обращений. Для собственного сервера и бота используются собственные настройки владельца; базовая локальная проверка не требует облачной инфраструктуры.

## Как проверить решение за 5 минут

Откройте **[публичный компактный симулятор](https://ascension-city-map.azamatbreach.workers.dev/classic.html)** или **[локальную страницу](http://127.0.0.1:3000/classic.html)**. Все названия кнопок в следующих шагах относятся к `/classic.html`.

### 1. Рассчитать официальный пример

На странице `/classic.html` нажмите **«Попробовать на примере»**, затем **«Посмотреть результат»**. В плане должны быть:

| Мера | Район |
| --- | --- |
| M7 — школа и детсад | Нура |
| M8 — центр семейного здоровья / поликлиника | Нура |
| M10 — освещение и камеры | Нура |
| M12 — единая цифровая платформа обращений | Весь город |
| M5 — перевод частного сектора на чистое топливо | Сарыарка |

Проверьте результат по таблице. Точка в точных значениях ниже — десятичный разделитель; интерфейс использует запятую и округляет до двух знаков.

| Показатель | До решений | Официальный пример A | Вариант B из следующего шага |
| --- | ---: | ---: | ---: |
| Общий Score | 52,56 | **56,54** | **55,30** |
| Изменение Score | — | +3,99 | +2,74 |
| Стоимость / остаток | 0 / 100 | **95 / 5** | **95 / 5** |
| Критических показателей | 2 | **0** | **1** |
| Оценка слабейшего района, Нуры | 49,18 | 52,96 | 51,86 |

Точные контрольные Score: `52.55768`, `56.54307`, `55.29777`. В блоке **«Дополнительный эффект сочетаний»** видно совместное действие M10 и M12 в Нуре.

### 2. Сравнить решение при том же бюджете

В блоке **«Ваш план»** у школы и детсада поменяйте район **Нура → Есиль**, остальные решения оставьте прежними. Снова нажмите **«Посмотреть результат»**: получится вариант B из таблицы. Стоимость остаётся 95, но один показатель Нуры остаётся ниже критической границы.

Раскройте **«Сравнить два последних расчёта»**. Сравнение показывает два последних расчёта; оценка Есиля меняется на **+1,10**, Нуры — на **−1,10**. **«Загрузить A»** возвращает решения первого варианта в форму — после загрузки выполните расчёт заново. **«Скачать сравнение (JSON)»** сохраняет снимки A/B для передачи и воспроизведения.

Раскройте **«Мои сценарии»**, укажите название и нажмите **«Сохранить расчёт»**. План можно загрузить после перезагрузки страницы или импортировать из JSON сравнения. Библиотека хранит до 20 сценариев в этом браузере на этом адресе; сравнение двух последних расчётов — в памяти вкладки. Импортированные оценки не принимаются за результат сервера: загруженный план нужно пересчитать.

### 3. Найти альтернативу одной мере

Заново загрузите демо и рассчитайте его. Раскройте **«Что можно улучшить в плане»**, затем нажмите **«Найти альтернативы»**. Для официального примера поиск проверяет 181 замену, из которых 117 допустимы, и показывает пять вариантов с разными компромиссами между Score, слабейшим районом и расходами.

**«Загрузить вариант 1»** заменяет M5 в Сарыарке на M3 в Нуре. Нажмите **«Посмотреть результат»**: ожидаются стоимость **100**, остаток **0** и Score **57,21** (точно `57.20556`). Предварительный поиск выполняется в Web Worker на вашем устройстве по общему ядру; загруженный вариант заново проверяет сервер. Поиск охватывает замену одного решения и не обещает глобального оптимума. [Границы поиска](docs/policy-options.md).

Для отдельной проверки ограничений снова рассчитайте официальный пример. В панели альтернатив раскройте **«Что обязательно сохранить»**, закрепите перевод частного сектора на чистое топливо (M5) в Сарыарке и защитите **«Качество воздуха»** (E2) в Сарыарке от ухудшения. Повторите поиск: будет проверено **144** замены, **86** допустимы, показано **6** из **7** вариантов Парето. Первый вариант сохраняет M5 и меняет M12 на M14; после загрузки и серверного расчёта ожидаются **56,64** и стоимость **97**. Защита сравнивает показатель с результатом текущего плана. Перед повторением поиска без ограничений снимите закрепление и защиту. [Приоритеты поиска](docs/policy-priority-constraints.md).

### 4. Проверить ограничения

Заново загрузите официальный пример. Пока выбраны все пять мер, добавить шестую нельзя. Удалите **«Освещение и камеры»** (M10): останутся четыре меры стоимостью **83**. В направлении **«Транспорт»** попытайтесь добавить **«Умные светофоры»** (M2, стоимость 22). Набор на **105** не принимается, выбор остаётся **4 из 5**, кнопка расчёта недоступна. Сервер также отклоняет такой набор: `POST /api/simulate` возвращает HTTP **422** с ошибкой и без нового Score.

### 5. Проверить карту и объяснение

Верните официальный пример и выполните расчёт. Раскройте **«Карта города»**, переключите показатель и состояние до/после, выберите район и режим 3D. При выборе другого города доступна география, а показатели Астаны скрываются: датасетов других городов в модели нет.

Движущиеся машины на карте — обозначенная в интерфейсе **симуляция транспорта**. Это анимация, а не GPS-позиции, реальные дорожные измерения или прогноз времени прибытия.

В блоке AI-анализа проверьте обозначение режима. Итог выбранного сценария вычисляется сервером; числа в панели альтернатив предварительно рассчитываются на устройстве. Доступная модель даёт AI-анализ; без ключа, при лимите или ошибке провайдера остаются рассчитанные числа и явно обозначенное расчётное объяснение. Отсутствие живого ответа модели не мешает повторить числовую проверку.

## Дополнительная проверка: материалы для принятия решения

После расчёта официального примера доступны следующие действия:

1. Раскройте **«Записка по решению»**, при желании заполните блок **«Название и цель записки (необязательно)»** и нажмите **«Скачать записку»**. Полученный HTML открывается самостоятельно, без сервера и сети, содержит пять мер, результат **56,54**, бюджет **95 / 5** и ограничения модели. Печать — через браузер; файл не требует запуска скриптов. После изменения плана сначала выполните новый расчёт. [Состав записки](docs/decision-brief.md).
2. Раскройте **«Поручения и исполнение»** и нажмите **«Создать черновик поручений»**: появятся пять записей по выбранным мерам. Заполните тестового ответственного, срок и критерий проверки, выйдите из поля и перезагрузите страницу: ручные изменения сохраняются при редактировании. В паспорте реализации можно отдельно указать CAPEX/OPEX в тенге и период OPEX. Эти сведения не меняют стоимость в условных единицах и Score учебного сценария. Реестр хранится в браузере и не отправляет поручения реальным службам. [Реестр и паспорта](docs/action-register.md).
3. Раскройте **«Паспорта данных»**, затем **«Посмотреть паспорт модели и добавить источник»**. Заполните тестовое наблюдение, оставьте **«Проверка человеком» = «Нужно проверить»** и нажмите **«Сохранить паспорт»**. Его можно выгрузить через **«Скачать паспорта»**. Такие записи хранятся отдельно от официального учебного датасета и не подставляются в расчёт. Заполнение паспорта само по себе не подтверждает достоверность наблюдения. [Паспорта источников](docs/evidence-register.md).

При переходе к другому городу расчётные панели и записка скрываются. Ранее сохранённые поручения остаются доступными, а создание нового набора требует свежего расчёта модели Астаны. [Проверка общего рабочего маршрута](docs/operator-integration.md).

## Центр управления: план текстом и шкала времени

На `/command-center.html` карта занимает весь экран, а конструктор и результаты открываются поверх неё. Доступность страницы и HTTP 200 от API сами по себе не подтверждают готовый AI-план: ответ должен пройти проверку официального ядра.

**Живой маршрут подтверждён 23 сентября в 17:43 GMT+5 на опубликованной версии `241c84b`:** запрос пяти мер вернул `mode: ai`, `valid: true`, бюджет **95**, после применения — Score **56,54307** и девять кадров от квартала 0 до 8. [Запрос, ответ и проверка интерфейса](docs/evidence/ai-plan-final-verification.json).

Откройте **[публичный центр управления](https://ascension-city-map.azamatbreach.workers.dev/command-center.html)** или **[локальный `/command-center.html`](http://127.0.0.1:3000/command-center.html)**. В блоке **Ascension AI** выберите пример **«Помочь Нуре»** или введите собственный запрос и нажмите **«Оценить мой план»**. `POST /api/plan` принимает только текст `prompt` длиной до 4000 символов. При доступной модели сервер предлагает меры из каталога; результат появляется только после проверки пяти уникальных мер, бюджета и совместимости официальным ядром. Готовый вариант можно выбрать кнопкой **«Применить и показать»**. Без ключа, при лимите или ошибке показывается недоступность AI-плана, без выдуманного результата; ручной конструктор продолжает работать. [Контракт планирования](docs/plan-runtime.md).

После успешного расчёта шкала времени показывает кварталы **0–8**. Для официального примера начальный кадр даёт Score **52,56**, конечный — **56,54**. Промежуточные кадры — учебное допущение о постепенном эффекте после задержки. `POST /api/trajectory` не вызывает модель и не требует API-ключа; стоимость в кварталах 1–8 относится ко всему плану, а не к освоению бюджета за квартал. Это не прогноз развития реального города. [Модель динамики](docs/trajectory-model.md), [управление картой и панелями](docs/command-center.md).

## Общий реестр команды: необязательная настройка

Локальные поручения можно вручную публиковать в общий реестр после настройки доступа. Роли **owner** и **editor** читают и публикуют реестр, **viewer** читает реестр и журнал. Публикация явная; при несовпадении версии возвращается конфликт HTTP **409**, чтобы изменения другого участника не перезаписывались молча.

Оператор задаёт `WORKSPACE_ORIGIN`, `WORKSPACE_SESSION_SECRET` и `WORKSPACE_ACCESS_POLICY` на сервере и отдельно выдаёт ключи доступа. Это другой доступ, чем `ADMIN_TOKEN` панели обращений. Без корректной настройки API возвращает **503 WORKSPACE_DISABLED**, локальные черновики продолжают работать. Node хранит общий реестр в `var/workspace.sqlite` либо `WORKSPACE_DB_PATH`, Worker — в `TEAM_WORKSPACE`. [Роли и настройка](docs/workspace.md), [хранение и HTTP-подключение](docs/workspace-runtime.md).

## Дополнительная проверка: обращения жителей

Выполняйте после локального `npm start`, используя вымышленные данные.

1. Откройте **[страницу жителя](http://127.0.0.1:3000/citizens.html)**. Введите, например: «Тестовое обращение: во дворе не работает освещение», укажите район и тестовый адрес. Подтвердите согласие формы и нажмите **«Отправить обращение»**. Геолокация не обязательна; фотографии предусмотрены в Telegram-пути.
2. Сохраните выданные **номер и личный код проверки**. Они нужны для просмотра статуса.
3. Откройте **[панель акима](http://127.0.0.1:3000/mayor.html)**. В стандартном локальном режиме токен не нужен. Найдите обращение, заполните **«Ответственный»**, установите статус **«В работе»** и нажмите **«Сохранить изменения»**. Затем выберите **«Решено»**, заполните **«Решение / результат»**, например «Тестовая проверка выполнена», и сохраните.
4. На странице жителя проверьте статус по номеру и коду: должны отображаться новое состояние и решение. Перезапустите сервер — отправленное обращение должно сохраниться.

Категория, приоритет и возможные повторы здесь определяются **локальными правилами**, которые сотрудник может исправить. AI симулятора не выполняет анализ обращений. Обращения не меняют исходные показатели районов.

Локальные данные сохраняются в `var/complaints.json`, вне публичной статики и Git. Один файл обслуживает один процесс сервера; другой путь задаётся через `COMPLAINTS_FILE`. Публичный Worker использует отдельный Durable Object `Complaints`: локальные и облачные обращения автоматически не синхронизируются. При удалённом доступе к панели требуется серверный `ADMIN_TOKEN`; без него разрешено только локальное демо. Подробности: [контракт обращений](docs/citizen-contract.md), [проверки модуля](docs/citizen-verification.md), [безопасность](docs/security.md).

Для собственного Telegram-бота предусмотрены `npm run bot:local`, `npm run bot:hosted` и `npm run bot:status`. Настройки ключей, локального polling и облачного webhook описаны в [инструкции Telegram](docs/telegram-hosting.md), шаги диалога — в [описании меню](docs/telegram-ux.md). Polling и webhook одновременно не работают; переключение не переносит обращения между хранилищами.

У публичного [@Ascension_City_bot](https://t.me/Ascension_City_bot) зарегистрирован webhook на `/api/telegram/webhook`; проверка Telegram показала пустую очередь и отсутствие ошибки доставки. Полный диалог `/start → обращение → ответ сотрудника` ещё не подтверждён реальным входящим сообщением. Старые локальные обращения в облако автоматически не перенесены.

## Формула и роль AI

Нужно выбрать ровно **пять уникальных мер**, не более двух из одного направления, общей стоимостью не выше 100. Для районной меры выбирается район. M1/M3 несовместимы в любом месте; M4/M7 и M5/M13 — в одном районе. Эффект меры учитывает задержку: `(8 − lag) / 8`; фиксированные синергии добавляются отдельно. Показатели ограничены диапазоном 0–100.

```text
Score = 0.7 × средняя оценка районов с весами населения
      + 0.3 × оценка самого слабого района
      − число значений «район × показатель» строго ниже 40
```

Оценка района — взвешенная сумма его показателей. Неиспользованный бюджет не даёт дополнительных баллов. [Официальные значения и правила в тестах](tests/simulator.acceptance.test.js).

Модель получает готовые факты и объясняет компромиссы; отдельный планировщик предлагает меры из каталога. Числовую сводку и допустимость плана определяет сервер. Качественный текст модели следует сверять с таблицей. Применение предложенного плана требует действия пользователя; реальные поручения автоматически не назначаются. [Граница доверия AI](docs/ai-grounding.md).

Для собственного AI-режима владелец сервера задаёт `OPENAI_API_KEY` и, при необходимости, `OPENAI_MODEL` в игнорируемом `.env.local`. В публичном демо ключ хранится в серверном секрете; посетитель его не вводит. Ожидание ответа ограничено 25 секундами. Общая квота публичного демо — 100 допусков к модели, до 10 в минуту и двух одновременно; планирование и объяснение используют общий допуск, ошибки провайдера также его расходуют. После исчерпания квоты работает расчётное пояснение, а составление нового AI-плана становится недоступным.

Локальное объяснение может использовать проверенную замену одного решения. Это поиск среди соседних вариантов, без гарантии глобального оптимума. В серверном объяснении Cloudflare Worker такой перебор отключён; это явно указано в ответе.

**Живое AI-объяснение проверено 23 сентября в 17:23 GMT+5 на версии `9b5a774`.** Два сценария A/B получили HTTP 200, `mode: ai`, `available: true`, модель `gpt-6-astra`. Текст модели различил школу в Нуре и школу в Есиле и сохраняющийся дефицит Нуры; сценарий с бюджетом 105 отклонён с HTTP 422. [Отчёт и полные входы/ответы](docs/ai-verification.md). Эта проверка не подтверждает отдельный `/api/plan` и не гарантирует свободную квоту сейчас; наличие ключа в `/api/health` также не доказывает успешный вызов модели.

## Автоматическая проверка

Проверенный релиз **v1.1.0**: **601 тест прошёл, 0 ошибок, 1 необязательный workerd-тест пропущен**. На публичном сайте проверены API и точное совпадение всех 113 статических файлов. GitHub Actions не запустился из-за блокировки биллинга аккаунта; это не считается успешным CI. [Результаты финальной проверки](docs/final-release.md). Инструкция клонирования выше фиксирует именно этот выпуск; последующие изменения `main` могут ещё не быть опубликованы.

В корне репозитория выполните:

```sh
npm test
node scripts/check-quality.js
npm run test:self-host
```

Ожидаемый итог — все проверки проходят, команды завершаются с кодом 0. Тесты проверяют официальные числа, ограничения бюджета и совместимости, HTTP-контракты, безопасный импорт, fallback AI, обращения и Telegram. `test:self-host` отдельно проверяет чистый запуск и сохранение обращения после реального перезапуска, используя временный каталог и вымышленные данные. Внешние AI/Telegram-вызовы в автоматических проверках заменены подставными ответами: тесты не требуют ключей и не подтверждают доступность живых сервисов. Проверку пользовательского пути выполняйте по шагам выше.

Готовый браузерный Worker включён в репозиторий. **Только для его пересборки после изменения расчётного ядра или данных** установите dev-зависимости и выполните:

```sh
npm ci
npm run build:policy-worker
npm run check:policy-worker
```

Проверка сравнивает сборку с сохранённым файлом; для обычного `npm start` эти команды не нужны. [Сборка и интеграционные проверки](docs/browser-integration.md).
