# Собрано — умный подбор event-подрядчиков

Прототип команды **Volga Production** для кейса «Умный подбор подрядчиков (#79-lite)». Заказчик задаёт условия мероприятия и получает **до трёх карточек с проверяемыми объяснениями** из предоставленного каталога Казахстана.

## Для жюри: приложение уже развёрнуто

1. **Откройте готовое приложение: [sobrano-production.up.railway.app](https://sobrano-production.up.railway.app).** Установка, регистрация и собственный API-ключ для проверки по этой ссылке не нужны.
2. Нажмите **«Найти совпадения»** с исходными параметрами формы. Ожидаемый результат — три карточки ведущих для корпоратива в Алматы на 15.10.2026 с бюджетом 1 000 000 ₸. В каждой карточке указаны условия и основание выбора; раскройте источник, чтобы сверить цитату с анкетой.
3. Проверьте примеры под формой: **«Другая дата»**, **«Флористы»**, **«Малый бюджет»**, **«Нет категории»**. После выбора примера снова нажмите **«Найти совпадения»**. Ожидаются соответственно изменившаяся подборка, два флориста, объяснение несовпадения условий и сообщение об отсутствии категории.
4. Для независимого локального запуска выполните [инструкцию Docker Compose ниже](#локальный-запуск-через-docker-compose). Она также подходит, если публичное демо недоступно.

На публичном сайте работает серверный AI-подбор. Повторные запросы могут возвращаться из кеша. При сбое внешнего API приложение явно обозначает резервный режим. Продукт не бронирует подрядчиков и не отправляет заявки; пустая выдача — отдельный объяснённый результат.

Текущая версия опубликована и проверена 23.09.2026: шесть API-сценариев с повтором, AI-ответы по ведущим и 16 браузерных тестов. Историческая проверка сохранения результатов после перезапуска описана отдельно. [Подробности и свидетельства проверки](docs/railway-deployment.md#состояние).

Чат по ведущим и восстановление страницы доступны в опубликованной версии. Пуш в GitHub сам по себе не запускает деплой Railway; текущий выпуск загружен через CLI.

## Локальный запуск через Docker Compose

Этот способ запускает всё приложение одной командой. Node.js и npm на компьютере устанавливать не требуется.

### Требования

- Docker Desktop (Windows/macOS) или Docker Engine с Docker Compose v2+ (Linux); Docker запущен.
- Копия репозитория. Для команды клонирования ниже нужны Git и доступ к репозиторию организаторов; можно также скачать и распаковать ZIP через GitHub.
- Свободный порт `3000`.
- Доступ к интернету: при сборке — Docker Hub и npm; при новых AI-запросах — `api.openai.com`.
- OpenAI API-ключ с балансом и доступом к `gpt-5.6-sol` и `text-embedding-3-small`.
- Исходный файл `data/hackathon_dataset_anonymized.csv` включён в репозиторий; 66 профилей, отдельная БД не нужна. Каталог `data/` хранит данные, которые приложение читает во время работы; размещать CSV в `public/` не нужно.

### 1. Получите проект

```sh
git clone https://github.com/BAITC-Hacks/hack-875e970e-volga-production.git
cd hack-875e970e-volga-production
```

Если проект уже скачан, откройте терминал в его корневой папке — там находятся `Dockerfile`, `compose.yaml` и `.env.example`. Все следующие команды выполняются из этой папки.

### 2. Настройте окружение

Создайте `.env` из примера, **если `.env` ещё нет**:

```sh
cp .env.example .env
```

В Windows PowerShell можно использовать `Copy-Item .env.example .env`. Откройте `.env` в текстовом редакторе и вставьте свой ключ в `OPENAI_API_KEY`. Не коммитьте ключ. Пример конфигурации без секрета:

```dotenv
OPENAI_API_KEY=вставьте_свой_ключ
OPENAI_MODEL=gpt-5.6-sol
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
CACHE_DIR=.cache/sobrano
```

Новые AI-запросы используют баланс вашего OpenAI API-аккаунта. Без ключа можно проверить интерфейс и строгую фильтрацию: оставьте `OPENAI_API_KEY=` пустым. Приложение будет явно показывать резервный режим; это не проверка полноценного AI-сценария.

### 3. Соберите и запустите приложение

```sh
docker compose up --build -d
docker compose ps
```

Дождитесь окончания сборки и статуса `healthy` у сервиса `app` в выводе `docker compose ps`. Первый запуск включает загрузку образа и npm-зависимостей. Ход работы можно посмотреть командой `docker compose logs --tail=50 app`.

Откройте **[http://localhost:3000](http://localhost:3000)**. Для проверки сервера откройте [http://localhost:3000/api/health](http://localhost:3000/api/health) в браузере или выполните:

```sh
curl --fail http://localhost:3000/api/health
```

Ожидаемый ответ: `{"status":"ok","profiles":66}`. Health проверяет загрузку каталога; доступность OpenAI проверяется следующим шагом.

### 4. Проверьте основной сценарий

Нажмите **«Найти совпадения»** с исходными параметрами формы и пройдите примеры из первого раздела README. [Таблица ожидаемых результатов](#проверка-основного-сценария) приведена ниже. Повторите одинаковый запрос: состав и порядок карточек должны сохраниться.

Данные уже включены в репозиторий: импортировать CSV, создавать БД или запускать миграции не нужно. При первом AI-запросе эмбеддинги 66 анкет создаются автоматически и сохраняются в Docker-томе `selection-cache`. Если API недоступен или не уложился в срок, появится явно обозначенный резервный режим. Причины и действия описаны в [разделе устранения проблем](#типичные-проблемы).

Для категории «Ведущий» после карточек отдельно загружается сравнение и открывается чат для уточнений. После обновления страницы в той же вкладке восстанавливаются форма, карточки, ответы и черновик вопроса через `sessionStorage`. Изменение условий сбрасывает подборку и диалог. Сохранение зависит от доступности хранилища браузера и ограничено сессией вкладки.

### 5. Остановите или запустите повторно

Остановка:

```sh
docker compose down
```

Повторный запуск с сохранённым кешем:

```sh
docker compose up -d
```

После изменения кода или `.env` снова выполните `docker compose up --build -d`.

Кеш сохраняется после остановки. `docker compose down -v` удаляет **только тома этого Compose-проекта**, включая сохранённые результаты; после этого AI-запросы оплачиваются заново. Используйте эту команду только для намеренного сброса/проверки чистого запуска.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | Серверный ключ OpenAI; без него работает явно обозначенный резервный подбор |
| `OPENAI_MODEL` | Модель выбора цитат и ответа в чате, по умолчанию `gpt-5.6-sol` |
| `OPENAI_EMBEDDING_MODEL` | Модель смыслового поиска, по умолчанию `text-embedding-3-small` |
| `CACHE_DIR` | Локально `.cache/sobrano`; Compose задаёт `/app/.cache/sobrano` |

Ключ не попадает в клиентский JavaScript, образ Docker или ответы API. `.env` исключён из Git и Docker-контекста. В OpenAI передаются описания анонимизированных анкет и параметры запроса; не вводите персональные данные в пожелания. Для Responses используется `store: false`. Локальный кеш содержит параметры запросов и результаты, без ключей.

## Разработка без Docker

Node.js 22+, npm; зависимости закреплены `package-lock.json`.

```sh
npm ci
# Подготовьте .env по инструкции выше.
npm run prepare:data
npm run dev
```

Откройте http://localhost:3000. `prepare:data` проверяет каталог и создаёт эмбеддинги заранее; это опционально. Для production: `npm run build`, затем `npm start`.

| Команда | Что проверяет / делает |
| --- | --- |
| `npm test` | Фильтры, данные, валидация, смысловое ранжирование, сбои, подтверждение цитат и кеш |
| `npm run typecheck` | Типы TypeScript |
| `npm run build` | Production-сборка Next.js |
| `npx playwright install chromium` | Однократная установка тестового браузера |
| `npm run test:e2e` | Браузерные проверки; приложение должно работать на порту 3000 |
| `node --import tsx scripts/smoke.ts` | Реальные API-запросы, повторяемость; сохраняет результаты в `docs/evidence/smoke.json` |
| `node --import tsx scripts/verify-runtime.ts` | Сравнивает 24 параллельных ответа с сохранённым smoke-прогоном; запускать после него, в том числе после перезапуска контейнера |

`APP_URL` позволяет smoke-скрипту и Playwright проверять другой адрес. Тесты `npm test` используют явно заданные тестовые сервисы и не расходуют API. Smoke и часть браузерных сценариев обращаются к настоящему API приложения; при настроенном ключе новые запросы могут расходовать API. Проверки восстановления вкладки, часть контролов и чата используют явно заданные ответы/перехват запросов и не подтверждают работу модели.

Smoke/runtime и браузерные скриншоты перезаписывают файлы в `docs/evidence/`. Для нового аудита сохраняйте результаты отдельно, чтобы не заменить исторические AI-свидетельства резервным прогоном. `scripts/production-*` воспроизводят исторический production-регресс, содержат фиксированный публичный адрес и не учитывают `APP_URL`.

## Устройство решения

```text
Форма → серверная валидация → город + категория
                              ↓
          дата + цена + формат + язык + длительность
                              ↓
     эмбеддинги: смысловая близость формата и пожеланий
                              ↓
            сортировка → максимум 3 подрядчика
                              ↓
  AI выбирает цитату → код проверяет её в исходной анкете
                              ↓
       фактическое объяснение + источник + причины исключения
                              ↓
    Для ведущих: карточки видны сразу → отдельный AI-ответ → уточнения в чате
```

- `app/`: интерфейс, стили и HTTP-маршруты; `lib/`: каталог, фильтрация, OpenAI, кеш и подбор.
- `tests/`: автоматические проверки; `scripts/`: подготовка данных и реальные проверочные прогоны.
- `docs/`: принятые решения и результаты технической проверки; `public/` пока содержит только `.gitkeep`, сохраняющий каталог для Docker-сборки. Иконка приложения — `app/icon.svg`.
- Next.js App Router + React + TypeScript; CSV разбирает `csv-parse`, вход и ответ модели проверяет Zod. Отдельной БД, векторного сервера и дообучения нет.

### Фильтрация и ранжирование

Город и категория проверяются по структурированным полям. Описание о выездах не отменяет фильтр города. Цена «от» должна быть не выше бюджета. Занятые на дату исключаются всегда. Если язык или часы заданы, они также обязательны. `max_hours = null` означает «присутствие не применимо»; не ноль и не неизвестную длительность. Список категорий разбирается как массив.

Семантический запрос содержит категорию, формат и пожелания; без пожеланий ищется опыт соответствующего формата. Косинусное сходство округляется до шести знаков, затем равенство разрешается по цене и `id`. Сходство не показываем как процент качества или вероятность успеха.

AI выбирает конкретную дословную цитату и тип особенности. Сервер проверяет идентификаторы и наличие цитаты в `description`, затем сам формирует текст с датой, форматом, бюджетом и выбранной особенностью. Свободные обещания модели в карточки не попадают. Под раскрываемым блоком доступен полный источник. Перед выбором цитаты применяется консервативный набор признаков конкретной услуги или способа работы (например, инструменты, состав, репертуар, оборудование, вместимость). Общие рекламные фразы не используются как индивидуальное основание. Если подходящий фрагмент не найден или не отличается от уже выбранных, подрядчик остаётся в выдаче с честным сообщением о нехватке конкретики; полная анкета доступна для проверки. Это эвристика для текущего каталога, а не полная оценка смысла: необычно сформулированные полезные сведения могут быть пропущены. Смысловая релевантность цитаты всё равно требует оценки человеком.

Для категории «Ведущий» модель `gpt-5.6-sol` с `reasoning.effort=low` также пишет связный ответ по не более чем трём уже отфильтрованным анкетам. Карточки возвращаются отдельным первым запросом и не ждут генерации текста. Первый вариант выделен как первый по смысловой близости; если смысловой этап недоступен, подпись честно меняется на «первый по начальной цене». Это порядок ранжирования, а не гарантия качества подрядчика. Сервер проверяет принадлежность переданных моделью `mentionedIds` текущей подборке. Форму нельзя изменить текстом чата; вопросы о другой категории и попытки переопределить правила получают ответ с предложением изменить форму. Ответы чата являются интерпретацией анкет и могут ошибаться, поэтому рядом остаются карточки с исходными сведениями. Инструкция модели требует опираться на анкеты и отделять предположения от сведений каталога. Для других категорий остаётся обычный подбор без чата.

### Детерминизм и сбои

Кеш содержит версию алгоритма, хеш CSV, модели и нормализованные параметры. Он хранит эмбеддинги, подборки и ответы чата; одновременные одинаковые запросы внутри одного процесса объединяются. Запись атомарная. Один и тот же запрос при неизменной версии данных сохраняет порядок и текст первого ответа после перезапуска благодаря постоянному тому.

На внешние этапы подбора карточек выделено суммарно 8 секунд, автоматических повторов SDK нет. Генерация ответа чата имеет отдельный лимит 8,5 секунды. Прямой запрос `/api/chat` без готового кеша сначала выполняет подбор: общего серверного лимита 10 секунд у него нет. Интерфейс показывает карточки до сравнения и ждёт каждый запрос до 10 секунд; сеть и операции с диском не входят в лимит внешних этапов. Если смысловой этап недоступен, остаются строгие фильтры и сортировка по цене/ID. AI-цитаты проверяются на принадлежность анкете, содержательность и повтор между карточками по детерминированным правилам. Если выбор цитат недоступен или не проходит проверку, резервный режим выбирает отличающиеся фрагменты анкет с конкретными сведениями либо явно сообщает, что отличительная особенность не выделена. Это проверено на исходном каталоге по календарю и ценовым порогам; смысловую полезность всех формулировок всё равно нужно оценивать человеку. Резервный режим явно указан и **тоже кешируется**, чтобы повтор не менял порядок. Для его намеренного пересчёта нужно очистить соответствующий кеш; не делайте этого между проверками детерминизма.

Гарантия относится к одному экземпляру приложения с сохранённым кешем и неизменными данными/версиями. Для нескольких серверов понадобятся общий кеш и распределённая блокировка. Удаление кеша или изменение моделей/данных — новый расчёт.

## HTTP API

`POST /api/recommendations`, `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "format": "корпоратив",
  "category": "Ведущий",
  "budget": 1000000,
  "language": "английский",
  "hours": 5,
  "wishes": "Спокойная подача для делового вечера"
}
```

Обязательны первые пять полей. Возвращаются `status`, `cards` (0–3), `query`, `total`, `eligible`, `excluded`, `message`, `ranking`, `explanationMode` и `warnings`. AI-текст не задерживает этот ответ.

Для вступительного сравнения ведущих отправьте `POST /api/chat` с JSON вида `{ "query": { ...поля формы... }, "message": "", "history": [] }`. Для уточнения укажите вопрос в `message`, например «Кто спокойнее и почему?». Маршрут доступен только для категории «Ведущий» и после заполнения всех обязательных полей. Сервер заново проверяет условия формы и подбирает кандидатов; текст вопроса и переданная история не могут менять город, дату, бюджет или категорию. Для контекста используются только три последние реплики пользователя; ответы ассистента из браузера игнорируются как недоверенные данные. При сбое модели возвращается явно обозначенный резервный ответ; карточки и строгие фильтры остаются доступными.

У карточки `evidenceStatus` равен `specific` для выбранной цитаты или `insufficient`, когда конкретная отличительная особенность не выделена. Во втором случае `evidence` — пустая строка, а `explanation` объясняет ограничение; полный `description` сохраняется. `explanationMode=ai` означает, что AI использован для доступных цитат, и не исключает карточки с `insufficient`.

- `matched`: хотя бы один подходящий профиль.
- `category_absent`: в этом городе нет такой категории.
- `no_match`: категория есть, но никто не проходит все ограничения.

В `excluded` счётчики причин пересекаются: один профиль может быть занят и одновременно дороже бюджета. Ошибочный ввод → `400` с полями; слишком большой запрос → `413`; недоступный каталог/кеш → `503`. Отсутствие результатов возвращает `200`.

## Проверка основного сценария

| Пример | Что ожидать до выбора тройки |
| --- | --- |
| Алматы, ведущий, корпоратив, 15.10.2026, 1 млн ₸ | 6 подходящих из 10; выдача до 3 |
| Те же условия, 16.10.2026 | 4 подходящих; изменившийся календарь меняет выдачу |
| Алматы, флорист, свадьба, 15.10.2026, 500 тыс. ₸ | 2 подходящих, оба показаны |
| Алматы, ведущий, корпоратив, 15.10.2026, 100 тыс. ₸ | `no_match`, причины видны |
| Астана, декоратор | `category_absent` |

Убедитесь, что занятых нет; повторите запрос и сравните порядок; раскройте источники. Результаты реальных запросов сохранены в `docs/evidence/smoke.json`; скриншоты проверки интерфейса — в той же папке. Это технические свидетельства проверок, не подмена работы приложения.

## Ограничения и дальнейшее развитие

- Каталог — 66 анонимизированных профилей, включая 13 синтетических от организаторов; 18 цен и 8 городов проставлены при подготовке. Это обозначено на карточках.
- Календарь только 23.09–31.12.2026. «Свободен» означает отсутствие занятости **в предоставленном календаре**, не подтверждение подрядчика.
- Цена «от» не гарантирует итоговую стоимость, пожелания не гарантируют наличие услуги; рекламные заявления не проверены независимо.
- Пользовательских исследований, измерений экономии времени и доказанного превосходства над альтернативами пока нет.
- Следующий этап развития — закрытый интерфейс для администратора каталога: добавление, исправление и снятие с публикации анкет без редактирования файла в коде. Потребуются постоянное хранилище, проверка обязательных полей, разграничение доступа и обновление AI-индекса/кеша при изменении опубликованных данных. Массовый импорт CSV/XLSX можно добавить позже как инструмент администратора; произвольные файлы посетителей не входят в текущий сценарий.
- Для актуальности сведений одного интерфейса недостаточно: понадобится дата последнего подтверждения и процесс проверки цен и занятости с подрядчиками. Пользу следующего этапа следует проверить с организаторами; сравнение подборок с сортировкой по цене пока не проводилось.
- Для публичной эксплуатации затем понадобятся общий кеш, ограничение запросов и мониторинг расходов.
- Публичное демо развёрнуто на Railway в одном экземпляре с постоянным кешем. Для длительной публичной эксплуатации нужны ограничение расходов и запросов. [Настройки и повторный деплой](docs/railway-deployment.md).

## Типичные проблемы

- **Docker daemon недоступен:** запустите Docker Desktop; проверьте `docker info`.
- **Не найден `.env`:** скопируйте `.env.example` в `.env` в корне проекта. Файл необходим для Compose, даже если ключ оставлен пустым.
- **Порт 3000 занят:** остановите локальный `npm run dev` либо измените левый порт в Compose на `3001:3000`, повторите `docker compose up -d` и откройте `http://localhost:3001`.
- **Сайт не открывается после запуска:** проверьте `docker compose ps` и `docker compose logs --tail=50 app`. Если сервис ещё запускается, дождитесь `healthy`; если он завершился, устраните ошибку из журнала и повторите запуск.
- **Резервный режим вместо AI:** проверьте ключ, баланс, доступ к обеим моделям и сеть. После исправления используйте новый запрос либо намеренно сбросьте кеш; сохранённые резервные ответы не пересчитываются автоматически.
- **`prepare:data` сообщает 401/403/429:** проверьте ключ/права/лимиты у провайдера. Секреты в логи не выводятся.
- **503 при подборе:** проверьте наличие CSV и права записи в каталог кеша; `docker compose logs --tail=50 app`.
- **Не собирается образ:** проверьте доступ к npm/Docker Hub, повторите `docker compose build`. Для первого запуска нужен интернет.
