# Latitude 51 — «Аким на 5 часов»

HackAlem AI-симулятор управления городом от команды Latitude51N.

## 1. Назначение

Latitude 51 помогает пользователю в роли акима выбрать пять городских мер в рамках бюджета 100, увидеть последствия по пяти районам Астаны и сравнить компромиссы. Целевая аудитория текущей версии — участники демо и жюри хакатона: сценарий показывает, как ограниченный бюджет и лаг реализации влияют на качество решений.

Показатели районов в симуляторе синтетические и относятся к модели задачи, а не к официальному прогнозу города.

## 2. Что реализовано

- выбор ровно пяти разных мер из каталога M1–M14;
- бюджет до 100 единиц, районные и городские меры;
- валидация районов, направлений, бюджета и несовместимых сочетаний;
- детерминированный расчёт Astana Quality of Life Score;
- визуализация пяти районов на карте и отображение изменений показателей;
- готовый сценарий организаторов стоимостью 95;
- поиск лучшей допустимой замены одной выбранной меры;
- серверный AI-анализ сильных сторон, рисков и компромиссов рассчитанного плана.

## 3. Пользовательский сценарий

1. Открыть `/` и перейти в симулятор или сразу открыть `/simulator`.
2. Выбрать район для районной меры и заполнить пять слотов. Городские меры применяются ко всем районам.
3. Получить подсказки о недоступных мерах и увидеть стоимость, остаток бюджета и изменения районов.
4. После заполнения пяти слотов получить Score и детализацию по районам.
5. Запустить поиск одной замены, при необходимости применить её, затем запросить AI-анализ.

Score и все числовые последствия вычисляются кодом. LLM получает готовый результат и формулирует объяснение; она не является источником чисел.

## 4. Модель и данные

Движок использует пять районов, десять показателей, доли населения, 14 мер, веса, лаги, синергии и несовместимости, заданные в `src/lib/engine/dataset.ts`.

- горизонт модели: 8 кварталов;
- эффект меры: `эффект × (8 − лаг) / 8`;
- после суммирования эффектов и синергий показатель ограничивается диапазоном 0–100;
- районная мера действует в выбранном районе, городская — во всех пяти и оплачивается один раз;
- `D_d` — взвешенная оценка района;
- `D_avg` — оценка, взвешенная по доле населения;
- `N_crit` — число значений показателей строго ниже 40;
- `Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit`.

Данные и формула реализованы локально. Файл GeoJSON в `public/geo/astana-districts.geojson` используется для границ районов. Внешняя карта MapLibre может загружать картографическую подложку OpenFreeMap при наличии сети.

## 5. Технологии и интеграции

- TypeScript и React 19;
- Next.js 16 App Router;
- Tailwind CSS 4;
- MapLibre GL, Three.js, React Three Fiber и drei;
- Motion и Phosphor Icons;
- Vitest для тестов;
- OpenAI Chat Completions API для `/api/analyze`.

Модель OpenAI задаётся переменной `OPENAI_MODEL`; по умолчанию используется `gpt-4o-mini`. API-ключ используется только серверным route handler. Статического AI-fallback в текущей версии нет: без ключа endpoint возвращает ошибку 503.

## 6. Архитектура

```text
src/lib/engine/dataset.ts  данные, веса, меры и ограничения
src/lib/engine/validate.ts правила допустимости плана
src/lib/engine/score.ts    расчёт Score и районных результатов
src/lib/engine/improve.ts  перебор допустимых замен одной меры
src/lib/engine/engine.test.ts контрольные и поведенческие тесты

src/app/page.tsx            лендинг
src/app/simulator/page.tsx  страница симулятора
src/components/Simulator.tsx состояние пользовательского сценария
src/components/PlanBuilder.tsx выбор мер и районов
src/components/CityMapPanel.tsx карта и визуализация районов
src/components/ResultsPanel.tsx Score, ошибки, улучшение и AI-анализ
src/app/api/analyze/route.ts серверная валидация, расчёт и запрос OpenAI
```

Клиент отправляет в `/api/analyze` только список решений. Сервер заново вызывает валидатор и движок, рассчитывает улучшение и формирует prompt из проверенных данных. Стоимость, эффекты и Score из браузера не принимаются.

## 7. Установка и запуск

Требуется Node.js 20 или новее.

```bash
npm install
cp .env.local.example .env.local
# при необходимости отредактируйте .env.local и добавьте OPENAI_API_KEY
npm run dev
```

Откройте http://localhost:3000. Симулятор находится по адресу http://localhost:3000/simulator.

Переменные окружения:

```text
OPENAI_API_KEY=ключ OpenAI для серверного анализа
OPENAI_MODEL=gpt-4o-mini
```

`.env.local` исключён из Git, а `.env.local.example` содержит только шаблонные значения.

## 8. Как проверить

Автоматические команды:

```bash
npm test
npm run lint
npm run build
```

Повторяемый демо-сценарий:

1. Откройте `/simulator?plan=reference` или нажмите «Загрузить пример организаторов».
2. Проверьте пять решений: M7 в Нуре, M8 в Нуре, M10 в Нуре, M12 для города, M5 в Сарыарке.
3. Убедитесь, что стоимость равна 95, а Score после округления до пяти знаков равен `56.54307`.
4. Нажмите «Найти лучшую замену», затем при наличии ключа — «Объяснить сценарий».
5. Нажмите «Начать заново» и проверьте, что план и производные результаты сбрасываются.

Контрольные значения движка: базовый Score без действий — `52.55768`; тесты также проверяют правила, лаг, городские меры, порядок решений и улучшение одной замены.

## 9. Ограничения текущей версии

- модель использует синтетические показатели и не является прогнозом реальных городских показателей;
- полный план требует ровно пяти решений, хотя остаток бюджета может быть положительным;
- поиск улучшения проверяет только замены одной меры и не доказывает глобальный оптимум;
- AI-анализ требует `OPENAI_API_KEY`, сетевого доступа к OpenAI и доступной модели;
- карта с внешней подложкой зависит от сети; локальный GeoJSON является частью репозитория;
- автоматические браузерные E2E-тесты в репозитории не настроены.
