# ProfitPilot — агент тарифных кампаний Beeline

Команда **0 iq enjoyers** · HackAlem · основная ветка для проверки: **`main`**.

Агент выбирает, кому предложить новый тариф и через какой канал, чтобы увеличить
выручку, а не просто добиться переходов. Он проверяет гипотезы пилотами и
возвращает **1–10 кампаний** с учётом бюджета, охвата и неопределённости.
По умолчанию работает **локально, без LLM и API-ключей**. Данные синтетические;
официальный пакет организатора не включён в репозиторий.

**Для жюри:** [критерии и объяснение решения](JUDGES.md) ·
[измеренные результаты](reports/team_strategy_release.md) · [происхождение кода](THIRD_PARTY.md).

## Быстрый запуск

Нужны Python **3.11 или 3.13** с `venv` и официальный `beeline_case_participants*.zip`.
Для приватного репозитория нужен доступ команды; ключи в исходники не вставляйте.

```bash
git clone https://github.com/BAITC-Hacks/hack-9a98b7fa-0-iq-enjoyers.git
cd hack-9a98b7fa-0-iq-enjoyers
python3 run.py --bundle "/path/to/beeline_case_participants.zip" --runs 10
```

Замените только путь к ZIP. Если единственный такой архив лежит в Downloads
или рядом с проектом, достаточно **`python3 run.py`**. Исходники править не нужно.

Команда создаёт `.venv-agent`, устанавливает зафиксированные зависимости,
запускает тесты и официальный оценщик, проверяет результат и собирает:

- `artifacts/ready-*/submit/` — `agent.py`, `submission.csv`, `requirements.txt`,
  `profitpilot_config.json`, инструкция и сведения о сторонних компонентах;
- `report.html` — локальный отчёт: кампании, ресурсы, пилоты, статус LLM;
- `summary.json`, манифесты и журналы — результаты проверок и хеши.

Точные пути выводятся после успешного завершения. CSV создаёт **неизменённый
официальный `make_submission.py`**; отдельный валидатор пересчитывает аудитории,
затраты, ограничения и совпадение CSV с планом.

## Без интернета, диагностика и демо

Первый запуск требует интернета для установки зависимостей. Подготовьте их
заранее, затем выполняйте расчёт в том же окружении:

```bash
python3 run.py --prepare-only
python3 run.py --offline --bundle "/path/to/beeline_case_participants.zip" --runs 10
```

`--offline` запрещает установку пакетов, но не создаёт сетевую песочницу ОС.
Без `--llm-model` агент не делает сетевых вызовов. Ключи не передаются оценщику.

```bash
python3 run.py --doctor  # диагностика без установки и изменения Git
python3 run.py --demo    # HTML сохранённого примера, без ZIP и пакетов
```

Демо помечено как сохранённый пример прежнего `fixed`: это не новый расчёт
и не результат настоящей LLM. Для актуального отчёта выполните обычный запуск.

## Как принимаются решения

1. История очищается от дублей и недопустимых знаменателей. Она даёт слабые
   предварительные оценки, а не причинные эффекты текущей аудитории.
2. Рассматриваются все допустимые тарифы и четыре канала. Крупные сегменты
   делятся разрешёнными фильтрами, без обращения к скрытым данным.
3. Следующие гипотезы и размеры проб выбираются по наблюдениям и приблизительной
   пользе новой информации с учётом стоимости потраченных контактов.
4. Связанные рабочие оценки переносят информацию между похожими гипотезами,
   сохраняя неопределённость для непроверенных сегментов.
5. SciPy/HiGHS выбирает отдельные или объединённые кампании: до **10**, до
   **5000** абонентов в каждой, **100 000** бюджета и **15 000** контактов,
   включая до **20 пилотов**. При отказе решателя есть жадная запасная логика.

Сбои пилота не теряют уже списанные ресурсы. Если пригодных пилотов нет или
валидный план невозможен, агент сообщает об этом, а не выдаёт ложный успех.
Модельные допущения описаны в отчёте; научная новизна не заявляется.

## Настройки и необязательная LLM

```bash
python3 run.py --offline --mode transfer --risk-weight 1.0 --max-pilots 12
python3 run.py --offline --mode fixed --runs 10
```

`transfer` — основной режим; `fixed` и старый `adaptive` оставлены для сравнений.
Настройки сохраняются в `profitpilot_config.json` рядом с агентом.

Локальная Ollama может предлагать приоритеты допустимых пилотов. Она не назначает
эффект, не исполняет код и не меняет ограничения. При недоступности работает
численная запасная логика. **Настоящий модельный прогон ещё не проверен**.
Ollama и веса автоматически не устанавливаются и для сдачи не требуются.
[Подготовка локальной LLM и ограничения](docs/LOCAL_LLM.md).

## Проверка непосредственно в официальном пакете

Для обычной сдачи используйте подготовленный каталог `submit/`. При прямой
проверке поместите его `agent.py` и `profitpilot_config.json` в распакованный
пакет организатора, установите зависимости из сдаваемого `requirements.txt`
и выполните **из каталога пакета**:

```bash
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Эти программы принадлежат официальному пакету, а не лежат в корне GitHub.
Наш `run.py` готовит такое окружение автоматически.
