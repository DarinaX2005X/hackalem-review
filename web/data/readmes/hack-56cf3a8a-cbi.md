# Умный подбор подрядчиков (#79-lite)

## 1. Название проекта

Умный подбор event-подрядчиков в Казахстане.

## 2. Для кого и какую проблему решает

Заказчику мероприятия нужно выбрать подрядчика из каталога своего города.
Сервис возвращает до трёх подходящих карточек и объясняет каждую рекомендацию
конкретными фактами из профиля.

## 3. Что реализовано

- Фильтры: город, категория, дата, стартовая цена, формат, язык, длительность.
- Составные категории, форматы и языки через `|`.
- Три исхода: `matched`, `no_category`, `no_match`.
- Карточки с `reason`, ценой, городом, категорией и флагами качества данных.
- Причины исключения и ID занятых кандидатов; стабильный порядок.
- CLI, офлайн-демо, необязательные AI-объяснения и устойчивый к ошибкам кеш.

## 4. Пользовательский сценарий

Ввести город, дату, формат мероприятия, категорию и бюджет; при необходимости —
язык и длительность. Код проверяет ограничения, ранжирует прошедших кандидатов
и вызывает `explain()` для каждой выбранной карточки. Пустой результат содержит
понятное сообщение с численными причинами. Один подрядчик может нарушать
несколько ограничений, поэтому суммы причин могут превышать число кандидатов.

## 5. Технологии

Python 3.13.0, стандартная библиотека; проверено с pytest 9.1.1 и OpenAI SDK
3.19.0. Опциональная модель — `gpt-4o-mini` через Responses API, переопределяется
переменной `OPENAI_MODEL`. Успешные API-объяснения хранятся как JSON в
`.cache/explanations`, ключ SHA-256 включает запрос, кандидата, модель и версию кеша.

## 6. Архитектура

`src/contractor_matcher.py` сохраняет три независимые ответственности:

1. `hard_filter()` — жёсткие проверки без LLM.
2. `rank()` — локальное лексическое пересечение токенов и баллы за язык/длительность.
   Сортировка: `score desc, price_from_kzt asc, id asc`.
3. `explain()` — только текст для уже выбранного кандидата; LLM не меняет порядок.

Готовые эмбеддинги пока не подключены. Локальный скор — лексический, не полноценный
семантический поиск. Обучения на каталоге нет.

Fallback выбирает короткий фрагмент описания, отдавая предпочтение деталям опыта
и специализации перед приветствием, добавляет стартовую цену и совпавшие
опциональные критерии. Fallback не кешируется. Повреждённый кеш и ошибки его
записи не прерывают выдачу. SDK настроен на тайм-аут 2 секунды и отсутствие
повторных попыток; это ограничение сетевых операций, а не строгая гарантия
общего времени ответа. Настройка сверена с
[документацией OpenAI](https://developers.openai.com/api/docs/guides/flex-processing).

`src/__main__.py` — CLI; `src/demo.py` — воспроизводимые сценарии;
`tests/test_matcher.py` — тесты, включая мок API без сетевых запросов.

## 7. Установка и запуск

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python -m src --city Алматы --date 2026-10-10 --format корпоратив \
  --category Ведущий --budget 2000000 --offline
```

Опциональные аргументы: `--hours 6`, `--language русский`,
`--catalog data/contractors.csv`. Для справки: `python -m src --help`.
Без установленного SDK офлайн-режим работает на стандартной библиотеке.

## 8. Как проверить решение

```bash
python -m pytest -q
python -m src.demo
```

Фактический результат тестов:

```text
13 passed in 0.03s
```

Реальные сценарии на приложенном CSV: Алматы, корпоратив, 2026-10-10.

| Сценарий | Бюджет | Статус | ID карточек |
|---|---:|---|---|
| Ведущий | 2 000 000 ₸ | matched | HK-72938, HK-88430, HK-75012 |
| Флорист | 2 000 000 ₸ | matched | HK-39372 |
| Ведущий | 1 ₸ | no_match | — |

Фактическое сообщение третьего сценария:

```text
По категории «Ведущий» в городе Алматы найдено 10 подрядчиков, но ни один не подошёл: 4 заняты на 2026-10-10, 10 не укладываются в бюджет 1 ₸, 1 не берут формат «корпоратив».
```

Пример объяснения карточки:

> Куррапика — категория «Ведущий», стартовая цена 500 000 ₸ в пределах бюджета 2 000 000 ₸. В описании: «Специализируюсь на проведении корпоративных мероприятий, торжеств и деловых встреч».

Три повтора запроса ведущего дали одинаковый порядок:
`HK-72938, HK-88430, HK-75012`.
На 2026-10-11 порядок: `HK-72938, HK-77838, HK-44923`.
HK-88430 и HK-75012 заняты 11 октября; HK-44923 занят 10 октября.
Причины и ID видны в `message` и `excluded.busy`.

Все три сценария вместе заняли около 0.0053 секунды локально в офлайн-режиме
(не гарантия скорости на другом компьютере). Полный фактический JSON-вывод,
дополнительный `no_category` и повторы сохранены в
[reports/demo-output.txt](reports/demo-output.txt).

## 9. Данные и интеграции

`data/contractors.csv` — неизменённая копия файла
`hackathon dataset anonymized .csv`, предоставленного участником из материалов
хакатона. В нём 66 профилей: Алматы — 50, Астана — 15, Зарубежье — 1;
13 профилей имеют `synthetic=true`.
Названия полей сохранены. `city_imputed`, `price_imputed` и `synthetic`
отображаются в JSON-карточках.
«Зарубежье» обрабатывается как отдельное точное значение города и не попадает
в выдачу Алматы/Астаны. Пустой `max_hours` не ограничивает длительность.

`OPENAI_API_KEY` опционален: без него или при ошибке API используется fallback.
`--offline` отключает API даже при наличии ключа. Ключи задаются в окружении,
не в исходниках; `.env`, кеш и виртуальная среда исключены из Git.
Успешные живые API-вызовы не проверялись: тесты используют моки.

## 10. Ограничения

- Стартовая цена не гарантирует итоговый бюджет; оценочные поля требуют уточнения.
- Отсутствие даты в `busy_dates` означает только отсутствие отметки о занятости.
- Описания — утверждения профилей, а не независимо проверенная репутация.
- Фактичность произвольного ответа LLM не проверяется автоматически.
- Нет бронирования, заявок, уведомлений, UI и эмбеддингов.
- Тайм-ауты и fallback повышают устойчивость, но строгий SLA до 10 секунд не обеспечен.
