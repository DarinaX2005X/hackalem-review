# Ketnavr: рекомендации по закупкам

**От Excel-выгрузок склада к объяснимому списку пополнения для менеджера по закупкам.**

Ketnavr обрабатывает данные поставщиков ИЭК и SystemElectric: продажи, остатки,
товары в пути и кратность заказа. Менеджер получает рекомендуемое количество,
срочность и обоснование, проверяет позиции в интерфейсе и выгружает результат
в CSV или Excel.

Проект решает задачу подготовки закупок по разрозненным таблицам. Это
хакатонный прототип поддержки решения, **не система автоматической отправки
заказов**. Количества рассчитываются в Python; OpenAI или NVIDIA могут улучшать
текст объяснения, но не управляют числовым расчётом.

**Быстрые ссылки:** [запуск](#установка-и-запуск) ·
[сценарий для жюри](#как-проверить-решение-жюри) ·
[ограничения](#ограничения-текущей-версии) ·
[общая версия](#развёрнутая-версия).

**Для запуска после `git clone` деплой не нужен.** Backend и frontend работают
локально. Нужен исходный ZIP из материалов задачи, а для живого чата также
свой API-ключ OpenAI или NVIDIA. Архив и секреты передаются отдельно от Git.
Без ключа доступны полный расчёт, фильтры, карточки и экспорт.

## Что реализовано

- Чтение локального ZIP-архива с Excel-таблицами двух поставщиков и сопоставление товаров по коду 1С.
- Расчёт прогнозного дневного спроса с ограничением месячных выбросов, поправками на тренд и сезонность.
- Учёт остатка, количества в пути, срока поставки, страхового запаса и округление заказа до кратности MOQ.
- Приоритеты «Критично», «Заказать скоро» и «Планово».
- Два списка: **«К закупке»** и **«Весь расчёт»**, включая товары с нулевым заказом.
- Поиск по названию и артикулу; совместные фильтры по поставщику, категории и срочности.
- Сортировки по приоритету, количеству к заказу и «Рекомендуемый порядок», сохраняющий порядок API.
- Карточка товара с объяснением, спросом, покрытием, остатками и параметрами заказа.
- Сводка по всей текущей выборке; неизвестные цены не заменяются нулями, неполная сумма помечается явно.
- Пагинация по 50 строк с прокруткой внутри таблицы и закреплёнными заголовками.
- Экспорт **всей отфильтрованной выборки**, а не только открытой страницы, в CSV и настоящий XLSX.
- Необязательные AI-объяснения через OpenAI или NVIDIA, с возвратом к расчётным шаблонам при сбое.
- Отдельно помеченный режим синтетического демо; ошибки API не подменяются демо автоматически.
- Сервер показа сохранённого снимка для временной публикации через Cloudflare Tunnel.
- Чат-помощник по всему расчёту с историей диалога: требует настроенного AI-провайдера; на необязательном сервере показа включается через `SHARE_CHAT_ENABLED=true`.

## Как работает решение

1. Оператор получает исходный Excel-архив и задаёт его путь и дату расчёта в настройках backend.
2. Backend читает таблицы, объединяет позиции по коду 1С и рассчитывает потребность.
3. Для каждой рассчитанной позиции формируются количество, приоритет и шаблонное объяснение. Если ИИ включён, часть объяснений может быть заменена ответом модели.
4. Frontend получает JSON, проверяет его формат и показывает список «К закупке».
5. Менеджер фильтрует товары, открывает карточки и проверяет основания заказа. Выбор «Планово» переключает интерфейс на полный расчёт с нулевой потребностью.
6. Менеджер выгружает выбранные позиции в CSV/XLSX. Дальнейшее согласование и отправка заказа выполняются вне приложения.

### Метод расчёта

Реализация находится в [`backend/app/calculator.py`](backend/app/calculator.py).
Используются до шести последних доступных месяцев продаж не позднее месяца
`AS_OF_DATE`. Верхние выбросы ограничиваются на основе медианы и медианного
абсолютного отклонения. Среднемесячный объём делится на 30,4, затем применяются
поправки на тренд и сезонность, если истории достаточно.

```text
Прогнозный дневной спрос = средний дневной спрос × тренд × сезонность
Доступное количество = остаток + товар в пути
Горизонт = срок поставки + дни страхового запаса
Потребность = max(прогнозный дневной спрос × горизонт - доступное количество, 0)
Заказ = потребность, округлённая вверх до кратности MOQ
Покрытие, дней = доступное количество / прогнозный дневной спрос
```

Тренд ограничен диапазоном 0,85–1,25, сезонный коэффициент: 0,8–1,2.
Это эвристический расчёт, а не обученная модель прогнозирования.

| Приоритет | Условие |
| --- | --- |
| `critical` / «Критично» | Покрытие меньше срока поставки. |
| `soon` / «Заказать скоро» | Покрытие не меньше срока поставки, но меньше горизонта со страховым запасом. |
| `normal` / «Планово» | Покрытие не меньше горизонта; дополнительный заказ равен 0. |

Позиции без пригодной положительной истории спроса в расчёт не включаются.
«Весь расчёт» поэтому не означает весь ассортимент исходных файлов.

## Технологии

| Компонент | Технологии в репозитории |
| --- | --- |
| Backend | Python, FastAPI, Uvicorn, Pydantic. |
| Обработка Excel | pandas, openpyxl; NumPy указан в зависимостях backend. |
| Расчёт | Python: `statistics`, `math`, `datetime`; собственные правила расчёта. |
| Frontend | JavaScript, React 19, Vite 6, CSS, иконки Lucide React. |
| Выгрузка | ExcelJS для XLSX; формирование CSV в браузере. |
| OpenAI | Responses API: `POST https://api.openai.com/v1/responses`. |
| NVIDIA | Chat Completions: `POST https://integrate.api.nvidia.com/v1/chat/completions`. |
| HTTP к моделям | Стандартная библиотека Python `urllib.request`, без SDK OpenAI. |
| Временная публикация | Отдельное приложение FastAPI и Cloudflare Tunnel (`cloudflared`). |
| Тесты | Python `unittest`, FastAPI TestClient/httpx, встроенный Node.js test runner. |

В [`backend/.env.example`](backend/.env.example) и конфигурации заданы
`OPENAI_MODEL=gpt-5.6-luna` и `NVIDIA_MODEL=meta/llama-3.1-8b-instruct`.
Это **настраиваемые идентификаторы из кода**, не гарантия доступа к модели
для любого API-аккаунта. Доступность зависит от используемого провайдера и ключа.

Зависимости: [`backend/requirements.txt`](backend/requirements.txt),
[`backend/requirements-dev.txt`](backend/requirements-dev.txt),
[`frontend/package.json`](frontend/package.json).

## Архитектура

### Локальная разработка

```text
Локальный ZIP с XLSX
  -> data_loader.py: чтение и объединение таблиц
  -> calculator.py: числовые рекомендации и шаблонные объяснения
  -> ai_client.py: необязательное обогащение reason через OpenAI/NVIDIA
  -> main.py: FastAPI, порт 8000, JSON
  -> Vite proxy: /api/* -> backend /*
  -> React, порт 5173: проверка контракта, таблица, фильтры, карточки
  -> CSV / XLSX в браузере
```

API-ключи хранятся только на backend. Браузер не обращается к моделям напрямую.
Базы данных нет: исходные таблицы и снимок для показа кэшируются в памяти процессов.

### Общая версия для показа

```text
main.py:8000 -> share.py:8010: снимок расчёта в памяти
frontend/dist -> share.py:8010: статическая сборка интерфейса
браузер посетителя -> Cloudflare Tunnel -> share.py:8010
```

При запуске `share.py` получает полный расчёт без ИИ, затем запрашивает
AI-объяснения для первых трёх позиций к заказу. Посетители читают уже сохранённый
снимок: обновление страницы не вызывает платные API. При недоступности ИИ остаются
расчётные объяснения. Недоступный основной backend не заменяется демо.

## Установка и запуск

Команды ниже предназначены для **Windows PowerShell**. Сервисы запускаются
в отдельных терминалах. Для первого запуска платные API и ключи не нужны.

### Требования

- Git и доступ к командному репозиторию, если код получается через `git clone`.
- Python 3.12+ с `venv` и `pip`.
- Node.js 22+ и npm.
- Исходный ZIP с Excel для работы на реальных данных. Он **не входит в Git** и передаётся командой отдельно.

### Шаг 1. Получить проект

```powershell
git clone https://github.com/BAITC-Hacks/hack-f8b85cde-ketnavr.git
cd hack-f8b85cde-ketnavr
```

Если проект уже скачан, откройте терминал в его корне.

### Шаг 2. Установить и настроить backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
New-Item -ItemType Directory -Path data -Force
Copy-Item -LiteralPath "$env:USERPROFILE\Downloads\Excel_IEK_Systeme_Electric_оформленные.zip" -Destination data/source.zip
```

Последняя команда копирует предоставленный архив из «Загрузок»; если он лежит
в другом месте, замените только исходный путь. Не распаковывайте и не меняйте
структуру ZIP. В `backend/.env` задайте следующие настройки:

```env
DATA_ZIP_PATH=data/source.zip
AS_OF_DATE=2026-09-22
MAX_RECOMMENDATIONS=0
SAFETY_STOCK_DAYS=14
IEK_LEAD_TIME_DAYS=18
SYSTEME_LEAD_TIME_DAYS=14
AI_PROVIDER=template
```

Относительный `DATA_ZIP_PATH` считается от папки `backend`, независимо от
рабочего каталога терминала. Можно вместо копирования указать свой абсолютный
путь к исходному ZIP. Архив должен существовать. `AS_OF_DATE` задаётся явно,
а не обновляется автоматически. `MAX_RECOMMENDATIONS=0` снимает ограничение
числа рекомендаций. Существующий `.env` и его ключи не перезаписывайте.

Запустите backend из каталога `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Оставьте этот терминал открытым. В другом терминале проверьте:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/health'
Invoke-RestMethod 'http://127.0.0.1:8000/data/summary'
Invoke-RestMethod 'http://127.0.0.1:8000/recommendations?ai=false&limit=5'
$full = Invoke-RestMethod 'http://127.0.0.1:8000/recommendations?ai=false&include_no_order=true&limit=0'
$full.recommendations.Count
```

`data_zip_exists` должен быть `true`. Документация основного API:
[Swagger UI](http://127.0.0.1:8000/docs).
Для предоставленного архива полный запрос возвращает **2144**, а не 120 строк.
`limit=5` выше служит только короткой проверкой, не настройкой интерфейса.

### Шаг 3. Запустить frontend

В новом терминале **из корня проекта**:

```powershell
cd frontend
npm install
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

Проверьте настройки `frontend/.env.local`:

```env
BACKEND_URL=http://127.0.0.1:8000
VITE_API_BASE_URL=/api
VITE_RECOMMENDATIONS_PATH=/recommendations?ai=false
VITE_DATA_MODE=api
```

```powershell
npm run dev:local
```

Откройте [локальный сайт](http://127.0.0.1:5173/). Frontend сам добавляет
`include_no_order=true&limit=0`, чтобы получить весь доступный расчёт.
`dev:local` принудительно использует backend `127.0.0.1:8000`, реальные данные
и `ai=false` для таблицы, даже если в старом `.env.local` осталась ссылка туннеля.
Чат остаётся доступен отдельно. Если порт занят, используйте
`npm run dev:local -- --port 5174` и адрес, который напечатает сервер.
Для собственных настроек `.env.local`, другого backend или демо запускайте
обычный `npm run dev`; после изменения настроек перезапустите Vite.

### Шаг 4. Необязательно: включить AI-объяснения

В `backend/.env` выберите провайдера и добавьте его ключ. Не вставляйте ключи
в README, Git, JavaScript или переменные `VITE_*`.

| Режим `AI_PROVIDER` | Что требуется и что происходит |
| --- | --- |
| `template` | Ключ не нужен, внешних вызовов нет. |
| `openai` | `OPENAI_API_KEY`; модель задаётся через `OPENAI_MODEL`. |
| `nvidia` | `NVIDIA_API_KEY`; модель через `NVIDIA_MODEL`, адрес через `NVIDIA_BASE_URL`. |
| `auto` | Пробует настроенный OpenAI, затем настроенный NVIDIA при отсутствии результата; без успешного ответа остаются шаблоны. |

`AI_MAX_ROWS=8` по умолчанию ограничивает число строк, отправляемых модели.
Запросы к провайдерам имеют таймаут 12 секунд и лимит выходного текста 900 токенов.
Внешнему сервису передаются названия и показатели выбранных товаров, поэтому
AI следует включать только при разрешении на такую обработку данных.

Перезапустите backend. Для прямого локального подключения замените настройку
frontend на `VITE_RECOMMENDATIONS_PATH=/recommendations?ai=true` и запустите
обычный `npm run dev` вместо `dev:local`. Проверить конфигурацию без раскрытия ключа можно через
`GET /ai/status`, но наличие ключа **не доказывает успешный вызов модели**.
Прямые запросы к основному backend с `ai=true` могут каждый раз расходовать токены.

### Шаг 5. Включить чат-помощник

В `backend/.env` добавьте свой действующий ключ, например:

```env
AI_PROVIDER=openai
OPENAI_API_KEY=YOUR_OPENAI_API_KEY
OPENAI_MODEL=gpt-5.6-luna
```

`YOUR_OPENAI_API_KEY` заменяется только в локальном `.env`, а не в этом README.
При необходимости укажите доступную вашему аккаунту модель. Для NVIDIA
используйте `AI_PROVIDER=nvidia`, `NVIDIA_API_KEY` и `NVIDIA_MODEL`.
Перезапустите backend. В локальном режиме портов **8000 + 5173**
`SHARE_CHAT_ENABLED` не нужен: он относится только к `app.share` на порту 8010.

Откройте сайт, дождитесь таблицы, нажмите **«Спросить ИИ»** и отправьте:
«Сколько позиций всего, сколько нужно заказать и сколько критичных?».
Ожидаемые факты для исходного архива: **2144 / 221 / 177**.
Формулировка ответа модели может отличаться.

Чат работает через `POST /api/assistant/chat` во frontend и
`POST /assistant/chat` на основном backend. Пример тела:

```json
{"question":"Почему нужен заказ?","history":[]}
```

Ответ: `{"answer":"Текст ответа модели"}`. Каждый отправленный вопрос может
расходовать токены; ключ остаётся на backend. Для экономии можно оставить
`VITE_RECOMMENDATIONS_PATH=/recommendations?ai=false`: таблица будет без
вызовов модели, **а чат продолжит работать** через отдельный POST.

Помощник получает сводку всего расчёта, до 18 подходящих товаров и до 10
сообщений истории. Он не видит только текущие фильтры и не отправляет заказы.
Без ключа или при сбое API отображается ошибка, а не выдуманный ответ.
Лимит: 10 вопросов в минуту и 2 одновременно на процесс, не денежный лимит.
Настройка для готовой сборки на 8010: [SHARING.md](SHARING.md).

### Запуск без исходного архива

Для демонстрации только интерфейса задайте в `frontend/.env.local`
`VITE_DATA_MODE=demo` и запустите обычный `npm run dev`, не `dev:local`. Backend в этом режиме не требуется.
Данные вымышлены и помечены как синтетические, в том числе в выгрузке.
Это не проверка расчёта по Excel. Кнопки входа в демо в рабочем интерфейсе нет.

## Как проверить решение жюри

### Пользовательский сценарий на реальных данных

1. Запустите проект с исходным архивом, указанной выше датой и `ai=false`, либо откройте общую версию из раздела «Развёрнутая версия».
2. В «К закупке» проверьте таблицу, наличие обоих поставщиков и показатели сводки.
3. Выберите `SystemElectric` и «Заказать скоро». Откройте любой товар и сопоставьте остаток, путь, спрос, MOQ и объяснение с количеством к заказу.
4. Скачайте CSV и Excel. Количество строк должно соответствовать **всей выборке по фильтрам**, а неизвестная цена не должна превращаться в ноль.
5. Сбросьте фильтры и выберите «Планово». Интерфейс перейдёт во «Весь расчёт»; в карточках будет объяснение, почему дополнительный заказ не требуется.
6. Вернитесь в «К закупке», выберите «Критично» и переключите страницы 2, 3 и 4. Панель пагинации должна оставаться на месте.
7. Выберите «Рекомендуемый порядок»: это порядок ответа API, без изменения количеств и приоритетов.
8. При настроенном AI задайте помощнику вопрос из шага 5. Без ключа этот шаг пропускается; расчёт и экспорт от AI не зависят.

Для набора и настроек на **22.09.2026** в
[`FRONTEND_HANDOFF.md`](FRONTEND_HANDOFF.md) зафиксированы контрольные значения:

| Выборка | Количество позиций |
| --- | ---: |
| К закупке | 221 |
| ИЭК / SystemElectric в списке к закупке | 205 / 16 |
| Критично / Заказать скоро | 177 / 44 |
| SystemElectric + Заказать скоро | 8 |
| Весь расчёт | 2144 |
| Планово, заказ 0 | 1923 |

Это контроль конкретного набора, **не оценка точности прогноза**. При замене
файлов, даты или параметров числа могут измениться. Без исходного архива
репозиторий сам по себе не позволяет воспроизвести эти результаты.

### Автоматические проверки

Из корня проекта:

```powershell
cd backend
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests
cd ..\frontend
npm test
npm run build
```

Модульные тесты не требуют реальных API-ключей. Они проверяют расчёт, контракт,
резервные AI-объяснения, сервер снимка, фильтры, сортировку, пагинацию, ошибки
и экспорт. Исходные Excel и платные провайдеры этими тестами не валидируются.

При проверке текущей версии 23.09.2026 прошли **27 тестов backend и 29 тестов frontend**.

`node tests/live-check.mjs` из `frontend` выполняет отдельную проверку
согласованного снимка 221/177/44 через работающий порт 5173. Скрипт запрашивает
`ai=true`: используйте его с сервером снимка через `BACKEND_URL=http://127.0.0.1:8010`,
если не хотите повторных вызовов моделей. Перед запуском перезапустите Vite
после изменения этой настройки.

## Данные и интеграции

### Excel

Загрузчик рассчитан на предоставленный архив
`Excel_IEK_Systeme_Electric_оформленные.zip`, содержащий папки **`IEK/`** и
**`Systeme electric/`** непосредственно внутри ZIP. Для каждого поставщика
используются XLSX-файлы, найденные по словам в имени:

| Таблица | Слова в имени | Назначение |
| --- | --- | --- |
| MOQ | `MOQ` | Код товара, артикул, название и кратность. |
| Продажи | `Ежемесячные`, `продажи` | История продаж по месяцам. |
| Остатки | `Ежемесячные`, `остатки` | Количество из последнего распознанного месячного столбца. |
| В пути, ИЭК | `Путь` | Количество поставок в пути. |
| В пути, SystemElectric | `Товар в пути` | Количество в пути, доступные категории и цены. |

Распознавание колонок и структуры описано кодом
[`data_loader.py`](backend/app/data_loader.py). Это адаптер заданных выгрузок,
не универсальный импорт произвольного Excel. Загрузка файла через сайт и
прямое подключение к 1С или API поставщиков не реализованы.

### HTTP API

Основной backend на порту 8000:

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Состояние, наличие ZIP и настройка AI. |
| `GET /data/summary` | Число загруженных товаров и позиций к заказу по поставщикам. |
| `GET /ai/status` | Провайдеры, модели и наличие ключей без их значений. |
| `GET /recommendations` | JSON: `schema_version`, `as_of`, `recommendations`. |
| `POST /assistant/chat` | Вопрос и история диалога; ответ модели в поле `answer`. |

Параметры `/recommendations`: `ai=false` отключает AI для запроса;
`include_no_order=true` включает рассчитанные строки с нулевым заказом;
`limit=0` возвращает весь выбранный набор, `limit=1..500` ограничивает число строк.
Если `limit` не передан, используется `MAX_RECOMMENDATIONS`.
По умолчанию `include_no_order=false`, `ai=true`.

Сервер показа на порту 8010 отдаёт `/api/recommendations` и `/api/health`
(также доступны пути без `/api`). Его `/health` показывает дату снимка,
число рекомендаций, размер полного расчёта и число изменённых AI-объяснений.
Swagger и диагностические маршруты основного backend в нём не опубликованы.
Полный формат ответа: [контракт API](outputs/API_CONTRACT.md).

## Ограничения текущей версии

- **Нет подтверждения или отправки заказов**, личных кабинетов, авторизации и разграничения доступа. CSV/XLSX передаются в дальнейший процесс вручную. Чат-помощник не оформляет заказы и требует действующего ключа провайдера.
- **Прогноз эвристический.** Нет оценки точности на отложенной выборке, доказанного экономического эффекта или обучения модели спроса.
- Детальная клиентская динамика и отдельные таблицы сезонности загрузчиком не читаются. Клиентские разовые закупки и упущенный спрос в периоды отсутствия товара отдельно не моделируются.
- Дата ограничивает выбор недавних месяцев продаж, но остаток берётся из последнего столбца файла, а сезонный расчёт использует всю доступную месячную историю. Это не механизм корректного исторического тестирования на любую дату.
- Количество в пути учитывается целиком, без проверки дат прибытия. Срок поставки общий для поставщика, по умолчанию 18 дней для ИЭК и 14 для SystemElectric.
- При недостающем MOQ используется 1, при отсутствующей единице измерения `шт.`, категория может определяться по названию. Эти допущения требуют проверки владельцем данных.
- Отсутствующие или неположительные цены из Excel становятся `null`; сумма считается только по известным ценам. Это не полный бюджет при наличии пропусков.
- AI не меняет числовые поля, но текст модели не проходит проверку всех фактов. Ответ следует проверять; в контракте нет поля `reason_source` для определения источника каждого объяснения.
- Основной backend кэширует загруженные таблицы. После замены ZIP по тому же пути перезапустите backend; для новой общей версии также перезапустите сервер снимка. Кнопка «Обновить» не загружает новый файл.
- Пагинация только клиентская: весь расчёт передаётся браузеру. Нагрузочные гарантии для больших наборов не заявляются.
- Публичный снимок доступен без пароля всем, у кого есть ссылка. Нужны разрешение владельца данных и отдельная доработка защиты для производственного использования.

## Сборка и публикация

Этот раздел необязателен: для проверки проекта из Git достаточно шагов
запуска backend и frontend выше. Аккаунты хостинга и туннель не требуются.

`npm run build` из `frontend` создаёт `frontend/dist`. Для готовой сборки
Vite dev proxy не работает: нужен общий origin с API или отдельно настроенные
серверный proxy/CORS. Основной backend разрешает CORS только локальному
frontend на порту 5173.

В репозитории реализован вариант публикации через `app.share:app`. После
настройки и запуска основного backend, сборки frontend с `/api` и `VITE_DATA_MODE=api`
сервер снимка запускается из `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.share:app --host 127.0.0.1 --port 8010
```

Локальная собранная версия: [http://127.0.0.1:8010/](http://127.0.0.1:8010/).
Полная последовательность сборки, запуска туннеля и остановки:
[`SHARING.md`](SHARING.md). Публиковать следует порт **8010**, не Vite и не
основной диагностический API. Ключи и исходный архив не входят в статическую
сборку, но показанные товарные данные посетители смогут скачать.

## Если не запускается

| Проблема | Что проверить |
| --- | --- |
| `data_zip_exists=false`, Excel не найден | Поместите исходный архив в `backend/data/source.zip` или исправьте `DATA_ZIP_PATH`, затем перезапустите backend. |
| API вернул HTML или соединение отсутствует | Backend должен работать на 8000; `BACKEND_URL=http://127.0.0.1:8000`, `VITE_API_BASE_URL=/api`. После правки перезапустите Vite. |
| Мало строк, не виден второй поставщик | Используйте актуальный `main`, `MAX_RECOMMENDATIONS=0`; полный API-запрос содержит `include_no_order=true&limit=0`. В ZIP должны быть обе папки поставщиков. |
| «Планово» пусто | Сбросьте остальные фильтры и выберите «Весь расчёт». На исходном наборе доступно 1923 позиции с нулевым заказом. |
| Чат сообщает, что AI не настроен | Провайдер не должен быть `template`; ключ хранится в `backend/.env`. Перезапустите backend. Для 8010 дополнительно включите `SHARE_CHAT_ENABLED=true` и перезапустите `app.share`. |
| Временная ошибка AI или HTTP 429 | Проверьте доступ к модели, лимиты аккаунта и сеть; при 429 подождите минуту. Не делайте частых повторов платных запросов. |
| Порт 5173 занят | Остановите старый Vite через `Ctrl+C` или используйте `npm run dev -- --port 5174`. |

При обновлении кода выполните `git pull --ff-only`, повторите установку
зависимостей и перезапустите backend/frontend. Не перезаписывайте существующие
`.env` файлами примеров. Для режима показа дополнительно выполните
`npm run build` и перезапустите `app.share`; работающий туннель не трогайте,
если необходимо сохранить текущую временную ссылку.
