# Аким на 5 часов

Браузерная учебная модель управления условным городом команды VIP POLO. Пять решений при бюджете 100 меняют Astana Quality of Life Score; AI объясняет готовый расчёт. Данные синтетические, районы условные, результат не является официальной оценкой Астаны или рекомендацией акимату.

Реализованы выбор, замена и отмена мероприятий, предварительный расчёт, серверная финальная проверка, результаты с фактами/trace, AI-адаптер, честный fallback, повтор анализа и JSON-экспорт. Оба API работают по контракту и не являются стартовыми заглушками 501.

Включена подробная SVG-карта из PR №5, коммит `a29ff8c`: кварталы, дороги, парки, река, набережная, мосты и условные ориентиры. Выбор трёх районов работает мышью и клавиатурой. Улицы и ориентиры придуманы; это схема без масштаба, а не географическая карта Астаны.

На общей версии с новой картой прошли lint, typecheck, 299 тестов и build. Полный Chromium-прогон ограничен песочницей macOS; настоящий AI ещё не подтверждён. Актуальные SHA, выполненные проверки и оставшиеся ограничения — в [docs/integration.md](docs/integration.md). Исторические отчёты отдельных модулей не подтверждают готовность общей версии.

## Установка и запуск

Нужны Node.js **24.19.0**, pnpm **11.19.0**, доступ к приватному репозиторию и npm. Версия Node закреплена в .node-version, pnpm — в packageManager. Установите их своим менеджером среды; пути компьютера автора не требуются.

После подтверждённого объединения PR №6 обычный запуск из main:

```sh
git clone https://github.com/BAITC-Hacks/hack-12254b16-vip-polo.git
cd hack-12254b16-vip-polo
git switch main
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm dev
```

Откройте http://localhost:3000. Для другого порта: `pnpm dev --port 3001`. Для проверки кандидата до merge в новом клоне вместо `git switch main` выполните `git switch --track origin/feat/integration-audit`. Существующую рабочую папку другой сессии не переключайте; каждый участник работает в своей копии.

Production-запуск:

```sh
pnpm build
pnpm start
```

Сборка не загружает внешние шрифты и не требует AI-ключа.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

На Linux для браузера может понадобиться `pnpm exec playwright install --with-deps chromium`. E2E сам запускает production-сервер на 127.0.0.1:3100; порт должен быть свободен. Не останавливайте чужой сервер. Конфигурация e2e очищает AI_PROVIDER, AI_MODEL и AI_API_KEY для своего сервера: обычный прогон проверяет честный fallback без обращения к платному провайдеру.

Обычные тесты проверяют схемы, данные, A–E, ID, модель, API, UI, состояния анализа и экспорт. Подстановки провайдера используются только в тестах и не доказывают доступность настоящего AI.

Отдельно, после настройки серверного окружения:

```sh
pnpm test:ai-live
```

Команда запускает `tests/live-ai/vitest.config.ts`. Требуется реальный ответ `source=ai`, `status=ready`; отсутствие настроек или fallback приводят к неуспешному live-тесту, а не к фиктивному успеху. Он не входит в обычный CI. Структурная проверка дополняется просмотром смысла реального ответа.

## AI и секреты

Реализован серверный адаптер OpenAI Responses API. Конкретная модель задаётся через AI_MODEL: её доступность для ключа команды необходимо проверить, подтверждённая модель пока не заявлена.

Создайте локальный файл настроек, сохранив существующий, если он уже есть:

```sh
test -f .env.local || cp .env.example .env.local
```

В редакторе задайте AI_PROVIDER=openai, доступную AI_MODEL, AI_API_KEY и при необходимости AI_TIMEOUT_MS (по умолчанию 15000). .env.local игнорируется Git; live-конфигурация читает его автоматически. Не отправляйте секрет в чат, не выводите его в логи и не используйте NEXT_PUBLIC.

Без ключа или при ошибке настройки/провайдера приложение сохраняет расчёт и возвращает `source=fallback, status=unavailable`. Таймаут и неподходящий ответ имеют отдельные статусы `timeout` и `invalid_response`. Fallback явно обозначен в интерфейсе и не считается успешной live-проверкой.

## Демонстрация

1. Выберите Северный район и по basic-мероприятию во всех пяти направлениях: расход 50, остаток 50, Score 51.67.
2. Замените транспорт на premium: расход 70, Score 52.53. Верните basic и проверьте восстановление результата.
3. Отмените мероприятие: завершение неполного плана недоступно. Верните решение.
4. Завершите сценарий. Серверный результат показывается до окончания анализа. Просмотрите факты, городские показатели и раскрываемый trace.
5. Без настройки AI увидите маркированный fallback. Повторите анализ, скачайте JSON, отредактируйте решения и начните новую игру.

Клавиатурный выбор района: Tab, затем Enter или пробел.

## Учебная модель и контрольные примеры

Бюджет 100; три района; model-v1/synthetic-v1. Пять индексов 0..100, больше — лучше. Score — среднее 15 конечных показателей, только итог округляется до двух знаков. Начальный Score 50. Правила и исходные числа: [контракт](docs/contract.md) и src/data.

| Сценарий | Выбор в north | Расход | Результат |
|---|---|---:|---|
| A | Все basic | 50 | Score 51.67 |
| B | Как A, transport-premium | 70 | Score 52.53 |
| C | Все standard | 100 | Score 53.33 |
| D | Все premium | 150 | BUDGET_EXCEEDED, HTTP 422 |
| E | A без service | 40 | Score 51.33 в draft; final — INCOMPLETE_SCENARIO |

Fixtures используются только в тестах. Прямой проверочный запрос A к production-серверу:

```sh
node -e 'const fs = require("node:fs"); process.stdout.write(JSON.stringify(JSON.parse(fs.readFileSync("tests/fixtures/scenario-A.json", "utf8")).request))' |
  curl -i http://localhost:3000/api/simulate -H 'Content-Type: application/json' --data-binary @-
```

Ожидается HTTP 200 и результат A. С тем же запросом /api/analysis возвращает HTTP 200 с серверным расчётом и AI либо маркированным fallback. Пустой объект у обоих маршрутов отклоняется с HTTP 400. Клиентские Score, стоимость и факты не принимаются; финальные сценарии проверяются сервером повторно.
