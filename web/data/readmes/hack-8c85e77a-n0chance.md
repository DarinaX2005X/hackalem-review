# МОСТ — задачи бизнеса и студенческие команды

Работающий MVP по кейсу HackAlem AI / AI Sana: бизнес уточняет задачу, подтверждает карточку и повышает её рейтинг. Любая команда может откликнуться, а бизнес выбирает одну, несколько или ни одной команды. После проверки фактического результата выбранной команде начисляются баллы.

## Открыть в VS Code и запустить

1. Откройте эту папку через **File → Open Folder**. Файл `package.json` должен находиться в корне открытой папки.
2. На Windows можно просто запустить **START-DEMO.cmd**. На компьютере, где создан проект, зависимости уже установлены.
3. Для запуска на другом компьютере установите Node.js 24 с npm и выполните в терминале VS Code:

```sh
npm ci
npm run demo
```

4. Откройте **http://localhost:5173**. В верхней полосе выбирайте бизнес или одну из пяти команд.
5. Остановите сервер сочетанием **Ctrl+C**.

`npm run demo` собирает приложение, применяет миграции, добавляет синтетические данные при первом запуске и запускает локальный сервер. API-ключи, отдельный сервер базы и регистрация для демонстрации не нужны. Изменения сохраняются на диске в `.demo-data` между перезапусками. После первого запуска готовой сборки можно использовать `npm run demo:start`.

Локальный демонстрационный сервер слушает только 127.0.0.1. Переключение личностей — специально для защиты проекта, а не производственная аутентификация.

## Соответствие кейсу

- Свободное описание потребности и минимум три уместных уточняющих вопроса.
- Редактируемая карточка: контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт, формат обратной связи, срок и условия.
- Явное подтверждение человеком. При редактировании подтверждение сбрасывается.
- Рейтинг 0–100 с расшифровкой. Пересчёт и сортировка каталога после подтверждённых изменений.
- Низкий рейтинг не запрещает публикацию или отклик.
- Каталог всех опубликованных задач, поиск, фильтры по теме и уровню готовности.
- Неограниченное число предложений, в том числе несколько от одной команды: идея, план, срок, ссылка на прототип, опыт и контакты.
- Ручное сравнение и окончательный выбор 0/1/нескольких команд. Невыбранные отклики отклоняются. Автоматического назначения нет.
- Выбранная команда отправляет отчёт с подтверждением фактического результата. Только владелец задачи подтверждает этап и начисляет 20 баллов; повторное начисление невозможно.
- По пять синтетических черновиков, карточек, профилей команд и предложений: `data/demo.json`.

## Формула рейтинга

Начисляются веса только тех критериев, чьи поля заполнены и подтверждены бизнесом. В редакторе показывается предварительный расчёт; в каталоге — сохранённый подтверждённый рейтинг.

| Критерий | Вес | Проверка в MVP |
|---|---:|---|
| Контекст и потребность | 20 | Контекст от 30 символов, потребность от 10 |
| Данные и материалы | 20 | От 20 символов |
| Ожидаемый результат | 15 | От 20 символов |
| Критерии успеха | 15 | От 15 символов |
| Ограничения | 10 | От 15 символов |
| Пользователи | 10 | От 10 символов |
| Связь с бизнесом | 10 | Контакт от 5 символов, формат обратной связи от 10 |

`rating = Σ(weight × completed × confirmed)`.

Длина текста — воспроизводимая эвристика полноты, не доказательство содержательного качества. Вес компании, репутация и чувствительные признаки участников не учитываются.

- **0–39:** требует уточнения (уровень «черновик» из кейса).
- **40–69:** рабочая.
- **70–89:** готовая.
- **90–100:** приоритетная, визуально выделена.

Статус личного неопубликованного черновика и уровень готовности опубликованной задачи — разные вещи. Личный черновик скрыт; опубликованная задача с 0 баллов видна всем командам и принимает предложения. Каталог сортируется по убыванию рейтинга, затем по времени создания. Фильтры не ограничивают доступ к полному каталогу. Срок в карточке информационный: приём закрывает сам бизнес.

## AI-функция

Используется **локальная заглушка**, разрешённая условиями кейса. Внешняя модель не вызывается. Помощник анализирует полноту, учитывает направление задачи, задаёт минимум три вопроса и возвращает карточку только с уже сообщёнными значениями. Пользователь дополняет и редактирует её вручную, затем подтверждает.

Полный промпт, формат и валидация находятся в `lib/assistant.ts`. Вход:

```json
{"description":"Нужен сайт","category":"Разработка","fields":{"title":"","problem":"Нужен сайт"}}
```

API принимает `{action:"clarify", description, fields}`; направление передаётся в `fields.category`. Выход содержит `mode:"local-stub"`, `questions` (3–7 строк), `draft` (полный набор строковых полей карточки) и `warning`. Неизвестные поля остаются пустыми. Каждый предложенный факт проверяется на совпадение с входом.

Некорректный JSON, неверная схема, менее трёх вопросов или добавленные факты отклоняются. Исходный текст сохраняется. Промпт и заглушку можно заменить адаптером внешнего API; сейчас это не реализовано и не выдаётся за работающую LLM.

## Архитектура

- `app/workspace.tsx`: React-интерфейс.
- `app/api/platform/route.ts`: серверные операции и проверки прав.
- `lib/readiness.ts`: единая формула рейтинга и уровни.
- `lib/assistant.ts`: локальная AI-заглушка, промпт и строгая проверка ответа.
- `db/schema.ts`, `drizzle/`: таблицы профилей, задач и предложений, миграции.
- `scripts/demo-server.mjs`: локальный HTTP-шлюз, Miniflare и постоянная D1.
- `scripts/demo-data.mjs`: генератор синтетических данных.
- `scripts/verify-workflows.mjs`: интеграционные проверки собранного Worker.

Стек: TypeScript, React 19, Vinext/Vite, Radix/Shadcn, Cloudflare Worker + D1, Drizzle, Zod. Модель данных: профиль владеет задачами или откликами; отклик принадлежит задаче; отчёт этапа и однократные баллы хранятся в отклике.

Черновик виден только владельцу. Предложение и контакты команды видят только команда и владелец задачи. Все операции изменения проверяют роль, владельца и Origin на сервере. Повторная отправка одного запроса не создаёт дубль благодаря уникальному идентификатору предложения.

В размещённой версии используется вход через ChatGPT и заголовки доверенного шлюза Sites. Не публикуйте локальный демошлюз или Worker с доверенными auth-заголовками напрямую без соответствующей защиты.

## Проверки

```sh
npx tsc --noEmit
npm run build
npm test
```

На момент сдачи: **88 автоматических проверок проходят**. Они используют отдельную временную базу и проверяют:

- нулевой рейтинг, рост до 100, пороги уровней и сортировку;
- ручное подтверждение, опубликованные дополнения и некорректную дату;
- вопросы AI и отклонение выдуманных/некорректных ответов;
- изоляцию черновиков и откликов, права ролей, Origin и безопасные ссылки;
- неограниченные отклики и защиту от повторной отправки;
- выбор 0, 1 и нескольких команд;
- отправку отчёта, подтверждение только бизнесом и однократные 20 баллов.

Для ручной проверки используйте `DEMO.md`.

## Ограничения MVP

AI работает по правилам, без внешней модели. Один подтверждаемый этап на отклик. Решение о выборе окончательное. Нет чата, платежей, файлов и почтовой рассылки. Профиль команды представляет её одним аккаунтом; совместное управление участниками не реализовано. Для большого каталога нужна пагинация. Все данные в локальном демо синтетические; ссылки example.com обозначают макеты.

Базовая производственная публикация Sites приватная. Полный межпользовательский сценарий для защиты доступен в локальном деморежиме.
