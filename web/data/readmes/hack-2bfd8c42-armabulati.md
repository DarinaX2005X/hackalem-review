# Dauys Hunt — от голоса к действиям

**Локальный ИИ-ассистент для протоколирования совещаний и контроля поручений.**

Проект команды **Armabulati** для HackAlem AI. Помогает секретарю превратить запись встречи в транскрипт, краткое содержание и список действий с ответственными и сроками. Руководителю доступны статусы исполнения и напоминания.

[Проверки и выпуск](https://github.com/BAITC-Hacks/hack-2bfd8c42-armabulati/actions/workflows/ci-release.yml) · [Скачать релиз](https://github.com/BAITC-Hacks/hack-2bfd8c42-armabulati/releases) · [Изменения 0.3.1](CHANGELOG.md)

> Аудио и текст обрабатываются на вашем компьютере. Облачные API для распознавания и анализа не используются. Интернет нужен для первоначальной установки и, если настроен, входа через Google/Facebook. Вход по email работает локально.

## Вход и личное пространство

При открытии приложения доступны вход и регистрация по email. При регистрации пароль нужно ввести дважды. Первая регистрация автоматически переносит прежние совещания в созданный аккаунт. Другие пользователи получают отдельное пространство.

Google и Facebook подключаются через `.env`; до настройки ключей кнопки неактивны. [Инструкция по аккаунтам, OAuth и безопасности](docs/accounts.md).

## Возможности

- Личные аккаунты, регистрация по email, вход/выход, смена пароля и изоляция данных; подготовлены интеграции Google/Facebook.
- Современная тема Dauys Hunt: индиго, бирюзовые и коралловые акценты, адаптивный экран входа.
- Цвет поручения зависит от срока: спокойный голубой → янтарный → мягкий красный за день до срока; выполненные задачи зелёные.
- Загрузка MP3, WAV, M4A, OGG, WEBM, MP4, FLAC, AAC и MKV; до 250 МБ и 2 часов.
- Запись микрофона в браузере после подтверждения уведомления участников.
- Локальное распознавание русского, казахского и смешанного языка; выбор языка в форме.
- Акустическая диаризация: голосовые эмбеддинги WeSpeaker и кластеризация, автоматическое или заданное число говорящих.
- Транскрипт с временными метками, прослушиванием записи, исправлением текста и говорящего.
- Поручения, ответственные, формулировки сроков, решения и саммари от локальной языковой модели.
- Ссылка каждого поручения на реплики-основания. Неоднозначные даты помечаются для проверки.
- Подтверждение имён голосовых групп, редактирование и проверка поручений.
- Статусы «К исполнению», «В работе», «Выполнено»; просрочка вычисляется по дате.
- Общий список поручений, поиск, фильтры, напоминания о ближайших и просроченных сроках.
- PDF, DOCX и JSON; опциональная замена известных имён при экспорте.
- Отдельный импорт текстового транскрипта, явно помеченный как текстовый сценарий.
- Локальная SQLite, очередь обработки, повтор после ошибки.
- Быстрый и точный режимы распознавания; кэш повторной загрузки идентичных записей.
- Транскрипт доступен ещё во время обработки; видны таймер, активность генерации и времена этапов.
- «Радар внимания»: отсутствующий ответственный, неопределённый/неподтверждённый срок, просрочка и непроверенные задачи.
- Поиск по исходным репликам с соседним контекстом и распределение длительности речи между голосовыми группами.
- Повестка следующей встречи из открытых поручений; экспорт проверенных задач в календарь (ICS).
- Ручное добавление пропущенных поручений с обязательной ссылкой на реплики-основания.
- Единые SVG-иконки; подсказки через 1,5 секунды при наведении или фокусе с клавиатуры.

## Быстрый запуск: Windows

Проверенная среда: **Windows x64, Python 3.12, CPU, 16 ГБ RAM**. Рекомендуется закрыть тяжёлые приложения и иметь хотя бы 6 ГБ свободной RAM и 10 ГБ свободного места. GPU не обязателен. Обработка на CPU занимает минуты и зависит от длины записи.

```powershell
git clone https://github.com/BAITC-Hacks/hack-2bfd8c42-armabulati.git
cd hack-2bfd8c42-armabulati
python --version
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File run.ps1
```

Если `python` не найден, передайте путь к Python 3.12:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1 -Python "C:\path\to\python.exe"
```

Откройте **[http://127.0.0.1:8765](http://127.0.0.1:8765)**. Для последующих запусков достаточно `start.cmd` или `run.ps1`. Остановка — `Ctrl+C` в терминале. Не запускайте несколько серверов с одной базой данных.

Установка вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe scripts\setup_models.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Скрипт скачивает Whisper large-v3-turbo для русского, специализированную казахскую Whisper large-v3-turbo, WeSpeaker ResNet34-LM, Qwen3-4B Q4_K_M и официальную CPU-сборку llama.cpp b11120. Казахские веса (~1,62 ГБ) один раз преобразуются в CPU INT8 (~0,81 ГБ); PyTorch и конвертер устанавливаются отдельно в `runtime/asr-convert`, при работе приложения не нужны. Ревизии зафиксированы в [`models.lock.json`](models.lock.json), версии Python-пакетов — в [`requirements.lock.txt`](requirements.lock.txt). Локальный манифест сохраняется в `models/manifest.json`.

**Обновление до 0.3.1:** сохраните `data/` и `.env`, остановите сервер, обновите исходники и выполните `python scripts/setup_models.py`. Для казахского и смешанного режима необходима новая модель. В старой записи нажмите **«Распознать заново»** и выберите «Қазақша» или «Қазақша + русский». Исходный протокол сохранится. Причина исправления и ограничения качества описаны в [проверке речи](docs/speech-quality.md).

Для закрытого контура выполните установку на разрешённой машине, затем перенесите исходники, `models/`, `runtime/` и подготовленные для целевой ОС зависимости. Во время работы интернет не требуется. Виртуальные окружения не следует переносить между разными ОС и путями установки.

### Linux

Автоматическое скачивание llama.cpp реализовано для Windows x64. ## Сценарий для жюри

1. Запустите приложение, зарегистрируйтесь или войдите; в «Состоянии системы» убедитесь, что установлены все четыре модели.
2. Нажмите «Новое совещание», укажите тему и **фактическую дату встречи**. От неё считаются относительные сроки.
3. Загрузите запись, выберите язык и, если известно, количество говорящих. Подтвердите уведомление участников.
4. Дождитесь статуса «Готов к проверке». Модели действительно обрабатывают файл; готовые результаты по имени файла не подставляются.
5. Откройте транскрипт, прослушайте реплики и подтвердите имена голосовых групп.
6. В поручениях раскройте основание, уточните ответственного и дату, отметьте проверку и сохраните.
7. Измените статус одного поручения на «Выполнено». Проверьте общий список и напоминания.
8. Экспортируйте PDF и DOCX. Перезапустите приложение — результаты сохраняются.

Для быстрой проверки **текстового** сценария импортируйте [`examples/meeting-mixed.txt`](examples/meeting-mixed.txt). Это синтетический пример RU/KZ, не тест распознавания речи. В нём два поручения и отклонённое предложение заказать сервер: последнее не должно становиться задачей.

## Архитектура и технологии

```text
Браузер: HTML / CSS / JavaScript
          │ localhost, HTTP
          ▼
FastAPI ───────── SQLite + локальные аудиофайлы
          │ последовательная очередь
          ▼
Отдельный Python-процесс
  PyAV → mono 16 kHz → faster-whisper (int8, CPU)
                    → слова и временные метки
  WeSpeaker ONNX → эмбеддинги → кластеризация голосов
          │ процесс завершён, память освобождена
          ▼
llama.cpp (localhost, временный API-ключ)
  Qwen3-4B → JSON по схеме → проверка ссылок на реплики
          │
  Разбор дат → поручения / решения / саммари
          ▼
Проверка секретарём → PDF / DOCX / JSON / контроль сроков
```

Языковая модель запускается на этапе анализа и завершается после него. Одновременно обрабатывается одно совещание. Длинные транскрипты разбиваются на части с перекрытием контекста.

| Компонент | Реализация |
|---|---|
| API и очередь | FastAPI, Uvicorn, ThreadPoolExecutor |
| Хранение | SQLite с WAL, каталог `data/` |
| Декодирование | PyAV; отдельная установка FFmpeg не требуется |
| Speech-to-text | [faster-whisper](https://github.com/SYSTRAN/faster-whisper), Whisper large-v3-turbo |
| Диаризация | [WeSpeaker](https://github.com/wenet-e2e/wespeaker), ONNX Runtime, Kaldi fbank, AgglomerativeClustering |
| Анализ текста | [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B-GGUF), [llama.cpp](https://github.com/ggml-org/llama.cpp), JSON schema |
| Экспорт | ReportLab, python-docx |
| Интерфейс | Vanilla JavaScript, адаптивный CSS; без CDN и внешних шрифтов |

## Скорость и полезные инструменты

**Повторная запись** кэшируется только внутри аккаунта владельца и определяется по SHA-256 содержимого, а не имени файла. Результат переиспользуется только при совпадении даты, языка, числа говорящих, режима и версии конвейера/манифеста моделей. Ручные правки и статусы исходного совещания не копируются. Удаление совещания-источника удаляет связанный кэш.

**Быстрый режим** сокращает число рассматриваемых вариантов распознавания с 3 до 1. Подходит для чистой записи, но может ухудшить точность; для сложной/смешанной речи оставлен точный режим по умолчанию. Просмотр транскрипта не требует окончания генерации саммари. Качество извлечения всё ещё требует проверки человеком.

Во вкладке **«Инструменты»** доступны радар проверки, баланс разговора, повестка и календарь. Баланс — доля длительности распознанных реплик, не оценка сотрудников. Поиск в транскрипте использует слова и их начала, а не генеративные ответы. В календарь попадают только незавершённые, проверенные поручения с подтверждённой датой.

## Приватность и известные ограничения

- Внешние сервисы при установке: PyPI, Hugging Face и GitHub. Скачиваются веса и движок; содержимое совещаний не передаётся. Лицензии моделей и зависимостей определяются их авторами.
- Сервер привязан к `127.0.0.1`. Добавлены аккаунты, scrypt, HttpOnly-сессии, CSRF/Origin-проверки, ограничение попыток входа, CSP и изоляция данных. **Нет корпоративного SSO/MFA, подтверждения email, шифрования SQLite/аудио и организационных ролей**. Не публикуйте порт напрямую в интернет; подробнее — [безопасность и OAuth](docs/accounts.md).
- Диаризация группирует похожие голоса, а не устанавливает личность. Шум, короткие реплики и одновременная речь ухудшают качество; число групп может быть неверным. Имена и привязки подтверждает секретарь.
- Модель может пропустить поручение, ошибиться в имени, сроке или саммари. Существование реплик-оснований проверяется программно; достоверность вывода проверяет человек.
- «К пятнице», «на следующей неделе», даты без года и нераспознанные сроки требуют подтверждения. Исходная формулировка сохраняется. Нормализация сложных казахских дат ограничена.
- Повторы и уточнения через границы частей длинного транскрипта могут обрабатываться неточно.
- Обезличивание заменяет известные имена буквальным совпадением. Склонения, организации и косвенные идентификаторы могут остаться. Перед демонстрацией реальных данных нужна ручная проверка.
- Напоминания обновляются каждые 4 секунды в открытом приложении. Браузерные уведомления требуют разрешения; фоновой рассылки email/SMS при закрытом приложении нет.
- Бот для Teams/Zoom/Google Meet, потоковая транскрибация, интеграция с СЭД и голосовая биометрическая идентификация не реализованы. Вход — запись файла или микрофона с последующей обработкой.
- Удаление убирает запись и данные совещания из приложения; это не криптографическое стирание свободных страниц SQLite и резервных копий.

## Развёртывание и развитие

**Рабочая версия запускается локально. Публичного веб-деплоя нет.** GitHub содержит исходники и инструкции; GitHub Pages не исполняет Python и локальные AI-модели этого проекта.

Для корпоративного размещения нужны сервер в закрытом контуре, корпоративная аутентификация/MFA, TLS, роли, управление хранением и резервными копиями. Направления развития: оценка RU/KZ/code-switching на размеченных записях, улучшение диаризации, сравнение полноты поручений с эталонами, фоновые уведомления и адаптеры СЭД.

Проект разработан с участием **Codex**. README описывает фактическую реализацию, а не гарантию оценки жюри.
