# AI Sana

**От бизнес-задачи к первому реальному проекту.**

AI Sana — веб-платформа, которая помогает бизнесу формулировать задачи с помощью AI, а студентам и студенческим командам — находить реальные проекты и предлагать решения. Заказчик описывает проблему своими словами, AI запрашивает недостающие сведения и формирует структурированную карточку для публикации.

Проект решает проблему недостаточно конкретных постановок задач: до поиска исполнителя бизнес уточняет пользователей, доступные данные, ограничения, ожидаемый результат и критерии успеха.

> **Состояние текущей версии:** в репозитории реализованы модули решения, но их интеграция содержит блокирующие ошибки. При проверке 23.09.2026 линтер, тесты приложений и сборка завершились с ошибками. Полный пользовательский сценарий в этом состоянии не подтверждён. Подробности — в разделах «Как проверить решение» и «Ограничения».

## Что реализовано

Перечень отражает существующий код и SQL-схемы; наличие модуля не означает, что весь сценарий сейчас проходит через интерфейс.

| Возможность            | Реализация в репозитории                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Регистрация и вход     | Supabase Auth, подтверждение email, восстановление сессии, выход, роли `business` и `student`                                 |
| Подготовка задачи с AI | Анализ описания, уточняющие вопросы, генерация карточки, ручное редактирование и принятие результата                          |
| Оценка постановки      | До 100 баллов по семи критериям с пояснениями и рекомендациями                                                                |
| Голосовой ввод         | Запись описания и ответов через микрофон, транскрибация и добавление текста в поле                                            |
| Работа с материалами   | Загрузка документов и изображений, извлечение фактов, выбор источников для анализа, повтор обработки, скачивание и удаление   |
| Каталог                | Страницы списка и карточки, поиск, фильтры и сортировка; загрузка опубликованных записей из Supabase                          |
| Отклики                | Название команды, идея, план, срок и ссылка на прототип; просмотр своих и входящих откликов; выбор или отклонение предложения |
| Профили                | Сведения об участнике, навыки, социальные ссылки, аватар; просмотр участников и поиск по имени                                |

Карточка AI содержит десять полей: название, контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт бизнеса и формат взаимодействия. Неизвестные сведения модель должна возвращать как `null` и перечислять отдельно. Публикация требует действия пользователя.

## Как работает решение

Основной сценарий, предусмотренный страницами, контроллерами и сервисами:

1. Представитель бизнеса регистрируется, подтверждает email и входит в кабинет.
2. Описывает проблему текстом или голосом, при необходимости прикладывает документы и скриншоты.
3. Backend передаёт описание и извлечённый контекст материалов в OpenAI. AI возвращает уточняющие вопросы.
4. Заказчик отвечает на вопросы. Второй запрос формирует карточку; пользователь проверяет и исправляет её.
5. После принятия карточки AI оценивает качество постановки и предлагает улучшения. Бизнес отдельно подтверждает публикацию.
6. Студент открывает задачу в каталоге и отправляет предложение с планом и сроком.
7. Бизнес просматривает отклики и выбирает либо отклоняет предложение; студент видит сохранённый статус.

Результат сценария — опубликованная постановка задачи и отклик команды с решением заказчика. Выполнение самого проекта студентами находится за пределами этого процесса.

## Архитектура проекта

```text
apps/web                 браузер: страницы, состояние, контроллеры
  ├─ Supabase SDK ──────► Auth, profiles, Storage аватаров,
  │                      business_tasks и task_proposals
  └─ /api ─────────────► apps/api
                          ├─ OpenAI: вопросы, карточка, оценка,
                          │          транскрибация и чтение файлов
                          └─ Supabase: профили, вложения,
                                      tasks, task_workspaces, proposals
packages/contracts       общие форматы данных и валидация
supabase/migrations      таблицы, представления, политики RLS и Storage
```

В режиме разработки Vite проксирует `/api` на Node.js-сервер. Вход выполняется через Supabase SDK; для защищённых HTTP-запросов frontend передаёт Bearer-токен. Модуль авторизации backend проверяет пользователя через Supabase Auth и читает роль из `profiles`. Доступ к данным дополнительно ограничивают SQL-политики RLS.

**Особенность текущего кода:** сосуществуют две схемы задач и откликов:

- `business_tasks` / `task_proposals` — прямые запросы браузерного сервиса `features/proposals/service.js`. На него ссылается текущий `main.js`; обработчик публикации в `events.js` переключён на этот сервис.
- `tasks` / `published_tasks` / `task_workspaces` / `proposals` — отдельная реализация через Node.js API с черновиками и приватными снимками анализа.

Эти схемы не синхронизируются автоматически. Каталог через прямой сервис и `GET /api/tasks` читают разные источники. Часть документов в `docs/` описывает только один из вариантов.

```text
apps/web/src/app/              запуск, маршрутизация, store и события
apps/web/src/pages/            страницы приложения
apps/web/src/features/         auth, tasks, proposals, profiles, attachments
apps/web/src/services/ai/      клиенты анализа и транскрибации
apps/api/src/modules/          auth, tasks, proposals, task-analysis, attachments
packages/contracts/src/       контракты и тестовые фикстуры
supabase/migrations/           SQL-миграции
scripts/dev.js                совместный запуск frontend и API
```

## Установка и запуск

### 1. Подготовить окружение

Нужны Node.js 24 (либо версия, соответствующая `^22.13.0 || >=24.0.0` из `package.json`), npm, проект Supabase и ключ OpenAI API с доступом к выбранным моделям. Для AI-функций нужен доступ к внешним сервисам.

Из корня репозитория:

```bash
npm ci
```

### 2. Создать локальные файлы настроек

Скопируйте примеры, если локальные файлы ещё не созданы. Команды для PowerShell:

```powershell
if (!(Test-Path apps/web/.env.local)) { Copy-Item apps/web/.env.example apps/web/.env.local }
if (!(Test-Path apps/api/.env)) { Copy-Item apps/api/.env.example apps/api/.env }
```

Заполните `apps/web/.env.local`:

```dotenv
VITE_API_BASE_URL=/api
API_TARGET=http://127.0.0.1:3001
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Заполните `apps/api/.env`. Переменные Supabase необходимо добавить вручную: в серверном `.env.example` они не перечислены, но используются кодом конфигурации.

```dotenv
HOST=127.0.0.1
PORT=3001
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
OPENAI_API_KEY=YOUR_OPENAI_API_KEY
OPENAI_MODEL=gpt-4.1-mini
OPENAI_TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe
```

Оба приложения должны указывать на один проект Supabase. Поддерживается publishable key или старый anon key; сервер также принимает `SUPABASE_ANON_KEY`. Secret/service-role ключи конфигурация отклоняет. OpenAI-ключ хранится только на сервере: переменные `VITE_*` попадают в браузерную сборку. Локальные `.env` исключены из Git.

### 3. Подготовить Supabase

Для **нового проекта** выполните файлы целиком в Supabase SQL Editor под `postgres` в следующем порядке:

| Шаг | Файл в `supabase/migrations/`              | Назначение                                   |
| --- | ------------------------------------------ | -------------------------------------------- |
| 1   | `20260923000100_registration_profiles.sql` | Профили, роли, регистрационный триггер       |
| 2   | `20260923000200_tasks.sql`                 | Задачи и публичное представление для API     |
| 3   | `20260923000200_task_attachments.sql`      | Вложения и приватный bucket                  |
| 4   | `20260923000300_task_workspaces.sql`       | Приватные рабочие состояния AI               |
| 5   | `20260923000300_profile_settings.sql`      | Расширенные профили и аватары                |
| 6   | `20260923000400_proposals.sql`             | Отклики для API-схемы                        |
| 7   | `20260923000400_task_proposals.sql`        | Задачи и отклики прямого браузерного сервиса |
| 8   | `20260923000500_proposal_decisions.sql`    | Решения по откликам API-схемы                |

Для существующей базы сначала проверьте применённые миграции: не все файлы допускают повторное выполнение. У нескольких файлов совпадают числовые префиксы; инструкция рассчитана на ручное выполнение SQL, готового проверенного процесса `supabase db push` в проекте нет. Миграции не загружают демонстрационные задачи.

В Supabase → Authentication → URL Configuration задайте Site URL `http://localhost:3000` и добавьте `http://localhost:3000` и `http://127.0.0.1:3000` в Redirect URLs. При включённом подтверждении email после регистрации перейдите по ссылке из письма.

### 4. Запустить приложения

> Настройка сервисов не устраняет ошибки исходного кода. Для работающего интерфейса и API сначала необходимо исправить перечисленные ниже блокеры.

```bash
npm run dev
```

Команда запускает Vite и Node.js API одновременно:

- интерфейс — `http://localhost:3000`;
- API — `http://127.0.0.1:3001`;
- остановка — `Ctrl+C`.

`npm start` и `npm run dev:full` запускают тот же сценарий. Раздельный запуск в двух терминалах:

```bash
npm run dev:api
npm run dev:web
```

После изменения окружения перезапустите приложения. При изменении порта API также обновите `API_TARGET`.

### 5. Собрать frontend

После исправления ошибок сборки:

```bash
npm run build
npm run preview
```

Результат — `apps/web/dist`. Preview использует порт 3000 и требует отдельно работающий API. Для размещения нужны раздача статических файлов и перенаправление `/api` на backend; запуск серверного workspace: `npm run start --workspace=@ai-sana/api`. Настройки прокси Vite не входят в статическую сборку.

## Как проверить решение

### Проверки текущего репозитория

```bash
npm run check
```

Команда последовательно запускает ESLint, тесты workspaces и сборку. Если первый этап падает, следующие не запускаются. Их можно проверить отдельно:

```bash
npm test
npm run build
```

Результаты проверки при подготовке README (23.09.2026, Node.js 24.21.0):

| Проверка        | Результат                                                           |
| --------------- | ------------------------------------------------------------------- |
| `npm run check` | Остановка на ESLint: 37 ошибок                                      |
| `npm test`      | Ошибки в API и web; пакет contracts: 15 тестов прошли               |
| `npm run build` | Ошибки разбора `features/proposals/actions.js` и `pages/catalog.js` |

Тесты содержат подмены сетевых зависимостей и не подтверждают работу реальных Supabase и OpenAI. Сквозная проверка внешних сервисов при подготовке этого README не выполнялась.

### Сценарий для жюри после устранения блокеров

Нужны настроенные сервисы и два аккаунта: бизнес и студент. Их удобно открыть в отдельных профилях браузера.

1. Проверить запущенный сервер:

   ```bash
   curl http://127.0.0.1:3001/api/health
   ```

   Ожидаемый ответ маршрута: `{"data":{"status":"ok"}}`. Это проверка процесса API, а не доступности всех интеграций.

2. Войти как бизнес и открыть `http://localhost:3000/#/create`. Ввести тестовое описание:

   > Небольшая кофейня хочет понять, какие товары чаще списываются. Есть CSV с датой, товаром, количеством продаж и списаний за три месяца. Нужен отчёт по товарам и дням недели для управляющего. Результат — таблица и графики с рекомендациями. Персональных данных нет. На работу отводится две недели.

3. Нажать «Проанализировать с AI», ответить на уточнения, сформировать карточку. Проверить, что неизвестные данные отмечены, а результат можно отредактировать.
4. Принять результат, проверить оценку и рекомендации, затем подтвердить публикацию. Ожидается появление записи в каталоге.
5. Под аккаунтом студента открыть `#/catalog`, выбрать эту задачу и отправить отклик: команда «Команда жюри», идея «Проанализировать списания», план «Проверить CSV, построить сводные таблицы и графики», срок «Две недели».
6. Под аккаунтом бизнеса открыть «Отклики», выбрать предложение. Под аккаунтом студента обновить «Мои отклики» и проверить статус.
7. Дополнительно проверить голосовой ввод и загрузку TXT/CSV с искусственными данными; убедиться, что извлечённые сведения можно просмотреть и исключить из анализа.

Описание кофейни — пример ввода для проверки, а не встроенная задача или подтверждённый результат проекта. До исправления интеграции этот сценарий не следует считать работающей демонстрацией.

## Данные и интеграции

- **Источники:** описание бизнеса, ответы на вопросы, загруженные материалы, профили и отклики пользователей. Импорт из CRM, внешних бизнес-каталогов или открытых датасетов не реализован.
- **Supabase Auth:** учётные записи и сессии. **PostgreSQL:** профили, обе схемы задач и откликов, рабочие состояния, метаданные вложений. **Storage:** приватные buckets `task-attachments` и `profile-avatars`.
- **OpenAI Responses API:** вопросы, карточка, оценка постановки и извлечение информации из файлов. В коде задано `store: false`; содержимое запросов всё равно передаётся внешнему сервису.
- **OpenAI Audio Transcriptions API:** распознавание записи микрофона. Приложение не записывает аудио в БД или файлы; оно обрабатывается в памяти.
- **Фикстуры:** `packages/contracts/src/fixtures.js` используется для тестирования. Рабочий каталог не заполняется фикстурами автоматически. Иллюстративные карточки на лендинге не являются записями базы.

В API-схеме `published_tasks` исключает приватные поля исходной задачи. В прямой схеме `business_tasks` публично читается вместе с JSON `fields`, в который сервис публикации передаёт всю карточку. Поэтому для этой схемы нельзя обещать приватность контакта из карточки: перед публикацией необходимо проверить её содержимое. Оригиналы вложений остаются в приватном хранилище.

## Ограничения

### Блокеры текущей версии

- Синтаксические ошибки в [actions.js](apps/web/src/features/proposals/actions.js) и [catalog.js](apps/web/src/pages/catalog.js) препятствуют сборке frontend.
- В [main.js](apps/web/src/main.js) отсутствуют импорты используемых фабрик профилей, вложений и сервиса откликов; используются необъявленные `workspace`, `publication` и другие переменные. В [events.js](apps/web/src/app/events.js) также используется необъявленный `workspace`.
- В [app.js](apps/api/src/app.js) отсутствуют импорты `createSupabaseProposalRepository`, `createProposalRouter` и `createProposalService`, необходимых для создания API-приложения.
- В [server.js](apps/api/src/server.js) конфигурация Supabase передаётся авторизации и вложениям, но репозитории задач и откликов не создаются с этой конфигурацией. Одного исправления импортов для работы API-хранилища недостаточно.
- В [analysis-controller.js](apps/web/src/features/tasks/analysis-controller.js) вызывается необъявленная `isCurrent`; в студенческой странице есть ссылки на необъявленные переменные. Полный список показывает ESLint.
- Две схемы хранения и контроллеры не сведены в единый процесс. Сквозное автосохранение, восстановление черновиков и согласованность каталога с API нельзя считать подтверждёнными.

### Функциональные границы

- Для AI необходим действующий OpenAI-ключ; автоматической замены анализа шаблонами нет. Оценка отражает качество постановки, а не гарантированную успешность проекта.
- Вложения: до пяти файлов на набор, каждый до 10 МБ. Поддерживаются PDF, DOCX, XLSX, TXT/CSV в UTF-8, PNG, JPEG и WebP. Извлечение может быть неполным; для XLSX предусмотрено предупреждение об ограниченном охвате строк.
- Голос: до двух минут на запись и до 10 МБ при отправке. Нужны разрешение на микрофон, поддержка MediaRecorder и HTTPS либо localhost.
- В прямой схеме откликов разрешён один отклик студента на задачу и одна выбранная команда. Редактирование текста уже отправленного предложения не реализовано.
- Избранное меняет состояние интерфейса и не подключено к постоянному хранилищу. Полноценного управления составом команды и восстановления пароля через письмо нет.
- Удаление аккаунта и очистка оставшихся объектов Storage не оформлены как завершённый пользовательский процесс.
- В репозитории нет подтверждённых результатов пользовательского пилота, измерений бизнес-эффекта или нагрузочного тестирования.
