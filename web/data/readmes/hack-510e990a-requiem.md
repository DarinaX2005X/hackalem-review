# EventMatch — объяснимый подбор подрядчиков для мероприятий

EventMatch — MVP для HackAlem. Он помогает организатору быстро найти до трёх подходящих подрядчиков из каталога: ведущего, флориста, площадку и другие категории.

Приложение принимает город, дату, формат события, категорию и бюджет; язык и длительность — дополнительные фильтры. Для каждого варианта оно показывает начальную цену, признаки профиля, причину соответствия и точный фрагмент описания. Подбор не является бронированием или рейтингом качества: это прозрачная фильтрация по данным каталога.

## Что решает продукт

Организатору не нужно вручную просматривать весь каталог и отдельно проверять условия каждого исполнителя. EventMatch:

- исключает подрядчиков, занятых на выбранную дату;
- учитывает город, категорию, стартовую цену, формат, язык и длительность;
- сортирует подходящие варианты по возрастанию начальной цены, а при равенстве — по ID;
- возвращает максимум три результата и объясняет, почему остальные не попали в выдачу;
- различает две ситуации без результатов: категории нет в городе или кандидаты есть, но не проходят условия;
- работает и без AI: в этом случае берёт релевантный фрагмент из описания по правилам каталога.

AI подключается опционально. Он выбирает один характерный фрагмент из уже предоставленных описаний максимум для трёх кандидатов. Он не влияет на доступность, цену, фильтрацию или порядок карточек; сервер проверяет все ID и использует безопасный резервный режим при ошибке, тайм-ауте или некорректном ответе.

Исходный каталог содержит 66 анонимизированных профилей, 17 категорий и данные о доступности в период с 23 сентября по 31 декабря 2026 года включительно.

## Технологии

| Область | Используется |
|---|---|
| Сервер | Node.js 22.12+ и Express 5 |
| Клиент | HTML, CSS и современный JavaScript без фреймворка и сборщика |
| Данные | Локальный CSV, разобранный с `csv-parse` и загружаемый в память при старте |
| AI, необязательно | OpenAI Responses API со строгой JSON Schema |
| Тесты | Встроенный раннер `node:test` |

База данных, авторизация и сторонние CDN не используются. Один Express-сервер обслуживает и страницу, и JSON API.

## Запуск

Нужны Node.js **22.12 или новее** и npm. Команды выполняются из папки приложения:

```sh
cd contractor-picker
npm ci
npm start
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). После установки зависимостей базовый режим не требует доступа к интернету и API-ключа.

Для разработки с автоматическим перезапуском сервера используйте:

```sh
npm run dev
```

На Windows, если PowerShell блокирует `npm.ps1`, запускайте те же команды через `npm.cmd`, например `npm.cmd start`.

### Настройки

Пример переменных находится в [`.env.example`](contractor-picker/.env.example). Можно создать локальный `.env` и при необходимости изменить `PORT` или `HOST`.

Чтобы включить AI-выбор фрагментов, добавьте в `.env` свой `OPENAI_API_KEY` и доступную модель в `OPENAI_MODEL`, затем перезапустите сервер. Не коммитьте `.env` и не передавайте ключ в браузер: запрос к API выполняется только сервером. Без ключа подбор остаётся полностью рабочим, а интерфейс показывает режим «AI не подключён».

## Как работает решение

```text
Браузер → POST /api/recommend → проверка входных данных
                                  ↓
                        фильтры каталога и сортировка
                                  ↓
                    до 3 карточек + проверяемые объяснения
                                  ↓
            OpenAI выбирает фрагмент описания (опционально)
```

Порядок проверок: город и категория → занятость на дату → бюджет → формат → язык → длительность. У прошедших фильтры кандидатов проверяется цена, затем ID. Поэтому повторный запрос к одной версии CSV возвращает один и тот же порядок.

Публичные методы API:

- `GET /api/meta` — справочники для формы и границы календаря;
- `POST /api/recommend` — подбор подрядчиков;
- `GET /api/health` — статус сервера и версия датасета.

Полная схема запросов и ответов описана в [контракте API](contractor-picker/docs/api-contract.md).

## Проверка решения

1. Установите зависимости и запустите полный набор проверок:

   ```sh
   cd contractor-picker
   npm run check
   ```

   Команда проверяет синтаксис клиента и сервера, затем запускает 18 тестов: данные CSV, фильтрацию, стабильный порядок, календарь, границы бюджета, язык, длительность, API, тайм-аут и безопасный fallback AI.

2. Запустите приложение (`npm start`) и откройте страницу. Начальный пример «Корпоратив в Алматы» должен показать три карточки: Куррапика (`HK-88430`), Аня Форджер (`HK-29829`) и Сон Гоку (`HK-27222`). Под карточками без ключа должна быть надпись, что объяснения составлены по каталогу.

3. Проверьте демонстрационные пресеты в интерфейсе:

   - «Флорист на свадьбу» — один результат;
   - «Банкетный зал» — два результата;
   - «Нет категории в городе» — отдельный сценарий отсутствующей категории;
   - «Не проходит бюджет» — отдельный сценарий, когда категория есть, но условия слишком строгие.

4. Измените только дату основного примера с 10 на 11 октября 2026 года. Интерфейс должен показать, что ранее подобранные Куррапика и Аня Форджер заняты на новую дату.

5. При необходимости проверьте API напрямую:

   ```sh
   curl http://127.0.0.1:3000/api/health
   ```

   Ожидаемый ответ содержит `status: "ok"`, число профилей и версию датасета.

6. Если настроен `OPENAI_API_KEY`, выполните любой успешный подбор. Под карточками должно появиться сообщение «AI выбрал особенности из описаний». При ошибке API приложение не должно ломать подбор: режим сменится на резервный с объяснениями из каталога.

Подробные ожидаемые результаты для демонстрации находятся в [сценариях](contractor-picker/docs/demo-scenarios.md), а сведения о выполненной проверке — в [verification.md](contractor-picker/docs/verification.md).
