# EvoMind

## Problem
Бизнес часто описывает свою задачу для студенческих команд слишком коротко
и расплывчато ("нужно понять, почему клиенты уходят") — студентам сложно
понять, за что браться, а хорошие задачи теряются среди непонятных.

## Solution
EvoMind — платформа-каталог, которая помогает бизнесу превратить черновое
описание в полноценную, оценённую задачу, и открыто связывает её со
студенческими командами. Ключевая идея: геймификация направлена **на
бизнес**, а не на студентов — чем подробнее описана задача, тем выше её
рейтинг готовности (0-100) и заметнее позиция в общем каталоге.

Сквозной сценарий: черновик → AI задаёт минимум 3 уточняющих вопроса →
редактируемая карточка → расчёт рейтинга по 7 критериям → публикация в
каталог → отклик студенческой команды → бизнес вручную принимает/отклоняет
предложение. Автоматического назначения команд нет.

## Что реализовано
- Конструктор задачи: свободный ввод, AI/fallback-анализ полноты, минимум 3
  уточняющих вопроса, редактируемая карточка, ручное подтверждение перед
  публикацией.
- Карточка задачи со всеми обязательными полями (название, контекст,
  потребность, пользователи, данные, ограничения, ожидаемый результат,
  критерии успеха, контакт, формат взаимодействия).
- Формула рейтинга 0-100 (см. ниже) с расшифровкой по критериям, списком
  недостающих полей и пересчётом после каждого сохранения.
- Открытый каталог: все опубликованные задачи, сортировка по рейтингу,
  фильтры по теме и уровню готовности.
- Отклики команд: неограниченное число предложений (идея, план, срок,
  ссылка на прототип) на задачу.
- Ручной выбор бизнеса: принять/отклонить любое количество предложений;
  автоматического назначения команды нет.
- AI-функция: анализ брифа и генерация вопросов через OpenAI Chat
  Completions с безопасным детерминированным fallback при отсутствии/сбое
  внешнего сервиса.

## Формула рейтинга задачи
Рейтинг 0-100 считается на backend (детерминированно, без ИИ) по 7
критериям — балл начисляется только если соответствующее поле заполнено и
подтверждено:

| Критерий | Вес | Условие начисления |
|---|---|---|
| Контекст и потребность | 20 | заполнены context и need |
| Данные | 20 | заполнено поле data |
| Ожидаемый результат | 15 | заполнено expectedResult |
| Критерии успеха | 15 | заполнено successCriteria |
| Ограничения | 10 | заполнено constraints |
| Пользователи | 10 | заполнено users |
| Связь с бизнесом | 10 | заполнены contact и interactionFormat |

Уровни готовности: 0-39 — `draft` (черновик), 40-69 — `workable` (рабочая),
70-89 — `ready` (готовая), 90-100 — `priority` (приоритетная). Низкий
рейтинг не скрывает задачу и не блокирует отклики — он лишь сигнализирует
студентам, насколько задача готова к работе. Рейтинг автоматически
пересчитывается при каждом сохранении карточки.

## Правила каталога
`GET /api/tasks` — возвращает все опубликованные задачи. Поддерживает:
- `?sort=score_desc|score_asc` — сортировка по рейтингу;
- `?readiness=draft|workable|ready|priority` — фильтр по уровню готовности;
- `?topic=...` — фильтр по теме.

Задачи с низким рейтингом остаются в каталоге (не скрываются), но занимают
позицию согласно рейтингу.

## Architecture
Монорепозиторий (pnpm workspaces):

```
apps/api      — NestJS REST API (бизнес-логика, рейтинг, AI-адаптер)
apps/web      — Next.js фронтенд (весь пользовательский сценарий)
packages/contracts — общие Zod-схемы и TypeScript-типы (единый источник правды
                      для API-контрактов между backend и frontend)
packages/db   — Drizzle ORM схема, миграции, seed-данные, SQLite
```

Frontend обращается к backend через типобезопасный HTTP-клиент, все запросы
и ответы валидируются общими Zod-схемами из `packages/contracts`.

## Technologies
- Backend: NestJS, TypeScript, Zod (валидация), Drizzle ORM, better-sqlite3
- Frontend: Next.js (App Router), React, TypeScript, Tailwind CSS,
  React Hook Form + Zod, TanStack Query
- Тесты: Vitest, Supertest (backend), Vitest + Testing Library (frontend)
- Пакетный менеджер: pnpm workspaces

## Installation
Требуется Node.js 20+ и pnpm.

```bash
pnpm install
pnpm db:migrate
pnpm db:seed
```

## Environment variables
| Переменная | Назначение | Обязательна |
|---|---|---|
| `PORT` | Порт backend API (по умолчанию 3001) | нет |
| `OPENAI_API_KEY` | Ключ OpenAI API для генерации уточняющих вопросов через Chat Completions | нет — без него используется детерминированный fallback |
| `OPENAI_MODEL` | Модель Chat Completions (по умолчанию `gpt-4o-mini`) | нет |
| `API_BASE_URL` | URL backend API для Next.js proxy (frontend) | нет, по умолчанию `http://127.0.0.1:3001` |

**Важно:** AI-функция полностью опциональна для проверки. Без
`OPENAI_API_KEY` система автоматически и безопасно использует
детерминированный fallback — генерирует минимум 3 релевантных уточняющих
вопроса без обращения к внешним сервисам. Эксперты могут проверить полный
сценарий без каких-либо личных аккаунтов или API-ключей участников.

## Run
Backend и frontend запускаются отдельно (два терминала):

```bash
pnpm dev:api   # NestJS API на http://localhost:3001
pnpm dev:web   # Next.js на http://localhost:3000
```

Либо production-сборка:

```bash
pnpm build
pnpm start:api          # backend
pnpm --filter @evomind/web start   # frontend
```

## Demo / Test credentials
Аутентификация не требуется (вне рамок MVP по ТЗ). Используются готовые
синтетические данные из seed: 5 задач, 5 команд (`team-1`...`team-5`), 5
предложений. Все данные полностью синтетические, контакты используют
зарезервированный домен `example.test`.

## How to verify main scenario
1. Открыть http://localhost:3000, ввести короткое описание проблемы на
   экране "Описание" (например "Хотим понять, почему клиенты уходят").
2. Ответить на 3 уточняющих вопроса.
3. Проверить/отредактировать карточку, сохранить — увидеть расчитанный
   рейтинг и его разбивку по критериям.
4. Опубликовать задачу — она появится в общем каталоге, с сортировкой и
   фильтрами по теме/готовности.
5. Открыть задачу из каталога → отправить отклик (поле "Команда":
   используйте `team-1`...`team-5` — демо-ID из seed).
6. Перейти на экран решений бизнеса → принять или отклонить предложение
   вручную.

Тот же сценарий можно проверить напрямую через API — см. примеры запросов
в Swagger UI: `http://localhost:3001/api/docs` (после `pnpm dev:api`).

## Third-party components/models/datasets
- NestJS, Next.js, React, Zod, Drizzle ORM, better-sqlite3, Vitest,
  Supertest, Testing Library, TanStack Query, React Hook Form, Tailwind CSS
  — все open-source, использованы согласно их лицензиям (см. `package.json`
  каждого пакета).
- Внешние датасеты не использованы. Все демонстрационные данные (задачи,
  команды, предложения) — синтетические, созданы специально для этого
  проекта в рамках соревновательной части.
- AI-функция опционально использует OpenAI Chat Completions через
  `OPENAI_API_KEY`; без ключа используется собственный детерминированный
  алгоритм fallback. Ключ участника не требуется для воспроизводимого запуска.

## Deployed version
Развёрнутой публичной версии нет — проект запускается локально по
инструкции выше (`Installation` + `Run`).

## Known limitations
- Регистрация, роли пользователей, реальная аутентификация — вне рамок MVP
  (явно исключены ТЗ).
- AI-функция по умолчанию работает в режиме fallback; интеграция с внешним
  LLM опциональна и не обязательна для прохождения сценария.
- Выбор команды в форме отклика — свободный текст с demo-ID (`team-1`...
  `team-5`), не выпадающий список (нет отдельного `GET /api/teams`
  эндпоинта — не входит в обязательный функционал ТЗ).
- Нет адаптации под мобильные устройства и production-инфраструктуры —
  явно вне рамок пяти часов по ТЗ.
