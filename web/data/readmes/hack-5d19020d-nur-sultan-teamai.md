# WIND AGENT

Agentic AI-система команды **Nur_Sultan_teamAI** для воспроизводимого почасового
прогноза нормализованной активной мощности двух ветровых турбин на 24–48 часов.

Проект решает задачу HackAlemAI: использует исторический SCADA и архивные прогнозы
погоды, доступные на момент выпуска прогноза. Текущие пользователи — команда и жюри.

> Версия является рабочим MVP. Временная зона SCADA и положение метки внутри
> 10-минутного интервала пока не подтверждены организаторами. Поэтому результаты
> помечены `provisional`, а strict-export заблокирован.

## Что реализовано

- импорт двух XLSX и почасовая агрегация только из полных часов с шестью 10-минутными значениями;
- обработка пропусков без замены их на нулевую мощность;
- архивная погода NOAA GFS без регистрации: Range-загрузка только `U/V` ветра на 100 м и температуры на 2 м;
- контроль временной доступности, единиц, высоты полей, контрольных сумм и источников;
- CatBoost и базовые модели, помесячная валидация 2025 года и отдельный holdout января 2026;
- прогнозы 10/50/90-квантилей и ежедневный 48-часовой replay февраля 2026 одной фиксированной моделью;
- LangGraph-супервизор с разрешёнными действиями, лимитом решений и безопасным локальным fallback;
- SQLite-очередь, worker, агентские traces, FastAPI, Streamlit UI и CSV-выгрузки;
- 55 автоматических тестов, Ruff и GitHub Actions.

## Проверенные результаты

Данные результаты получены фактическим запуском root-версии с предоставленными XLSX и
архивом GFS. Это не метрики февраля: фактическая мощность за февраль не предоставлена.

| Проверка | Результат |
|---|---:|
| Выбранная модель | `catboost_small` |
| Помесячная macro RMSE, 2025 | `0.3021` |
| Базовая модель среднего, macro RMSE | `0.3486` |
| Январь 2026, RMSE турбины 1 | `0.2821` |
| Январь 2026, RMSE турбины 2 | `0.2810` |
| Daily origins в replay | `29` |
| Строк 48-часового прогноза | `2 784` |
| Строк, относящихся к февралю | `2 688` |
| Тесты | `55 passed` |

Мощность измеряется в нормированном диапазоне исходных данных `0…1`, не в МВт:
номинальная мощность турбин не предоставлена.

## Как работает

```text
XLSX SCADA ─► проверка и почасовая агрегация ──┐
                                               ├─► CatBoost ─► 48-часовой прогноз ─► API / UI / CSV
архив NOAA GFS ─► GRIB Range ─► погодные признаки ─┘                    │
                                                        LangGraph ─► проверки и trace
```

Для выбранного origin система выбирает более ранний запуск GFS с консервативным
запасом времени публикации, извлекает нужные погодные поля, строит прогноз и сохраняет
неизменяемый артефакт с manifest и SHA-256. LLM может только выбрать одно из действий:
прочитать аудит, карточку модели, запустить численный расчёт либо завершить задачу.
LLM не создаёт и не исправляет численные прогнозы.

сценарий агента продолжают работать.

## Установка и запуск

Требуются Windows 10/11, интернет при первой установке и исходные XLSX в соседней папке
`given` с `turbine 1` и `turbine 2` в именах файлов.

```powershell
git clone https://github.com/BAITC-Hacks/hack-5d19020d-nur-sultan-teamai.git
cd hack-5d19020d-nur-sultan-teamai
.\scripts\setup.ps1
```

Если нужен облачный LLM-диспетчер, создайте локальный `.env`:

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
OPENAI_API_KEY=
NVIDIA_API_KEY=
NVIDIA_BASE_URL=https://integrate.api.nvidia.com/v1
NVIDIA_MODEL=nvidia/nemotron-nano-3-30b-a3b
WIND_LLM_BUDGET_USD=2.00
```

Укажите API-ключ, а не URL для активации кредита. `.env` намеренно исключён из Git.

Полный MVP-конвейер с возможностью продолжения:

```powershell
.\scripts\run.ps1 run-all --profile mvp
```

Он импортирует XLSX, загружает 114 архивных выпусков погоды, проверяет пять моделей,
обучает финальную и строит 29 ежедневных выпусков за тестовый период.

```powershell
.\scripts\start.ps1 -OpenBrowser
```

- UI: <http://127.0.0.1:8501>
- API: <http://127.0.0.1:8000/docs>
- health: <http://127.0.0.1:8000/health>

Остановка: `.\scripts\stop.ps1`.

## Как проверить решение

1. Выполните `setup.ps1` и `run-all --profile mvp`.
2. Запустите `start.ps1 -OpenBrowser`.
3. Во вкладке **«Проверка точности»** изучите сравнение моделей и holdout января 2026.
4. Во вкладке **«Прогноз»** выберите выпуск и турбину, проверьте 48-часовой график,
   источник GFS, cutoff модели, квантили и скачайте CSV.
5. В левой панели выберите дату, локальный диспетчер и нажмите **«Рассчитать 48 часов»**.
6. Во вкладке **«Агент и задачи»** проверьте очередь и trace решений.
7. Запустите локальную проверку:

```powershell
.\scripts\run.ps1 release-check
```

## Данные и интеграции

Исходные XLSX содержат статистическое время, скорость ветра, нормализованную активную
мощность и температуру с марта 2023 по 31 января 2026 года. Координаты из задания:

| Турбина | Широта | Долгота |
|---|---:|---:|
| 1 | 43.645150 | 78.535604 |
| 2 | 43.643198 | 78.538828 |

Открытый источник погоды — `noaa-gfs-bdp-pds`. Для GRIB-объектов сохраняются URL,
byte range, `Last-Modified`, ETag и SHA-256.

## Ограничения

- Для MVP принято `Asia/Almaty`, метка — начало 10-минутного интервала; это ждёт
  подтверждения организаторов.
- Задержка публикации GFS принята равной 8 часам и дополнена серверными метками,
  но не подтверждена организаторами.
- Сетка GFS 1° грубо описывает локальный рельеф; высота ступицы и паспорт турбин неизвестны.
- Фактической мощности за февраль нет, поэтому февральские метрики не вычисляются.
- Январское покрытие интервала 10–90% около 67%, а не номинальные 80%; это явно показано в UI.
- MVP использует выборку origins для обучения и валидации; `weather --profile full` требует больше
  времени и места.
- TimesFM и двухэтапная OOF-коррекция из расширенного плана в MVP не входят.
- Dockerfile есть, но на машине разработки проверен нативный Windows-запуск, Docker daemon был недоступен.

## Безопасность

- Write-endpoints требуют локальный bearer token.
- Файлы сохраняются атомарно с SHA-256, а пути артефактов проверяются.
- LLM видит ограниченный JSON-контекст и не имеет shell-доступа.
- `.env`, кэш погоды, runtime, модели, прогнозы и логи не попадают в Git.
