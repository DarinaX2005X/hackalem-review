# ARYS — прогнозирование выработки ВЭС

Единый проект команды **АРЫС** для HackAlem: Django-портал с нативным HTML/CSS/JavaScript, модуль текущих и архивных прогнозов погоды и обученная ML-модель двух турбин. Основная ветка — **main**. Веса уже находятся в репозитории; для прогнозирования не нужны GPU, NVIDIA key, Brev или обучение.

> Это готовая интегрированная хакатонная сборка, а не подтверждённая промышленная система управления ВЭС. Временная привязка исходных измерений не подтверждена: модель честно возвращает `alignment_confirmed=false`. Для запуска требуется явный `--allow-provisional`. Февральской фактической мощности для оценки качества нет.

## Что умеет проект

- Прогнозировать нормализованную мощность каждой из двух турбин на 48 последовательных часов.
- Показывать все 48 или первые 24 часа, график, погоду, журнал расчёта и историю.
- Работать в live (Django выбирает «сейчас») и историческом replay (заданный момент решения).
- Получать только погодные прогнозы JMA GSM: ветер на 10 м, температура на 2 м; не подменять их наблюдениями/реанализом.
- Сохранять погодные снимки, версию модели, статус согласования и ошибки; экспортировать CSV/JSON.
- Проверять возможности загруженных весов через metadata и кэшировать результат по снимку + турбине + версии модели.
- Обновлять прогноз при изменении погоды или модели. Ошибки никогда не заменяются выдуманной мощностью.

## Быстрый запуск — Windows PowerShell

Все команды выполняйте в корне проекта. Для текущей рабочей копии:

```powershell
Set-Location 'C:\Users\evgen\Desktop\Hackathon\Hackalem AI\Source'
```

На другом компьютере клонируйте основную ветку:

```powershell
git clone --branch main https://github.com/BAITC-Hacks/hack-15d1fa83-team.git
cd hack-15d1fa83-team
```

Требуется **Python 3.12**. Создавайте среду только если её ещё нет:

```powershell
py -3.12 -m venv .venv
```

Не пересоздавайте `.venv`, пока из неё запущены серверы: Windows может блокировать `Scripts/python.exe`. Активация и изменение ExecutionPolicy не нужны.

Установка и подготовка базы:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py seed_demo
```

Несмотря на историческое название, `seed_demo` добавляет только две турбины с координатами и не переключает ML на заглушку, не переписывает существующие координаты.

**Запуск всего проекта одной командой:**

```powershell
.venv/Scripts/python.exe tools/run_project.py --allow-provisional
```

Откройте **http://127.0.0.1:8000**. ML-сервис работает на **http://127.0.0.1:8001**. Выберите турбину, источник Open-Meteo и нажмите «Построить прогноз». Интернет нужен погодному модулю, но не вычислениям ML. Ctrl+C останавливает оба дочерних процесса. Запускатель не останавливает чужие процессы при занятом порте; можно указать `--web-port 8002 --ml-port 8003`.

Флаг `--allow-provisional` разрешает использование конкретного неподтверждённого артефакта, но **не делает alignment_confirmed истинным**. Без флага текущая модель отказывается запускаться.

## Архитектура и ответственность

```text
Браузер (HTML / CSS / JavaScript)
  → Django: live/replay, проверка возможностей ML
    → Weather: JMA GSM / импортированный архив
    → SQLite: неизменяемый погодный снимок
    → POST ML /v1/predict: 48 подготовленных часов
    ← 48 значений мощности + версия + alignment_confirmed
  → проверка ответа, кэш, история, CSV/JSON
  → график 24/48 часов
```

Django владеет получением погоды, выбором прогноза, проверкой исторической доступности, кэшем и хранением. ML загружает включённые веса один раз и выполняет CPU-инференс. Обучение и скачивание погоды внутри `/v1/predict` не выполняются. Legacy-маршрут ML `/power/forecast` сохранён для совместимости, но единый проект его не использует и не настраивает ему погодный URL.

Агент здесь — детерминированная оркестрация с журналом этапов, не LLM. Команда `refresh_forecasts` выполняет один проход обновлений; постоянный планировщик автоматически не устанавливается.

## Турбины и погодные данные

| Турбина | Широта | Долгота |
| --- | ---: | ---: |
| turbine_1 | 43.645150 | 78.535604 |
| turbine_2 | 43.643198 | 78.538828 |

Координаты взяты из задания: [турбина 1](https://maps.app.goo.gl/iN6svMt69D5qRpFU9), [турбина 2](https://maps.app.goo.gl/8UQMwsYavY6nLvFY8). Обе поддерживаются включёнными весами. Они близко расположены: одинаковые значения погодной сетки возможны, но ID турбин и запросы не смешиваются.

Параметры Open-Meteo: `models=jma_gsm`, `hourly=wind_speed_10m,wind_direction_10m,temperature_2m`, `wind_speed_unit=ms`, `temperature_unit=celsius`, `timezone=UTC`. Координаты и настройки сетки соответствуют загрузчику обучения. Ветер 100 м или GFS/ICON нельзя переименовать в эти признаки.

| Режим | Выбор времени и данных |
| --- | --- |
| Live | Django выбирает текущий UTC-момент и следующий целый час; текущий JMA-прогноз |
| Replay / Open-Meteo | Previous Runs, переменные _previous_dayN; сведения о выпуске оценочные |
| Replay / импорт | Последний проверенный выпуск, доступный на as_of и покрывающий 48 часов |
| Demo | Только явно выбранная синтетика; не оценка точности |

Пользователь не вводит время выпуска прогноза. `as_of` в replay — момент принятия решения, а не `issued_at`. Live отклоняет присланные клиентом as_of/start_time.

Previous Runs не раскрывает точное время каждого выпуска/публикации. Запас 8 часов в Django — консервативная эвристика, **не доказательство отсутствия утечки будущего**. Такие результаты помечены `estimated_fixed_lead`. Для строгого конкурсного replay нужны оригинальные выпуски с подтверждённой доступностью. У live выдачи время выпуска неизвестно и остаётся null; время получения не выдаётся за него.

Подробности формата и импорта — [погодный модуль](docs/WEATHER_ARCHIVE.md). Старые 100-метровые снимки сохранены для просмотра, но исключены из новой инференс-цепочки.

## API и ML-контракт

[Дизайн интеграции](docs/ML_INTEGRATION.md) · [ML-контракт](docs/ML_SERVICE_CONTRACT.md) · [общий OpenAPI](docs/openapi.json) · [OpenAPI ML-сервиса](docs/ml-service.openapi.json).

Django на порту 8000:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/v1/health/ | Состояние Django, не гарантия доступности ML |
| GET | /api/v1/ml/metadata/ | Нормализованные возможности реально загруженных весов |
| GET | /api/v1/turbines/ | Турбины и координаты |
| POST / GET | /api/v1/forecasts/ | Создать прогноз / история |
| GET | /api/v1/forecasts/{id}/ | Результат, погода, журнал и ошибки |
| POST | /api/v1/forecasts/{id}/refresh/ | Обновить с проверкой снимка и версии модели |
| GET | /api/v1/forecasts/{id}/ml-input/ | Точное тело запроса к ML |
| GET | /api/v1/forecasts/{id}/export.csv | Все 48 прогнозов, версия и alignment |
| POST | /api/v1/weather/forecast/ | Погода без вызова ML |
| GET | /api/v1/weather/snapshots/{id}/ | Снимок и происхождение |
| POST | /api/v1/weather/import/ | Импорт проверенного архивного выпуска |

Live-запрос к Django:

```json
{"mode":"live","turbine_id":"turbine_2","provider":"open_meteo","weather_model":"jma_gsm"}
```

Replay-запрос:

```json
{"mode":"replay","turbine_id":"turbine_2","provider":"archive","weather_model":"jma_gsm","as_of":"2026-01-31T18:00:00Z","start_time":"2026-02-01T00:00:00Z"}
```

ML на порту 8001: `GET /health`, `GET /v1/metadata`, `POST /v1/predict`, интерактивные `/docs`. В запросе predict — schema_version=windpower.input.v1, turbine_id, weather_model=jma_gsm и ровно 48 records:

| Поле каждой записи | Значение |
| --- | --- |
| target_time | Aware ISO 8601, целые последовательные часы, желательно UTC Z |
| wind_speed_10m_ms | Ветер 10 м, м/с, от 0 до 100 |
| wind_direction_10m_deg | Откуда дует ветер, от севера по часовой стрелке, 0–360° |
| temperature_2m_c | Температура 2 м, °C, от −100 до 70 |

Строки вместо чисел, null, boolean, NaN/Infinity, пропуски/дубли и неизвестные поля запрещены. Давление, возраст и сведения о выпуске хранятся в Django, а не в predict body.

Ответ: windpower.output.v1, turbine_id, weather_model, model_version, alignment_confirmed и 48 совпадающих часов с predicted_normalized_power в [0,1]. Это **доля**, не проценты/МВт. График показывает проценты, JSON/CSV сохраняют долю. Выбор 24 часов не сокращает ML-запрос.

Metadata артефакта использует supported_turbines, supported_weather_models, fields, версии схем, required_records и alignment_confirmed. Django адаптирован к этой фактической структуре; поддержка турбин не угадывается по названию модели.

Ошибки 401 (токен), 422 (контракт/турбина/источник), 502/504 (ответ/доступность/тайм-аут) видны в интерфейсе и истории. При смене артефакта между metadata и predict возвращается 409, чтобы не записать ответ под неверной версией кэша.

## Настройки

`.env.example` — справочник. Python-приложения **не читают .env автоматически**: экспортируйте переменные в терминале и перезапускайте процессы. Compose использует .env только для подстановки своих переменных.

| Переменная | Назначение |
| --- | --- |
| ML_BACKEND | http по умолчанию; demo только явно |
| ML_SERVICE_URL | Доступный адрес POST /v1/predict |
| ML_METADATA_URL | Необязательно; по умолчанию соседний /v1/metadata |
| ML_SERVICE_TOKEN | Одинаковый Bearer-токен у Django и ML; пустой допустим локально |
| MODEL_PATH | Путь к включённому или новому проверенному артефакту |
| ALLOW_PROVISIONAL_MODEL | 1 разрешает текущую неподтверждённую модель; по умолчанию 0 |
| HTTP_TIMEOUT | Тайм-аут обращений Django, 30 секунд |
| API_TOKEN | Отдельный токен входящего Django API, не токен ML |
| DJANGO_DB_PATH | Необязательный путь SQLite; по умолчанию db.sqlite3 в корне |
| DJANGO_DEBUG / DJANGO_SECRET_KEY / DJANGO_ALLOWED_HOSTS | Настройки окружения Django |

Токены ML/API **не являются NVIDIA/Brev API key**. Для двух отдельных терминалов задайте одинаковый ML_SERVICE_TOKEN в обоих. При едином запускателе он наследуется обоими процессами. Секреты не коммитить.

Ссылка на ветку GitHub — исходный код, не работающий API. В разных контейнерах localhost не указывает на соседний сервис.

## Веса, обучение и честные ограничения

Включена модель **mlp-76540e5972a6**, JMA GSM, обе турбины: [веса](models/production/model.json), [manifest и SHA-256](models/production/manifest.json), [метрики](models/production/metrics.json). Сеть MLP 64 → 32 → 1, ReLU/sigmoid, 2 881 параметр; нормализация и веса уже экспортированы для NumPy-инференса. Обучение на CUDA: 28 эпох, выбран checkpoint 18.

Признаки: три погодные величины, производные скорости/направления, циклические UTC-час/день года и ID турбины. Датасет: 96 900 строк, 48 450 пар «турбина–час», два архивных смещения. Обучение до октября 2025; validation октябрь–декабрь; оценка январь 2026.

| Январь 2026 | Обе турбины | Турбина 1 | Турбина 2 |
| --- | ---: | ---: | ---: |
| MAE | 0.178525 | 0.173897 | 0.183153 |
| RMSE | 0.238635 | 0.232772 | 0.244357 |
| Bias | +0.066447 | +0.059136 | +0.073758 |

Это ошибки в долях нормализованной шкалы, не MAPE и не «процент точности». Январь содержит 2 956 примеров с коррелирующими архивными вариантами и просматривался в разработке, поэтому не является полностью слепым внешним тестом. [Сравнения альтернатив](docs/MODEL_COMPARISON.md) сохранены; выбранные веса при объединении не переобучались и не менялись.

Остаются ограничения:

1. Начало/конец десятиминутного интервала измерений не подтверждены; принято начало, часовой пояс Asia/Almaty с историческим изменением смещения. Поэтому alignment_confirmed=false.
2. Fixed-offset архив не доказывает доступность точного выпуска в прошлом.
3. Измерения заканчиваются 31 января: точность 1–28 февраля не заявляется.
4. Для перевода доли в МВт нужны подтверждённые номинальные мощности и соглашение нормализации.
5. SQLite и синхронная оркестрация рассчитаны на хакатонную нагрузку; это не отказоустойчивый промышленный диспетчер.

Создание следующих моделей вынесено в `training_toolkit/run.py`; подробности в [руководстве обучения](docs/TRAINING.md). CPU-инференс не устанавливает PyTorch/CatBoost. Облачные задания, GPU, платежи и переобучение не запускаются автоматически.

## Replay и обновления

```bash
python manage.py import_weather path/to/verified-run.json
python manage.py backtest --provider archive --weather-model jma_gsm --turbine turbine_2 --output output/turbine-2.csv
python manage.py refresh_forecasts --limit 20
```

Backtest рассчитывает отдельные 48-часовые горизонты ежедневно с моментом решения в 18:00 UTC предыдущего дня. Пересекающиеся прогнозы не усредняются. Существующий CSV не перезаписывается, ошибка останавливает прогон с сохранением выполненной части. Для другой турбины используйте другой файл. Синтетический пример импорта намеренно отклоняется, а не выдаётся за реальный архив.

## Docker Compose и production

Для локальной демонстрации двух сервисов с постоянной SQLite-базой:

```powershell
$env:ALLOW_PROVISIONAL_MODEL = '1'
docker compose up --build
```

Портал: http://127.0.0.1:8000. Внутри Compose Django обращается к `http://windpower-ml:8000/v1/predict`. Порты привязаны только к localhost. Остановка: `docker compose down`; не добавляйте `-v`, если нужно сохранить базу. Docker-сборку следует проверить там, где доступен Docker Engine; состояние проверки отражено в VERIFICATION.

Compose использует development runserver и **не предназначен для публичного production**. Для внешнего развёртывания нужны WSGI/ASGI-сервер, HTTPS/reverse proxy, static, PostgreSQL/очередь при нагрузке, секреты и ограничение доступа. При DJANGO_DEBUG=0 установите уникальный DJANGO_SECRET_KEY, API_TOKEN и точные ALLOWED_HOSTS. UI требует входа; создайте пользователя `python manage.py createsuperuser`. Сервисный токен обязателен на открытом ML endpoint.

### Если что-то не запускается

- **ML не готов / alignment**: запустите с явным --allow-provisional после прочтения ограничений; не меняйте флаг внутри весов.
- **ModuleNotFoundError windpower**: выполните pip install -r requirements.txt именно Python из .venv.
- **Порт занят**: завершите свой старый сервер или выберите другие порты; не пересоздавайте работающий venv.
- **401**: одинаковый ML_SERVICE_TOKEN на обоих сервисах; API_TOKEN — отдельная настройка Django.
- **422**: проверьте JMA GSM, 10 м, диапазоны, 48 целых UTC-часов и ID.
- **Погода недоступна**: проверьте сеть и наличие JMA для периода. Автоматического fallback нет.
- **Старые снимки**: они остаются в истории, но для новой модели нужен новый JMA 10 м снимок.
