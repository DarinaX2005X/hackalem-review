# BAITC Task Platform

Платформа помогает бизнесу сформулировать задачу для команды исполнителей, а командам — предложить решение. Бизнес описывает потребность свободным текстом, уточняет детали, проверяет карточку задачи и вручную выбирает предложение.

## Что работает

- AI-анализ черновика и **3–5 уточняющих вопросов** (столько допускают текущий prompt и API-контракт).
- Структурированная Task Card и детерминированный рейтинг готовности 0–100, который рассчитывает backend.
- Явное подтверждение задачи бизнесом; в каталог попадает любая подтверждённая задача независимо от рейтинга и статуса.
- Каталог, команды, предложения и ручное принятие или отклонение предложения.
- Demo-профили бизнеса и фрилансера с редактированием через API.
- Светлая и тёмная темы с сохранением выбора в браузере.

Путь пользователя: **бизнес → черновик → вопросы AI → карточка → рейтинг → подтверждение → каталог → предложение команды → ручное решение бизнеса**.

## Технологии и устройство проекта

Backend — FastAPI, Pydantic, SQLAlchemy и SQLite по умолчанию. `backend/app/ai_service.py` выполняет два этапа AI-обработки; `backend/app/task_rating.py` отдельно считает рейтинг по полям Task. Frontend — React, TypeScript и Vite. Vite проксирует API-запросы на локальный backend.

Основные API: `POST /tasks/draft`, `PATCH /tasks/{task_id}`, `GET /tasks/{task_id}/rating`, `GET /catalog`, `GET /teams`, `POST /proposals`, `GET /tasks/{task_id}/proposals`, `PATCH /proposals/{proposal_id}`, `GET /profiles/{profile_id}`, `POST /profiles`, `PATCH /profiles/{profile_id}`. Документация FastAPI доступна на `http://127.0.0.1:8000/docs` после запуска.

## Локальный запуск

Нужны Python и Node.js с npm. Команды ниже — для PowerShell; запускать из корня репозитория, кроме явно указанного `cd`.

### Backend

```powershell
cd backend
python -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install -r requirements.txt
$env:USE_AI_STUB = "true"
& ".\.venv\Scripts\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Режим `USE_AI_STUB=true` не делает внешних AI-запросов и подходит для проверки интерфейса. Backend создаёт SQLite-файл `backend/tasks.db` и при старте добавляет отсутствующие demo-записи без сброса существующих данных.

Для проверки **реального AI через локальный LM Studio** вместо stub запустите локальный сервер LM Studio, загрузите модель и задайте переменные перед запуском backend:

```powershell
$env:USE_AI_STUB = "false"
$env:OPENAI_BASE_URL = "http://127.0.0.1:1234/v1"
$env:OPENAI_API_KEY = "your-key-or-local-placeholder"
$env:OPENAI_MODEL = "qwen/qwen3-vl-8b"
```

`OPENAI_MODEL` должен совпадать с ID модели, который возвращает локальный `/v1/models`. Реальный ключ OpenAI для LM Studio не нужен. Для обычного OpenAI-compatible клиента можно не задавать `OPENAI_BASE_URL` (или оставить его пустым) и передать свой ключ и модель через переменные окружения. Не сохраняйте ключи в Git.

### Frontend

В другом терминале из корня репозитория:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Откройте адрес, который покажет Vite (обычно `http://127.0.0.1:5173`). Для сборки: `npm.cmd run build`. Vite proxy ожидает backend на `http://127.0.0.1:8000`.

### Тесты backend

```powershell
cd backend
& ".\.venv\Scripts\python.exe" -m pytest tests -q
```

## Повторяемый demo-сценарий

1. Откройте приложение под demo-ролью «Бизнес». В разделе «Создать задачу» опишите потребность.
2. Получите 3–5 вопросов, ответьте и проверьте сформированную карточку. Недостающие данные можно дополнить вручную; рейтинг и статус возвращает backend.
3. Нажмите явное подтверждение. Задача появится в каталоге при любом рейтинге и статусе; неподтверждённые задачи не публикуются.
4. Переключитесь на «Фрилансер», откройте задачу и отправьте предложение от выбранной demo-команды.
5. Переключитесь на «Бизнес», откройте задачу и вручную примите или отклоните отклик. Затем проверьте статус в роли фрилансера.
6. Измените demo-профиль и перезагрузите страницу: сохранённые значения должны остаться. Переключите тему и обновите страницу — выбор темы сохранится.

При включённом stub AI результат служит проверке механики, а не качества модели. Для реального Stage 1/2 используйте локальный LM Studio или иной совместимый endpoint.

## Demo-данные и ограничения

Seed содержит 5 исходных черновиков и 5 подтверждённых Task Card с разными рейтингами, 5 команд с названием, интересами, навыками и технологиями, 5 demo-предложений, 23 demo-профиля бизнеса и 35 demo-профилей фрилансера. Черновики хранятся в `original_draft` соответствующих задач, не как второй Task contract. Все записи добавляются идемпотентно, существующая БД не очищается. Внешних бизнес-интеграций seed не подключает.

Полноценной регистрации, паролей, JWT и разграничения доступа нет: переключение demo-роли хранится в `localStorage`. Предложения выбирает человек; автоматического подбора команды нет. Task пока не содержит связи с BusinessProfile, поэтому компания и отрасль конкретной задачи не атрибутируются автоматически. Демо-профили не представляют реальных пользователей.

**Развёрнутая версия:** Не развёрнуто. MVP запускается локально.
