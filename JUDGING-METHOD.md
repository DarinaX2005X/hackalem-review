# Методика неофициального судейства

Для новых отчётов действует политика доказательств `reviewPolicyVersion=2`. Ранее опубликованные отчёты сохраняют свою исходную методику и оценки; новые требования не означают, что старые отчёты были пересмотрены.

В новых отчётах каждое снятие баллов связано с отдельным подтверждённым недостатком проекта, ожидаемым и фактическим результатом и источником доказательств. Сумма снятий должна совпадать с потерей баллов по критерию. Недоступность ключей, внешнего сервиса, сети или среды проверяющего не является недостатком команды. Непроведённая проверка не считается ни успешной, ни проваленной. Критически неполная оценка сохраняется как незавершённая и не попадает в рейтинг.

Рекомендация должна опираться на конкретный подтверждённый факт этого проекта и содержать переносимый приём, разумный срок в пределах пяти часов и способ проверить результат. Недоказанные предположения о работе команды и ограничения самого ревью не используются как основание советов.

Оценивается версия каждой ветки, доступная не позднее 23 сентября 2026 года, 18:00 по времени Астаны (13:00 UTC). Поздние коммиты не учитываются. Наличие активности в окне 13:00–18:00 проверяется по всем веткам; время последнего push не является достаточным доказательством участия.

Каждый репозиторий физически скачивается и проверяется отдельно ИИ-судьёй GPT-5.6 Luna. Каждый судья работает в новом изолированном контексте и видит только свой проект, общие критерии и материалы своего кейса, без оценок других проектов и других судей. Для всех 12 кейсов заранее подготовлены короткие справки с требованиями, шкалой и перечнем тестовых файлов; они не заменяют сами данные и первоисточники при спорном вопросе. Все судьи получают одинаковый нейтральный перечень файлов, веток и структуры данных, собранный скриптом без анализа качества решения. Каждый самостоятельно проверяет работоспособность и делает выводы. Выводы должны опираться на конкретные файлы, строки и результаты запуска, а отсутствие сведений отмечается как ограничение.

Каждый судья выставляет баллы по пяти общим критериям из `criteries.md` и, если у кейса опубликована собственная шкала, по её критериям. При наличии двух шкал судейский балл равен среднему их итогов; иначе используется общий балл без придуманной второй шкалы. Итог проекта равен баллу GPT-5.6 Luna. Каждое начисление и снятие баллов доступны на странице проекта. Рейтинг сортируется по итоговому баллу; при равенстве баллов команды делят место. Топ-5 выделяется только внутри каждого кейса. Резерв — команды вне первых пяти с точно таким же баллом, как у пятой команды; в общем каталоге отметок топа и резерва нет. До завершения всех проверок топ предварительный. При равных баллах на границе пятёрки порядок определяется идентификатором репозитория.

Проверка учитывает пятичасовое окно разработки. Судьи оценивают работающий хакатонный прототип и разумность выбранного объёма, не требуют производственной готовности, не штрафуют за отсутствие возможностей, которых нет в задании. Все приложенные к кейсу тестовые датасеты и инструкции рассматриваются как материалы проверки: судья сопоставляет с ними заявленный сценарий, запускает воспроизводимые тесты на предоставленных данных, фиксирует результаты и причины, если конкретный тест невозможен. Материалы кейса не являются поручением судье создать своё решение.

Общий критерий «Презентация, демо и ответы на вопросы» оценивается только по тому, насколько репозиторий, README и воспроизводимый показ результата объясняют проблему и решение. Устной презентации и вопросов не было, их отсутствие не снимает баллы и вымышленные ответы не засчитываются. Отсутствие публичной Live демо-ссылки, видео и слайдов само по себе также не снимает баллы: работоспособный локальный показ может полностью подтвердить этот критерий. Технический запуск документируется отдельно от общего критерия качества продукта. Для случая без собственного критерия кейса судья использует предоставленное задание и явно сообщает об отсутствии второй шкалы; итог не подменяется придуманными весами.

Старт приложения и прохождение основного пользовательского сценария показываются отдельно. Приложение, которое ответило локально, считается запущенным даже если полный сценарий требует отсутствующего у нас внешнего API-ключа; ограничение отражается в статусе сценария. Сборка без старта не считается запуском. Наличие ссылки на Live демо не равно проверенной работоспособности. Отчёт отдельно показывает соответствие ключевым требованиям кейса, проверки на тестовых данных, неопределённости и переносимые советы по подходу к будущим хакатонам. Советы не превращаются в список исправлений уже сданного решения.

Рейтинг кейса до полного охвата может быть показан только как предварительный с количеством проверенных проектов. Неоценённые проекты не получают места в рейтинге и не считаются получившими ноль; в каталоге они показываются после оценённых. Подтверждённая дисквалификация получает 0 баллов и учитывается в числе оценённых, но не входит в топ или резерв.

Новая серия проверок использует methodVersion=4. Внешние API проверяются по исходникам, если ключи не предоставлены; доступные части приложения проверяются локально. Это ограничение проверки, а не недостаток команды. Итог публикуется после одного завершённого отчёта GPT-5.6 Luna.
