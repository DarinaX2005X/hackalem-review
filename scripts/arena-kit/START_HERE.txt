HACKALEM — ПАКЕТ ДЛЯ НЕЗАВИСИМОГО ВНЕШНЕГО АГЕНТА

Пакет подходит для любой ИИ-платформы с необходимыми инструментами. Он не запускает модель и не требует входа в наши аккаунты. Его распаковывает и использует агент на СВОЕЙ машине. Ни домашней папки, ни токенов, ни существующих оценок здесь нет.

ЧТО ЗАГРУЖАТЬ
1. Полный ZIP: все 1053 репозитория в списках, все 12 заданий, исходные материалы и данные, критерии, схемы и инструменты.
2. Если размер загрузки или продолжительность сессии ограничены, используй отдельный ZIP одного кейса. Состав и формат те же; inventory/repos.json задаёт точное число ожидаемых отчётов именно этого архива.
3. Вставь текст из PASTE_PROMPT.txt. Не нужно вставлять весь JSON-каталог в чат.

Исходники 1053 репозиториев НЕ включены: агент скачивает их по одному с GitHub. Полный список находится в inventory/repos.json, человекочитаемые списки — repo-lists/. Уже выставленные оценки намеренно не включены, чтобы внешний судья был независимым.

ТРЕБОВАНИЯ К СРЕДЕ
Терминал, Git, Python 3.10+ и доступ к GitHub. Для инструментов валидации: python -m pip install -r requirements.txt.
Для исполнения кода участников нужен Docker либо эквивалентная отдельная песочница, предоставленная средой. Не запускай недоверенный код в общей среде с файлами других проектов, ключами или доступом к управляющему Docker socket. Если подходящей изоляции нет, не выдумывай успешный запуск: явно документируй ограничение и продолжай допустимую статическую проверку.
Доступность этих возможностей и длительность сессии конкретной платформы не гарантируются этим пакетом. Лимиты модели, объём контекста, диск, сеть и время исполнения — разные ограничения. Наличие «безлимита» сообщений не означает, что 1053 проверки завершатся за один запуск.

КОМАНДЫ (в корне распакованного пакета)
python tools/kit.py list
python tools/kit.py list --case 4
python tools/kit.py prepare --repo REPO_ID
python tools/kit.py prompt --repo REPO_ID --model "РЕАЛЬНОЕ ИМЯ МОДЕЛИ"

Последняя команда сохранит отдельный промпт в results/evidence/REPO_ID/judge-prompt.txt. Если модель скрыта, не указывай выдуманное имя: оставь значение Model not disclosed.
Рабочая копия: work/checkouts/REPO_ID/source. Точный SHA, ветки и оговорки времени: results/evidence/REPO_ID/snapshot.json.

Каждую реально выполненную проверку запускай через журналирование, например:
python tools/check.py --output-dir results/evidence/REPO_ID --check-id build-1 --label build -- docker build -t review-XXXXXXXX-build work/checkouts/REPO_ID/source
Для docker run обязательно своё имя с префиксом review-XXXXXXXX, лимиты памяти/CPU и изоляция. Пример выше — шаблон команды, его нужно адаптировать к проекту. runtime.checks.id должен совпасть с --check-id.
stdout/stderr и exit code сохраняются автоматически. На внешнюю ошибку не начисляй штраф. Не редактируй логи, чтобы они совпали с желаемым отчётом.

После отчёта:
python tools/kit.py validate --repo REPO_ID
После каждого завершённого проекта обновляй результат; после партии сохраняй ZIP:
python tools/kit.py finalize --output review-results.zip
Для выбранного кейса из полного пакета:
python tools/kit.py finalize --case 4 --output review-case-04-results.zip

Код выхода 2 у finalize означает ЧАСТИЧНЫЙ результат. ZIP всё равно создан и содержит полный список оставшихся/заблокированных проектов. Это позволяет продолжить работу в другой сессии. Код 0 означает, что каждый проект охвачен валидным готовым отчётом либо подтверждённым решением о дисквалификации. Валидатор проверяет структуру и согласованность, а не доказывает правдивость произвольного текста.

ОЧИСТКА
Не скачивай все репозитории одновременно. После сохранения отчёта, журналов и snapshot.json удаляй только собственные контейнеры, временный checkout и clone соответствующего REPO_ID. Сначала проверь полный путь внутри work/, отсутствие перенаправлений и отсутствие ещё работающих проверок. Не удаляй results/, задания и данные. Не вызывай глобальную очистку среды, где работают другие задачи.

РЕЗУЛЬТАТ
Верни файл review-results.zip. Внутри — manifest.json, SUMMARY.txt, reports/<repoId>.json, decisions/<repoId>.json и evidence/<repoId>/.
Имена файлов — точные ID из inventory/repos.json. Формат — UTF-8 JSON, не Markdown и не скриншоты. Один самостоятельный отчёт на репозиторий.
Этот формат структурно соответствует нашему разбору (methodVersion=4, reviewPolicyVersion=2), но поле model сохраняет реального внешнего судью. Текущий сайт принимает только свой активный набор судей: внешние отчёты нужно импортировать отдельно после проверки происхождения. Не переименовывай внешнюю модель в одного из текущих судей для обхода этого ограничения.

ПРАВИЛА ВРЕМЕНИ
Окно: 23.09.2026, 13:00–18:00 по Астане (UTC+05:00), то есть 08:00–13:00 UTC. Последующие изменения не оцениваются. Более поздний коммит не дисквалифицирует уже сданное вовремя решение.
В inventory/snapshots.json сохранены известные срезы без оценок. В inventory/snapshot-overrides.json — две проверенные поправки HaveFun/A7: GitHub зафиксировал push до дедлайна, хотя локальные часы коммитов с -07:00 неверны. Используй именно разрешённые SHA и доказательства; исходные даты не исправляй задним числом.
Для иных конфликтов часов проверь серверные свидетельства. Не объявляй отсутствие проекта по одному неправильно выбранному README-срезу. Если достоверного разрешения конфликта нет, верни blocked, а не выдуманную дисквалификацию.
inventory/known-decisions.json содержит известные решения с доказательствами. Сбой clone, ошибка имени пути, нехватка диска, отсутствие инструмента или API-ключа не являются дисквалификацией.

ВИЗУАЛЬНАЯ ПРОВЕРКА
Пользователь проверяет браузер сам. Не использовать CUA, Playwright, Selenium, Puppeteer, headless-браузеры, автоматические скриншоты или их аналоги. Проверки — статические, unit/domain и HTTP/API. Отсутствие визуальной проверки не штрафовать.
