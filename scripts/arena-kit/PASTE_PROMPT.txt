Я прикрепляю архив HackAlem review kit. Распакуй его на своей машине и прочитай START_HERE.txt, FORMAT.txt и instructions/review-template.txt.

Задача: независимо проверить ВСЕ репозитории из inventory/repos.json, последовательно по кейсам из inventory/case-order.json. В полном архиве их 1053; в архиве отдельного кейса — только проекты этого кейса. Для каждого скачай точный допустимый срез, изучи реализацию, проверь сборку, запуск и основной сценарий на предоставленных данных там, где это возможно. Задания находятся в cases/, общие критерии — criteries.md, справки — case-briefs/. Не реализуй решение за участника и не меняй исходники, чтобы улучшить оценку.

Сначала проверь доступность терминала, Git, Python, сети и изоляции исполнения. Не обещай полный runtime-разбор, если среда его не позволяет. Выполни python -m pip install -r requirements.txt. Используй tools/kit.py для списка, подготовки рабочего среза, отдельного промпта, проверки JSON и сборки итогового ZIP. Реальные команды проверок записывай через tools/check.py с уникальными --check-id. Не запускать код участников с секретами или привилегиями.

Работай по одному репозиторию, начиная с первого ещё не завершённого. Каждый проект оценивай независимо: не читай чужие оценки, не сравнивай с ранее проверенными и не переносить выводы между командами. Если платформа позволяет отдельный контекст для проекта — используй его. Не создавай дополнительных ИИ-субагентов. При продолжении новой сессии сверяй результаты по manifest.json и валидируй имеющиеся отчёты перед пропуском, чтобы ничего не потерять и не повторить.

Сохраняй подробный русский отчёт в results/reports/<repoId>.json по schemas/report.schema.json. В model укажи фактическое имя модели из интерфейса; если оно скрыто — Model not disclosed. Не угадывай модель и не приписывай себе чужое название. Баллы и причины каждого снятия должны опираться на конкретный код или реально выполненную проверку. Сохраняй полные журналы отдельно, не перегружай публичный текст служебными путями и деталями стенда.

Мы оцениваем пятичасовой прототип. Устной презентации и вопросов не было; этот критерий оценивается по документации и воспроизводимому результату. Отсутствие Live URL, ключей внешних сервисов, нашего доступа, инструментов или времени проверки не является дефектом участника и не уменьшает баллы. Если критических доказательств для оценки недостаточно, запиши blocked-решение без балла по schemas/decision.schema.json. Не ставь автоматически ноль или максимум. Дисквалификация допустима только по подтверждённому отсутствию коммитов в окне либо первому решению после дедлайна, с проверкой всех веток и конфликтов часов. Зарегистрированный состав команды неизвестен: не проверяй и не штрафуй участие каждого члена команды.

Не использовать браузеры, CUA, Playwright, Selenium, Puppeteer, headless-проверки и скриншоты. Статические, unit/domain и HTTP/API проверки разрешены. Непроверенное визуальное поведение обозначай честно.

После каждого проекта проверь JSON и сохрани результат. Не держи отчёты только в сообщениях или памяти. После каждой партии сохраняй промежуточный ZIP и освобождай только свои временные файлы/контейнеры. Если сессия/время/диск заканчиваются, немедленно собери частичный архив командой finalize: она перечислит незавершённые проекты. Не заявляй, что проверены все, если часть только просмотрена в README, пропущена или заблокирована.

Итог: верни скачиваемый review-results.zip, созданный tools/kit.py finalize. В нём должны быть manifest.json, SUMMARY.txt, индивидуальные JSON-отчёты/решения и журналы evidence/. В полном пакете manifest должен учитывать все 1053 ID. В ответе кратко укажи число reviewed, disqualified, blocked, pending, invalid и приложи ZIP. После промежуточного архива продолжай остальные проекты, пока позволяют инструменты и лимиты.
