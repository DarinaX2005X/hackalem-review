# BeeGrowth Agent

## 1. Название проекта

**BeeGrowth Agent · HackAlem AI · Beeline Tariff Marketing Campaigns**

## 2. Краткое описание

BeeGrowth помогает маркетинговому аналитику выбрать аудиторию, целевой тариф и канал коммуникации при ограниченных бюджете и числе контактов. Агент проверяет гипотезы небольшими пилотами и возвращает план тарифных кампаний в официальном формате.

Целевая метрика — дополнительный ARPU по уникальным абонентам минус стоимость всех коммуникаций, включая пилоты. Исходная сумма `predicted_arpu` не является доходом агента.

**Все данные синтетические.** Приведённые числа — локальные результаты на мок-модели; они не описывают реальный бизнес Beeline и не гарантируют прибыль или балл скрытого судейства.

## 3. Что реализовано

- Построение гипотез из профиля аудитории и истории смен тарифов.
- Последовательные пилоты через публичный `env.run_pilot` и обновление оценок по их наблюдениям.
- Выбор финальных кампаний с проверкой фильтров, пересечений аудиторий, бюджета и контактов.
- Генерация официального `submission.csv` штатным скриптом организаторов.
- Русскоязычное демо: аудитория, seed, пилоты, финальный план, прогнозы агента, локальная оценка и журнал объяснений; скачивание JSON и официального CSV.
- Внешняя раздельная диагностика: пилоты, те же пилоты вместе с финалом и разница двух результатов. Оценивание выполняется после завершения `Agent.act()`; результат оценщика не возвращается агенту.

## 4. Как работает решение

1. Среда передаёт профиль аудитории, тарифы, каналы и остатки ресурсов. В предоставленном профиле 23 441 абонент; размеры вычисляются из данных.
2. История смен тарифов другой выборки даёт начальные гипотезы о сочетаниях аудитории, тарифа и канала. Она не считается истинными эффектами текущей аудитории.
3. Агент проводит небольшие пилоты, получает шумные наблюдения и обновляет оценки для проверенных гипотез.
4. По обновлённым оценкам он выбирает непересекающиеся финальные аудитории под оставшиеся ресурсы и возвращает кампании с официальными фильтрами.
5. `make_submission.py` формирует `submission.csv`. В демо пользователь просматривает план и отдельно сравнивает прогноз агента с результатом локального оценщика.

## 5. Технологии

| Технология | Фактическое применение |
|---|---|
| Python | Агент, среда, оценка, генератор CSV и проверки |
| NumPy | Численные оценки, работа с неопределённостью |
| pandas | Чтение CSV, обработка истории, группировка и фильтрация аудитории |
| Streamlit | Локальное демо; `streamlit.testing.v1.AppTest` для его проверок |
| Статистический алгоритм | Исторические начальные оценки, последовательное обновление по пилотам, поправка на риск и жадный выбор кампаний |
| `unittest` | Проверки контракта, поведения, диагностики и демо |

В исполняемом решении нет LLM, внешней AI-модели, внешнего API или обязательного облачного сервиса. API-ключи не нужны. Инструменты разработки не являются зависимостями приложения.

## 6. Архитектура и алгоритм

| Слой | Компоненты | Взаимодействие |
|---|---|---|
| Алгоритм | `agent.py` | `Agent().act(env) -> list[dict]`; использует публичные данные и ответы пилотов |
| Среда | `environment.py`, `mock_environment.py` | Предоставленные организаторами интерфейс, ресурсы, пилоты и фабрика локальной среды |
| Проверка | `scoring_core.py`, `local_eval.py` | Официальная локальная оценка после завершения агента |
| Выходной артефакт | `make_submission.py` | Запускает агента с seed=42 и создаёт официальный CSV |
| Демонстрация | `demo_app.py` | Запускает корневого агента и показывает отдельные прогнозы и оценку |
| Диагностика | `split_eval.py` | Внешнее сравнение пилотов и добавочного вклада финала |

Агент не получает истинные эффекты оценщика или внутренние ID пилотов. Основная версия и демо не зависят от `snapshots` и `experiments`; эти каталоги нужны для исторических сравнений и архивных тестов.

**Гипотезы.** Базовая ячейка — `current_tariff × arpu_segment`. Слишком большие аудитории разбиваются разрешёнными фильтрами по данным и звонкам. Историческое изменение ARPU сглаживается 30 псевдонаблюдениями слабой гипотезы по цене. На ячейку выбираются три целевых тарифа и рассматриваются доступные каналы. Частота состоявшихся переходов не используется как вероятность отклика.

**Обновление.** Начальная вероятность отклика 0.15 — слабое предположение, а не измеренная конверсия. Для каждой гипотезы ведётся отдельная нормальная оценка с начальным std=0.20. Пилот обновляет её с дисперсией наблюдения `0.804² / n`, где `n` — фактически возвращённое число абонентов. Коэффициент канала применяется к начальной гипотезе; наблюдаемый эффект уже включает канал. Критерий `mean - std` — поправка на риск, не гарантия прибыли.

**Поиск.** Сначала исследуются до шести разных ячеек, затем — преимущественно неоднозначные повторы и краткая проверка других каналов лидеров. Начальный пилот рассчитан на 100 человек, повторный размер зависит от неопределённости и ограничивается аудиторией и ресурсами. Внутренний потолок — 16 пилотов, до трёх на гипотезу. Перед вызовом сохраняется резерв на целую финальную кампанию.

**Финал.** Прогноз полного охвата равен `mean × сумма predicted_arpu − стоимость контактов`. Жадный выбор учитывает поправку на риск, бюджет, контакты и пересечение финальных аудиторий. При отсутствии положительной оценки используется допустимый резервный план с возможным убытком. Прогноз не скорректирован на пересечения с пилотами.

Проверяются лимиты: 1–10 финальных кампаний, до 5000 абонентов на кампанию, 15 000 контактов и 100 000 у.е. вместе с пилотами; ограничения среды — до 20 пилотов по 10–200 человек. При математически невыполнимых входах, например пустой аудитории, агент возвращает пустой план с причиной в журнале. На проверенных штатных данных план допустим.

## 7. Установка и запуск

Для закреплённых зависимостей нужен Python ≥ 3.12. Проверенная конфигурация: Python 3.14.6, NumPy 2.5.3, pandas 3.0.6, Streamlit 1.64.0. Откройте PowerShell в корне репозитория:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Если установленный Python доступен как `python`, первая команда может быть `python -m venv .venv`. Активация окружения не требуется. Существующее рабочее `.venv` пересоздавать не нужно. Установка пакетов требует доступа к PyPI; после установки агент, оценщик и демо работают локально. Виртуальное окружение не переносится между машинами и не включается в Git.

Для запуска нужны исходники из таблицы архитектуры, `requirements.txt`, `customer_profile.csv`, `data/change_tariff.csv` и `data/dict_tariff.csv`. Все они входят в комплект. Остальные прямые импорты относятся к стандартной библиотеке Python или модулям репозитория.

### Решение проблем

Если `python` выдаёт `The file cannot be accessed by the system`, причиной может быть недоступный Windows alias. Используйте установленный интерпретатор или launcher `py`. На машине разработки рабочий Python находился в `D:\anaconda\python.exe`; это особенность машины, не зависимость проекта.

При недоступности PyPI нужен сетевой доступ для установки пакетов в локальное `.venv`. Все команды выполняйте из корня репозитория: официальные скрипты используют относительные пути к данным. Установка на другой ОС отдельно не проверялась.

Старый `verify_artifacts.py` читает исходный манифест с абсолютными Windows-путями. Он не входит в обязательный сценарий запуска; переносимая загрузка приложения не требует этого скрипта, архивов или личных путей.

## 10. Ограничения

- Основная стратегия почти перестаёт исследовать новые гипотезы после шестой проверки. Она не проходит экспериментальное требование продолжать поиск после шести отрицательных пилотов; отдельный тест фиксирует это поведение.
- Исторический top-3 может пропустить хороший тариф. История относится к другой выборке; слабая вероятность отклика не измерена по маркетинговым предложениям.
- Каналы оцениваются независимо, финальный выбор жадный. Глобальный оптимум не гарантирован.
- Пилоты дают шумные наблюдения. Прогноз не учитывает пересечения с ними и может существенно расходиться с локальным эффектом; резервный и выбранный финальный план могут быть убыточными.
- Мок-оценка проверяет механику на синтетических эффектах. Изменение seed меняет шум и выборку внутри одной мок-модели, не создавая новую модель поведения. Результат скрытого судейства неизвестен.
- В guide указано 14 824 смены тарифа, фактически в CSV — 14 823. В данных есть пропуски и недопустимые исходные ARPU; обработка отражена в аудите.

## 11. Развёрнутая версия и демонстрация

**Публичного размещения BeeGrowth Agent нет.** Подтверждён только локальный запуск; адрес `127.0.0.1` доступен на компьютере, где запущен сервер, и не является публичной ссылкой.

Запустите из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m streamlit run demo_app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Откройте `http://127.0.0.1:8501` на этом компьютере и нажмите «Запустить агента». Команда отключает сбор статистики использования и автоматическое открытие браузера. Для остановки нажмите `Ctrl+C` в терминале.

Новый запуск использует корневой `agent.py`. Сохранённые результаты связаны с его SHA-256 и сбрасываются при смене версии. Переключение элементов страницы не запускает новые пилоты. Отчёт можно скачать в JSON; отдельная кнопка создаёт официальный CSV через `make_submission.py` и предлагает его скачивание. Добавочный вклад финала показывается из сохранённой раздельной диагностики — отдельной карточки в интерфейсе нет. Порядок двухминутного показа: [DEMO.md](DEMO.md).

Версия для сдачи — BeeGrowth Agent в ветке `main` [репозитория команды](https://github.com/BAITC-Hacks/hack-1c50feda-yassawi). Подготовка публикации сохраняет историю команды и контрольный хеш агента; состав объединённой версии и её проверки описаны в [протоколе публикации](diagnostics/publication/report.md). Данные для формы «Сдать решение» подготовлены в [SUBMISSION.md](SUBMISSION.md); отправка этой формы на платформе — отдельное действие, пока не подтверждённое. Подробности подготовки репозитория: [PACKAGING.md](PACKAGING.md).
