# RADAR — задачи встречают талант

RADAR — образовательная веб-платформа, на которой бизнес размещает реальные задачи, а студенты и молодые специалисты получают практический опыт, усиливают портфолио и видят измеримый рост навыков.

Сервис объединяет две рабочие зоны: кабинет заказчика и кабинет исполнителя. AI-редактор помогает бизнесу превратить черновое описание в понятный бриф, оценивает его полноту и задаёт уточняющие вопросы. Студенты видят наиболее проработанные задачи первыми и заранее понимают, чему научатся во время работы.

## Образовательная цель

Проект показывает полный цикл двустороннего цифрового продукта:

1. ролевой вход в сервис;
2. создание реальной бизнес-задачи;
3. AI-проверка и улучшение брифа;
4. публикация и ранжирование задач;
5. отклик студента;
6. выбор исполнителя заказчиком;
7. оценка и развитие профессиональных навыков.

Главная идея RADAR: молодой специалист учится не на абстрактном упражнении, а во время выполнения настоящей задачи бизнеса с конкретным результатом для портфолио.

## Основной пользовательский сценарий

1. Пользователь открывает страницу входа и выбирает роль **«Заказчик»** или **«Исполнитель»**.
2. Заказчик заполняет название задачи, описание, бюджет, срок, необходимые навыки и образовательный результат.
3. Серверный AI-анализ оценивает полноту брифа по шкале от 0 до 100 и при необходимости задаёт до четырёх наводящих вопросов.
4. После ответов рейтинг пересчитывается, а задача публикуется в рабочем пространстве.
5. В кабинете исполнителя задачи располагаются по убыванию рейтинга брифа.
6. Студент выбирает задачу, отправляет содержательный отклик и отслеживает его статус.
7. Заказчик рассматривает отклики и принимает или отклоняет кандидата.
8. В **AI Skill Gap Radar** студент сравнивает текущие навыки с целевыми и видит приоритеты развития.

## Отличительная функция — AI Skill Gap Radar

RADAR не ограничивается подбором задач. Для каждого навыка сервис показывает:

- текущий уровень;
- целевой уровень;
- величину разрыва;
- приоритет развития;
- связь навыка с реальными задачами платформы.

Так студент получает не общий AI-совет, а понятный маршрут: какой навык развивать следующим и в каком проекте его можно применить.

## Настройка `.env.local`

Откройте файл `.env.local` в корне проекта и заполните нужные значения:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

Назначение переменных:

- `OPENAI_API_KEY` — секретный серверный API-ключ OpenAI;
- `OPENAI_MODEL` — модель для анализа брифа; если строка пустая, используется `gpt-4o-mini`;
- `NEXT_PUBLIC_SUPABASE_URL` — URL проекта Supabase;
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — публичный anon/publishable key Supabase;
- `SUPABASE_SERVICE_ROLE_KEY` — привилегированный серверный ключ Supabase.

Не добавляйте кавычки или пробелы вокруг `=`. После изменения `.env.local` остановите сервер через `Ctrl+C` и снова выполните `npm.cmd run dev`.

`OPENAI_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` являются серверными секретами. Их нельзя использовать в Client Components, добавлять к ним префикс `NEXT_PUBLIC_`, возвращать из API, выводить в HTML или логи.

## Получение OpenAI API key

1. Откройте [OpenAI Platform](https://platform.openai.com/).
2. Создайте или выберите API project.
3. Настройте API-биллинг и лимит расходов.
4. Откройте раздел **API keys** и создайте новый secret key.
5. Сразу вставьте его после `OPENAI_API_KEY=` в локальном `.env.local`.
6. Никому не отправляйте ключ и не добавляйте его в README или Git.

Подписка ChatGPT и биллинг OpenAI API являются отдельными продуктами. Наличие подписки ChatGPT само по себе не предоставляет API-баланс.

### Как работает AI-проверка

Кабинет заказчика отправляет заполненный бриф на серверный Route Handler `/api/brief/analyze`. Сервер обращается к OpenAI и возвращает:

- рейтинг полноты от 0 до 100;
- уровень полноты `low`, `medium` или `high`;
- краткое резюме;
- образовательную ценность задачи;
- до четырёх наводящих вопросов.

Ответы заказчика отправляются на повторный анализ. При публикации рейтинг сохраняется вместе с задачей и используется для сортировки студенческой ленты.

Если ключ отсутствует или OpenAI временно недоступен, приложение автоматически использует локальный детерминированный анализ. В интерфейсе будет указано **«Локальный анализ»** вместо **«GPT-анализ»**.

## Создание и настройка Supabase

Supabase не требуется для локальной демонстрации: сейчас интерфейс хранит сессию, задачи и отклики в `localStorage`. Подготовленная схема нужна для перехода к настоящей многопользовательской базе и авторизации.

Для подключения Supabase:

1. Создайте проект в [Supabase Dashboard](https://supabase.com/dashboard).
2. В окне **Connect** или разделе **Project Settings → API** скопируйте Project URL.
3. Публичный anon/publishable key вставьте в `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. Серверный `service_role` key вставьте в `SUPABASE_SERVICE_ROLE_KEY`.
5. Никогда не используйте `service_role` в браузерном коде.

## Применение миграций базы

1. Откройте созданный проект в Supabase.
2. Перейдите в **SQL Editor**.
3. Откройте локальный файл `supabase/migrations/202609230001_initial_schema.sql`, скопируйте SQL и выполните его.
4. Затем выполните `supabase/migrations/202609230002_marketplace.sql`.
5. Проверьте наличие таблиц `profiles`, `projects`, `applications`, `student_skills`, `assessments` и `skill_gaps`.
6. Убедитесь, что Row Level Security включён и политики созданы.

Supabase CLI для этого не обязателен. Если команда использует CLI, миграции можно применять через `supabase db push`, но проект не требует глобальной установки этого инструмента.

## Загрузка демонстрационных данных

После применения миграций:

1. откройте `supabase/seed.sql`;
2. скопируйте его содержимое в Supabase SQL Editor;
3. выполните запрос;
4. убедитесь, что появилась таблица `demo_skill_gaps` с демонстрационными записями.

Seed-скрипт можно запускать повторно. Он не создаёт поддельные учётные записи Supabase Auth.

## Демонстрация для жюри

Перед показом выполните `npm.cmd run check`, затем `npm.cmd run dev`.

Рекомендуемый сценарий:

1. На странице входа выберите роль заказчика.
2. Создайте задачу с намеренно коротким описанием.
3. Покажите AI-рейтинг и наводящие вопросы.
4. Ответьте на вопросы, пересчитайте рейтинг и опубликуйте задачу.
5. Выйдите и войдите как исполнитель.
6. Покажите сортировку задач, образовательный результат и отправьте отклик.
7. Откройте Skill Gap Radar и измените текущий уровень навыка.
8. Вернитесь в кабинет заказчика и примите кандидата.

Такой показ демонстрирует весь цикл: **бизнес-задача → AI-уточнение → практика студента → измеримый рост навыков**.

2. Перейдите в раздел **Source Control**.
3. Просмотрите каждый изменённый файл.

5. Добавьте нужные файлы в Stage.
6. Введите осмысленное сообщение коммита и нажмите **Commit**.
7. Нажмите **Publish Branch** и выберите видимость репозитория.

## Безопасная работа с токенами

- храните реальные ключи только в `.env.local` или в секретах платформы хостинга;
- никогда не отправляйте ключи в чат, почту, issue, скриншоты или логи;
- не добавляйте `.env.local` в Git даже для приватного репозитория;
- перед коммитом проверяйте `git diff --cached`;
- используйте в браузере только публичные переменные с префиксом `NEXT_PUBLIC_`;
- не передавайте `OPENAI_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` клиентскому коду;
- если секрет был опубликован, немедленно отзовите его и создайте новый — простого удаления строки недостаточно.

## Известные ограничения текущей версии

- форма входа определяет роль, но пока не выполняет серверную проверку пароля;
- сессия, задачи и отклики сохраняются в `localStorage`, поэтому не синхронизируются между браузерами и устройствами;
- SQL-схема Supabase подготовлена, но приложение ещё не использует Supabase Auth и базу во время работы;
- серверный AI-маршрут перед публичным размещением необходимо защитить авторизацией и ограничением частоты запросов;
- рейтинг качества брифа является помощником, а не гарантией успешного выполнения задачи;
- отсутствуют административная панель, уведомления и полноценные end-to-end тесты;
- AI-рекомендации требуют проверки человеком.

Лицензия намеренно не добавлена. Перед публичным распространением владелец проекта должен выбрать её отдельно.
