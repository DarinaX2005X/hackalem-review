# EventMatch — подбор подрядчиков для мероприятий

EventMatch помогает найти подрядчика для мероприятия: пользователь описывает задачу на русском, а помощник уточняет детали и собирает условия поиска. После подтверждения система возвращает до трёх рекомендаций с индивидуальными объяснениями.

**LLM понимает запрос; детерминированный код решает, кого рекомендовать.** Модель ведёт диалог и извлекает структурированные параметры; допуск подрядчиков и порядок результатов определяет Python.

## Что реализовано

- Сбор локации, даты, формата мероприятия, категории и бюджета за несколько сообщений; язык и длительность необязательны.
- Уточнение недостающих и неоднозначных условий, исправления и продолжение поиска в том же разговоре, подтверждение перед подбором.
- Обработка посторонних и небезопасных сообщений без запуска подбора.
- Жёсткие фильтры, детерминированное ранжирование и максимум три карточки с объяснениями на основе фактов каталога.
- Исходы `SUCCESS`, `CATEGORY_NOT_FOUND`, `NO_MATCH` и фактические причины отказа.
- Проверка периода доступности, обозначение синтетических профилей и ориентировочных данных.
- Безопасное отображение ошибок API и детерминированные объяснения при сбое генерации текста.

Текущий интерфейс — только чат, без переключения режимов. Кнопка «Новый поиск» сбрасывает разговор; «О сервисе» и «Как работает подбор» находятся под чатом. Поддерживаются светлая и тёмная темы. Состояние разговора хранится только в сессии.

## Технологии

Python **3.10+**, Streamlit **1.64.0**, OpenAI SDK **2.x** / Responses API, Pydantic **2.x** / Structured Outputs, python-dotenv **1.x**, pytest **8–9**. Детерминированный движок, включая локальный TF-IDF и косинусное сходство, использует стандартную библиотеку Python. База данных не нужна.

## Архитектура

```text
app.py                            # запуск и композиция Streamlit
src/eventmatch/
├── paths.py                      # пути каталога и .env
├── domain/matcher.py              # Request, Contractor, загрузка, фильтры, рейтинг
├── application/
│   ├── conversation.py           # диалог, уточнения, подтверждение, поиск
│   ├── availability.py           # проверка периода доступности
│   └── presentation.py           # резюме, исходы, резервные объяснения
├── ai/
│   ├── models.py                 # независимые от провайдера схемы
│   └── prompts.py                # инструкции извлечения и объяснений
├── infrastructure/openai_client.py # OpenAI SDK, настройки, обработка ошибок
└── ui/
    ├── chat.py                   # текущий разговорный интерфейс
    ├── components.py             # карточки, оформление, справка
    ├── state.py                  # интеграция состояния со Streamlit
    ├── manual.py                 # сохранённый модуль; не подключён к app.py
    └── demo_scenarios.py          # фиксированные запросы для CLI-проверки
scripts/
├── demo.py                       # проверка четырёх сценариев без API
└── eval_live.py                  # отдельные проверки с настоящим API
tests/
├── support.py
├── unit/
└── integration/
data/hackathon dataset anonymized .csv
.streamlit/config.toml
.env.example
pyproject.toml
requirements.txt
```

Направление зависимостей: **UI → application → domain**. Application использует схемы `ai` и внедрённый backend, но не импортирует Streamlit или OpenAI SDK. `infrastructure` реализует вызовы провайдера по AI-контракту; `app.py` связывает компоненты. Domain не зависит от UI, API или инфраструктуры.

```text
Пользователь → Streamlit UI → conversation
                                 ├── OpenAI → структурированные изменения запроса
                                 └── валидация → подтверждение → matcher
                                                                  ↓
                                             Top-3 / CATEGORY_NOT_FOUND / NO_MATCH
                                                                  ↓
                                    объяснения по фактам → карточки Streamlit
```

LLM не решает, соответствует ли подрядчик локации, категории, дате, бюджету, формату или длительности, и не определяет порядок выдачи. Текст объяснений хранится отдельно от результатов matcher; при ошибке генерации используются детерминированные формулировки.

## Данные

В репозиторий включён `data/hackathon dataset anonymized .csv` — **66 профилей: 53 исходных и 13 синтетических**. Основные поля: `city`, `categories`, `price_from_kzt`, `event_formats`, `languages`, `max_hours`, `busy_dates`, `description`. Поля-списки в CSV разделяются символом `|`.

- Локации каталога: **Алматы, Астана, Зарубежье**. Автоматического отнесения произвольного зарубежного города к «Зарубежью» нет.
- Доступность известна только за **23.09.2026–31.12.2026 включительно**. Внутри периода отсутствие даты в `busy_dates` означает доступность по каталогу, без внешнего подтверждения. Чат отклоняет даты вне периода и просит уточнение; проверка находится вне matcher.
- `max_hours=null` у 9 профилей означает неприменимое ограничение длительности: такой профиль не исключается по часам. Это не обещание неограниченного времени работы.
- `synthetic` отмечается как «Синтетический профиль». У 18 профилей `price_imputed` показывается как «Ориентировочная цена», у 8 `city_imputed` — «Локация указана ориентировочно».

**`price_from_kzt` — начальная цена «от», не окончательная смета и не почасовой тариф.** Условие `price_from_kzt <= budget` означает только: «Начальная цена подрядчика не превышает указанный бюджет». Итоговая стоимость может быть выше: готовых пакетов и окончательных предложений в каталоге нет. Цена не умножается на длительность.

## Внешние сервисы

OpenAI Responses API используется для понимания сообщений, структурированного извлечения условий, уточнений и формулировки объяснений по выбранным профилям. Модель по умолчанию в коде и шаблоне настроек — **`gpt-4.1-mini`**. Проверка доступности, обязательных условий и ранжирование выполняются локально, без модели.

Другие внешние сервисы для работы приложения не требуются. Разговор требует сетевого доступа к OpenAI и доступного API-баланса; локальный CLI-подбор работает без ключа.

## Алгоритм подбора

### 1. Жёсткая фильтрация

Совпадение локации и категории после нормализации регистра, пробелов и `ё/е`; отсутствие даты в `busy_dates`; поддержка формата; начальная цена не выше бюджета; достаточная длительность, если часы заданы и ограничение применимо. Язык — мягкое предпочтение, а не причина исключения.

### 2. Детерминированное ранжирование

| Составляющая | Баллы | Правило |
| --- | ---: | --- |
| Формат | 20 | Все прошедшие фильтр поддерживают формат |
| Язык | 0 или 30 | 30 при совпадении или отсутствии предпочтения |
| Бюджет | 0–15 | `15 × max(0, 1 − abs(цена / бюджет − 0.75) / 0.75)` |
| Длительность | 10–15 | `10 + 5 × min((max_hours − часы) / часы, 1)`; без запроса или ограничения — 15 |
| Описание | 0–20 | Косинусное сходство локальных TF-IDF-векторов запроса и описания × 20 |

Бюджетная составляющая предпочитает начальную цену около 75% бюджета. TF-IDF использует весь каталог; текст запроса составляется из категории, формата и языка. **Оценка показывает соответствие запросу, а не качество подрядчика.**

Одинаковый структурированный запрос и каталог дают одинаковый порядок. Сортировка — по полной оценке по убыванию, при равенстве — по строковому ID по возрастанию; округление выполняется после сортировки. Выбираются максимум три профиля.

## Основные исходы

| Исход | Значение |
| --- | --- |
| `SUCCESS` | Найден хотя бы один подходящий профиль; показано до трёх |
| `CATEGORY_NOT_FOUND` | В выбранной локации нет нужной категории |
| `NO_MATCH` | Категория есть, но никто не прошёл все условия |

При `NO_MATCH` показаны фактические причины: занятость, неподходящий формат, превышение начальной цены или недостаточная длительность. Причины считаются независимо: один профиль может нарушить несколько условий. Ограничения автоматически не ослабляются.

## Проверка основного сценария

1. Настройте ключ и запустите `streamlit run app.py`.
2. Откройте URL из терминала. Если разговор уже начат, нажмите «Новый поиск».
3. Отправьте: **«Нужен ведущий на свадьбу в Алматы 2 ноября 2026 года, бюджет до 2 000 000 ₸, на 6 часов, на русском.»**
4. Помощник должен собрать условия и показать «Проверьте условия». Проверьте локацию, дату, категорию, формат, бюджет, часы и язык. Если модель просит уточнение, ответьте теми же значениями.
5. Нажмите **«Найти подрядчиков»**. До подтверждения новый подбор не выполняется.
6. Ожидается `SUCCESS`: **4 подходящих профиля, Top-3 в порядке Сон Гоку → Хаул → Эмилия**, с ценами «от» и индивидуальными объяснениями. Число прошедших фильтры проверяется также CLI; обычный UI показывает три карточки.

Можно продолжить: «нет, бюджет миллион» — бюджет обновится перед новым подтверждением. На «а подешевле?» помощник уточнит предел бюджета, если конкретная сумма не названа. Формулировки модели могут различаться; проверяйте условия подтверждения.

### Проверка редкой категории

Начните новый поиск и отправьте: **«Нужен флорист на свадьбу в Алматы 14 ноября 2026 года, бюджет до 400 000 ₸, на русском.»** Длительность не задавайте. Подтвердите: ожидается одна карточка **Тихиро Огино** с пометкой «Синтетический профиль».

### Проверка пустого результата

Новый поиск: **«Нужен ведущий на свадьбу в Алматы 14 ноября 2026 года, бюджет до 1 000 ₸, на 6 часов, на русском.»** После подтверждения ожидается `NO_MATCH`: 5 профилей заняты, 4 не поддерживают формат, у 10 начальная цена выше бюджета. Карточек нет; суммы причин могут пересекаться.

Для `CATEGORY_NOT_FOUND`: **«Нужен декоратор на свадьбу в Астане 14 ноября 2026 года, бюджет до 400 000 ₸.»** После подтверждения — сообщение об отсутствии категории в локации.

### Проверка детерминизма

Повторите основной сценарий через «Новый поиск», сохранив все семь параметров. Порядок карточек должен совпасть. Текст LLM-объяснений может отличаться; состав и порядок рекомендаций — нет.

### Проверка календаря

После основного сценария отправьте **«Изменим дату на 14 ноября 2026 года»**, сохранив остальные условия, и подтвердите. Для 02.11.2026 подходят 4 профиля: Top-3 Сон Гоку, Хаул, Эмилия. Для 14.11.2026 подходят 3: **Сон Гоку, Эмилия, Мицури Канроджи**. Меняется только дата; различие вызвано календарями занятости.

Затем запросите **«Изменим дату на 1 января 2027 года»**: помощник должен сообщить о периоде 23.09.2026–31.12.2026 и попросить дату внутри него, не выполняя новый поиск.

## Режим проверки для жюри

Откройте http://localhost:8501/?review=1 (при другом порте замените его). Основной продукт остаётся тем же чатом. Дополнительно доступны свёрнутые разделы **«Условия этого поиска»** и **«Подробности подбора»** с составляющими оценки карточек.

Режим не меняет фильтры, оценки или порядок и не является механизмом авторизации. Ручного поиска и переключателя сценариев в текущем интерфейсе нет, в том числе в review-режиме. Подготовленные сценарии запускаются через `python scripts/demo.py`.

## Известные ограничения

- Подбор ограничен комплектным каталогом; доступность известна только за 23.09.2026–31.12.2026.
- Начальная цена не гарантирует окончательную стоимость. Бронирование, оплата и связь с подрядчиком не реализованы.
- TF-IDF измеряет лексическое сходство, не понимает все синонимы и не оценивает качество услуги.
- Разговор зависит от сети и OpenAI API. При ошибке понимания запроса новый поиск не выполняется: отображается сообщение, после восстановления доступа запрос можно повторить. Если сбоит только генерация объяснений, выбранные карточки сохраняются с детерминированным текстом.
- Резервной ручной формы в текущем UI нет. Без API можно проверить matcher через `scripts/demo.py`, но не провести полноценный новый разговор.
- LLM может ошибиться при извлечении или формулировке; проверка условий пользователем обязательна, а проверка текста моделью не даёт абсолютной гарантии. Модель не может изменить факты выбора и ранжирование.
- Зависимости, кроме Streamlit, заданы диапазонами, поэтому установка не фиксирует все транзитивные версии.
