# EduVibe

MVP для кейса AI Sana «Рейтинг качества бизнес-задач и открытый выбор команд». Платформа помогает бизнесу превратить краткую потребность в понятное студентам ТЗ. AI задаёт уточняющие вопросы, бизнес редактирует и подтверждает карточку, а система рассчитывает её готовность и публикует в каталоге. Команды отправляют приватные предложения; бизнес вручную выбирает одну, несколько или ни одной команды.

## Запуск

Нужны Git, Docker с Docker Compose и свободные порты 5173 и 8000.

```bash
git clone git@github.com:BAITC-Hacks/hack-31e4e4c0-eduvibe.git
cd hack-31e4e4c0-eduvibe
cp .env.example .env
# Укажите OPENAI_API_KEY в .env для вопросов от модели.
docker compose up --build -d
docker compose ps
curl http://localhost:5173/api/v1/health
```

- Приложение: http://localhost:5173
- API и схемы запросов: http://localhost:8000/docs
- Исправный health: `{"status":"ok","database":"ok"}`.

Миграции и синтетические данные загружаются автоматически. Без ключа OpenAI вопросы работают в явно обозначенном резервном режиме.

Для доступа из той же локальной сети откройте `http://IP_КОМПЬЮТЕРА:5173`. Запросы к `/api/v1` проходят через frontend к backend; менять адрес API не нужно.

Обновление: `git pull`, затем `docker compose up --build -d`. Данные MySQL сохраняются в volume. Остановка — `docker compose down`; добавление `-v` удалит данные.

### Конфигурация

Все переменные и значения по умолчанию — в [.env.example](.env.example). Для обычного запуска достаточно добавить ключ; остальные настройки можно оставить без изменений.

| Настройка | Назначение |
|---|---|
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Ключ backend и модель; по умолчанию `gpt-4.1-mini` |
| `OPENAI_TIMEOUT_SECONDS`, `AI_FALLBACK_ENABLED` | Таймаут 20 секунд; резервный режим включён |
| `MYSQL_*` | База, пользователь и пароли MySQL |
| `DATABASE_URL` | Подключение для локального backend; Compose формирует его из `MYSQL_*` |
| `VITE_API_URL` | `/api/v1`; изменение требует пересборки frontend |
| `CORS_ORIGINS` | Разрешённые origin для прямого доступа браузера к API |

## Сценарий демонстрации

Пример для выступления до пяти минут:

1. Войти как бизнес, создать тему «Доставка выпечки» и описание: «В пекарне диспетчер вручную распределяет доставки между курьерами. Адреса ведём в таблице, заказы опаздывают». Показать исходный рейтинг.
2. Получить минимум три AI-вопроса. Ответить известными фактами: пользователи — диспетчер и пять курьеров; данные — 20 тестовых заказов; результат — веб-прототип распределения; критерий — распределить 20 заказов за пять минут.
3. Перенести ответы в карточку, отредактировать, сохранить. Показать рост рейтинга, расшифровку и оставшиеся пробелы. Подтвердить и опубликовать.
4. В отдельной вкладке войти как студенческая команда, найти кейс в каталоге и отправить идею решения, план, срок и ссылку, например `https://example.com/prototype`.
5. Вернуться к бизнесу, обновить отклики и вручную выбрать или отклонить предложение. У студента обновить статусы.
6. Для выбранной команды подтвердить выполненный этап и начислить баллы.

Бизнес может редактировать и удалять свои кейсы. До нового подтверждения студенты видят прежнюю опубликованную версию; после удаления у авторов сохраняется история откликов. Другие команды не видят чужие предложения.

## Архитектура

```text
Браузер → frontend: React + TypeScript + Vite (:5173)
                    ↓ /api/v1
          backend: FastAPI, Python 3.11 (:8000) → OpenAI API
                    ↓ SQLAlchemy 2 / Alembic
          db: MySQL 8.4
```

Три сервиса запускаются через [docker-compose.yml](docker-compose.yml).

- [backend/app](backend/app) — API, схемы валидации, модели, бизнес-логика и AI-сервис.
- [backend/migrations](backend/migrations) — миграции БД.
- [frontend/src](frontend/src) — интерфейс и API-клиент.
- [backend/tests](backend/tests) — автоматические проверки.

API использует префикс `/api/v1` и JSON. После демонстрационного входа запросы передают `Authorization: Bearer <token>`. Доступ к изменениям кейса и списку его откликов проверяется на сервере по роли и владельцу. Полные схемы доступны в Swagger.

## Рейтинг и каталог

Рейтинг — сумма весов непустых полей, от 0 до 100. Формула находится в [rating.py](backend/app/services/rating.py).

| Поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт бизнеса | 5 |
| Формат взаимодействия | 5 |

Название и тема в баллы не входят. До подтверждения показан предварительный расчёт; каталог использует последнюю подтверждённую карточку. Неизвестные сведения остаются пустыми. Интерфейс показывает баллы по каждому полю, недостающую информацию и рекомендации.

Уровни: **0–39 — черновик**, **40–69 — рабочая**, **70–89 — готовая**, **90–100 — приоритетная**.

Все опубликованные кейсы доступны всем командам, включая задачи с низким рейтингом. Каталог сортируется по убыванию баллов, при равенстве — по ID; доступны фильтры по теме и уровню готовности. Число откликов не ограничено. Автоматического назначения команды нет.

Рейтинг оценивает заполненность, а не достоверность текста. Командные баллы считаются отдельно: бизнес однократно назначает 1–100 баллов за подтверждённый этап выбранного отклика.

## Демонстрационные данные

Синтетический набор находится в [seed.py](backend/app/seed.py). На чистой базе создаются:

| Набор | Количество | Состав |
|---|---:|---|
| Черновики | 5 | Описание, отрасль/тема, сведения разной полноты |
| Опубликованные карточки | 5 | Все поля карточки, рейтинг, разные уровни готовности |
| Команды | 5 | Название, интересы, навыки, технологии |
| Отклики | 5 | Команда, идея, план, срок, ссылка |

Пустое значение поля означает неизвестные сведения. Повторный запуск не дублирует набор. Ссылки на доменах `example.com` и `example.test` — демонстрационные.

## AI

Промпт, вход и обработка ответа находятся в [clarifications.py](backend/app/services/ai/clarifications.py). Модель получает `topic`, `initial_description` и `current_card` — значения всех полей текущей карточки — и возвращает JSON:

```json
{"questions":[
  {"id":"q1","field":"users","text":"Кто будет пользоваться результатом?"},
  {"id":"q2","field":"data_materials","text":"Какие данные доступны команде?"},
  {"id":"q3","field":"success_criteria","text":"Как вы проверите успешность решения?"}
]}
```

Сервер проверяет 3–7 вопросов, допустимые и неповторяющиеся поля, непустой текст. Если пробелов меньше трёх, AI уточняет детали заполненных полей. Модель не заполняет карточку выдуманными фактами: ответы вводит пользователь, затем редактирует и подтверждает их.

`ai_mode: live` означает ответ модели; `fallback` — шаблонные вопросы при отсутствии ключа, таймауте, ошибке API или некорректном ответе. При `AI_FALLBACK_ENABLED=false` API возвращает контролируемую ошибку 502/503/504. Режим относится к последней генерации вопросов; для новой попытки обновите их в интерфейсе.

Описание и карточка передаются OpenAI. Используйте синтетические данные без секретов: автоматического удаления чувствительных сведений из текста нет.

## Проверки

Из корня репозитория:

```bash
# Все backend-тесты; образ пересобирается из текущего кода.
docker compose run --build --rm --no-deps --entrypoint python backend -m pytest -q

# Только минимальные наборы данных и повторный запуск seed.
docker compose run --build --rm --no-deps --entrypoint python backend -m pytest tests/test_seed.py -v

# Сборка frontend, локально нужен Node.js 22.
npm --prefix frontend ci
npm --prefix frontend run build

# Диагностика работающего приложения.
curl http://localhost:5173/api/v1/health
docker compose logs --tail=100 backend
```

Тесты используют отдельную SQLite в памяти и не подключаются к рабочей MySQL. Проверяются сессии, роли и владение, приватность откликов, жизненный цикл кейса, рейтинг и каталог, решения бизнеса, однократное начисление баллов, валидация, ошибки AI и наборы данных. Ответы OpenAI в тестах имитируются; реальный вызов проверяется через интерфейс по `ai_mode: live`.

Для ручной проверки пройдите сценарий выше, затем отправьте отклики от двух команд, выберите несколько или отклоните все. Проверьте, что студент видит только свои отклики, неподтверждённые правки публикации скрыты, а удалённый кейс исчезает из каталога. Без ключа должен явно отображаться резервный режим.

## Ограничения и материалы

Вход демонстрационный: любой посетитель может выбрать любой тестовый профиль. Проверка прав работает в пределах выбранной сессии; полноценной проверки личности нет. Регистрация, чат, загрузка файлов и полный проектный трекер в MVP не входят. Vite preview используется для демонстрации, промышленный деплой не заявляется.

Команда: **Dexarim** — backend, AI, БД, Docker и интеграция; **B_l_a_c_kS_u_n** — frontend и интерфейс.

Кейс предоставлен AI Sana; данные созданы командой. До старта были подготовлены контекстные шаблоны документации. При разработке использовался OpenAI Codex. Сторонние библиотеки и версии зафиксированы в [requirements.txt](backend/requirements.txt) и [package-lock.json](frontend/package-lock.json); инфраструктура использует Docker и MySQL.
