# TRACE — Граф денег

**Локальное рабочее место AML-аналитика: от переводов к объяснимой структуре финансовых связей.**

Проект для финансового кейса Freedom на хакатоне HackAlem AI. Помогает аналитику, который начинает проверку с известных клиентов, увидеть связи, найти узлы сбора и распределения средств, выделить сообщества и выбрать порядок ручной проверки.

Результаты — структурные гипотезы по наблюдаемой сети, а не доказательства преступления или виновности. Основной сценарий работает локально, без API-ключей и внешних сервисов.

> Этот README описывает ветку `main` репозитория [BAITC-Hacks/hack-7a019b2e-llm-solo](https://github.com/BAITC-Hacks/hack-7a019b2e-llm-solo), проверенную на коммите `e747bc26663dcbc67ca5c12c3f9727db5e4b293d`. Команды ниже относятся к её структуре (`moneygraph/`, `frontend/`, корневой `requirements.txt`).

## Что реализовано

- Чтение трёх Parquet-файлов с проверкой схем, идентификаторов, денежных сумм, дат и согласованности рёбер с транзакциями.
- Направленный взвешенный граф со всеми входными узлами, включая изолированные.
- Шесть ролей клиентов, числовые основания и оценка соответствия эвристике.
- Кластеризация Louvain: состав сообществ, число seed, внутренний оборот, ведущие узлы и гипотеза.
- Рейтинг до 50 клиентов для ручной проверки с объяснением вклада признаков.
- Сопоставление входящих и исходящих объёмов в окне 0–2 календарных дней без повторного использования одного входящего объёма.
- Интерфейс TRACE: поиск точного `gid`, граф, фильтры, окраска по роли или кластеру, карточки клиентов, просмотр операций и CSV-экспорт.
- Экспериментальная панель чата «След» с привязкой к выбранному клиенту; сервер модели пока не подключён, без него ответы не генерируются.
- Самодостаточный HTML-отчёт и полный JSON-снимок для интерфейса.
- Запись параметров, версий библиотек, времени расчёта и хешей исходников; отдельная проверка согласованности выгрузок.

## Как работает решение

1. Аналитик помещает выданные Parquet-файлы в `data/`.
2. Запускает расчёт. Пайплайн валидирует данные, строит граф, вычисляет признаки, роли, кластеры и рейтинг.
3. Получает CSV, JSON и HTML в `artifacts/`.
4. Открывает TRACE через локальный сервер либо импортирует JSON в интерфейс без сервера.
5. Выбирает клиента из рейтинга или ищет его по `gid`, изучает переводы, основания роли и ограничения наблюдения.
6. Использует результат для дальнейшей ручной проверки. Роли и оценки не пересчитываются в браузере.

### Роли и объяснимость

Порядок правил: `coordinator` → `distributor` → `consolidator` → `transit` → `terminal` → `peripheral`. Первая подходящая роль становится основной; интерфейс может показать все сработавшие правила.

Здесь входящая/исходящая степень означает число уникальных контрагентов без самопереводов; seed — исходный клиент обхода.

| Роль | Основное правило по умолчанию |
| --- | --- |
| `coordinator` | Суммарная степень ≥4, положительная betweenness не ниже 90-го перцентиля активных узлов, связи с ≥2 другими кластерами и достижимость от ≥3 seed |
| `distributor` | ≥5 получателей; исходящая степень ≥2 × max(входящая степень, 1) |
| `consolidator` | ≥5 плательщиков и достижимость от ≥2 seed |
| `transit` | Не seed и не обрезанный узел; положительный вход, входящие и исходящие связи; отношение выхода к входу 0,8–1,2; сопоставленный объём покрывает ≥80% входа и выхода в окне 0–2 дня |
| `terminal` | Не seed и не обрезанный узел; положительный наблюдаемый вход и отсутствие исходящих контрагентов |
| `peripheral` | Остальные случаи, включая недостаточность наблюдений |

`role_score` — сила соответствия правилу: базовые 0,60 и по 0,10 за три дополнительных признака в `classify`; максимум 0,90. Для обрезанных узлов максимум 0,60; для `peripheral` — 0,20. Это не вероятность виновности.

Приоритет рассчитывается по формуле `0,30 × seed_reach + 0,25 × flow + 0,20 × bridge + 0,15 × fan + 0,10 × role_support`: нормированный охват seed, перцентиль оборота, посредничества, числа контрагентов и поддержка роли. Для `peripheral` поддержка роли равна нулю; для изолятов весь приоритет равен нулю. Равенства разрешаются сортировкой по `gid` по возрастанию.

Louvain работает на неориентированной проекции; внутренний оборот считается по направленным рёбрам исходного графа. Параметры и случайный seed задаются в `config/roles.json`. Betweenness по умолчанию точная; предусмотрен режим `approximate`.

## Установка и запуск

### 1. Получить код `main`

Для новой копии проекта:

```powershell
git clone --branch main https://github.com/BAITC-Hacks/hack-7a019b2e-llm-solo.git trace-main
cd trace-main
```

Если уже работаете в другой ветке, используйте отдельную папку: эти команды не требуют переключать существующую рабочую копию.

### 2. Создать окружение и установить зависимости

Windows PowerShell, Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Linux/macOS с установленным Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Интернет нужен для получения кода и зависимостей. Далее основной сценарий работает локально. Используйте Python из созданного окружения при каждом запуске.

### 3. Добавить данные

Распакуйте данные организаторов, сохранив структуру:

```text
data/
  nodes.parquet
  edges.parquet
  transactions.parquet
```

Датасет не поставляется в Git. CSV не являются поддерживаемым входом текущего `moneygraph/io.py`.

### 4. Рассчитать результаты

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m moneygraph --data data --out artifacts
```

Для Linux/macOS замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

### 5. Открыть интерфейс

Расчёт и запуск локального сервера:

```powershell
.\.venv\Scripts\python.exe -m moneygraph --data data --out artifacts --serve
```

Откройте **http://127.0.0.1:8765/frontend/** для TRACE или **http://127.0.0.1:8765/report.html** для самостоятельного отчёта. Остановка сервера — `Ctrl+C`; другой порт задаётся, например, `--port 8766`.

Без сервера можно открыть `artifacts/report.html`. Для TRACE откройте `artifacts/frontend/index.html`, нажмите «Импорт данных» и выберите `artifacts/graph.json`.

При установленном Node.js 22+ доступны `npm run analyze` и `npm start`; они вызывают Python через вспомогательный скрипт. Для статического интерфейса `npm install` и сборка не нужны.

Готовые файлы фронтенда уже включены в репозиторий. После изменения `frontend/app-source.js`, `agent*.js`, `styles-source.css` или `agent.css` пересоберите их командой `node frontend/build.cjs`. Проверка актуальности сборки: `node frontend/build.cjs --check`.

## Как проверить решение

### Автоматическая проверка

После расчёта выполните:

```powershell
.\.venv\Scripts\python.exe -m moneygraph.verify --data data --out artifacts
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Успешная проверка экспортов возвращает JSON с `status: "ok"` и код завершения 0. Проверяются схемы, покрытие узлов, операции и повторы, суммы, кластеры, рейтинг, согласованность CSV/JSON, хеши и ограничение времени 300 секунд. При использовании собственного конфига передайте одинаковый `--config` в расчёт и проверку.

Для тестов JavaScript при установленном Node.js:

```powershell
node --test frontend/*.test.cjs
npm test
```

Наличие тестов в репозитории не означает, что они уже прошли в вашем окружении. Время текущего расчёта смотрите в `artifacts/run.json`; фиксированный результат и скорость на любом ноутбуке не гарантируются.

### Сценарий демо на пять минут

1. **30 секунд:** объясните задачу и неполноту наблюдаемой сети.
2. **60 секунд:** покажите запуск и три CSV, затем результат `moneygraph.verify`.
3. **90 секунд:** откройте TRACE, выберите клиента из рейтинга и покажите основания роли и вклады в приоритет.
4. **60 секунд:** найдите второго клиента по полному `gid`, покажите его связи, кластер и операции.
5. **60 секунд:** покажите клиента с границей `depth=4` или изолят; объясните, почему отсутствие связей не доказывает конечное получение средств.

Проверьте точный поиск длинного ID, направление стрелок, фильтры и совпадение карточки с экспортом. Для проверки без сети используйте локальный импорт `graph.json`.

## Данные и интеграции

Источник — обезличенная выгрузка организаторов:

| Файл | Обязательные поля |
| --- | --- |
| `nodes.parquet` | `gid`, `depth`, `is_seed` |
| `edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `transactions.parquet` | `src`, `dst`, `date`, `sum_kzt` |

Денежные суммы валидируются с точностью до сотых KZT. `edges` уже агрегирует транзакции: два источника не складываются как независимый оборот. Совпадающие строки операций сохраняются, поскольку без банковского ID нельзя объявить их дублями.

Идентификаторы сохраняются точными целыми в Python и строками на границе JSON/браузера. При импорте CSV в Excel выбирайте текстовый тип для ID. HTML и JSON содержат данные сети: режим доступа должен соответствовать режиму исходного датасета.

### API-ключ и отдельный LLM-пример

Основной графовый анализ и TRACE не требуют ключа. Клиентская панель «След» уже есть в интерфейсе, но для реальных ответов ей нужен серверный `POST /api/ai/analyze`, описанный в `AI_CONTRACT.md`. В текущем Python-сервере этот endpoint не реализован; панель сообщает «ИИ пока не подключён». Создание `.env` само по себе чат не подключит.

В `src/` сохранён отдельный консольный пример: классификация текста как приветствия, запроса помощи или неизвестного сообщения. Он не определяет финансовые роли и не подключён как чат сайта.

Пример без API:

```powershell
npm run llm:demo -- --offline "Привет"
```

Для необязательного вызова API в копии `main` создайте `.env` из шаблона:

```powershell
Copy-Item .env.example .env
```

Заполните `OPENAI_API_KEY` в `.env`. Модель по умолчанию в коде — `gpt-4.1-mini`, параметр `OPENAI_MODEL`; наличие доступа к модели определяется вашим API-проектом. Запуск `npm run llm:demo -- "Привет"` может отправить текст во внешний API и расходовать средства аккаунта. Ключ не помещается в HTML или Git; `.env` исключён из отслеживания. Подключение к реальному API при подготовке README не проверялось.

## Ограничения

- Сеть ограничена исходящей выгрузкой до четырёх переходов; в описании набора указан один месяц и переводы от 5 000 KZT внутри банка. Полная финансовая активность клиентов неизвестна.
- У seed вход неполон; отсутствие выхода на границе `depth=4` не означает конечного получателя. Разность входа и выхода не является балансом счёта.
- Даты не задают порядок внутри дня. Временное сопоставление — допущение; в признаках предусмотрен и вариант без внутридневных совпадений.
- Достижимость от seed не доказывает движение конкретных денег или руководство группой. Кластер — структурная гипотеза.
- Нет ground truth ролей, обучения модели и подтверждённой accuracy. Пороги и оценки требуют предметной проверки.
- Онлайн-поток транзакций и внешнее обогащение не реализованы. У чата сайта готова клиентская часть, но отсутствует серверная интеграция модели. Отдельной БД нет: расчёт ведётся в памяти, результат хранится в файлах.
- NetworkX, точная центральность и полный JSON рассчитаны на локальный MVP. Миллион узлов потребует компактного графового хранения, приближённых вычислений, пакетной обработки и выдачи подграфов. Такая масштабная реализация не заявляется.
- После сбоя старые результаты нельзя считать свежими: повторите расчёт и проверку выгрузок.
