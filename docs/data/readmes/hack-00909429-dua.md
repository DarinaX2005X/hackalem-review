# BIRGE

**BIRGE** — Telegram-платформа, где бизнес публикует реальные задачи, а выпускники находят проекты, в которых могут применить свои способности.

Проект создан для образовательного кейса AI Sana. MVP реализует полный обязательный сценарий: черновик бизнес-задачи → AI-уточнение → карточка и рейтинг → публикация → выбор задачи выпускником → предложение → ручное решение бизнеса.

## Что умеет бот

### Для бизнеса

- принимает первоначальное описание задачи;
- определяет недостающие сведения и формирует уточняющие вопросы;
- собирает редактируемую карточку задачи;
- рассчитывает прозрачный рейтинг готовности от 0 до 100;
- публикует задачу в общем каталоге;
- показывает отклики и AI-совместимость кандидатов;
- позволяет вручную принять или отклонить предложение.

### Для выпускника

- создаёт профиль навыков, интересов и проектов;
- показывает задачи в формате свайпов «Хочу участвовать / Пропустить»;
- объясняет AI-совместимость с каждой задачей;
- принимает идею решения, план и ссылку на прототип;
- показывает статус отправленных предложений.

## Быстрый запуск

Требуется только Python 3.10 или новее. Сторонние библиотеки не нужны.

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте название и username бота.
3. Скопируйте полученный токен.
4. Скопируйте файл `.env.example` и назовите копию `.env`.
5. Вставьте токен в `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
DATA_FILE=data/birge.json
```

6. На Windows дважды нажмите `start.bat`.

Или запустите вручную:

```bash
python bot.py
```

После появления сообщения `BIRGE started` откройте созданного бота и отправьте `/start`.

> Не публикуйте файл `.env` и токен бота в GitHub. Файл уже добавлен в `.gitignore`.

## Команды

- `/start` — главное меню;
- `/menu` — вернуться в меню;
- `/demo` — добавить демонстрационные задачи, если каталог пуст;
- `/help` — краткая помощь.

При первом запуске две демонстрационные задачи добавляются автоматически.

## Формула рейтинга задачи

Рейтинг соответствует условиям кейса:

| Раздел | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Всего** | **100** |

Уровни готовности:

- 0–39 — черновик;
- 40–69 — рабочая;
- 70–89 — готовая;
- 90–100 — приоритетная.

Рейтинг считается обычным кодом, поэтому он воспроизводим и не зависит от случайного ответа языковой модели.

## AI-функции

MVP использует объяснимый локальный AI-модуль, который работает без API-ключей:

1. Анализирует первоначальное описание и выбирает актуальные уточняющие вопросы.
2. Проверяет полноту карточки и объясняет, какие разделы нужно улучшить.
3. Сравнивает требования задачи с навыками, проектами, интересами и доступностью выпускника.
4. Показывает процент совместимости и понятные причины результата.

Алгоритм не учитывает престиж школы, пол, национальность, здоровье и другие чувствительные признаки. AI ничего не решает за человека: выпускник самостоятельно выбирает задачу, а бизнес вручную принимает предложение.

### Формат AI-анализа совместимости

Вход:

```json
{
  "task": {"skills": "Python, Telegram Bot API", "title": "Бот для школьников"},
  "profile": {"skills": "Python", "projects": "Два Telegram-бота", "interests": "образование"}
}
```

Выход:

```json
{
  "score": 82,
  "reasons": [
    "Совпадающие навыки: Python",
    "Задача соответствует интересам кандидата",
    "Есть описанный проектный опыт"
  ]
}
```

## Архитектура

```text
Telegram
   ↓
bot.py — диалоги, роли и пользовательский сценарий
   ├── ai_service.py — вопросы, рейтинг и совместимость
   ├── storage.py — локальное JSON-хранилище
   ├── telegram_api.py — работа с Telegram Bot API
   └── config.py — настройки из .env
```

Данные находятся в `data/birge.json` и создаются автоматически. Для чистой демонстрации остановите бота, удалите этот файл и запустите бота снова.

## Что сознательно не входит в MVP

- настоящая авторизация;
- сложная ролевая модель;
- чат и видеозвонки;
- платёжная система;
- файловое хранилище;
- автоматический выбор кандидата;
- производственная база данных.

Эти функции не включены в MVP намеренно. Цель хакатона — не создать полноценную коммерческую платформу за несколько часов, а показать работающий основной сценарий: от создания качественной бизнес-задачи до отклика выпускника и ручного выбора кандидата.

В следующей версии проекта можно добавить авторизацию, постоянную базу данных, чат между сторонами, календарь встреч и расширенные права доступа. Однако для текущего этапа важнее доказать, что BIRGE действительно помогает выпускникам и бизнесу находить друг друга и начинать совместную работу.
