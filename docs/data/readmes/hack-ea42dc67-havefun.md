# Агент управления тарифными маркетинговыми кампаниями

Трек 04 «Телекоммуникации», кейс Beeline, HackAlem AI.

Агент помогает аналитику выбрать сегменты абонентов, целевые тарифы и каналы связи.
Он проверяет гипотезы пилотами и возвращает план маркетинговых кампаний.
Цель — прирост ARPU за вычетом стоимости коммуникаций, включая пилоты.

**Все данные и эффекты синтетические.** Это учебная симуляция из пакета организатора,
а не реальные показатели Beeline и не доказанная прибыль на реальных клиентах.

## Установка и основной сценарий

Нужен Python 3.11+; приведённые результаты получены на Python 3.12.
Выполняйте команды из корня репозитория: пути к данным относительные.

~~~bash
python -m venv .venv
~~~

Активация в PowerShell:

~~~powershell
.\.venv\Scripts\Activate.ps1
~~~

Активация в macOS/Linux:

~~~bash
source .venv/bin/activate
~~~

Установка зависимостей и проверка:

~~~bash
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 5
python selfcheck.py
python scenarios.py
python make_submission.py
~~~

Основной прогон должен завершиться со статусом PASS и сформировать корректные кампании.
Точный состав плана зависит от наблюдений пилотов; не фиксируйте его для всех seed.
make_submission.py создаёт submission.csv в формате организатора.
requirements.txt содержит pandas, numpy, FastAPI, uvicorn и SDK openai.
Версии заданы нижними границами, поэтому будущая установка может разрешить другие версии.

## Веб-интерфейс

~~~bash
python app.py
~~~

Откройте http://localhost:8000; проверка сервиса — http://localhost:8000/api/health.
Интерфейс показывает разведку, финальные кампании, общий результат и журнал гипотез.
Доступны сравнение стратегий, устойчивость, сценарии других эффектов и изменение бюджета.
Кнопка экспорта плана создаёт CSV для аналитика; это отдельный формат, не submission.csv.

## Docker

В репозитории есть Dockerfile, docker-entrypoint.sh и docker-compose.yml.
Первая сборка требует доступ к реестру образов и Python-пакетам.

~~~bash
docker build -t hackalem-agent .
docker run --rm hackalem-agent
docker run --rm hackalem-agent selfcheck
docker run --rm hackalem-agent stability
docker run --rm hackalem-agent scenarios
docker run --rm hackalem-agent submission
docker run --rm -p 127.0.0.1:8000:8000 hackalem-agent web
~~~

Вариант через Compose:

~~~bash
docker compose up --build
docker compose run --rm agent selfcheck
docker compose run --rm agent scenarios
docker compose down
~~~

Compose публикует порт 8000 согласно docker-compose.yml; интерфейс — http://localhost:8000.
Образ содержит HEALTHCHECK для HTTP-сервиса. CLI-команды завершаются после выполнения.
Режим submission записывает CSV внутри контейнера; с --rm файл исчезает вместе с ним.
Для файла на компьютере используйте python make_submission.py либо скопируйте его
из сохранённого контейнера командой docker cp.
Базовый тег python:3.12-slim изменяемый; побитовая повторяемость будущих сборок не гарантируется.

## Как принимает решение агент

1. Строит исторический приор по сегменту и целевому тарифу из data/change_tariff.csv.
2. Ранжирует гипотезы и резервирует часть пилотов для сегментов с отрицательным приором.
3. Проводит push-пилоты: они бесплатны по стоимости связи, но расходуют контакты
   и могут уменьшить ARPU. Основной размер — 200, разведочный — 100; малые группы меньше.
4. Отбирает гипотезы по оценке эффекта с поправкой на шум.
5. Сохраняет измеренные пары «исходный тариф → цель» при объединении кампаний;
   для непилотированных групп использует ограниченный перенос внутри сегмента.
6. Разбивает аудиторию под лимиты и распределяет каналы по ожидаемой экономике.
7. Возвращает план; языковая модель при наличии доступа только формулирует объяснение.

Лимиты кейса: до 10 финальных кампаний, до 5 000 контактов на кампанию,
до 15 000 контактов и 100 000 у.е. суммарно с пилотами; до 20 пилотов.
Параметры шума, размеров пилотов и порога уверенности заданы в agent.py.
Они не все выводятся из данных. История задаёт предположения, пилоты дают шумные наблюдения.

## Другие модели эффектов

CLI-команда python scenarios.py проверяет **7 миров**, каждый на seed 0 и 1.
Веб-кнопка и /api/scenarios сейчас показывают **6 базовых миров**;
регрессионный мир с разными целями у источников проверяется дополнительно через CLI.

| Мир | Средний чистый результат |
|---|---:|
| Как в истории | 3 168 084 |
| Прибылен HIGH | 4 874 524 |
| Прибылен только MID | 2 489 736 |
| Всё слабо растёт | 154 509 |

| Нулевая модель | −1 812 |

Все семь прошли критерии скрипта. Для миров «около нуля» разрешён убыток до

В нулевой модели seed 0 дал 0, seed 1 — −3 624: даже там возможны расходы на кампании.
Два seed и ограниченный набор миров не доказывают устойчивость на любых скрытых эффектах.

## Ограничения и границы проверки

- Агент может вернуть пустой план, если не нашёл приемлемых гипотез. Это **не гарантирует**
  отсутствие прибыльных возможностей. Требование кейса «1–10 кампаний» формально
  не выполнено при нуле; допустимость такого отказа должен подтвердить организатор.
- Пустой финальный план не отменяет эффекты уже проведённых пилотов.
- Перенос на непилотированные группы остаётся предположением и может ошибаться.
- Оценка выгоды каналов приближённая: насыщение конверсии не определяется полностью
  одним push-пилотом. Запас для дорогих каналов не гарантирует оптимальный выбор.
- selfcheck.py проверяет перечисленные в нём случаи, включая искусственный отказ
  функции объяснения. Он не заменяет проверку всех данных, лимитов и конкурентных запросов.
- Проверенные отрицательные seed в run, ask и CSV возвращают HTTP 422.
  Последовательная проверка настроек не обнаружила прежнего влияния на stability;
  это не исчерпывающая гарантия для всех параллельных запросов.

## Языковая модель и окружение

OPENAI_API_KEY необязателен. Без него объяснение собирается локально по шаблону,
а вопросы к модели возвращают сообщение о недоступности. Числовой план не зависит от LLM.
При наличии ключа выполняются внешние API-вызовы; возможны расходы по условиям провайдера.
OPENAI_MODEL задаёт желаемую модель; без него explain.py пытается выбрать доступную.
Compose передаёт OPENAI_API_KEY, но OPENAI_MODEL при необходимости нужно добавить отдельно.
Для Docker можно передать переменные через -e OPENAI_API_KEY -e OPENAI_MODEL,
предварительно установив их в окружении. Не сохраняйте ключи в исходниках.
TRANSFER_TO_SEGMENT=0 отключает перенос на непилотированные группы; стандартный режим — 1.
