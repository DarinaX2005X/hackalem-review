# Smart Contractor

Умный подбор event-подрядчиков в Казахстане: до трёх подходящих профилей, проверка свободной даты, бюджета, формата, языка и длительности. Интерфейс со стеклянными панелями и вечерним mesh-градиентом подключён к работающему Python API.

**В комплекте:** все 66 профилей исходного датасета, 13 синтетических профилей с отметками, пять сценариев для демонстрации, матрица доступности на семь дней, слепой режим, аудит отсева, OpenAI-интеграция с резервными объяснениями, Docker и Render Blueprint.

## Быстро загрузить на GitHub

1. Распакуйте архив. Откройте папку, в которой лежат **`main.py`, `requirements.txt`, `Dockerfile` и этот README**.
2. Создайте на GitHub пустой репозиторий, например `smart-contractor`. Для команд ниже не добавляйте README на сайте при создании — он уже есть в проекте.
3. В терминале в папке проекта выполните:

```bash
git init -b main
git add .
git commit -m "Initial Smart Contractor application"
git remote add origin https://github.com/YOUR_USERNAME/smart-contractor.git
git push -u origin main
```

Замените `YOUR_USERNAME` своим логином. Если Git просит представиться, задайте свои `user.name` и `user.email`. Авторизацию GitHub выполните обычным способом через Git Credential Manager, GitHub CLI или SSH; токены в файлы проекта добавлять не нужно.

Без терминала можно воспользоваться GitHub Desktop: **Add local repository → create a repository → Commit → Publish repository**. Публикуйте папку проекта целиком, чтобы сохранить скрытые `.github`, `.gitignore`, `.env.example` и `.gitattributes`.

**GitHub хранит исходники. Для работающего сайта нужен Python/Docker-хостинг.** GitHub Pages сам по себе не запускает FastAPI и OpenAI-интеграцию. Порядок публикации сайта: [DEPLOY.md](DEPLOY.md).

## Запуск на компьютере

Нужен Python 3.11+; локальная проверка выполнена на Python 3.12.

**Windows PowerShell:**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe main.py
```

**macOS / Linux:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python main.py
```

Откройте **http://127.0.0.1:8000**. Документация API: **http://127.0.0.1:8000/docs**. Есть также скрипты `start.ps1` и `start.sh`, которые создают окружение, устанавливают зависимости и запускают приложение.

Для объяснений через OpenAI добавьте **свой новый ключ** в `OPENAI_API_KEY` файла `.env`. Ключей в поставке нет. Без ключа приложение полностью выполняет подбор и составляет объяснения из каталога; интерфейс явно сообщает о резервном режиме. Из браузера ключ никогда не отправляется — API вызывается сервером.

## Что делает приложение

- Строго исключает подрядчиков, занятых на выбранную дату.
- Применяет фильтры: категория → город → дата → бюджет → формат → язык → длительность.
- Сортирует оставшихся по `(budget - price_from_kzt, id)` по возрастанию; берёт первые три. Это близость цены к бюджету, а не оценка качества подрядчика.
- Различает три результата: `SUCCESS`, `CITY_CATEGORY_NOT_FOUND`, `NO_CANDIDATES_MATCHED`.
- При выдаче из 1–2 карточек возвращает `partial_reason`; при пустой выдаче показывает объяснение и числа отсева.
- После поиска показывает семь дат: выбранную по центру и по три дня с каждой стороны. Числа учитывают все условия и весь каталог до ограничения выдачи тремя карточками. Клик по дате меняет поле формы и повторяет поиск.
- Сохраняет исходные `synthetic`, `city_imputed`, `price_imputed` и отображает соответствующие отметки.
- Скрывает имена в слепом режиме, сохраняя порядок и факты. ID остаётся для проверки воспроизводимости.

Счётчики воронки последовательные: один профиль исключается один раз, на первом непройденном условии. Первый этап показывает количество **в выбранной категории**, а не весь каталог. Окно календаря: **23.09.2026 — 31.12.2026**. `max_hours = null` означает отсутствие лимита часов присутствия. Цена указана «от» и не является подтверждённой сметой.

В матрице красный цвет означает «Нет мест», жёлтый — 1–2 варианта, зелёный — 3 и более. Она остаётся доступна при пустой выдаче. За пределами календаря кнопки отключены и подписаны «Вне календаря»; такие дни не считаются свободными. На узком экране ряд прокручивается горизонтально и центрируется на выбранной дате. При ручном изменении условий матрица скрывается до следующего поиска, чтобы не показывать устаревшие числа.

`renderDateMatrix(selectedDate, formParams, dataset)` в `static/app.js` создаёт кнопки и обработчики, а `getDateMatrix` в `static/date-matrix.js` применяет те же семь фильтров, что и сервер. Браузер получает только поля для фильтрации в `availability_profiles` из `/api/meta`, без имён и описаний. Подсчёт соседних дат не вызывает LLM и не выполняет семь сетевых запросов. Совпадение клиентских счётчиков с `matcher.py` проверяется автоматическими тестами.

## Как используются LLM

Фильтрация и ранжирование реализованы обычным кодом. LLM не меняет состав подборки. Для максимум трёх отобранных профилей `AsyncOpenAI` конкурентно выбирает 1–2 конкретных фрагмента описания, возвращая индексы через Structured Outputs. Сервер проверяет индексы, берёт только существующие фрагменты и добавляет точные условия заказа. Свободные, непроверенные утверждения модели в карточки не попадают.

Модель по умолчанию — `gpt-4o-mini`, `temperature=0`. Дедлайн одного вызова, включая очередь, — 6,5 секунды; повторные попытки SDK отключены. При ошибке или таймауте используется резервное объяснение. Текст профиля считается данными, а не инструкциями. Дообучение не используется.

Порядок карточек детерминирован. Успешные объяснения кэшируются в памяти до 1024 записей и совпадают при переключении слепого режима. После перезапуска выбранные моделью цитаты могут отличаться: `temperature=0` не является абсолютной гарантией идентичного текста.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | пусто | Серверный ключ OpenAI; пустое значение включает резервный режим |
| `OPENAI_MODEL` | `gpt-4o-mini` | Модель с Chat Completions и Structured Outputs |
| `LLM_TIMEOUT_SECONDS` | `6.5` | Дедлайн, ограничен максимумом 8 секунд |
| `RATE_LIMIT_PER_MINUTE` | `30` | Лимит запросов подбора с одного IP |
| `PORT` | `8000` | Порт приложения |
| `DATASET_PATH` | JSONL в корне | Альтернативный путь к данным |
| `DOMAIN` | пусто | Домен Caddy при деплое через Compose |

Кэш, лимит запросов и очередь находятся в памяти одного процесса. Для нескольких экземпляров сервиса нужно общее хранилище лимитов и кэша. Бюджет расходов OpenAI задаётся отдельно в аккаунте провайдера. Холодный запуск хостинга и задержка сети не входят в целевое время обработки работающего API до 10 секунд.

## API и сценарии для защиты

- `GET /healthz`: состояние приложения и число профилей. `llm_configured` подтверждает только наличие ключа в настройках.
- `GET /api/meta`: значения списков, окно календаря, готовые сценарии, `availability_profiles` для матрицы дат (категории, город, цена, форматы, языки, лимит часов и занятые даты).
- `POST /api/match`: подбор. `explanation_source: openai` в карточке подтверждает фактический ответ модели.

```json
{
  "city": "Алматы",
  "category": "Ведущий",
  "event_date": "2026-09-23",
  "event_format": "корпоратив",
  "budget": 1500000,
  "duration_hours": null,
  "language": null,
  "blind_mode": false
}
```

Над результатами доступны пять реальных запросов из `demo-queries.json`: ведущие осенью (прошли 4, выбраны 3), другая дата, флористы с неполной выдачей, все 7 банкетных залов Алматы заняты 6 декабря, отсутствие категории в Астане. Кнопки работают через API; вымышленной карточки из макета в приложении нет.

## Проверки и GitHub Actions

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Для проверки матрицы нужен также Node.js в `PATH` (в CI используется Node 22); можно указать путь переменной `NODE_BINARY`. Без Node тесты клиентского подсчёта будут пропущены, а тесты сервера выполнятся. Для самого сайта Node не нужен.

В `.github/workflows/ci.yml` настроены тесты Python 3.11/3.12, сверка JavaScript-матрицы с серверным подбором, проверка синтаксиса JavaScript, сборка Docker-образа и запуск контейнера с `PORT=8080`. Workflow запускается на push и pull request, не использует API-ключи и ничего не публикует на хостинг. Посмотреть результат после загрузки можно во вкладке **Actions**.

Подробности фактически выполненной локальной проверки: [TEST_REPORT.md](TEST_REPORT.md).
