# Shabyt — умный подбор подрядчиков для мероприятий

> Решение для кейса HackAlem AI **«Умный подбор подрядчиков (#79-lite)»**.

Shabyt помогает заказчику выбрать подходящего event-подрядчика из каталога по конкретным условиям мероприятия: городу, дате, типу события, категории и бюджету. Дополнительно можно учитывать язык и длительность работы.

Сервис не просто выводит каталог, а **фильтрует кандидатов, детерминированно ранжирует подходящих и возвращает до 3 карточек с конкретным объяснением**, почему каждый подрядчик попал в выдачу.

---

## 1. Проблема и решение

При выборе подрядчиков на мероприятие пользователь сталкивается с большим количеством профилей, но не всегда понимает:

- кто работает в нужном городе;
- кто свободен на конкретную дату;
- кто подходит по бюджету;
- кто берёт нужный формат мероприятия;
- кто работает на нужном языке и нужное количество часов;
- почему один подходящий профиль оказался выше другого.

**Shabyt** автоматизирует этот отбор. Пользователь задаёт параметры мероприятия, после чего система возвращает до трёх наиболее подходящих профилей и объясняет подбор на основе данных каталога.

---

## 2. Что реализовано

### Поиск и фильтрация

Система учитывает:

- город;
- дату мероприятия;
- тип мероприятия;
- категорию подрядчика;
- бюджет;
- язык — опционально;
- длительность — опционально.

Подрядчик исключается из выдачи, если он:

- занят на выбранную дату;
- не укладывается в бюджет;
- не работает с выбранным форматом мероприятия;
- не поддерживает выбранный язык;
- не подходит по длительности работы.

### Детерминированное ранжирование

После фильтрации кандидаты ранжируются без ML/LLM по воспроизводимым правилам:

1. чем ближе цена `price_from_kzt` к бюджету снизу, тем выше кандидат;
2. добавляется бонус за совпадение языка;
3. добавляется бонус за релевантные слова запроса в описании профиля;
4. при одинаковом score используется сортировка по `id`.

Одинаковый запрос даёт одинаковый порядок карточек.

### Три отдельных результата поиска

API и интерфейс различают состояния:

- `ok` — найдены подходящие подрядчики;
- `no_category` — в выбранном городе нет такой категории;
- `no_match` — категория есть, но никто не прошёл условия запроса.

Если подходят только один или два профиля, сервис возвращает их и объясняет, почему результатов меньше трёх.

### Объяснения рекомендаций

Для каждой карточки формируется краткое фактическое объяснение.

Есть два режима:

- **локальный детерминированный режим** — работает без API-ключа;
- **OpenAI** — если задан `OPENAI_API_KEY`, backend запрашивает LLM-объяснение. Модель по умолчанию задаётся как `gpt-4o-mini` через `OPENAI_EXPLAIN_MODEL`.

Если внешний LLM недоступен или не отвечает вовремя, сервис возвращает локальное объяснение вместо падения запроса.

### Frontend

Реализован адаптивный интерфейс на React + TypeScript:

- форма поиска;
- выбор всех категорий каталога;
- демо-пресеты для быстрой проверки;
- состояния загрузки и ошибок;
- отдельные состояния пустой выдачи;
- карточки результатов;
- сортировка результатов в интерфейсе;
- раскрытие деталей профиля;
- светлая/тёмная тема;
- мобильная адаптация.

### Проверки

В репозитории есть:

- `backend/tests/` — pytest-тесты backend;
- Vitest-тесты frontend;
- `frontend/scripts/check-core.cjs` — дополнительные проверки логики;
- `CHECK_WINDOWS.bat` — единая команда проверки перед демонстрацией;
- `QA_REPORT.md` и папка `qa/` с сохранёнными результатами предыдущих прогонов.

Сохранённый в репозитории backend-лог содержит `90 passed`, а core-проверки frontend — `203 core checks passed`. Перед финальной сдачей рекомендуется повторить `CHECK_WINDOWS.bat` на машине команды.

## 3. Как работает решение

Основной пользовательский сценарий:

1. Пользователь открывает Shabyt.
2. Выбирает город, дату, тип мероприятия, категорию и бюджет.
3. При необходимости указывает язык и длительность.
4. Frontend отправляет `POST /api/search`.
5. Backend загружает каталог подрядчиков.
6. `filters.py` отбрасывает неподходящие профили.
7. `ranking.py` детерминированно ранжирует прошедших фильтр кандидатов.
8. Для топ-3 формируется объяснение через OpenAI либо локальный fallback.
9. Frontend показывает до трёх карточек и объяснение результата.

Если подходящих кандидатов нет, пользователь получает понятную причину, а не пустой экран.

## 6. Данные

Используется предоставленный организаторами анонимизированный каталог event-подрядчиков.

Основной файл:

```text
backend/data/hackathon-dataset-anonymized.jsonl
```

В нём **66 профилей**.

Дополнительно проект загружает:

```text
backend/synthetic_profiles.jsonl
```

В нём **3 дополнительных synthetic-профиля** для демонстрации редких категорий.

Итого backend загружает **69 уникальных профилей**, из которых **16 имеют `synthetic: true`** с учётом synthetic-профилей, уже присутствующих в исходном датасете.

Каталог содержит 17 категорий и города:

- Алматы;
- Астана;
- Зарубежье.

Календарь занятости ограничен диапазоном:

```text
23.09.2026 — 31.12.2026
```

Frontend содержит эквивалентный каталог `frontend/public/data/contractors.json` для статического режима.

## 7. Установка и запуск

### Требования

- Python **3.11+**
- Node.js **^20.19.0 или >=22.12.0**
- npm

API-ключ OpenAI **не обязателен** для запуска.

### Самый простой запуск на Windows

Из корня проекта:

```powershell
.\START_WINDOWS.bat
```

Скрипт:

1. создаст `backend/.venv`;
2. установит Python-зависимости;
3. установит frontend-зависимости через `npm ci`;
4. выполнит production build frontend;
5. запустит FastAPI.

После запуска открыть:

```text
http://127.0.0.1:8000/
```

Swagger:

```text
http://127.0.0.1:8000/docs
```

Health check:

```text
http://127.0.0.1:8000/health
```

Из корня проекта:


**Не публикуйте `.env` и API-ключи в GitHub.**

## 11. Ограничения текущей версии

- Проект **не выполняет бронирование** подрядчиков.
- Нет отправки заявок и уведомлений подрядчику.
- Нет пользовательской регистрации и авторизации.
- Нет контактов подрядчиков — используется анонимизированный хакатон-датасет.
- `price_from_kzt` — цена «от», а не финальная смета.
- Доступность определяется только календарём датасета, а не реальной системой бронирования.
- Поиск по датам доступен только для **23.09.2026–31.12.2026**.
- OpenAI используется только для объяснений и является опциональным; без ключа работает rule-based fallback.
- NVIDIA API в текущем коде не подключён.
- Статический GitHub Pages-режим работает без backend и поэтому использует локальную логику и локальные объяснения.
