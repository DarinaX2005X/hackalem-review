# ОргАнализ — интерфейс Person 3

Прототип Streamlit для сравнения организационной структуры и функций до и после реорганизации. Интерфейс показывает результаты агента, обоснования и конкретные фрагменты источников. Решения об изменениях принимает backend команды.

## Запуск в VS Code (Windows, PowerShell)

Требуется Python 3.11 или новее. Выполняйте команды в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Если окружение уже создано и зависимости установлены, нужна только последняя команда.
Откройте http://localhost:8501. Остановить приложение: Ctrl+C в терминале.
В VS Code выберите интерпретатор `.venv\Scripts\python.exe` через `Ctrl+Shift+P` → `Python: Select Interpreter`.

## Ключи NIM

Для режима «Документы» нужны `NVIDIA_API_KEY` и `NIM_MODEL`. Их можно задать перед запуском:

```powershell
$env:NVIDIA_API_KEY = "<ваш ключ>"
$env:NIM_MODEL = "<модель NIM с function calling>"
$env:NIM_BASE_URL = "https://integrate.api.nvidia.com/v1"
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Либо скопируйте `.streamlit/secrets.example.toml` в `.streamlit/secrets.toml` и заполните значения. Реальный `secrets.toml` игнорируется Git. Также ключ можно ввести в боковой панели Streamlit на время текущей сессии.

## Что работает сейчас

- **Демонстрация**: вымышленные документы, потенциальная потеря функции, дублирование и конфликт интересов. Не требует ключа NIM.
- **Документы**: два комплекта DOCX/PDF/XLSX, по несколько файлов, до 30 МБ на файл. Кнопка анализа включается после подключения `backend.py` и загрузки обоих комплектов.
- **Готовый JSON**: просмотр результата команды по предварительному контракту.
- Пять вкладок: подразделения, функции, дублирование, конфликты, заключение и рекомендации.
- Для выбранного вывода можно раскрыть источник: ID, документ, версия, пункт и текст.
- Скачивание JSON и текстового отчёта с обоснованиями и источниками.
- Проверка формата JSON, уникальности ID источников и существования каждой ссылки.
- После изменения загруженных документов предыдущий результат скрывается.

Интерфейс не выполняет реальный анализ, пока команда не подключит backend. Он не сохраняет загруженные документы на диск. Их обработка и политика хранения после подключения backend зависят от реализации команды.

## Подключение Person 1 и Person 2

Формат пока **предварительный**, так как общего JSON у команды ещё нет. Согласуйте `ui_contract.py` перед интеграцией; бизнес-валидация остаётся у Person 1.

1. **Person 2** возвращает фрагменты с полями `id`, `document`, `version` (`before`/`after`), `location` (пункт/страница/лист и строка), `text`. ID должны быть уникальны для обоих комплектов, даже если имена файлов совпадают.
2. **Person 1** создаёт `backend.py` рядом с `app.py` с функцией:

```python
def analyze_documents(before, after) -> dict:
    # before и after: списки InputDocument(name: str, content: bytes).
    # Вызвать парсер, NIM и валидацию; вернуть отчёт по ui_contract.py.
    # sources брать из парсера, а не генерировать моделью.
    ...
```

3. Функция возвращает обычный словарь. Если у команды другая схема/сигнатура, преобразуйте её в `backend_adapter.py`.

Поля результата:

| Поле | Содержимое |
| --- | --- |
| `departments` | Выводы со статусами `created`, `preserved`, `reorganized`, `removed` |
| `functions` | Выводы со статусами `preserved`, `transferred`, `lost`, `duplicated`, `new`; списки `before_units`, `after_units` |
| `duplicates`, `conflicts`, `recommendations` | Списки выводов |
| `conclusion` | Один итоговый вывод |
| `sources` | Фрагменты парсера |

У каждого вывода обязательны `title`, `explanation`, непустой `source_ids`. Пустые списки разделов допустимы. Полный пример доступен в `examples/demo.json`: загрузите его в режиме «Готовый JSON». Машиночитаемая схема — `examples/report.schema.json`.

`source_ids` и Pydantic проверяют структуру и наличие ссылок, но не доказывают, что цитата подтверждает вывод. Это проверяют агент, backend и ответственный сотрудник. Для потенциальной потери функции нужно проверять полноту комплекта «после»: отсутствие упоминания в одном фрагменте не доказывает потерю функции.

## Файлы

- `app.py` — интерфейс и экспорт отчёта; начни редактирование здесь.
- `backend_adapter.py` — подключение к функции команды.
- `ui_contract.py` — предварительный контракт интерфейса.
- `demo_data.py` — учебный пример.
- `tests/test_ui.py` — проверка ссылок, интерфейса и передачи документов backend.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

API интерфейса: [Streamlit](https://docs.streamlit.io/develop/api-reference), проверка UI: [AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).

Для демонстрации откройте вкладку «Функции», выберите потерю реестра договоров, раскройте пункты «до» и «после», затем покажите дублирование и потенциальный конфликт. Скачайте отчёт и загрузите его обратно через «Готовый JSON».
