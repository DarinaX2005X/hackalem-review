# AI Sana Challenge Hub

**От бизнес-задачи к первому решению**

AI Sana Challenge Hub — MVP платформы, которая помогает бизнесу превратить короткое описание проблемы в понятную задачу для студенческих команд.

Главная механика проекта — **рейтинг готовности бизнес-задачи**.

Чем полнее и полезнее бизнес описывает задачу, тем выше её рейтинг и позиция в каталоге.

---

## Основной сценарий

```text
Бизнес
  ↓
Короткий черновик задачи
  ↓
AI-уточнение
  ↓
Редактируемая карточка
  ↓
Рейтинг готовности 0–100
  ↓
Подтверждение бизнеса
  ↓
Публикация в каталоге
  ↓
Отклик студенческой команды
  ↓
Ручное решение бизнеса
```

Система **не назначает команды автоматически**.

Студенты самостоятельно выбирают задачи, а бизнес самостоятельно принимает решение по полученным предложениям.

# Что реализовано

## Для бизнеса

Бизнес может:

- создать черновик задачи;
- выбрать направление;
- получить уточняющие вопросы;
- дополнить информацию;
- отредактировать сформированную карточку;
- увидеть предварительный рейтинг;
- подтвердить сведения;

- просматривать свои задачи;

## Для студентов

Студент может:

- просматривать общий каталог;
- искать задачи;

- открыть полную карточку;
- выбрать свою команду при отправке отклика;
- отправить идею, план, срок и ссылку;
- просматривать свои отклики;
- видеть решение бизнеса.

# Рейтинг готовности

Рейтинг оценивает **полноту подтверждённого описания задачи**, а не качество компании или команды.

Максимум — **100 баллов**.

| Критерий | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность бизнеса | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| **Итого** | **100** |

## Уровни

| Баллы | Уровень |
|---:|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Заполненные сведения учитываются в итоговом рейтинге только после подтверждения бизнесом.

Если карточка изменяется, сведения необходимо подтвердить повторно.

---

# Влияние рейтинга на каталог

Рейтинг используется как основная геймификационная механика.

```text
Более полная задача
        ↓
Более высокий рейтинг
        ↓
Более высокая позиция в каталоге
```

Низкий рейтинг **не блокирует публикацию**.

Даже задача уровня «Черновик» может быть опубликована и оставаться доступной студенческим командам.

При одинаковом рейтинге новые задачи могут отображаться выше.

---

# AI-функция

В MVP реализован локальный AI-режим.

Он используется для уточнения исходного описания задачи.

Система:

1. получает черновик, направление и уже известные сведения;
2. определяет недостающие поля;
3. формирует релевантные уточняющие вопросы;
4. возвращает структурированный результат;
5. не добавляет неизвестные факты самостоятельно.

Пользователь может:

- изменить ответы;
- оставить неизвестные сведения пустыми;
- отредактировать итоговую карточку;
- самостоятельно подтвердить сведения перед публикацией.

## Ограничение AI

AI не может:

- придумывать отсутствующие факты;
- назначать студенческую команду;
- скрывать задачи от студентов;
- принимать решение вместо бизнеса.

Контракт AI описан отдельно:

```text
docs/AI-CONTRACT.md
```

Внешнюю LLM можно подключить через тот же серверный контракт без изменения основного пользовательского сценария.


```text

```

# Основные API

```text
GET  /api/state
POST /api/ai
POST /api/tasks
POST /api/proposals
POST /api/decision
```

`/api/state` возвращает состояние, необходимое клиентскому приложению.

`/api/ai` выполняет локальное уточнение задачи.

`/api/tasks` создаёт и обновляет карточки.

`/api/proposals` сохраняет отклики студенческих команд.

`/api/decision` сохраняет ручное решение бизнеса.

Набор находится в [fixtures/demo-data.json](fixtures/demo-data.json). Он содержит четыре связанные коллекции по пять записей:

Рейтинги пяти карточек: **100, 85, 65, 30 и 10**. Два разных предложения для кофейни позволяют показать сравнение команд бизнесом. Остальные отклики относятся к образованию, экологии и логистике. Контакты и ссылки синтетические, внешние прототипы по адресам example.com не предоставляются.

JSON можно скачать на сайте в разделе **«Как это работает» → «Скачать JSON-набор»**. API `/api/demo-data` возвращает исходный учебный набор, а `/api/state` — актуальную рабочую базу с пользовательскими изменениями.

При первом запуске новой базы приложение читает этот файл. Существующая SQLite-база остаётся без изменений. Для просмотра нового набора без удаления текущей работы:

```bash

```

PowerShell:


### Удобство и достоверность демонстрации

Незавершённый конструктор автоматически сохраняет последнюю редактируемую карточку в этом браузере. После перезагрузки в каталоге появляется «Продолжить заполнение». Можно вернуться на предыдущий шаг, не теряя ответы. Локальная копия не публикуется и не заменяет сохранение на сервере. Восстановление всегда требует нового подтверждения, при конфликте серверной версии нужно заново открыть актуальную карточку. Локально хранится одна последняя редактируемая карточка; открытие другой карточки для редактирования заменяет её. После успешного сохранения на сервере локальная копия удаляется.

XP команды начинается с **0** и складывается только из баллов подтверждённых этапов. Кабинет и список команд показывают одинаковый результат. Порог уровней: 0, 50, 100 и 200 XP; последний уровень максимальный.

Проверки: `python3 -m unittest discover -s tests -v` (12 тестов, включая объём, связи и рейтинг набора). Для дополнительных регрессионных проверок интерфейсной логики, если установлен Node.js: `node --test tests/test_ui.js` (6 тестов). Node.js не требуется для запуска сайта.
