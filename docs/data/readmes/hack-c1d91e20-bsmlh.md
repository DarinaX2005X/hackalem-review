# AI SANA

AI SANA — MVP платформы, которая превращает сырую бизнес-идею в понятную, структурированную и готовую к работе задачу для студенческих команд.

Бизнес описывает задачу своими словами, AI помогает выявить пробелы и задаёт уточняющие вопросы, затем формируется редактируемая карточка. Готовность задачи оценивается прозрачным детерминированным рейтингом 0–100. После публикации студенческие команды находят задачу в каталоге, отправляют предложения, а бизнес вручную выбирает или отклоняет команды.

## Что реализовано

- выбор роли: **Бизнес / Студенческая команда**;
- лёгкие профили для обеих ролей;
- создание бизнес-задачи из свободного текста;
- AI-анализ недостающих данных;
- уточняющие вопросы;
- редактируемая карточка задачи;
- **live readiness preview** во время заполнения;
- строгий рейтинг готовности 0–100;
- объяснение начисленных баллов;
- top-рекомендации, что добавить для повышения рейтинга;
- каталог опубликованных задач;
- отклики студенческих команд;
- ручной выбор / отклонение команды бизнесом;
- SQLite-хранилище;
- работа без OpenAI API через локальный fallback;
- автоматические тесты рейтинга и интеграционного сценария.

## Главный сценарий

```text
Бизнес
→ выбирает роль
→ заполняет профиль
→ описывает задачу
→ AI анализирует описание
→ AI задаёт уточняющие вопросы
→ пользователь дополняет данные
→ readiness preview растёт
→ формируется редактируемая карточка
→ бизнес подтверждает данные
→ рассчитывается официальный рейтинг
→ задача публикуется
→ студент открывает каталог
→ отправляет предложение
→ бизнес просматривает отклик
→ вручную выбирает или отклоняет команду
```

## Ключевая идея

Главная геймификация направлена на **качество бизнес-задачи**.

Чем конкретнее и полезнее описание, тем выше readiness score и тем лучше позиция задачи в каталоге.

Важно:
- AI **не выставляет итоговый score сам**;
- рейтинг считает `core/rating.py` по прозрачным правилам;
- AI не выбирает команду;
- финальное решение остаётся за человеком.

## Рейтинг готовности

Максимум: **100 баллов**.

| Категория | Вес |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

### Уровни

- **0–39** — Черновик
- **40–69** — Рабочая
- **70–89** — Готовая
- **90–100** — Приоритетная

### Как начисляются баллы

Рейтинг намеренно строгий:

- пустое поле → 0;
- неподтверждённое поле → 0;
- мусорные ответы вроде `asdf`, `-`, повторов слов → 0;
- расплывчатые ответы вроде «все», «есть данные», «чтобы работало» не получают полный балл;
- полный балл выдаётся только за конкретную и полезную информацию.

## Live readiness preview

Во время заполнения пользователь видит **прогноз готовности**:

- текущий score;
- уровень;
- progress bar;
- сколько баллов не хватает до следующего уровня;
- top-рекомендации по самым ценным недостающим данным.

После подтверждения карточки считается официальный score.

## AI-функции

AI используется для двух задач:

### 1. Анализ полноты

`analyze_task(raw_text, card)`

Определяет, каких данных не хватает, и формирует уточняющие вопросы.

### 2. Сборка карточки

`build_card(raw_text, answers)`

Формирует структурированную карточку только из информации, которую сообщил пользователь.

AI не должен придумывать неизвестные факты.

Если OpenAI API недоступен, используется локальный deterministic fallback.

## Быстрый demo script

1. Бизнес вводит слабое описание: `Хотим чат-бота для клиентов`.
2. Показываем низкий preview score.
3. AI задаёт уточняющие вопросы.
4. Добавляем пользователей, данные, ожидаемый результат и измеримый критерий.
5. Показываем рост readiness.
6. Подтверждаем карточку и публикуем.
7. Переключаемся на студенческую команду.
8. Открываем каталог.
9. Отправляем предложение.
10. Возвращаемся как бизнес.
11. Открываем отклики.
12. Вручную выбираем или отклоняем команду.

## Правила каталога

- все опубликованные задачи доступны командам;
- задачи сортируются по readiness score;
- низкий score не скрывает задачу;
- студент может откликнуться даже на задачу с низкой готовностью.

## Профили ролей

### Бизнес

Лёгкий профиль содержит основные данные компании и контактную информацию.

### Студенческая команда

Профиль команды используется как мини-резюме и содержит:
- название;
- описание;
- интересы;
- навыки;
- технологии;
- контакты.

## Безопасность и устойчивость AI

Даже если AI ошибается или API недоступен:

- score не контролируется LLM;
- `core/rating.py` остаётся источником истины;
- неподтверждённые поля не получают официальный балл;
- приложение продолжает работу через fallback;
- выбор команды не автоматизируется AI.
