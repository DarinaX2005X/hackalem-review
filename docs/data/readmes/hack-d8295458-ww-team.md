# task-catalog

Каталог бизнес-задач для студенческих команд: черновик → уточнения → карточка → рейтинг → публикация → отклик → выбор команды.

## Как запустить

Установите зависимости:

```sh
npm install
```

Скопируйте `.env.example` в `.env`:

```dotenv
DATABASE_URL="file:./dev.db"
OPENAI_API_KEY=""
NVIDIA_API_KEY=""
```

API-ключи опциональны: без них сценарий работает с локальной заглушкой. Ключи доступны только серверу. После изменения `.env` перезапустите сервер.

```sh
npx prisma migrate dev
npx prisma db seed
npm run dev
```

Откройте http://localhost:3000/catalog. В PowerShell при блокировке скриптов используйте `npm.cmd` и `npx.cmd`. Если клиент Prisma не сгенерирован, выполните `npx prisma generate`.

Seed создаёт 5 неподтверждённых черновиков, 5 подтверждённых карточек и 5 откликов — по одному на подтверждённую карточку. Демо-контакты и ссылки используют `example.com`. Черновики различаются подробностью `rawDraft`, но структурированные поля ещё пусты: рейтинг 0. Подтверждённые карточки имеют все семь полей рейтинга: 100 баллов.

Повторный seed не создаёт дубликаты: используются фиксированные ID `seed-draft-*`, `seed-card-*`, `seed-proposal-*`. Он восстанавливает содержимое демозаписей, сохраняя статус выбранного бизнесом отклика. Пользовательские записи не удаляются. База хранится в `prisma/dev.db`; база и `.env` исключены из Git. После seed обновите открытую вкладку каталога.

## Архитектура

Стек: Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS 3, Prisma 6, SQLite. Seed запускается через `tsx`.

```text
prisma/
  schema.prisma       BusinessTask и Proposal
  migrations/         SQL-миграции
  seed.ts             Демоданные с пересчётом рейтинга
src/
  app/
    business/         Пошаговое создание задачи
    catalog/          Каталог и /catalog/[id] для редактирования
    admin/            Временный список для проверки
    api/clarify/      Уточняющие вопросы
    api/build-card/   Подготовка карточки
    api/tasks/        Публикация и PATCH /api/tasks/[id]
    actions.ts        Отправка отклика и выбор команды
  components/         Формы, рейтинг, навигация
  lib/
    ai.ts             askAI(systemPrompt, userText)
    task-ai.ts        Промпты и проверка ответа AI
    task-card.ts      Заглушки stubQuestions, stubCard и валидация
    rating.ts         calculateScore, getStatus, withRating
    tasks.ts          Запись задач с пересчётом рейтинга
    prisma.ts         Общий Prisma Client
 tests/               Тесты и интеграционный сценарий
```

`askAI` последовательно пробует OpenAI (`gpt-4o-mini`), NVIDIA NIM (`meta/llama-3.1-8b-instruct`), затем возвращает `null`. У каждого провайдера таймаут 8 секунд через AbortController. Источник логируется на сервере и показывается у вопросов и карточки: OpenAI / NVIDIA (резерв) / Заглушка.

Заглушка без сети выбирает четыре вопроса по ключевым словам и переносит ответы в карточку. При недоступности AI или некорректном JSON форма показывает пояснение и позволяет продолжить с локальным результатом. До подтверждения карточка в БД не записывается. Публикация требует непустые `title` и `rawDraft`; отклик — название команды, `idea` и `plan`. Пробельные строки считаются пустыми.

## Формула рейтинга задачи

Рейтинг — сумма весов непустых структурированных полей. `null`, пустые и пробельные строки дают 0. `rawDraft` и `title` сами по себе баллов не добавляют.

| Поле | Описание | Вес |
| --- | --- | ---: |
| `context` | Контекст и потребность | 20 |
| `dataMaterials` | Данные и материалы | 20 |
| `expectedResult` | Ожидаемый результат | 15 |
| `successCriteria` | Критерии успеха | 15 |
| `constraints` | Ограничения | 10 |
| `users` | Пользователи | 10 |
| `contact` | Контакт и формат связи | 10 |
| **Итого** | | **100** |

| Баллы | Статус | Уровень готовности |
| --- | --- | --- |
| 0–39 | `draft` | Черновик |
| 40–69 | `working` | В работе |
| 70–89 | `ready` | Готова |
| 90–100 | `priority` | Приоритетная |

`calculateScore` возвращает `{ score, breakdown, missing }`, `getStatus` определяет статус. Рейтинг измеряет заполненность, а не качество формулировок. При публикации и сохранении правок сервер пересчитывает баллы и статус; присланные клиентом значения игнорируются. В форме расчёт виден сразу при вводе. Подтверждение (`confirmed`) независимо от рейтинга: можно подтвердить неполную карточку.

## Правила каталога

- Задачи отсортированы по `createdAt` по убыванию: новые сверху. Отклики внутри задачи — также новые сверху.
- Каталог показывает все задачи, включая неподтверждённые черновики. Фильтры по статусу, подтверждению и баллам пока не реализованы. Рейтинг не влияет на сортировку.
- «Открыть и редактировать» ведёт на `/catalog/[id]`. После сохранения рейтинг обновляется в БД и интерфейсе.
- Отклик создаётся со статусом `pending`. В разделе «Отклики» кнопка «Выбрать команду» переводит выбранный отклик в `accepted`, остальные отклики этой задачи — в `rejected`.
- Повторный выбор заменяет предыдущий в одной транзакции. Новые отклики после выбора получают `pending`, пока бизнес не сделает новый выбор. Выбор команды не меняет рейтинг задачи.
- После действий используются `revalidatePath` и `router.refresh()`. Кнопки блокируются и показывают «Загрузка...».

Это локальное демо без авторизации: редактирование и выбор команды доступны всем посетителям. Перед публичным размещением нужны роли и права доступа. На момент установки `npm audit` сообщил о 9 уязвимостях (8 high, 1 critical), включая Next.js 14; перед публикацией следует обновить зависимости и повторить аудит.

## Тестовые сценарии

1. **Создание и публикация.** На `/business` введите потребность, нажмите «Продолжить», ответьте на вопросы. Без ключей появится бейдж «Заглушка». В карточке заполните семь полей: рейтинг станет 100. Подтвердите — задача появится в каталоге. Пустые название или черновик не должны публиковаться.
2. **Редактирование рейтинга.** Откройте подтверждённую демозадачу в каталоге. Очистите контекст: рейтинг изменится со 100 на 80, статус — на «Готова», появится подсказка. Сохраните, вернитесь в каталог и проверьте результат после обновления страницы.
3. **Отклик и выбор бизнеса.** Отправьте отклик с командой, идеей и планом. Он должен появиться без ручной перезагрузки. Выберите команду, затем другую: только один отклик должен быть принят. Без идеи или плана отправка блокируется.

Автоматические проверки:

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

Тесты проверяют переключение провайдеров и таймауты с подменённым fetch, обработку JSON, обязательные поля, состояния формы, все 128 комбинаций заполнения и границы статусов. Реальные AI-запросы не выполняются.

При запущенном dev-сервере выполните `node tests/scenario.cjs`: сценарий проверяет API, SQLite, отклики и выбор/замену команды. Он удаляет только свои тестовые записи. Это интеграционная проверка без браузера.
