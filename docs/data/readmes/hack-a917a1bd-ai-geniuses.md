# OrgLens — анализ организационных изменений

Локальный прототип для HackAlem AI: загрузите документы **ДО** и **ПОСЛЕ**, сопоставьте подразделения и функции, проверьте риски по точным цитатам, выгрузите JSON и HTML-заключение. Интерфейс и сообщения — на русском языке.

**Выводы носят рекомендательный характер и требуют проверки ответственным сотрудником.** Отсутствие закрепления в загруженном комплекте не означает, что компания перестала выполнять функцию.

Для AI-анализа извлечённый текст передаётся в OpenAI API. Используйте документы, которые разрешено обрабатывать этим способом. Приложение не выполняет весь анализ локально. Исходные файлы, извлечённый текст и результаты сохраняются локально; кэш ответов модели тоже может содержать цитаты и сведения из документов. Не размещайте `data/` в публичном хранилище.

## Быстрый запуск

Требуются **Python 3.12+** и **Node.js 22.12+**. Все команды ниже выполняются из папки `OrgLens`, если не указано иное. Для работы без API-ключа пропустите редактирование ключа: загрузка, чтение документов и просмотр источников доступны, AI-анализ завершится понятной ошибкой конфигурации.

### Запуск готового приложения на Windows

Если зависимости уже установлены, запустите **`start-orglens.cmd`** двойным щелчком и откройте **<http://127.0.0.1:8000/>**. Не закрывайте окно сервера во время работы. Если приложение уже запущено, просто откройте адрес — второй сервер не нужен.

Этот режим собирает настоящий интерактивный React-интерфейс и отдаёт его вместе с API с одного адреса. Кнопки загружают документы, запускают анализ, открывают источники и скачивают отчёты. Это не статический предпросмотр. Команды вручную:

```powershell
npm.cmd --prefix frontend run build:portable
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

`build:portable` использует установленные TypeScript и Vite/Rollup в текущем процессе Node.js; не запускает сервис esbuild. Проверка типов включена, минификация отключена. После изменения исходников повторите сборку. Для первой установки выполните команды ниже. Два отдельных сервера остаются вариантом для разработки.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Copy-Item .env.example backend\.env
# Откройте backend/.env в редакторе и укажите OPENAI_API_KEY.
Set-Location frontend
npm.cmd ci
Set-Location ..
```

Первый терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Второй терминал:

```powershell
Set-Location frontend
npm.cmd run dev -- --host 127.0.0.1
```

После установки также доступны `./start-backend.ps1` и `./start-frontend.ps1`. Активация виртуального окружения не обязательна. Не перезаписывайте существующий `backend/.env` при обновлении проекта.

### Linux / macOS

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cp .env.example backend/.env
# Укажите ключ в backend/.env.
cd frontend
npm ci
cd ..
```

Первый терминал:

```bash
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Второй терминал:

```bash
cd frontend
npm run dev -- --host 127.0.0.1
```

Альтернатива после установки: `sh start-backend.sh` и `sh start-frontend.sh`.

- Готовое приложение и API: <http://127.0.0.1:8000> (после `build:portable`).
- Интерфейс в режиме разработки: <http://127.0.0.1:5173>.
- Состояние: <http://127.0.0.1:8000/api/health>.
- Схема API: <http://127.0.0.1:8000/docs>.

Сервер слушает только loopback. **Не используйте несколько workers**: очередь задач находится в памяти одного процесса. Запуски обрабатываются последовательно в отдельном рабочем потоке. Перезапуск прерывает анализ; при следующем запуске оставшиеся `queued/running` помечаются как прерванные, а сохранённые источники и частичные данные остаются доступны. Автоматического возобновления нет.

## Настройка OpenAI

Backend читает `backend/.env`; переменные окружения процесса имеют приоритет. Пример находится в `.env.example`, реальный ключ в репозитории не хранится. Модель по умолчанию — `gpt-4.1-mini`, заменяется только через `OPENAI_MODEL`. Доступ к модели определяется реальным ответом API; скрытого переключения моделей нет.

Используется официальный Python SDK, **Responses API** и `responses.parse(..., text_format=PydanticModel, store=False)`. Синтаксис проверен по [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и сигнатуре установленного SDK. Возможности указанной модели описаны на [официальной странице gpt-4.1-mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). `store=False` — параметр API, а не обещание отсутствия обработки или хранения данных провайдером по условиям аккаунта.

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `OPENAI_API_KEY` | пусто | Секрет только на backend |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Выбранная модель |
| `OPENAI_MAX_CALLS_PER_RUN` | 40 | Бюджет физических запросов, включая повторные попытки |
| `OPENAI_MAX_CONCURRENCY` | 2 | Верхняя граница одновременных запросов в процессе |
| `OPENAI_TIMEOUT_SECONDS` | 90 | Время ожидания запроса |
| `OPENAI_MAX_OUTPUT_TOKENS` | 16000 | Максимальный размер ответа |
| `MAX_FILE_MB` | 20 | Размер одного исходного файла |
| `MAX_FILES_PER_VERSION` | 12 | Файлы в каждом комплекте |
| `MAX_DOCUMENT_CHARS` | 120000 | Символы извлечённого текста одного документа |
| `MAX_ANALYSIS_CHARS` | 240000 | Символы всего комплекта |
| `EXTRACTION_BATCH_CHARS` | 18000 | Размер пакета извлечения |
| `COMPARISON_BATCH_SIZE` | 16 | Размер пакета сравнения |
| `DATA_DIR` | `OrgLens/data` | Необязательный путь к локальным данным |

После изменения окружения перезапустите backend. Для временных сетевых ошибок, ограничений частоты и серверных ошибок предусмотрены ограниченные повторы с задержкой. Ошибки ключа, доступа, квоты, отказ модели и невалидные ответы не маскируются фиктивными результатами. Исчерпание бюджета сохраняет доступную часть анализа. Подробности запросов и секреты не выводятся пользователю.

## Данные и архитектура

```text
React + TypeScript + Vite
  → multipart загрузка ДО/ПОСЛЕ
FastAPI → очередь одного процесса → DOCX / PDF / XLSX парсеры
  → блоки с точными адресами → AI-извлечение атомарных функций
  → проверка источников → сопоставление подразделений
  → сопоставление функций между всеми подразделениями ПОСЛЕ
  → проверка отсутствия по исходному комплекту ПОСЛЕ
  → поиск пересечений / конфликта независимости
  → проверка доказательств → детерминированное заключение
  → сохранённый JSON + HTML-отчёт + polling интерфейса
```

- `backend/app/schemas.py`: Pydantic-модели сущностей, источников и статусов.
- `backend/app/parsers/`: безопасное извлечение с адресами и предупреждениями.
- `backend/app/services/`: OpenAI, извлечение, сравнение, проверка источников, отчёт.
- `backend/app/storage.py`: атомарные JSON-записи и изоляция по UUID анализа.
- `backend/app/main.py`: API, загрузки, очередь, скачивание оригиналов.
- `frontend/src/`: рабочий интерфейс, матрица, фильтры, источники, заключение.
- `demo/`: реальные синтетические документы и отдельные ожидания для оценки.
- `backend/tests/`: проверки с тестовым провайдером, без реального OpenAI.

Файлы сохраняются в `data/<analysis_id>/documents/<document_id>`, состояние — в `analysis.json`, ответы модели — в `cache/`. Оригинальное имя никогда не используется как путь. Запись JSON выполняется через временный файл и атомарное переименование. Кэш привязан к данным, версии комплекта, модели, версии промпта и схеме ответа внутри анализа; он не переносит источники между независимыми запусками. Обновление страницы только читает сохранённое состояние и не запускает AI повторно. Удаление каталога конкретного анализа вручную удаляет его документы и результаты; автоматической политики хранения нет.

Модель не имеет инструментов, доступа к shell, интернету или секретам. Текст документов явно помечается как недоверенные данные. Это уменьшает риск prompt injection, но не доказывает семантическую безошибочность модели. Backend проверяет идентификаторы, версии, дословные цитаты, роли и обязательные основания выводов; неподтверждённые результаты становятся неопределённостью или отбрасываются с предупреждением.

## Поддерживаемые форматы и допущения

- **DOCX**: абзацы и таблицы в порядке документа; адреса абзацев, пунктов и ячеек. Номера страниц не придумываются. Автоматическая нумерация Word не восстанавливается: вместо неё используются адреса абзацев с предупреждением; явные номера в тексте сохраняются. Колонтитулы, текстовые поля, рисунки, SmartArt и вложенные объекты могут быть недоступны; предупреждения отражаются в полноте.
- **PDF с текстовым слоем**: номера реальных страниц, текстовые фрагменты. Смешанные PDF проверяются постранично; недоступные изображения и страницы отмечаются. OCR не реализован. Неоднозначная многоколоночная верстка и графические оргсхемы требуют ручной проверки.
- **XLSX**: листы, адреса ячеек, контекст строк и колонок. Формулы и макросы не исполняются; формульные ячейки и недоступная графика отмечаются. Старые `.doc` и `.xls` необходимо конвертировать.
- Пустые, повреждённые, зашифрованные и неподдерживаемые файлы видны в реестре со статусом и ошибкой. Один файл не скрывает остальные.
- Помимо настраиваемых лимитов, OOXML ограничен 60 МБ распакованных данных / 3000 элементов архива; XLSX — 10000 строк, 256 колонок и 50000 ячеек; PDF — 300 страниц. Превышения не скрываются.
- Связь подразделений — гипотеза при отсутствии прямого приказа. Упразднение требует прямого документа. Старые положения не считаются автоматически утратившими силу; неясность их действия отражается в ограничениях.
- Сравниваются действие, объект, область ответственности и роль. Подготовка и согласование заявки не являются автоматическим дублированием. Повтор текста одного подразделения в нескольких документах не считается межведомственным дублированием.
- Даже полностью прочитанный загруженный комплект может быть неполным относительно всех документов компании. Потеря формулируется только как отсутствие подтверждённого закрепления в проверенном комплекте. При неполноте чтения такой вывод нельзя считать обоснованным.

| Потеря и прямая отмена | Разные отношения, дополнительная проверка исходных блоков ПОСЛЕ, охват поиска и ограничения |
| Дублирование и конфликт независимости | Проверка роли, действия, объекта, области и источников обеих функций |
| Проверяемость каждого вывода | Отдельный evidence validator, цитаты, безопасный реестр источников, статусы основания |
| Итоговое заключение | Только проверенные сущности и выводы, ссылки на источники и идентификаторы рисков |
| Длительный анализ | Фоновая задача, реальные этапы/счётчики и polling, восстановление статуса после перезапуска |
| Интерфейс результатов | Пять вкладок, все отношения матрицы, фильтры, панель источника, оригинал PDF по странице |
| Сохранение | `analysis_id` в адресе и интерфейсе, атомарные файлы, повторное открытие без AI-вызова |

| Демо | Реальные файлы поступают в тот же процесс обработки; ожидания не читаются runtime |
| Нет ключа / API ошибается | Понятная ошибка, прочитанные источники доступны, нет подстановки результатов |
| Локальная безопасность | UUID-пути, проверка принадлежности источников, экранирование, локальные CORS/Host/Origin, лимиты |
| Проверки | Unit/integration с отдельным FakeLLMProvider, отдельная ограниченная live evaluation |

## Демо и проверка

Фактически выполненные команды, результаты и непроверенные сценарии приведены в [VERIFICATION.md](VERIFICATION.md).

Нажмите **«Попробовать на примере»**. Приложение прочитает шесть файлов из `demo/before` и `demo/after` и запустит тот же процесс, что и для пользовательской загрузки. Документы помечены «Синтетические демонстрационные данные». Кнопка не читает `expected_findings.json` и не возвращает готовые карточки.

Для своих документов используйте блоки **«Было»** и **«Стало»**, затем **«Сравнить документы»**. Результат открывается с краткого **«Обзора»**. Разделы **«Подразделения»**, **«Функции»**, **«Риски»**, **«Документы»** и **«Итоги»** доступны в меню. Подробности и источники раскрываются внутри карточек, отчёт скачивается из раздела **«Итоги»**. На узком экране меню адаптируется под ширину окна.

Сценарий: Центр ИТ разделён на разработку и инфраструктуру; ИБ создана; закупки и бухгалтерия сохранены. Резервное копирование передано, закрепление реестра лицензий не найдено, права доступа могут дублироваться, аудит собственной разработки создаёт риск независимости. Подготовка и согласование заявки имеют разные роли.

Пересоздание синтетических файлов (не требуется для обычного запуска):

```powershell
.\.venv\Scripts\python.exe scripts\generate_demo.py
```

Unit/integration и сборка (PowerShell):

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m pytest -q
Set-Location ..\frontend
npm.cmd run typecheck
npm.cmd run build
Set-Location ..
```

Linux/macOS: `cd backend && ../.venv/bin/python -m pytest -q`; затем `cd ../frontend && npm run typecheck && npm run build`.

**Тестовый провайдер находится только в тестах.** Он проверяет обработку схем, источников, условий выводов, ошибки и полноту. Эти проверки не доказывают качество реальной модели.

Ограниченная живая оценка (нужен ключ в `backend/.env`; расходует запросы API):

```powershell
.\.venv\Scripts\python.exe scripts\live_evaluation.py
```

Linux/macOS: `.venv/bin/python scripts/live_evaluation.py`. Оценка сопоставляет типы событий, функции и названия подразделений с отдельным `demo/expected_findings.json`, проверяет ссылки. Точные сгенерированные формулировки не сравниваются. Без ключа оценка сообщает об отсутствии конфигурации, а не возвращает успех.

## API

| Метод и маршрут | Результат |
|---|---|
| `GET /api/health` | Доступность, наличие настройки AI без ключа, модель, лимиты |
| `POST /api/analyses` | Multipart `before`/`after`, повторяемые поля; `202 {analysis_id}` |
| `POST /api/demo-analysis` | Создаёт анализ синтетического комплекта |
| `GET /api/analyses/{id}` | Статус, этап, документы, блоки и доступный результат |
| `GET /api/analyses/{id}/sources/{block_id}` | Блок с реальными метаданными и документом |
| `GET /api/analyses/{id}/documents/{document_id}` | Оригинальный файл только данного анализа |
| `GET /api/analyses/{id}/report` | HTML-отчёт с цитатами |
| `GET /api/analyses/{id}/export` | JSON всего анализа |

Статусы: `queued`, `running`, `completed`, `partial`, `failed`. `completed` означает завершённую обработку предоставленного комплекта, не абсолютную достоверность выводов. `complete` отражает полноту доступной обработки. Числовые вероятности достоверности не используются.

## Ограничения MVP

Нет production-авторизации, корпоративных ролей, внешних интеграций, OCR, юридической экспертизы, обучения модели, базы данных и распределённой очереди. Это **не готовый многопользовательский корпоративный сервис**. Не публикуйте backend в интернете. CORS/Host-проверки не заменяют авторизацию. Локальные файлы доступны пользователям с правами на каталог данных.

Модель может пропустить функции и неверно интерпретировать цитату. Структурная и дополнительная смысловая проверка снижают риск, но не заменяют экспертную верификацию. Консервативные проверки могут отклонить правильное сопоставление и показать недостаточность данных. Большие комплекты могут исчерпать лимит запросов; уменьшите комплект или осознанно увеличьте бюджет. Разные формулировки названия одного подразделения могут потребовать ручной проверки.

## Демонстрация жюри: 2–3 минуты
