# «Аким на 5 часов» — Saryarqa City Simulator

Учебный симулятор управления Астаной по кейсу HackAlem AI. Соберите **пять решений** на общий бюджет **100 единиц**, сравните последствия для районов и сохраните результат своего акима. Главная задача — улучшать город, учитывая не только среднее значение, но и самый слабый район.

**Важно:** показатели и эффекты — синтетическая модель из кейса, а не прогноз для реальной Астаны. Числа вычисляет детерминированный движок; ИИ не назначает баллы.

Проект предназначен для учебных занятий, обсуждения городских приоритетов и демонстрации бюджетных компромиссов. Игрок выступает в роли акима: распределяет ограниченные средства между транспортом, экологией, социальной инфраструктурой, безопасностью и городскими сервисами. Карта показывает последствия, расчёт позволяет сравнить планы, а советник объясняет уже проверенные результаты.

## Быстрый запуск

Нужен **Node.js 18+**. У приложения нет сторонних runtime-зависимостей; `npm install` не нужен.

```powershell
git clone https://github.com/BAITC-Hacks/hack-d5c78ff1-saryarqa.git
cd hack-d5c78ff1-saryarqa
git switch main
npm start
```

Если репозиторий уже открыт, достаточно выполнить `npm start` в папке с `package.json`. Для первого запуска ключи API и база данных не нужны: расчёт, карта, локальный помощник и локальные профили работают самостоятельно. Отдельного этапа сборки нет: сервер отдаёт JavaScript-модули, CSS и локальные ресурсы напрямую. В проекте нет команд `npm run build` или `npm run dev`.

Откройте [localhost:3000](http://localhost:3000). Не открывайте `index.html` через `file://`: модулям и API нужен HTTP-сервер.

Другой порт в PowerShell:

```powershell
$env:PORT = '3031'
npm start
```

Сервер слушает `127.0.0.1`. Остановить его можно `Ctrl+C`. После изменения серверного кода или `.env` перезапустите процесс.

Проверка доступности из второго терминала: `curl.exe http://127.0.0.1:3000/api/services` в Windows или `curl http://127.0.0.1:3000/api/services` в Linux/macOS. Этот запрос сообщает состояние интеграций, но сам по себе не проверяет весь пользовательский сценарий.

## Что можно сделать

- **Игра:** выбрать район, назначить меры, наблюдать изменения на карте и сравнить итог со стартом. Есть вид сверху, объёмная проекция, переключение слоёв и прогулка по Нуре.
- **Расчёт:** собрать тот же план без карты и получить результат по тем же правилам. Районные меры требуют явного назначения района.
- **Профиль акима:** создать имя, сохранить ключ входа, выйти и восстановить профиль по ключу. Это вход по секретному ключу профиля; email и пароль не требуются.
- **История и топ акимов:** сохранять рассчитанные планы, возвращаться к ним и сравнивать лучшие результаты. Сервер заново проверяет и рассчитывает план перед сохранением; присланный клиентом балл не принимается.
- **Советник:** задать вопрос о бюджете, районах, формуле или улучшении плана. Живой AI зависит от серверной настройки; при ошибке доступен явно обозначенный локальный помощник по фактам расчёта.
- **Черновик:** выбранные решения, предпочтения вида и личный рекорд сохраняются в этом браузере. После изменения плана старый результат сбрасывается.

Интерфейс на русском. Сарайшық присутствует на карте как справочный район, но не входит в расчётный набор из пяти районов. Прогулка, транспорт и жители иллюстрируют город и не меняют балл.

## Сценарий для демонстрации

1. Откройте приложение. Исходный индекс — **52,56**.
2. Нажмите **«Пример из кейса»**: M7 → Нура, M8 → Нура, M10 → Нура, M12 → весь город, M5 → Сарыарка.
3. Проверьте бюджет: **95 / 100**. Нажмите **«Показать прогноз»**. В режиме игры можно пропустить анимацию кнопкой **«К прогнозу»**.
4. Результат: **56,54**; точное значение `56.54307`; критических показателей — **0**.
5. Откройте советника, задайте вопрос о бюджете или слабейшем районе. Источник ответа обозначен в интерфейсе.
6. Войдите в профиль, сохраните результат и проверьте историю и рейтинг. Повторное сохранение того же плана не создаёт дубликат.
7. Измените план и рассчитайте его заново. Для недопустимого набора выводятся причины, балл не присваивается.

Для прогулки нажмите **«Гулять по Нуре»** на карте. Используйте WASD/стрелки или экранные кнопки. Мобильные кнопки удерживаются для движения; центрирование возвращает камеру к акиму.

## Сохранения и вход

Есть два независимых уровня хранения:

| Уровень | Что хранит | Граница |
|---|---|---|
| `localStorage` браузера | Черновик, вид карты, личный рекорд и ключ текущего профиля | Только этот браузер; очистка данных удалит локальную копию |
| Серверное хранилище | Профили, история допустимых планов, лучшие результаты | Supabase или явно выбранный локальный сервер |

Без конфигурации Supabase локальный Node-сервер использует файл в исключённой из Git папке `.akim-data/`. Для явного локального режима:

```powershell
$env:AKIM_STORAGE_MODE = 'local'
npm start
```

Это рейтинг **данного локального сервера**, не глобальный рейтинг опубликованного сайта. Файл должен сохраняться между перезапусками. В бессерверном развёртывании используйте Supabase: локальный диск функции не подходит для постоянного хранения.

Ключ профиля даёт доступ к его истории. Сохраните его приватно; не публикуйте в презентации, Git или скриншотах. Если ключ утрачен и данных браузера нет, восстановления через email в этой версии нет. На общем компьютере выходите из профиля.

## Supabase и AI

Скопируйте `.env.example` в `.env` или `.env.local`, если файла ещё нет. Не перезаписывайте существующую конфигурацию. Сервер загружает эти файлы автоматически. При локальной разработке настройки проекта имеют приоритет над унаследованными переменными IDE; при NODE_ENV=production приоритет сохраняется за окружением платформы.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Серверный ключ OpenAI для живого анализа и чата |
| `OPENAI_MODEL` | Доступная вашему аккаунту модель; пример указан в `.env.example` |
| `SUPABASE_URL` | URL своего проекта Supabase |
| `SUPABASE_SECRET_KEY` | Серверный secret key; предпочтительный вариант |
| `SUPABASE_SERVICE_ROLE_KEY` | Альтернатива для legacy service-role ключа |
| `AKIM_STORAGE_MODE=local` | Явно использовать локальное дисковое хранилище |
| `PORT` | Порт локального сервера, по умолчанию 3000 |

Примените [миграцию таблиц и рейтинга](supabase/migrations/202609230001_akim_rankings.sql) в своём Supabase-проекте. Ключи передаются только серверу, не в клиентскую сборку. Таблицы защищены RLS; запись результатов проходит через API приложения.

`GET /api/services` сообщает доступность хранилища и наличие конфигурации AI без раскрытия ключей. `configured: true` означает наличие настройки, а не успешную авторизацию у провайдера. Ошибка `AI_AUTH_FAILED` означает, что провайдер отклонил ключ: исправьте серверную настройку и перезапустите процесс. Локальный разбор продолжит работать.

## Правила и формула

Допустимы ровно пять уникальных мер, стоимость до 100 включительно, максимум две меры одного направления. Все районные меры имеют допустимый район; городские — без района. Несовместимые пары отклоняются.

Движок последовательно учитывает задержку `(8 − lag) / 8`, фиксированные синергии, ограничение показателей диапазоном 0–100, веса показателей и населения. Затем:

```text
Score = 0.7 × средний индекс по населению
      + 0.3 × индекс слабейшего района
      − количество значений строго ниже 40
```

Значение ровно 40 не штрафуется. Внутри расчёта сохраняется полная точность; округление используется только для отображения. Некорректный план не получает результат.

## Архитектура

Стек: HTML, CSS, JavaScript ES Modules и SVG в браузере; встроенный HTTP-сервер Node.js; `node:test` для автоматических проверок. Supabase предоставляет PostgreSQL-хранилище, OpenAI — дополнительный анализ через серверный API. По умолчанию сервер запрашивает модель `gpt-6-luna`; её можно изменить переменной `OPENAI_MODEL` на модель, доступную вашему аккаунту. Клиентских UI-фреймворков и сторонних runtime-пакетов нет.

Поток данных: выбор мер → проверка правил → детерминированный результат → карта и прогноз. Запрос на сохранение или AI-анализ передаёт план серверу, который повторяет расчёт. База хранит проверенный план, а модель получает каталог допустимых фактов и рекомендаций.

| Компонент | Ответственность |
|---|---|
| `simulator.js` | Единственный источник официальных констант, проверки и формулы |
| `app.js`, `index.html`, `styles.css` | Игровой интерфейс, калькулятор и вывод результата |
| `game/session.js`, `game/storage.js` | Одна сессия плана и валидируемые локальные сохранения |
| `game/cloud.js`, `game/account-ui.js`, `game/cloud-panel.js` | Вход, синхронизация, история и рейтинг |
| `game/forecast.js`, `game/advisor.js` | Проверенные варианты улучшения и локальный помощник |
| `api/analyze.js`, `backend/analysis.js` | Повторный расчёт на сервере, запрос к OpenAI и проверка выбранных фактов |
| `api/player.js`, `api/runs.js`, `api/leaderboard.js` | Профили, история и рейтинг через авторизованные запросы |
| `backend/storage.js`, `backend/local-storage.js` | Supabase и локальное серверное хранилище |
| `scene/` | SVG-карта, проекции, слои, аким, транспорт и воспроизведение |
| `game/art.js`, `assets/exports/` | Реестр и готовые художественные ресурсы |
| `server.js` | HTTP-сервер с разрешёнными публичными путями и ограничением тела API |

Игра, калькулятор, история и советник используют один движок. AI получает уже вычисленные факты; ответ проверяется по разрешённым идентификаторам фактов. История из базы повторно проверяется перед восстановлением в интерфейсе.

### Границы доверия и prompt injection

Вопрос пользователя не даёт права менять формулу, баллы или серверные настройки. Модель выбирает идентификаторы из подготовленного сервером каталога фактов; сервер отклоняет неизвестные идентификаторы и формирует текст из соответствующих проверенных записей. Тесты API проверяют подмену клиентского балла, недопустимые планы и выдуманные ответы провайдера. Это конкретные ограничения приложения, а не заявление об универсальной защите от всех атак на LLM.

## Проверки

```powershell
npm test
node tools/check-assets.mjs
```

Проверяются официальные контрольные значения, ограничения плана, сессия/черновики, графика, карта, серверные маршруты, аутентификация и проверка AI-ответов. Моки внешних API в тестах не доказывают доступность живого провайдера.

Дополнительные браузерные сценарии находятся в `tests/browser-smoke.mjs` и `tests/integration-browser.mjs`. Для них отдельно нужны Chrome и Playwright; приложение от Playwright не зависит. Задайте `AKIM_TEST_URL` на адрес запущенного сервера и при внешней установке `PLAYWRIGHT_MODULE_PATH` на абсолютный путь пакета. Артефакты проверки сохраняются локально и не входят в deliverable.

Пример запуска браузерной проверки в PowerShell после отдельной установки Playwright и запуска сервера:

```powershell
$env:AKIM_TEST_URL = 'http://127.0.0.1:3000'
node tests/integration-browser.mjs
node tests/browser-smoke.mjs
```

## Если запуск не удался

| Симптом | Что проверить |
|---|---|
| `node` или `npm` не найден | Установите Node.js 18+ и заново откройте терминал; проверьте `node --version` |
| PowerShell запрещает запуск `npm.ps1` | Используйте `npm.cmd start` и `npm.cmd test`, не меняя системную политику |
| `EADDRINUSE` | Порт занят: задайте другой `PORT`, как в примере выше |
| Пустая страница при открытии файла | Откройте HTTP-адрес работающего сервера, а не `file://` |
| Карта загружается медленно | Дождитесь загрузки локальных геоданных; расчёт доступен отдельно от карты |
| AI недоступен или `AI_AUTH_FAILED` | Проверьте серверный ключ, модель и квоты; перезапустите сервер после изменения `.env` |
| История Supabase недоступна | Проверьте URL, серверный ключ и применение миграции; для автономной демонстрации используйте локальное хранилище |

`npm start` — локальный запуск, а не публикация в интернете. На сервере должны работать и HTTP API, и выдача статических ресурсов; одного размещения HTML на GitHub Pages недостаточно для AI и облачных профилей. Переменные окружения и миграцию настраивают отдельно в выбранном хостинге. Пуш кода не переносит локальные ключи в окружение хостинга.

## Выбор города и объединённая карта

В шапке можно выбрать **Астану, Алматы или Шымкент**. Все три карты используют локальные снимки доступных объектов OpenStreetMap внутри указанных границ: улицы, здания, воду и зелёные зоны. Числовая модель кейса доступна только для Астаны. При переходе в другой город её панели расчёта скрыты, а план и результат сохраняются до возврата.

Полные слои хранятся в gzip; сервер выдаёт их по разрешённым GeoJSON-адресам. SVG отображает геометрию видимой области, объединяя дороги и здания в группы путей. Это уменьшает число DOM-элементов без искусственного лимита количества видимых зданий. Данные загружаются при выборе города; объём полной карты влияет на первый запуск. Источники и границы: [реестр городских карт](scene/data/cities/README.md).

Проверка переходов между городами, сохранности плана и нового интерфейса: `node tests/sync-browser.mjs` (те же Chrome/Playwright и переменные окружения, что выше).

## Данные, ресурсы и ограничения

Формула и числовой набор взяты из организаторского «Датасета районов», задача — из кейса «Аким на 5 часов». География не является источником числовых показателей модели. Карта использует отобранные OSM/городские GIS-данные, собственный SVG-рендерер и локальные художественные ресурсы, без загрузки полной базы организаций.

- [Источники геоданных и ограничения](scene/data/astana/SOURCES.md)
- [Описание карты](scene/data/astana/INTEGRATION.md)
- [Происхождение графики](assets/game/SOURCES.md)
- [Проверка требований кейса](docs/REQUIREMENTS-AUDIT.md)

Это 2.5D-проекция, не полноценный 3D-движок. Высоты, население сцены и движение транспорта иллюстративны. Прогулка ограничена Нурой; рекомендации ищут допустимые улучшения одной заменой, а не гарантируют глобальный оптимум. Права на отдельные исходные художественные заготовки и актуальность муниципальных контуров требуют отдельной проверки по реестрам источников.

Живой AI требует действующего ключа и доступной модели. Во время интеграции выполнен контрольный запрос к OpenAI с HTTP 200, `source=openai`, `grounded=true` и проверенным баллом `56.54307`; сведения об этой проверке и Supabase приведены в [отчёте об интеграциях](docs/INTEGRATIONS.md). Эти результаты относятся к проверенному окружению команды и не гарантируют доступность чужих ключей или будущего развёртывания. Локальный помощник отдельно обозначен и не выдаётся за генеративный AI. Подтверждённый публичный URL в этой версии README не заявлен.
