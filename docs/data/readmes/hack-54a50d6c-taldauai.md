# TaldauAI — протокол совещания с проверяемыми поручениями

Локальный прототип для секретаря: запись → транскрипт → говорящие → поручения и саммари → ручная проверка → DOCX → контроль сроков. Он помогает фиксировать поручения, ответственных и сроки, которые легко потерять при ручном протоколировании. **Результат ИИ — черновик, а не утверждённый протокол.**

**Финальная интеграция 23.09.2026:** объединены ML/backend, редактор с ручной проверкой, уведомления, новый интерфейс и лендинг фронтендера `dc4cd0f`. Лендинг открывается на `/`, рабочее приложение — на `/app`. Старые адреса перенаправляются. История проверок и ограничения приведены ниже.

## Возможности и статус требований

| Требование | Фактическое состояние |
|---|---|
| Русский, казахский, смешанная речь | Локальный Mixed CTC; Whisper — альтернатива. Есть синтетические языковые проверки; ошибки на естественной речи сохраняются |
| Диаризация | Локальная pyannote, метки голосов и ссылки на реплики. `SPEAKER_00` — **не установленная личность** |
| Исполнитель, действие, срок | Qwen через локальную Ollama; возможны пропуски, дубли, ошибки имени и даты |
| Саммари | Тема, обсуждение, решения и открытые вопросы при наличии опоры в транскрипте; структурированные поручения |
| Ручная проверка | Переименование участников; исправление текста/срока; свободный ввод внешнего ответственного; добавление, удаление и отдельное подтверждение поручений |
| Экспорт | DOCX после подтверждения всех поручений. PDF не реализован; DOCX покрывает вариант «PDF/DOCX» |
| Контроль | Статусы исполнения, срочность, общий журнал автоматических локальных напоминаний |
| Ввод записи | Файл; микрофон; на `/live` — микрофон и звук выбранной вкладки при поддержке браузера. Обработка после остановки и отправки |
| Teams / Zoom / Google Meet | Бот-участник и прямая интеграция отсутствуют. Запись вкладки не является такой интеграцией |
| Дополнительные функции | СЭД, идентификация по тембру, email/мессенджер-рассылка отсутствуют |

Для новых автоматически извлечённых поручений реализована предварительная классификация срочности **по сроку**, а не по смыслу: до 2 дней включительно и просрочка — высокая, 3–7 дней — средняя, более 7 дней — низкая. Без даты используется средняя срочность без выдумывания срока. Расчёт выполняется на день обработки в `TALDAU_TIMEZONE`; результат остаётся на ручную проверку. Старые и вручную добавленные поручения не пересчитываются; после изменения даты секретарь проверяет срочность самостоятельно. Классификация по направлению не реализована.

При работающем backend напоминания создаются автоматически за два дня до срока, в день срока и отдельно при просрочке, только для подтверждённых незавершённых поручений. Интервал по умолчанию — 60 секунд; уникальность версии поручения и вида уведомления предотвращает повторы. `/notifications` — **общий локальный журнал**, фильтр по имени не является личным кабинетом или доставкой адресату. Сценарий персональной автоматической рассылки выполнен частично. Ручной `/remind` формирует текст, но не отправляет email.

## Архитектура и данные

```text
Браузер → React/Vite → /api → FastAPI
                              ├─ аудио → backend/data/uploads/
                              ├─ BackgroundTasks → Python ml.process_meeting
                              │   ffmpeg → Mixed CTC / Whisper → pyannote
                              │   → необязательная KazLLM → Qwen/Ollama → JSON
                              └─ SQLAlchemy → PostgreSQL
                                  → редактор / подтверждение / DOCX / уведомления
```

ML вызывается **внутри процесса API**, не отдельным HTTP-сервисом. Backend и ML устанавливаются в **одно Python-окружение**. Тяжёлые задачи последовательно проходят через внутрипроцессную блокировку. Запускайте **один Uvicorn worker, без `--reload`**. Это не долговечная очередь: после аварии незавершённая задача сама не возобновляется, запись нужно загрузить заново. Готовые результаты и правки остаются в PostgreSQL.

В БД хранятся совещания, путь к аудио, согласие, дата, участники, сегменты, поручения, саммари, предупреждения, исходный ML JSON и уведомления. Аудио находится в файловой системе. Схема создаётся миграциями Alembic; личный дамп и `seed` для реальной обработки не нужны.

[Адаптер](backend/app/services/ml_adapter.py) валидирует JSON v1, а не извлекает поля заново из прозы. Исходный ASR-текст и таймкоды сохраняются; `source_segment_ids` связывают поручения с репликами, `warnings` показывают ограничения. Полный ответ ML и его исходный `needs_review` хранятся отдельно от человеческого подтверждения: каждое новое поручение требует ручной проверки. `suggested_name` и `assignment_quote` сохраняются в сыром JSON, отдельного интерфейса для этих полей нет. При наличии KazLLM UI показывает `suggested_text` рядом с исходным текстом.

Результат сохраняется одной транзакцией. Исключение переводит совещание в `failed`; отсутствие модели не подменяется демоданными. Подтверждение требует ответственного и даты: если срок не прозвучал, секретарь должен уточнить его, модель не должна выдумывать дату.

Редактирование требует `expected_revision`, устаревшая версия получает 409. Сначала сохраняются правки, затем отдельно подтверждается новая версия. Изменение текста, исполнителя, срока, срочности или имени связанного участника снимает подтверждение. Отметка «Проверено» появляется после успешного ответа API; статус исполнения меняется отдельно.

Саммари проверяет дословные цитаты в сегментах, но совпадение цитаты не гарантирует правильность её толкования. При сбое генерации остаются отмеченные выдержки и предупреждение. Ручные изменения поручений не обновляют саммари автоматически. Из `backend/` можно обновить его без повторного ASR командой `../.venv/bin/python -m app.refresh_summary MEETING_ID` (PowerShell: `..\.venv\Scripts\python.exe -m app.refresh_summary MEETING_ID`). Команда учитывает текущие поручения, сохраняет исходный ML JSON и проверяет версии перед записью.

## Окружение и зависимости

Проверено: **macOS 26.5.2 arm64, Apple M4 Pro, 24 GiB объединённой памяти**, Python **3.11.15**, Node **25.8.0**, npm **11.11.0**, ffmpeg **9.0.2**, PostgreSQL **16**. ASR/диаризация — `TALDAU_DEVICE=cpu`; Ollama управляет ускорением самостоятельно. Это характеристики проверенной машины, **не минимальные требования**. Пиковая память и минимальное железо не измерены. Windows, WSL2, Linux и CUDA в этой проверке не запускались.

Используйте Python **3.11**. Для других версий отдельно проверяйте совместимость ML wheels. Установка FastAPI не доказывает совместимость torch/pyannote. Node 25 использован при проверке; полный прогон с другой версией не заявляется.

## Установка и запуск

- **[macOS — Terminal, zsh/bash](docs/SETUP_MACOS.md)**: полный путь установки и запуска.
- **[Windows — PowerShell и отдельный вариант WSL2](docs/SETUP_WINDOWS.md)**: без заявления о проверке Windows, с обнаруженными рисками совместимости.
- **[Модели, доступ и лицензии](docs/MODELS.md)**: подготовка весов до запуска.

Порядок: чистый клон → единая `.venv` в корне → зависимости → `backend/.env` → PostgreSQL → миграции → веса/Ollama → doctor → API → frontend → приёмка ниже. Для сдачи используйте объединённую ветку `main`.

`docker compose up -d postgres` поднимает **только PostgreSQL**. По умолчанию: БД `127.0.0.1:5433`, API `127.0.0.1:8000`, UI `http://127.0.0.1:5173`, Ollama `127.0.0.1:11434`. Vite проксирует `/api` в backend. Swagger: `http://127.0.0.1:8000/docs`. Публичная deployed-версия не заявляется.

`/api/health` проверяет API и БД, **не модели**. `ml.doctor` проверяет наличие файлов/модулей/моделей Ollama, но не заменяет inference. Запущенный frontend также не доказывает работоспособность всего приложения.

## Переменные окружения

`backend/.env` читает `app.config`; переменные процесса имеют приоритет. После изменения перезапустите API. Относительные пути ASR, диаризации и фикстуры в backend разрешаются от **корня репозитория**. Отдельный `python -m ml` не читает `.env`: передайте переменные и запускайте из корня либо используйте абсолютные пути. Корневой `.env` не является конфигурацией API.

| Параметр backend | По умолчанию в коде | Реальный запуск / назначение |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg://postgres:postgres@localhost:5433/taldau` | Согласовать с БД; это пример локальной учебной БД |
| `ASR_BACKEND` | `local_ml` | `local_ml` |
| `LLM_BACKEND` | `local_ml` | `local_ml` |
| `TALDAU_TIMEZONE` | `Asia/Almaty` | Часовой пояс дат и напоминаний |
| `TALDAU_ASR_ENGINE` | `whisper` в ML | **`mixed-ctc`**, как в примере `.env` |
| `TALDAU_ASR_MODEL` | Не задан | Обязательно `models/mixed-stt` |
| `TALDAU_DIARIZATION_MODEL` | Не задан | Обязательно `models/speaker-diarization-community-1` |
| `TALDAU_LLM_MODEL` | `qwen2.5:7b` | Локальная модель поручений и саммари |
| `TALDAU_SUMMARY_MODEL` | Используется `TALDAU_LLM_MODEL` | Необязательно `qwen2.5:14b`, после установки |
| `TALDAU_KAZLLM_MODEL` | Не задан | Необязательная коррекция; базовый запуск — отключено |
| `TALDAU_OLLAMA_URL` | `http://127.0.0.1:11434` | Только loopback HTTP, без облачного fallback |
| `TALDAU_DEVICE` | `cpu` | `cuda` требует отдельной подготовки и проверки |
| `TALDAU_ML_RESULT_FIXTURE` | Не задан | **Не задавать**: непустой путь имеет приоритет над настоящим ML |

`frontend/.env` читает Vite отдельно; после изменений перезапустите Vite:

| Параметр | По умолчанию | Пример |
|---|---|---|
| `VITE_USE_MOCKS` | Выключено, включается только строкой `true` | `false` для API-приёмки |
| `TALDAU_API_PROXY` | `http://127.0.0.1:8000` | Адрес API для dev proxy |

Переменные процесса Vite также могут перекрывать `.env`. `TALDAU_DB_PORT` относится к Compose: при смене порта измените и `DATABASE_URL`. Инструкции создают `.env` только при отсутствии и не перезаписывают существующие настройки.

## Настоящий сценарий приёмки

1. Откройте лендинг `http://127.0.0.1:5173` и перейдите в приложение `/app`. Используйте React-приложение, не отдельные HTML-макеты с демоданными.
2. Создайте совещание, дата **23.09.2026**. Подтвердите уведомление участников и согласие на запись/ИИ-обработку. Флажок фиксирует заявление оператора, а не заменяет реальное уведомление.
3. Загрузите [acceptance_mixed.wav](examples/audio/acceptance_mixed.wav), укажите **2** говорящих. Это синтетический вымышленный диалог из [сценария](examples/acceptance_scenario.json).
4. Дождитесь `done`. Не перезапускайте API во время обработки. При `failed` изучите сообщение и журнал backend.
5. Проверьте транскрипт, таймкоды, говорящих, саммари, предупреждения и источники поручений. Метки голосов могут переставиться между запусками.
6. Только теперь сравните с [эталоном](examples/acceptance_reference.json): два поручения — договор к 24.09.2026 и отчёт к 25.09.2026. **Эталон не передаётся модели**; дата и число участников — исходные метаданные, не готовые ответы.
7. Проверьте имена по репликам. Исправьте участника, ответственного (можно внешний отдел), срок. Сохраните. Добавьте пропущенное поручение и удалите ошибочное/дублированное.
8. Подтвердите каждое поручение отдельно. При ошибке API подтверждение не должно выглядеть сохранённым; после изменения требуется новая проверка.
9. Скачайте DOCX, откройте и сравните с правками. До подтверждения всех поручений экспорт блокируется.
10. Проверьте `/tasks` и `/notifications`. Уведомления зависят от текущей даты. В отдельной тестовой БД можно создать подтверждённое тестовое поручение с сегодняшним/прошедшим сроком и дождаться интервала сканирования.
11. После завершения обработки остановите API через Ctrl+C и запустите той же командой. Обновите UI: результат, правки и DOCX должны сохраниться. Для проверки БД используйте `docker compose restart postgres`, без удаления volume.

Одна смешанная запись не оценивает все языковые режимы. Отдельно проверьте русский, казахский и смешанный WAV с известным текстом; для полного языкового сценария нужны два голоса, поручение и срок в каждом. [ML_EVALUATION.md](ML_EVALUATION.md) содержит результаты пяти коротких синтетических ASR-примеров. Реальные демонстрационные записи анонимизируйте и не публикуйте без разрешения.

## Безопасность и ограничения

В реальном режиме аудио получает локальный backend; ffmpeg/ASR/pyannote работают локально. Ollama получает текст сегментов, метаданные и инструкции для извлечения/саммари, не исходное аудио. ML задаёт offline-режим Hugging Face, отключает телеметрию pyannote/ONNX Runtime и разрешает Ollama только на loopback без proxy/redirect. Интернет нужен для первоначальной установки. Для закрытого контура заранее подготовьте пакеты, Docker-образ, полные веса и повторите приёмку с отключённой внешней сетью. Полного сетевого аудита в этой проверке не было.

`localhost` внутри Docker/WSL — другая среда. Базовая конфигурация запускает API и Ollama на одном хосте, в Docker — только БД. Для WSL запускайте Ollama рядом с backend в той же среде. Не заменяйте её внешним облачным API.

Прототип **не готов для чувствительных корпоративных данных без доработки**: нет авторизации, ролей, TLS в приложении, прикладного шифрования записей/БД и полноценного аудита. Не публикуйте API/БД в интернете. `backend/data/uploads`, PostgreSQL и диагностические результаты требуют контроля доступа ОС. Удаление поручения реализовано; удаления совещания вместе с аудио через UI/API и автоматической политики хранения нет. Удаление поручения не удаляет исходную запись и сырой ML JSON.

Остаются ошибки ASR/диаризации, неопределённые имена, пропуски/дубли поручений, неоднозначные сроки и ошибки смысла саммари. CPU-обработка длинных записей может быть длительной. Нет долговечной очереди/восстановления, персональной доставки уведомлений, PDF, СЭД и бота видеоконференций. Windows/WSL, CUDA, полный автономный запуск без сети и масштабирование не подтверждены.

## Диагностика

| Симптом | Действие |
|---|---|
| PostgreSQL недоступен | Docker запущен; из корня `docker compose ps`, `docker compose exec postgres pg_isready -U postgres -d taldau`; порт совпадает с URL |
| Занят 5433 | Другой `TALDAU_DB_PORT` и тот же порт в `DATABASE_URL`; не запускайте две БД на одном порту |
| Занят 8000 / 5173 | Остановите свой прежний процесс либо выберите другой порт; обновите proxy. `--strictPort` не даст Vite незаметно сменить порт |
| Неверный URL БД | Формат `postgresql+psycopg://user:password@host:port/database`, правильное окружение и отсутствие старой переменной процесса |
| Нет таблиц | Из `backend/` тем же Python: `-m alembic upgrade head`, затем `current` и `check` |
| Нет onnxruntime/torch/pyannote | Проверьте `python -c "import sys; print(sys.executable)"`; ML requirements должны стоять в окружении API |
| Нет ffmpeg | Установите системный ffmpeg; `ffmpeg -version` должен работать в терминале API |
| Не найдены веса | Doctor с backend config, правильный engine и полный каталог. Отдельный CLI не читает `.env` |
| Ollama / модель недоступна | `ollama list`, `/api/tags`, один `ollama serve`; заранее `ollama pull qwen2.5:7b` |
| Не хватает памяти | Остановите лишние ML-процессы, отключите необязательные KazLLM/14B, один worker, короткий WAV |
| Windows-путь / PowerShell / WSL | См. отдельную инструкцию; не переносите macOS `.venv` в Windows; Ollama в той же среде |
| CORS / UI не видит backend | Открывайте через Vite; проверьте `/api`, proxy и health. Не открывайте `index.html` напрямую |
| Подозрительно быстрый результат | Уберите фикстуру и `stub`, выключите `VITE_USE_MOCKS=true`, перезапустите API/Vite |
| `failed` | Смотрите `error_message` и stderr API; исправьте причину, загрузите заново. Фикстура не является исправлением |
| Задача прервана перезапуском | Очередь не восстанавливается; повторно загрузите запись, не очищайте БД |
| DOCX заблокирован | `done`, заполненные исполнитель/дата, сохранение и отдельное подтверждение всех задач |
| `@/api` не найден / маркеры конфликтов | Проверьте `src/api.ts`, Vite config и `git status`; согласованно завершите merge. Скрытие overlay ошибку не исправляет |

Остановка: дождитесь обработки, Ctrl+C у API/Vite, `docker compose stop postgres` из корня. Повторный запуск: PostgreSQL, Ollama, API, Vite. **Не используйте `docker compose down -v` для остановки или ремонта — он удаляет данные.**
