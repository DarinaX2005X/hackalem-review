# EKT AI — AI-консультант по электротехническим товарам

Хакатон-прототип помощника для покупателей **ekt.kz**: консультация на естественном языке, поиск товаров по названию или артикулу, просмотр характеристик и добавление выбранных позиций в демонстрационную корзину.

Проект помогает покупателю сформулировать требования к электротехническому товару и найти варианты в подключённом каталоге. В репозитории есть веб-интерфейс, HTTP API, AI-агент и отдельно собираемый виджет для встраивания на страницу.

**Статус:** прототип. Серверная корзина общая для всех пользователей одного процесса; оформление заказа не реализовано. AI подключён в основном чате, но не в плавающем виджете.

**Репозиторий:** [BAITC-Hacks/hack-3b719372-avengers](https://github.com/BAITC-Hacks/hack-3b719372-avengers).

Описание проверено 23 сентября 2026 года по исходникам архива `hack-3b719372-avengers-main.zip`, совпадающим с кодом коммита [`08ea0d3`](https://github.com/BAITC-Hacks/hack-3b719372-avengers/tree/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39) без учёта переводов строк. Значения секретов из `.env` не использовались в документе.

## Что реализовано

| Возможность | Реализация и границы |
| --- | --- |
| AI-консультация | Основной чат отправляет сообщение и историю на `/api/chat`. Агент использует OpenAI Responses API и модель `gpt-5-mini`. |
| Поиск для AI | Модели доступен инструмент `search_products`, вызывающий поиск backend по каталогу. |
| Поиск в интерфейсе | Отдельная форма поиска по названию или артикулу; карточки дополняются данными из endpoint деталей товара. |
| Карточки товаров | Название, артикул, цена в ₸, наличие, изображение при наличии URL, доступные характеристики, складские остатки и ссылка на товар. |
| Фильтрация | В основной странице — фильтр «Только в наличии» и сортировка полученных результатов по цене. |
| Корзина | Добавление после подтверждения, проверка остатка на backend, просмотр количества и суммы. API также поддерживает изменение количества, удаление и очистку. |
| Встраиваемый виджет | Поиск по каталогу, карточки, подтверждение количества перед добавлением, просмотр серверной корзины. Стили изолированы через Shadow DOM. |
| Обработка ошибок | Тайм-ауты запросов, сообщения о недоступности сервисов, повтор поиска/отправки через интерфейс. |
| Демо без backend | Основная страница умеет искать по трём встроенным тестовым товарам и хранить локальную корзину в браузере. Ограничение демочата описано ниже. |

Системный промпт предписывает агенту отвечать на языке покупателя, уточнять параметры, не выдумывать товары, цены и наличие и показывать не более трёх вариантов. Это инструкции модели, а не программная гарантия корректности ответа.

## Как работает решение

1. Покупатель открывает основную страницу и пишет, например: «Найди автомат на 16 А».
2. Frontend передаёт текст и историю диалога в `POST /api/chat`.
3. Backend вызывает AI-агента. При вызове моделью `search_products` агент получает товары через модуль поиска backend.
4. Backend запрашивает страницы каталога EKT с HTTP Basic Auth. Поиск сопоставляет слова запроса с названием и артикулом и ранжирует товары по числу совпадений.
5. Агент передаёт результат поиска модели и получает текстовый ответ. Backend возвращает `answer` и обновлённую `history`.
6. Для просмотра карточек покупатель использует отдельную форму поиска либо плавающий виджет. Frontend дополнительно запрашивает детали найденных товаров.
7. После нажатия «В корзину» и подтверждения backend проверяет количество по данным каталога и обновляет свою демо-корзину.

**Текст AI и карточки — разные потоки:** ответ `/api/chat` сам по себе не заполняет панель карточек. Плавающий виджет обращается к поиску напрямую и не вызывает AI.

## Архитектура

```text
Основная страница React
  ├─ AI-чат → POST /api/chat → ai.agent → OpenAI Responses API
  │                              └─ search_products → backend.products
  ├─ Поиск → GET /api/search ────────────────────────────┘
  ├─ Карточки → GET /api/products/{id} → backend.ekt_api → API EKT

```

## Установка и запуск

### 1. Подготовить окружение

Нужны Git для клонирования, Python, Node.js и npm, а для полноценной демонстрации — доступ к OpenAI и API каталога EKT.

- Для повторения исходного окружения можно использовать **Python 3.12**: включённое в репозиторий окружение было создано на 3.12.3. Формальный диапазон поддерживаемых версий Python проект не задаёт.
- Для frontend используйте **Node.js 22.12 или новее**. В lock-файле Vite и его React-плагин требуют `^20.19.0 || >=22.12.0`.
- Не используйте включённый в архив `backend/venv`: он содержит пути к компьютеру автора. Создайте новое окружение.

Ниже команды для **Windows PowerShell**. Если команда `py -3.12` сообщает `No suitable Python runtime found`, сначала установите Python 3.12; наличие `.venv` не устанавливает отсутствующий интерпретатор. Доступные версии показывает `py --list`.

```powershell
git clone https://github.com/BAITC-Hacks/hack-3b719372-avengers.git
cd hack-3b719372-avengers
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m pip install openai
```

При работе с ZIP распакуйте его и откройте терминал в папке с `ai`, `backend` и `frontend`; вместо клонирования выполните команды начиная с создания `.venv`. Активация окружения не нужна: команды используют его интерпретатор напрямую.

### 2. Настроить доступ к сервисам

Локально создайте или отредактируйте `ai/.env`:

```dotenv
OPENAI_API_KEY=YOUR_OPENAI_API_KEY
```

Локально создайте или отредактируйте `backend/.env`:

```dotenv
EKT_API_URL=https://your-catalog-api.example/base
EKT_API_USERNAME=YOUR_EKT_USERNAME
EKT_API_PASSWORD=YOUR_EKT_PASSWORD
```

Это **заполнители**, не рабочие учётные данные. Адрес базового API и доступ выдаёт владелец интеграции. `EKT_API_URL` укажите без завершающего `/`: код добавляет `/products` и `/products/detail` самостоятельно. Для OpenAI нужен ключ с доступом к используемой модели и доступной квотой.

| Переменная | Где используется |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI SDK; `ai/agent.py` загружает `ai/.env` |
| `EKT_API_URL` | Базовый URL каталога; `backend/ekt_api.py` |
| `EKT_API_USERNAME` | Имя пользователя для HTTP Basic Auth |
| `EKT_API_PASSWORD` | Пароль для HTTP Basic Auth |
| `VITE_API_URL` | Адрес backend для frontend (локальный или публичный), задаётся при запуске/сборке Vite |

Секреты должны оставаться на стороне backend. Не помещайте ключ OpenAI или пароль EKT в переменные `VITE_*`, HTML или исходники frontend. В поставке уже присутствуют `.env`; не переносите их значения в README и не публикуйте свои ключи. Если находящиеся в Git значения действующие, их следует заменить у провайдера. `frontend/.gitignore` не защищает файлы в соседних `ai/` и `backend/` и содержит маркеры конфликта слияния.

### 3. Запустить backend

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
```

- Проверка процесса: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health).
- Интерактивная документация FastAPI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

OpenAI-клиент создаётся при импорте приложения, поэтому без `OPENAI_API_KEY` запуск может завершиться ошибкой ещё до обращения к чату. Успешный `/health` подтверждает работу приложения, но не проверяет доступность EKT или OpenAI.

### 4. Запустить frontend

Во втором терминале, из корня проекта:

```powershell
cd frontend
npm ci
$env:VITE_API_URL = "http://127.0.0.1:8000"
npm run dev -- --host 127.0.0.1 --port 5173
```

Откройте адрес, напечатанный Vite; при свободном порте это [http://127.0.0.1:5173](http://127.0.0.1:5173). Оставьте оба терминала работающими: закрытие процесса backend или frontend остановит соответствующую часть приложения.

Вместо переменной терминала можно создать `frontend/.env.local` с `VITE_API_URL=http://127.0.0.1:8000`. После изменения настройки перезапустите Vite. Если адрес пуст, основная страница переходит в деморежим, а виджет не выполняет реальный поиск.

### 5. Собрать frontend и виджет

В каталоге `frontend`, с настроенным `VITE_API_URL`:

```powershell
npm run build
npm run build:widget
npm run preview -- --host 127.0.0.1 --port 4173
```

Основная сборка попадает в `frontend/dist`, отдельный виджет — в `frontend/dist-widget/widget.js`. `preview` предназначен для локальной проверки основной сборки; backend запускается отдельно.

Пример подключения виджета после размещения `widget.js` на своей странице:

```html
<script
  src="/widget.js"
  data-ekt-widget
  data-api-base="http://127.0.0.1:8000"
></script>
```

Это пример локальной интеграции. Адрес backend для отдельного виджета задаётся во время загрузки через `data-api-base`. Основная страница уже монтирует виджет сама.

Основания: [настройка API](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/backend/ekt_api.py), [frontend API](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/frontend/src/api.js), [точка входа виджета](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/frontend/src/widget/entry.jsx), [конфигурация сборки](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/frontend/vite.widget.config.js).

## Как проверить решение жюри

### Сценарий с подключёнными сервисами

1. Запустите backend и frontend по инструкции выше.
2. Проверьте `/health`: ожидается `{"status":"healthy"}`.
3. В отдельной форме каталога найдите товар по известному артикулу из доступного каталога. Если артикула нет, попробуйте короткий запрос «автомат». Конкретные результаты зависят от данных API и охваченных поиском страниц.
4. Откройте «Характеристики и склады» у результата. Проверьте отображение цены, наличия и доступных параметров. Отсутствующие сведения не должны восприниматься как подтверждённые.
5. Выберите доступный товар с указанной ценой, нажмите «В корзину», подтвердите добавление и откройте корзину. Должны появиться позиция, количество и сумма. Реальный заказ при этом не создаётся.
6. В основном AI-чате отправьте «Найди автомат на 16 А», затем уточните запрос. Ожидается текстовый ответ от модели; точное содержание заранее не фиксируется.
7. Откройте плавающий «Помощник EKT» и выполните поиск по артикулу. Это проверка отдельного поискового виджета, а не ещё одного AI-чата.

Без доступа к внешним сервисам можно проверить только демопоиск основной страницы: уберите `VITE_API_URL` из окружения и `.env.local`, перезапустите Vite и найдите `Schneider`. Результат берётся из встроенных тестовых данных. Демо-корзина хранится в `localStorage`; её цены и наличие не являются данными EKT.

### Проверка HTTP API

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/health"
$query = [uri]::EscapeDataString("автомат")
Invoke-RestMethod "http://127.0.0.1:8000/api/search?q=$query"

$payload = @{ message = "Найди автомат на 16 А"; history = @() } | ConvertTo-Json -Depth 10
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/chat" -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
```

Для следующего сообщения передайте массив `history` из предыдущего ответа. Endpoint чата возвращает `answer` и `history`, а не массив карточек товаров.

### Автоматические проверки

Из корня проекта, после установки Python-зависимостей:

```powershell
$env:OPENAI_API_KEY = "test-placeholder"
.\.venv\Scripts\python.exe -m unittest backend.test_reliability -v
Remove-Item Env:OPENAI_API_KEY
```

Запускайте этот блок в отдельном тестовом терминале. Временное значение нужно только для создания OpenAI-клиента при импорте; тесты подменяют сетевые зависимости и не требуют настоящего ключа. Удаление переменной позволяет при следующем запуске прочитать ключ из `ai/.env`.

В файле три тестовых метода: совместное использование кеша при параллельном поиске и ранжирование, обновление кеша после истечения срока и ошибки, безопасные HTTP-ошибки чата. Это не полная проверка приложения: тесты не проверяют реальную сеть, качество ответов модели или браузерный сценарий. В `package.json` нет команды `test`; доступны команды сборки.

## HTTP API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Статус backend и сообщение |
| GET | `/health` | Статус процесса |
| GET | `/api/products?page=1` | Страница внешнего каталога |
| GET | `/api/products/{product_id}` | Детали товара |
| GET | `/api/search?q=...` | Поиск; ответ содержит `query`, `count`, `products` |
| POST | `/api/chat` | JSON с `message` и `history`; ответ с `answer` и `history` |
| GET | `/api/cart` | Корзина: `items`, `total`, `items_count` |
| POST | `/api/cart/add?product_id=...&quantity=1` | Добавить товар |
| PATCH | `/api/cart/{product_id}?quantity=...` | Изменить количество; `0` удаляет позицию |
| DELETE | `/api/cart/{product_id}` | Удалить позицию |
| DELETE | `/api/cart` | Очистить общую корзину |

Параметры добавления и изменения количества передаются в query string, а не JSON. Изменения корзины затрагивают общую демо-корзину текущего процесса.

Для чата предусмотрены ответы `504` при тайм-ауте, `503` при лимите/квоте OpenAI, `502` при ошибке внешней зависимости и `500` при неожиданной ошибке. Это поведение маршрута, не результат проверки доступности конкретных сервисов.

Основание: [backend/main.py](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/backend/main.py).

## Данные и интеграции

- **Каталог EKT:** backend обращается к `${EKT_API_URL}/products?page=...` и `${EKT_API_URL}/products/detail?id=...` с HTTP Basic Auth. Подключённый адрес определяется локальной настройкой; домен `ekt.kz` сам по себе не является подтверждённым адресом этого API.
- **OpenAI:** агент отправляет историю диалога, а при поиске — также найденные записи каталога, в Responses API. Модель указана в коде как `gpt-5-mini`.
- **История:** frontend хранит её в состоянии React и передаёт с каждым запросом. Постоянное серверное хранилище диалогов не реализовано.
- **Кеш:** поисковый каталог хранится в памяти на 60 секунд. Обновление страниц выполняется пулом до пяти потоков с блокировкой одновременного обновления.
- **Тестовые данные:** три товара в `frontend/src/main.jsx` используются только в демопоиске. `TEST_PRODUCTS` в `ai/tools.py` не используется текущей функцией поиска и не служит резервным каталогом при ошибке API.

Основания: [поиск и кеш](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/backend/products.py), [AI-инструмент](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/ai/tools.py), [загрузка деталей на frontend](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/frontend/src/catalog.js).

## Ограничения текущей версии

1. **Корзина не персональная и не постоянная.** Она хранится в глобальном словаре Python, общая для запросов одного процесса и теряется при перезапуске. Несколько процессов будут иметь разные корзины. Авторизация пользователей и сессионное разделение не реализованы.
2. **Нет оформления заказа.** Backend не отправляет корзину в магазин; платёжные, заказные и доставочные endpoints отсутствуют.
3. **AI не управляет корзиной.** Единственный инструмент агента — `search_products`. Отдельного инструмента получения деталей товара у модели также нет. Упоминание подтверждения корзины в промпте не добавляет эту возможность.
4. **Поиск ограничен.** По умолчанию загружаются первые 10 страниц; возвращается максимум 20 результатов. Это совпадение слов по подстрокам названия и артикула, без семантического поиска, морфологии и проверки технической совместимости. Пустой результат не доказывает отсутствие товара во всём каталоге.
5. **AI-ответ и карточки не синхронизированы автоматически.** Карточки формируются отдельным поиском; виджет не подключён к `/api/chat`.
6. **Редактирование серверной корзины ограничено в UI.** Основная страница отключает изменение количества и удаление при подключённом backend, хотя соответствующие API-маршруты есть. Виджет позволяет выбрать количество при добавлении и просмотреть корзину.
7. **Вложения не отправляются.** Виджет проверяет расширение и размер до 10 МБ для JPEG, PDF, Excel и Word, показывает предпросмотр JPEG, но загрузка и обработка файлов отсутствуют. Выбранное вложение блокирует отправку текста до удаления.
8. **Демочат содержит несогласованность полей.** Демоответ создаётся с полем `message`, а вывод читает `answer`, поэтому без backend ответ может отображаться пустым. Демо следует показывать через поиск тестовых товаров, не как работающую AI-консультацию.
9. **Нет полной изоляции и защиты публичного сервиса.** CORS разрешает все origins, собственная авторизация и ограничение частоты запросов отсутствуют. Перед публичным запуском это требует доработки. Ошибки маршрутов каталога включают строку исключения внешнего запроса.
10. **Окружение требует подготовки.** Python-зависимости не закреплены, `openai` отсутствует в requirements, в поставке есть виртуальное окружение и `.env`, а `frontend/.gitignore` содержит маркеры конфликта. Установка в чистое окружение обязательна для корректной проверки переносимости.
11. **Нет подтверждённых метрик качества.** В исходниках нет результатов оценки точности рекомендаций, нагрузочных измерений или доказательства работы всей цепочки на реальных сервисах. История диалога не ограничивается по длине на backend.

Основания: [корзина](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/backend/cart.py), [вложения](https://github.com/BAITC-Hacks/hack-3b719372-avengers/blob/08ea0d390dd4c1cc61642ff5fb973ba4edd2fc39/frontend/src/widget/attachment.js), а также исходники frontend, агента и API, указанные выше.

## Развёрнутая версия и локальная демонстрация

Подтверждённая публичная ссылка на работающую версию проекта в проверенных исходниках не найдена. Для демонстрации используйте локальный запуск. **ekt.kz — целевой магазин, а не подтверждённый deployment этого прототипа.**

Для запуска на своём компьютере хостинг не нужен: frontend и backend запускаются локально по инструкции выше. Для реального каталога и AI-консультации необходимы интернет и настроенные доступы к EKT и OpenAI.

В общей «Инструкции для участников HackAlem AI» (стр. 1–2) ссылка на развёрнутую версию запрашивается «если она есть». Общая инструкция требует разместить итоговый код в выданном команде GitHub-репозитории, подготовить README и сдать решение через платформу; обязательный публичный хостинг в ней не указан. Дополнительные требования конкретного кейса EKT необходимо сверить с его заданием.
