# Аким на 5 часов

Учебный веб-симулятор команды **NT** для **HackAlem**. Пользователь выбирает
пять городских мероприятий в пределах бюджета, оценивает результат, а затем
пересматривает план после события и сравнивает последствия одной замены.

**Сценарий:** пять решений → результат → событие → замена → сравнение.

> Все показатели и эффекты — синтетические данные учебной модели.
> Результаты не являются официальной статистикой, методикой акимата или
> прогнозом реального развития Астаны.

## Текущее состояние

Общая версия **main** объединяет интерфейс **Semba**, движок **Nikita** и API/AI
**Bakytzhan**. Интерфейс включает обновлённый дизайн:
белую основу, зелёные основные действия, синие информационные акценты и жёлтые
уведомления.

**Интерфейс пока работает на подготовленных mock-сценариях `demo-v1`.**
Новый расчётный API `organizer-v1` также включён в **main**.
Подключение интерфейса к нему, выбор районов и языка ещё не завершены.
Переключение одного env-флага не выполняет эту интеграцию.
Публичный сайт и доступ браузера к платному AI пока не настроены.
Одного `AI_ENABLED=true` для такого доступа недостаточно.

Для показа жюри используйте описанный ниже браузерный сценарий.
API-ключ, база данных и Docker для него не нужны.

## Запуск для жюри

### 1. Что установить

- **Node.js 24.x** с npm.
- **Git**.
- Современный браузер.
- Доступ к приватному репозиторию команды.

Интернет понадобится для скачивания проекта и установки зависимостей.
Заранее подготовленное локальное mock-демо не обращается к AI-провайдеру.

### 2. Скачать проект

Откройте терминал и выполните:

```sh
git clone --branch main https://github.com/BAITC-Hacks/hack-14dc5002-nt.git
cd hack-14dc5002-nt
npm ci
```

Ветка **main** содержит общую проверенную версию команды.
Если GitHub сообщает `Repository not found`, проверьте доступ вашего аккаунта
к приватному репозиторию.

Если проект уже скачан, сохраните свои незакоммиченные изменения, затем обновите
чистую рабочую копию:

```sh
git switch main
git pull --ff-only origin main
npm ci
```

### 3. Создать настройки

В корне проекта, рядом с `package.json`, создайте файл **`.env.local`**:

```dotenv
NEXT_PUBLIC_USE_MOCK_API=true
AI_ENABLED=false
```

Если файл уже существует, измените только эти значения и сохраните остальные
настройки. На Windows убедитесь, что имя файла не стало `.env.local.txt`.

Для этого показа `OPENAI_API_KEY` и `OPENAI_MODEL` не нужны.
Файл `.env.local` исключён из Git; передавать секреты жюри не требуется.

### 4. Собрать и запустить

Если сервер проекта уже работает в другом терминале, сначала остановите его
сочетанием **Ctrl+C**.

```sh
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

Откройте **[http://127.0.0.1:3000](http://127.0.0.1:3000)**.

Оставьте терминал открытым до конца демонстрации.
Для остановки приложения нажмите **Ctrl+C**.

На странице должны быть видны:

- заголовок **«Как изменится город от ваших решений?»**;
- пометки **«Демо-сценарии»** и **«Модель demo-v1»**;
- бюджет 100 условных единиц;
- кнопки **«Загрузить демо-план»** и **«Рассчитать результат»**.

### Альтернатива: запуск для разработки

Вместо production-сборки и `start` можно выполнить:

```sh
npm run dev -- --hostname 127.0.0.1 --port 3000
```

Адрес остаётся тем же. В этом режиме изменения кода автоматически появляются
в браузере. Не запускайте оба режима одновременно на одном порту.

`NEXT_PUBLIC_USE_MOCK_API` встраивается в браузерный код при сборке.
После изменения значения перезапустите dev-сервер либо заново выполните
`npm run build` и перезапустите production-сервер. Настройки самого терминала
могут перекрывать значения из `.env.local`.

## Что показать жюри

Для чистого начала удобно открыть приложение в приватном окне: обычный браузер
может восстановить ранее сохранённый базовый план.

1. Нажмите **«Загрузить демо-план»**.
   Будут выбраны пять мероприятий: выделенные автобусные полосы, строительство
   школы, озеленение общественных пространств, освещение безопасных маршрутов
   и городские услуги онлайн.
2. Нажмите **«Рассчитать результат»**.
   Покажите **5 / 5** выбранных мероприятий, расходы **90 / 100**,
   результат **57**, показатели направлений и районов.
3. Перейдите к разделу **«Что изменилось?»**.
   В карточке **«Строительство школы отменено: участок недоступен»**
   нажмите **«Смоделировать событие»**.
4. Покажите, что в промежуточном плане осталось **4 мероприятия**,
   его результат **не рассчитывается**, а для замены доступно **40 единиц**.
   Исходный снимок остаётся сохранённым.
5. Выберите именно **«Модульные учебные корпуса»**.
   Нажмите **«Подтвердить выбранную замену»**.
   Не выбирайте автоматически первую рекомендацию: старый mock поддерживает
   не все варианты подтверждения.
6. Покажите сравнение: исходный результат **57** при расходах **90**,
   новый результат **56,6** при расходах **96**, изменение **−0,4**.
   Симулятор показывает компромисс: замена не обязана улучшать общий балл.
7. В блоке **«Объяснение последствий»**, после подтверждения замены,
   нажмите **«Получить объяснение»**.
   Появится текст с пометкой **«Шаблонное объяснение»**.
8. При необходимости перезагрузите страницу: исходный план восстановится,
   ветка события сбросится. Для повторного показа снова загрузите демо-план.

| Этап demo-v1 | Мероприятий | Расходы | Остаток / доступно | Score |
| --- | ---: | ---: | ---: | ---: |
| Исходный план | 5 | 90 | 10 | 57 |
| После отмены школы | 4 | 60 | 40 | Отсутствует |
| После замены на модульные корпуса | 5 | 96 | 4 | 56,6 |

### Краткий текст для защиты

> «Мы показываем интерфейс на подготовленном демонстрационном сценарии.
> Пользователь распределяет ограниченный бюджет между пятью городскими мерами.
> После отмены одного решения исходный план сохраняется, а в отдельном сценарии
> можно выбрать замену и сравнить последствия. Новый расчётный движок готовится
> к подключению к этому интерфейсу. Данные учебные и синтетические».

### Границы текущего показа

- Числа в браузерном mock-режиме берутся из подготовленных fixtures.
- Произвольные комбинации могут вернуть `MOCK_SCENARIO_NOT_DEFINED`.
- Объяснение базового плана в старом mock не подготовлено.
  Показывайте объяснение после подтверждения замены школы.
- Пометка `template` означает шаблон; этот показ не подтверждает вызов AI.
- Сохранённый базовый план и ветка события разделены. Изменение выбора
  не переписывает исходный снимок до нового расчёта.
- Подсказки несовместимости и зависимостей описывают правила.
  Жёлтое предупреждение появляется при нарушении в текущем выборе.

## Новый API: серверная часть в том же приложении

Новая серверная реализация включена в
[main](https://github.com/BAITC-Hacks/hack-14dc5002-nt/tree/main).
Она использует `organizer-v1`, а не модель браузерного демо выше:

| Параметр | demo-v1 в текущем UI | organizer-v1 в новом API |
| --- | --- | --- |
| Районы | Условные D1–D3 | Есиль, Алматы, Сарыарка, Байконур, Нура |
| Каталог | 16 мер, включая меру события | 14 мер |
| Горизонт | 12 месяцев | 8 кварталов |
| Формат плана | `actionIds` | `selections: [{actionId, districtId?}]` |
| Эталонный расход | 90 | 95 |
| Эталонный Score | 57 | 56.54307 |
| Языки объяснений | Подготовленный русский mock | `ru`, `kk`, `en` |

Числа этих моделей не взаимозаменяемы.
Не переключайте текущий интерфейс на новый API только изменением флага.

Сервер organizer-v1 принимает пять уникальных мер в пределах 100 единиц,
не более двух мер одного направления. Для районных мер требуется район;
для городских район не передаётся. Сервер проверяет ограничения и рассчитывает
эффекты, лаги и синергии. События отмены и обязательной меры — сценарии команды.

### Отдельный запуск серверной версии

Этот раздел необязателен для браузерного показа жюри. Все серверные маршруты
уже работают в запущенном выше приложении, даже при клиентском mock-флаге true.
Для отдельной проверки API можно использовать **другую папку**:

```sh
git clone --branch main https://github.com/BAITC-Hacks/hack-14dc5002-nt.git hackalem-api
cd hackalem-api
npm ci
```

Создайте в этой папке `.env.local`:

```dotenv
NEXT_PUBLIC_USE_MOCK_API=false
AI_ENABLED=false
AI_LOCAL_DEMO=false
```

Запустите API на отдельном порту:

```sh
npm run dev:local -- --port 3001
```

Каталог будет доступен по
[http://127.0.0.1:3001/api/catalog](http://127.0.0.1:3001/api/catalog).
Главная страница этой серверной версии ещё не является новым подключённым UI.

Пример получения реального расчёта в **PowerShell**, во втором терминале:

```powershell
$apiBase = 'http://127.0.0.1:3001'
$catalog = (Invoke-RestMethod -Uri ($apiBase + '/api/catalog')).data
$body = $catalog.demoPlan | ConvertTo-Json -Depth 20
$result = Invoke-RestMethod -Uri ($apiBase + '/api/simulate') -Method Post `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
$result.data | Select-Object valid, totalCost, remainingBudget, officialScore
```

Для эталонного плана organizer-v1 ожидаются
`valid=true`, `totalCost=95`, `remainingBudget=5`,
`officialScore=56.54307`.

| Метод | Маршрут нового API | Назначение |
| --- | --- | --- |
| GET | `/api/catalog` | Каталог и сценарии команды |
| POST | `/api/simulate` | Проверка и расчёт плана |
| POST | `/api/events/preview` | Предварительные допустимые замены |
| POST | `/api/events/confirm` | Подтверждение одной замены |
| POST | `/api/explain` | Объяснение результата на RU/KK/EN |

Полный контракт, примеры событий и объяснений:
[инструкция интеграции](docs/ORGANIZER-INTEGRATION.md).

## Роль AI

Числа рассчитывает детерминированный движок, а не языковая модель.
В новом API сначала создаются проверенные факты. При включённом AI модель
выбирает факты и их порядок; текст и числовые значения формирует сервер.

При выключенном AI, отсутствии настроек, ошибке или таймауте возвращается
`source=template`. Для показа жюри оставьте **`AI_ENABLED=false`**.
Опциональное подключение AI описано в инструкции интеграции.
Обычный production-браузер пока получает шаблон; публичный доступ к платным
вызовам требует отдельной настройки и общего серверного лимита.

Ключи хранятся только на сервере. Не добавляйте их в Git или в переменные
с префиксом `NEXT_PUBLIC_`.

## Если приложение не запускается

| Симптом | Решение |
| --- | --- |
| `node` или `npm` не найден | Установите Node.js 24.x и заново откройте терминал |
| PowerShell блокирует `npm.ps1` | Используйте `npm.cmd ci`, `npm.cmd run build`, `npm.cmd run start -- --hostname 127.0.0.1 --port 3000` |
| GitHub сообщает `Repository not found` | Проверьте адрес и доступ аккаунта к приватному репозиторию |
| `EADDRINUSE` | Остановите предыдущий сервер или используйте `npm run start -- --hostname 127.0.0.1 --port 3002` и откройте порт 3002 |
| `Could not find a production build` | Сначала выполните `npm run build` и дождитесь завершения |
| Сайт не открывается | Проверьте, что сервер работает, терминал открыт и адрес содержит правильный порт |
| `MOCK_SCENARIO_NOT_DEFINED` | Загрузите демо-план и повторите точную последовательность показа |
| Неверный каталог или `UI_CONTRACT_OUTDATED` | Для текущего UI нужен `NEXT_PUBLIC_USE_MOCK_API=true`; после изменения пересоберите приложение |
| После изменения env режим прежний | Проверьте переменные терминала, остановите сервер, пересоберите и запустите снова |
| Показывается предыдущий план | Откройте приватное окно либо загрузите демо-план и пересчитайте |
| Объяснение помечено как шаблон | Это ожидаемый режим демонстрации без AI |

## Технологии и структура интерфейса

**Next.js 15, React 19, TypeScript**, серверные маршруты в одном приложении,
Zod для проверки входных данных. Авторизация пользователей и база данных
для локального MVP не требуются.

```text
src/
  app/
    page.tsx              Страница приложения
    globals.css           Общие стили
    api/                  Серверные маршруты текущей ветки
  features/dashboard/
    SimulationDashboard.tsx   Интерфейс и состояние сценария
    stored-plan.ts            Чтение сохранённых ID и версии модели
  contracts/              Типы данных
  data/                   Каталог
  lib/client-api.ts       Адаптер текущего UI
  mocks/                  Подготовленные сценарии demo-v1
docs/                     Описание проекта и интеграции
```

localStorage сохраняет план и версию модели. Сохранённые числовые результаты
не используются как доверенный источник: план проверяется повторно.
