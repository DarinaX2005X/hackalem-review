# Agentic AI для прогнозирования выработки ВЭС (AURA)

## 1. Название проекта
AURA: Agentic AI-система прогнозирования выработки ветроэлектростанций (ВЭС).

## 2. Краткое описание
Проект решает критически важную задачу точного прогнозирования почасовой выработки ветроэлектростанций на горизонте 24–48 часов. Точные прогнозы помогают операторам энергосистем и владельцам ВЭС балансировать нагрузку в сети, планировать продажи электроэнергии и избегать штрафов за небаланс. Система работает в режиме AI-агента, полностью автоматизируя весь цикл от сбора данных до выдачи финального прогноза.

## 3. Что реализовано
*   **Автономный Agentic AI-цикл:** система сама запрашивает внешние погодные данные, обрабатывает их, запускает модель и формирует почасовой прогноз.
*   **Соблюдение "честности" (Time-Travel):** для предсказания на тестовый период используются строго **архивные погодные прогнозы** (как если бы мы находились в прошлом), без использования фактических значений из будущего.
*   **Точная ML-модель:** ансамбль на базе XGBoost для прогнозирования нормализованной активной мощности.
*   **Микросервисная архитектура:** оркестратор на Go, ML-движок на Python и адаптивный веб-интерфейс AURA.

## 4. Как работает решение
Пользователь открывает веб-интерфейс и выбирает нужную дату в тестовом периоде (например, 1 февраля 2026 года). 
1. Backend принимает запрос и делегирует задачу ML-агенту.
2. ML-агент обращается к открытым источникам (Open-Meteo), скачивая погодный прогноз (GFS), который был сгенерирован *именно на момент 1 февраля*, гарантируя отсутствие заглядывания в будущее.
3. Данные препроцессятся, обогащаются историей (SCADA) и скармливаются модели XGBoost.
4. Сформированный почасовой прогноз на следующие 24–48 часов возвращается по HTTP и визуализируется на дашборде. При изменении входных условий расчет автоматически повторяется.

## 5. Технологии
*   **Языки:** Go (Backend/Оркестрация), Python 3.12 (ML), JavaScript/HTML/CSS (Frontend).
*   **ML & Data:** `XGBoost`, `scikit-learn`, `pandas`, `numpy`.
*   **Фреймворки:** `Gin` (Go API), нативный HTTP в Python (`http.server`).
*   **Инфраструктура:** Docker, Docker Compose.
*   **API / Внешние сервисы:** Open-Meteo API (`previous-runs-api`) для получения архивных GFS прогнозов.

## 6. Архитектура проекта
Архитектура состоит из трех контейнеризированных компонентов:
*   `frontend` (порт 4173): Легковесный сервер, раздающий статику AURA и проксирующий API-запросы к Backend.
*   `backend` (порт 8080): Go/Gin REST API. Принимает клиентские запросы, управляет стейтом и маршрутизирует задачи.
*   `ml` (порт 8000): Python-сервис. Выполняет роль AI-агента — хостит обученные `joblib` модели, общается с Open-Meteo, проводит инференс и возвращает JSON-результаты Бэкенду.

## 7. Установка и запуск
Требования: Docker и Docker Compose (Git-репозиторий должен содержать CSV-датасеты турбин в папке `ml/data` или корне, если вы собираете модель с нуля).

```bash
# 1. Склонируйте репозиторий
git clone <url-репозитория>
cd hack-938e08c5-birkaliito

# 2. Запустите оркестрацию через Docker Compose
cd backend
docker compose up --build -d
```
Первый запуск займет около 2-4 минут (скачиваются ML-библиотеки и слои Docker).
*   **Frontend интерфейс:** [http://localhost:4173](http://localhost:4173)
*   **Swagger документация:** [http://127.0.0.1:8080/docs](http://127.0.0.1:8080/docs)

## 8. Как проверить решение
1. Откройте интерфейс [http://localhost:4173](http://localhost:4173).
2. Выберите турбину и установите тестовый период прогнозирования (например, с 01.02.2026 по 02.02.2026).
3. Нажмите кнопку формирования прогноза.
4. Вы увидите интерактивный график выработки ВЭС на ближайшие часы, построенный на основе реальной предсказательной модели, а не синтетических данных. Жюри может сверить почасовую детализацию с реальной выработкой из скрытого тестового набора.

## 9. Данные и интеграции
*   **Исторические данные:** предоставленные CSV-файлы SCADA (скорость ветра, мощность, температура окружающей среды).
*   **Погода:** Интеграция с `previous-runs-api.open-meteo.com`. Мы используем модель GFS (Global Forecast System) с симуляцией задержки публикации в 6 часов, чтобы честно воспроизводить состояние информации на "вчера".

## 10. Ограничения
*   Модель обучена специфично под 2 предоставленные турбины. Добавление новой турбины потребует запуска пайплайна дообучения.
*   Система чувствительна к rate-limit'ам бесплатного тарифа Open-Meteo (при массовом ретроспективном тестировании могут потребоваться задержки между запросами).

## 11. Ссылка на deployed-версию
Деплой-версия в сети отсутствует по условиям конфиденциальности датасета; проект предназначен для локального запуска жюри через `docker compose` (см. пункт 7).
