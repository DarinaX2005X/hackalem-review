# Точка события — умный подбор event-подрядчиков

**Точка события** помогает заказчику выбрать подрядчиков для мероприятия в Казахстане. Вместо длинного каталога сервис возвращает до трёх доступных вариантов и для каждого объясняет решение фактами из профиля.

Пользователь указывает город, дату, формат события, нужную категорию и бюджет. При необходимости добавляет язык и длительность. Сервис проверяет календарь занятости, обязательные условия и смысл описания профиля, после чего показывает короткую, понятную подборку.

Проект создан для хакатона #79-lite. Данные — 66 анонимизированных профилей, в том числе 13 синтетических, которые заметно помечаются в интерфейсе.

Подробные инструкции по частям проекта находятся в [backend/README.md](backend/README.md) и [frontend/README.md](frontend/README.md). Главный README описывает продукт и полный сценарий запуска.

## Какую проблему решаем

Каталог подрядчиков сам по себе не отвечает на главный вопрос заказчика: **кто реально подходит на мою дату и почему?** Поиск превращается в ручное сравнение десятков профилей, а занятость часто выясняется только после обращения к подрядчику.

Сервис сокращает этот путь:

1. Не показывает занятого подрядчика.
2. Не выдаёт варианты выше заданного бюджета или с неподходящим форматом, языком либо длительностью.
3. Возвращает не более трёх кандидатов в стабильном порядке.
4. Объясняет каждый результат: доступность, цену, соответствие формату и конкретный факт из описания профиля.
5. Если ответа нет, прямо говорит, что произошло: категории нет в городе или кандидаты не проходят условия.

## Наши преимущества

**Короткая подборка вместо долгого поиска.** Обычный каталог отдаёт десятки профилей для ручного сравнения. Мы показываем до трёх кандидатов, которые уже прошли проверку условий.

**Календарь учитывается до рекомендации.** Пользователь не тратит время на подрядчика, занятого в нужную дату: занятость — обязательный фильтр, а не информация «после звонка».

**Понятно, почему выбран именно этот профиль.** У каждой карточки есть проверяемое объяснение: доступность, цена, формат, язык, длительность и факт из конкретного описания.

**Смысл запроса, а не только совпадение слов.** Семантический поиск находит релевантные описания даже при другой формулировке. BM25 дополняет его точными совпадениями.

**Стабильный результат.** Один и тот же запрос возвращает один и тот же порядок. При одинаковом балле применяется стабильное правило сортировки по `id`.

**AI работает локально.** В проект встроен собственный локальный нейросетевой модуль поиска: multilingual embeddings запускаются через FastEmbed и ONNX Runtime внутри Docker. Внешний AI API, ключи и оплата запросов не нужны.

## Что видит пользователь

Интерфейс показывает форму, карточки рекомендаций и три подготовленных сценария для демонстрации:

- **Плотная категория** — фотографы на осеннюю дату: видно ранжирование нескольких кандидатов.
- **Редкая категория** — флористы: сервис возвращает столько карточек, сколько действительно есть, и объясняет нехватку.
- **Без результата** — кандидаты существуют, но бюджет намеренно не позволяет выбрать ни одного.

После успешной выдачи можно нажать «Сравнить с 14 ноября» и увидеть, как календарь меняет состав подборки. Отдельно отображаются причины исключения кандидатов и пометка синтетических профилей.

Карточка подрядчика кликабельна: нажмите «Открыть профиль» или любую область карточки. Справа откроется подробный профиль с категорией, городом, стартовой стоимостью, источником данных, причиной рекомендации и параметрами текущего подбора. Профиль можно открыть мышью, клавишей Enter или пробелом и закрыть клавишей Escape.

## Быстрый запуск

Нужны:

- Docker Desktop с Docker Compose;
- Node.js 22.12 или новее;
- интернет только при первом Docker build, чтобы скачать локальную модель. При дальнейших запусках внешний AI API не требуется.

### 1. Запустить API и хранилища одной командой

В PowerShell из корня репозитория:

```powershell
cd backend
Copy-Item .env.example .env
docker compose up -d --build
```

В macOS/Linux замените `Copy-Item .env.example .env` на `cp .env.example .env`.

Эта команда запускает всю серверную часть: PostgreSQL, Elasticsearch, Redis, импортёр данных и FastAPI. Compose ждёт healthcheck хранилищ, после чего импортёр проверяет CSV, загружает 66 профилей, строит векторы описаний и только затем разрешает старт API.

Дождитесь завершения импорта и проверьте состояние:

```powershell
docker compose ps
docker compose logs importer
curl.exe http://localhost:8000/ready
```

У `importer` должен быть статус `exited (0)`, у `api` — `healthy`, а `/ready` должен вернуть `"status":"ready"`. Документация API доступна на [http://localhost:8000/docs](http://localhost:8000/docs).

### 2. Запустить веб-интерфейс

Откройте второй терминал:

```powershell
cd frontend
npm ci
Copy-Item .env.example .env
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). В режиме разработки Vite сам направляет запросы `/api` на FastAPI.

### 3. Остановить сервисы

```powershell
cd backend
docker compose down
```

Данные PostgreSQL и Elasticsearch сохраняются в Docker volumes. Чтобы переиндексировать исходный CSV, выполните:

```powershell
docker compose run --rm importer
```

## Как проверить решение

### Через интерфейс

1. Откройте `http://localhost:5173`.
2. Нажмите по очереди три кнопки демо-сценариев: «Плотная категория», «Редкая категория», «Без результата».
3. В успешной подборке нажмите «Сравнить с 14 ноября».
4. Нажмите «Открыть профиль» на любой карточке и проверьте детали подрядчика и параметры текущего подбора.
5. Убедитесь, что карточек максимум три, занятые исполнители не показаны, а причины на карточках различаются.

### Через API

Пример плотной категории:

```powershell
curl.exe -X POST http://localhost:8000/api/v1/recommendations `
  -H "Content-Type: application/json" `
  -d '{"city":"Алматы","event_date":"2026-10-10","event_format":"свадьба","category":"Фотограф","budget_kzt":6000000}'
```

В ответе важны:

- `status: "matched"`;
- не более трёх элементов в `items`;
- `explanation` у каждой карточки;
- `meta` с количеством подходящих кандидатов и причинами исключений.

Проверьте и два граничных случая, изменив параметры запроса:

- **Категория отсутствует в городе:** укажите `category: "Отель"` и `city: "Алматы"`. Ожидаемый статус — `category_not_found`.
- **Кандидаты есть, но не подходят:** укажите `budget_kzt: 1`. Ожидаемый статус — `no_eligible_candidates`.

## Как работает подбор

```text
Форма пользователя
        │
        ▼
FastAPI ──► Redis-кэш ──► Elasticsearch
                                │
                 город + категория + BM25 + семантическая близость
                                ▼
       фильтры: дата, бюджет, формат, язык, длительность
                                │
                                ▼
       ранжирование → до 3 карточек → персональные объяснения
```

1. Импортёр валидирует исходный CSV через Pydantic и сохраняет каталог в PostgreSQL.
2. Встроенный локальный нейросетевой модуль использует `paraphrase-multilingual-MiniLM-L12-v2`: FastEmbed запускает ONNX-модель и создаёт для каждого профиля 384-мерный вектор. Вектор хранится в Elasticsearch рядом со структурированными данными.
3. По запросу система ограничивает поиск городом и категорией, сочетает семантическую близость описания с BM25 и получает кандидатов.
4. Бизнес-правила исключают занятые, дорогие и несовместимые профили.
5. Оставшиеся кандидаты ранжируются по запасу бюджета и релевантности описания. Порядок фиксируется по `id`, если баллы равны.
6. Объяснение собирается только из подтверждённых фактов конкретного профиля: дата, цена, формат, язык, длительность и релевантный фрагмент описания.

Чтобы не задерживать пользователя при сбоях инфраструктуры, Redis ограничен 250 мс на операцию, Elasticsearch — 4 секундами без повторных попыток, а веб-интерфейс прекращает ожидание через 10 секунд.

### Локальная нейросетевая часть

Мы не вызываем LLM или внешний AI API во время подбора. Docker-образ заранее получает open-source multilingual MiniLM, а FastEmbed выполняет инференс через ONNX Runtime внутри контейнера. Модель превращает текст запроса и описания подрядчиков в числовые векторы, чтобы находить смысловую близость на русском, казахском и английском. Решение о допуске кандидата всё равно принимают прозрачные бизнес-правила: дата, бюджет, формат, язык и длительность.

## Технологии

- **Веб-интерфейс:** Vue 3, TypeScript, Vite, Tailwind CSS и Reka UI.
- **API:** Python 3.12+, FastAPI, Pydantic и Uvicorn.
- **Поиск и AI:** Elasticsearch 8, BM25, FastEmbed, ONNX Runtime и multilingual MiniLM.
- **Данные:** PostgreSQL 16, Redis 7 и CSV-импортёр.
- **Инфраструктура:** Docker Compose.
- **Проверки:** pytest, Vitest, TypeScript type-check и Vite production build.
