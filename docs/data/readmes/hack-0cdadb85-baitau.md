# Умный подбор подрядчиков

Приложение для подбора специалистов на мероприятия: свадьбы, корпоративы, тои
и другие события. Заказчик задаёт условия и получает до **3 подходящих подрядчиков**
с объяснением выбора.

Интерфейс работает на Streamlit. Подбор и объяснения выполняются локально,
без LLM и ключей внешних API.

## Быстрый запуск

Выполняйте команды из корня проекта — папки с `app.py` и `requirements.txt`.
Нужен Python с модулями `venv` и `pip`.

**1. Создайте виртуальное окружение:**

```bash
python -m venv .venv
```

**2. Активируйте его командой для вашей системы:**

Linux / macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Windows cmd:

```bat
.venv\Scripts\activate.bat
```

**3. Установите зависимости и запустите приложение:**

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте адрес из терминала — обычно [http://localhost:8501](http://localhost:8501).
Для остановки нажмите `Ctrl+C` в терминале. Единственная прямая внешняя
зависимость проекта — `streamlit`; остальные пакеты установятся вместе с ней.

Если появилась ошибка `No module named 'streamlit'`, активируйте окружение
и повторите установку через `python -m pip install -r requirements.txt`.

## Как пользоваться

1. Укажите город, дату, формат мероприятия, категорию услуг и бюджет в тенге.
2. При необходимости задайте язык и длительность в блоке **«Дополнительные параметры»**.
3. Нажмите **«Подобрать подрядчиков»**.

В карточках будут имя, категория, город, цена «от» и объяснение выбора.
Если вариантов нет, приложение предложит изменить условия. Если подрядчики есть,
но не прошли фильтры, покажет причины: занятость, бюджет, формат, язык или длительность.

## Демо за несколько минут

Используйте эти параметры для подбора:

| Параметр | Значение |
| --- | --- |
| Город | Алматы |
| Дата | 2026-11-14 |
| Формат | свадьба |
| Категория | Фотограф |
| Бюджет | 400 000 ₸ |
| Длительность | 8 часов |
| Язык | русский |

На исходном каталоге результат содержит
`HK-68220`, `HK-76268`, `HK-91112` в этом порядке.

Измените **только дату на 2026-11-15** и повторите подбор. Останутся
`HK-68220` и `HK-91112`: у `HK-76268` новая дата указана в `busy_dates`.
Оба запроса возвращают `matched` и `fallback=False`.

## Как устроен подбор

Сначала алгоритм выбирает подрядчиков нужной категории в выбранном городе.
Затем исключает тех, кто занят на указанную дату, превышает бюджет или
не поддерживает формат мероприятия, запрошенный язык либо длительность.

Оставшиеся кандидаты получают оценку по начальной цене относительно бюджета,
языку и лимиту часов. Кандидаты упорядочиваются по убыванию оценки;
при равенстве — по возрастанию цены, затем ID. При одинаковых данных и запросе результат одинаковый.
Объяснения составляются из фактов профиля и условий запроса.

| Статус | Что означает |
| --- | --- |
| `matched` | Найдено от 1 до 3 подходящих подрядчиков. |
| `no_category_in_city` | В выбранном городе нет подрядчиков этой категории. |
| `no_eligible_candidates` | Категория в городе есть, но никто не прошёл остальные условия. |

### Защита от сбоев

`safe_pipeline_call()` проверяет входные данные и ответ Core. При ошибке,
некорректном ответе или ожидании дольше 15 секунд возвращает резервный ответ
из `helpers/mock_data.json` с признаком `fallback=True`.

**Резервная подборка — заранее подготовленный демо-сценарий.** Её параметры
могут отличаться от текущего запроса; интерфейс сообщает о переходе в демо-режим.
Если резервные данные тоже недоступны или невалидны, helpers возвращает пустой
ответ с `fallback=True`.

## Данные и хранение

| Файл | Назначение |
| --- | --- |
| `helpers/contractors.json` | Исходный каталог: **66 профилей**, из них **13 синтетических**. Не изменяется при работе приложения. |
| `helpers/mock_data.json` | Резервный ответ для демо при сбое подбора. |
| `given_data/` | Исходный анонимизированный CSV и HTML-превью. |

Данные проходят нормализацию и валидацию. Занятые даты `busy_dates` сохраняются
в формате `YYYY-MM-DD` и участвуют в фильтрации. Флаги `synthetic`, `city_imputed`
и `price_imputed` сохраняют сведения о синтетических профилях и восстановленных
городах и ценах. UI отмечает синтетические профили и позволяет посмотреть,
какие поля были восстановлены.

`load_contractors()` возвращает 66 исходных профилей. Загрузка каталога
и выполнение подбора не изменяют исходный JSON-файл.

## Архитектура и контракт

```text
app.py — Streamlit: форма запроса, карточки и сообщения
  │
  ├── helpers/utils.py — загрузка, нормализация и валидация
  │     └── contractors.json — исходные 66 профилей
  │
  └── helpers/utils.py — safe_pipeline_call()
        ├── core/generator.py — фильтры → оценка → top-3 → объяснения
        └── mock_data.json   — резервный ответ при сбое
```

Пример запроса к `run_pipeline(request, contractors)` через `safe_pipeline_call`:

```json
{
  "city": "Алматы",
  "date": "2026-11-14",
  "event_format": "свадьба",
  "category": "Фотограф",
  "budget_kzt": 400000,
  "duration_hours": 8,
  "language": "русский"
}
```

Первые пять полей обязательны. Бюджет — положительное целое число в тенге.
`duration_hours` и `language` можно не передавать или указать как `null`.

Основные поля ответа через `safe_pipeline_call`:

| Поле | Содержимое |
| --- | --- |
| `status` | Один из трёх статусов выше. |
| `query` | Параметры запроса, которому соответствует ответ. |
| `results` | До трёх карточек с оценкой и объяснением; пустой список при отсутствии рекомендаций. |
| `meta` | Число кандидатов и результатов, диагностика причин отказа. |
| `fallback` | `False` при штатном ответе Core, `True` при резервном ответе. |

## Ограничения текущей версии

- Приложение рекомендует подрядчиков. Бронирования, оплаты и аккаунтов нет.
- Доступность определяется только сохранёнными `busy_dates`.
- Выбор дат в UI ограничен диапазоном **23.09.2026–31.12.2026**.
- Бюджет сравнивается с ценой «от», которая не является итоговой сметой заказа.
- `max_hours: null` означает, что часовой лимит не указан; такой профиль
  не исключается по длительности.
