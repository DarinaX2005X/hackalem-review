# SOILE

SOILE — работающий MVP платформы, где бизнес оформляет практическую задачу, получает прозрачный рейтинг её готовности и публикует карточку в открытом каталоге. Студенческие команды самостоятельно выбирают задачи и отправляют предложения, а бизнес вручную принимает или отклоняет отклики.

## Запуск

Проект не требует установки зависимостей, но для реальной AI-функции нужен Node.js 18+ и ключ OpenAI API. Ключ используется только сервером и не попадает в браузер.

В PowerShell задайте ключ только для текущего окна терминала и запустите приложение:

```powershell
cd soile-platform
$env:OPENAI_API_KEY="ваш_ключ"
npm start
```

После запуска откройте `http://127.0.0.1:4173`.

Если на порту 4173 ещё работает прежний `python -m http.server`, остановите его через `Ctrl+C` или перед запуском задайте другой порт, например `$env:PORT="4174"`.

Ключ создаётся в [OpenAI API Dashboard](https://platform.openai.com/api-keys); для API-проекта также должен быть настроен биллинг. Не добавляйте ключ в `dist/app.js`, Git или публичную конфигурацию. Модель можно переопределить переменной `OPENAI_MODEL`; по умолчанию используется `gpt-6-astra`.

Текущий `.openai/hosting.json` публикует только статическую папку `dist`. Для production-развёртывания реальной AI-функции запускайте `server.mjs` на Node-хостинге и задавайте `OPENAI_API_KEY` в секретах этого хостинга.

## Демонстрационный сценарий

1. В режиме «Бизнес» нажмите «Заполнить демо-пример», измените любое поле, выполните AI-проверку рейтинга и опубликуйте задачу.
2. В разделе «Мои задачи» отредактируйте опубликованную задачу: её id и отклики сохранятся, а рейтинг пересчитается.
3. Архивируйте задачу и убедитесь, что она исчезла из студенческого каталога; затем восстановите её.
4. После проверки рейтинга отметьте значком `✦` нужные поля, нажмите «Улучшить с AI», проверьте рекомендации и примените или отклоните их.
5. Переключитесь в режим «Студент», найдите задачу в каталоге и отправьте отклик.
6. Вернитесь в режим «Бизнес», откройте «Отклики» и вручную примите или отклоните предложение.

## Рейтинг готовности

Рейтинг рассчитывается AI по смыслу, конкретности и согласованности семи блоков:

- контекст и потребность — 20 баллов;
- данные и материалы — 20 баллов;
- ожидаемый результат — 15 баллов;
- критерии успеха — 15 баллов;
- ограничения — 10 баллов;
- пользователи — 10 баллов;
- связь с бизнесом — 10 баллов.

Длина текста сама по себе не даёт баллов: случайные слова, повторения, нерелевантный текст и противоречия получают нулевую или низкую оценку. После ручного изменения любого поля прежняя оценка помечается устаревшей; для публикации нужно снова нажать «Проверить рейтинг с AI». Принятые AI-улучшения сначала автоматически проверяются: если их рейтинг ниже текущей подтверждённой AI-оценки, исходный черновик сохраняется без изменений. Оценка сохраняется вместе с задачей в `localStorage`.

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Низкий рейтинг не скрывает задачу и не запрещает отклик.

## AI-функция

AI-помощник работает через OpenAI Responses API и строгий JSON Schema. Действие «Проверить рейтинг с AI» анализирует всю карточку, а компактная панель показывает только название критерия и баллы; сервер ограничивает баллы фиксированными весами и самостоятельно считает итог. После оценки возле семи рейтинговых полей появляются переключатели `✦`: бизнес отмечает только нужные поля, а действие «Улучшить с AI» показывает редактируемые рекомендации исключительно для выбранных полей. AI использует подтверждённые детали всей карточки, заметно улучшает структуру и конкретность выбранного текста и автоматически повторяет редактуру, если первый вариант почти совпал с исходником или не повышает рейтинг. Модальное окно открывается только после повторной проверки варианта с рейтингом минимум на один балл выше текущего (для рейтинга 100 — не ниже 100). Рекомендации можно применить или отклонить целиком; невыбранные поля не отправляются на улучшение и не изменяются.

Системные инструкции требуют не добавлять неподтверждённые факты и считать текст черновика недоверенными данными, а не командами для модели. Сервер проверяет полноту AI-оценки, ограничивает размер и частоту запросов и возвращает безопасные сообщения при ошибках API. Если `OPENAI_API_KEY` не задан, интерфейс покажет инструкцию по настройке вместо фиктивного результата.

## Архитектура

- `dist/index.html` — семантическая разметка приложения и диалоги;
- `dist/styles.css` — адаптивная дизайн-система без UI-фреймворка;
- `dist/app.js` — состояние, рейтинг, фильтрация, отклики и WebMCP-инструменты;
- `server.mjs` — статический Node-сервер и защищённый AI API-прокси;
- `package.json` — команды запуска и синтаксической проверки без сторонних зависимостей;
- `localStorage` — локальное сохранение черновика, режима редактирования, статусов задач, откликов и баллов команды; старые задачи без статуса считаются опубликованными;
- `.openai/hosting.json` — конфигурация статической публикации.

В коде зарегистрированы три WebMCP-инструмента: чтение каталога, создание черновика и отправка отклика. Они используют то же состояние, что и видимый интерфейс.

## Тестовые данные

В проект включены 5 карточек задач, 4 профиля команд и 5 откликов. Данные синтетические и не содержат персональной информации.

## Ограничения MVP

Нет регистрации, серверной базы данных, файлового хранилища, уведомлений и real-time чата. Эти функции намеренно исключены из пятичасового объёма и могут быть добавлены без изменения основного пользовательского сценария.
