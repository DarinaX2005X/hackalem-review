# HackAlem AI — умный подбор подрядчиков

Проект команды JJS для HackAlem AI, трек «Креативные индустрии».
Сервис помогает организатору мероприятия выбрать до трёх подрядчиков из каталога
по городу, дате, формату и бюджету. Для каждой рекомендации показаны конкретные
причины выбора и подтверждающие факты профиля.

Это инструмент выбора: бронирования и отправки заявок подрядчикам нет.

## Что реализовано

- Streamlit-интерфейс подключён к настоящему `src.recommender.recommend(request)`.
- Загружается `project/data/contractors.csv`: **66 профилей, 13 столбцов**.
- Mock-режим удалён; кнопки сценариев только заполняют форму.
- Жёсткие фильтры, детерминированное ранжирование и объяснения на основе данных.
- Три исхода: подобрали, категории нет, никто не подходит под все условия.
- Воронка отбора, сведения о происхождении данных и сравнение двух дат.
- Проверенные подсказки: минимальный бюджет или ближайшая последующая доступная дата.
- Проверки core и UI: **48 passed**.

## Запуск в Windows / VS Code

Проверенная среда: **Python 3.14.7**, **Streamlit 1.64.0**.
Версии пакетов в `requirements.txt` не закреплены.

Откройте корень репозитория в VS Code, затем **Терминал → Создать терминал**:

```powershell
cd project
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Если терминал уже находится в `project`, повторять `cd project` не нужно.
Откройте **Local URL**, напечатанный Streamlit, обычно http://localhost:8501.
При вопросе `Email:` оставьте поле пустым и нажмите Enter.
Для остановки сервера нажмите **Ctrl + C** в терминале запуска.

Для изолированной установки можно использовать виртуальное окружение.
Из `project`, без активации и изменения политики PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

После установки зависимостей подбор работает локально. API-ключи,
внешние LLM-сервисы и отдельный HTTP-backend не требуются.

## Интерфейс

Обязательные параметры: город, дата, тип мероприятия, категория подрядчика,
бюджет в тенге. Длительность и язык можно не указывать.
Календарь ограничен **23 сентября — 31 декабря 2026 года** и в UI, и в core:
за пределами этого периода доступность неизвестна.

Карточки показывают имя, категории, город, стартовую цену и объяснение.
В блоке **«Почему этот подрядчик»** доступны форматы, языки, цена, длительность
и исходное описание. В **«Технических деталях»** — ID, score и его компоненты.

Значки отражают происхождение данных:

- **Синтетический профиль** — `synthetic`;
- **Цена восстановлена** — `price_imputed`;
- **Город восстановлен** — `city_imputed`.

Значки включаются для значений `true`, `1`, `yes` без учёта регистра.
Цена «от» требует уточнения у подрядчика. Score не является оценкой качества
или вероятностью успешного мероприятия.

UI не пересортировывает результаты и не меняет score. При пустой выдаче сервисный
слой может выполнить дополнительные запросы к core для проверки подсказок.
Текущие запрос и ответ — словари; отдельного `src/models.py` нет.
TF-IDF реализован стандартной библиотекой Python. `pandas` и `scikit-learn`
перечислены в зависимостях, но текущий engine их не использует.

## Данные

Core читает `project/data/contractors.csv` в UTF-8 с поддержкой BOM.
Каталог содержит следующие столбцы:

```csv
id,anon_name,categories,city,city_imputed,synthetic,price_from_kzt,price_imputed,event_formats,languages,max_hours,busy_dates,description
```

- `id` — непустой уникальный идентификатор, `anon_name` — анонимизированное имя.
- `categories` — одна или несколько категорий.
- `event_formats`, `languages`, `busy_dates` — списки форматов, языков и занятых дат.
- Списки поддерживают разделители `|`, `;` или JSON-массив строк.
- `price_from_kzt` — конечное неотрицательное число.
- `busy_dates` использует формат `YYYY-MM-DD`.
- Пустой `max_hours`, `null`, `None` или `NaN` означает, что ограничение длительности
  не применяется; иначе требуется конечное неотрицательное число.
- `synthetic`, `city_imputed`, `price_imputed` сохраняются в ответе как строки CSV.

Loader использует реальные названия `anon_name`, `categories`, `event_formats`.
Переименовывать их в старые `name`, `category`, `event_type` не нужно.
Названия языков должны совпадать с запросом: автоматического перевода `ru` в
`русский` сейчас нет.

Отсутствующий файл или неверная схема вызывают ошибку загрузки, а не ложный
статус «категории нет». UI сообщает об ошибке без подстановки временных данных.

## Фильтрация и ranking

Сначала выбираются город и категория. Далее кандидаты последовательно проходят:

1. Свободную дату.
2. Поддержку формата мероприятия.
3. Цену не выше бюджета.
4. Поддержку языка, если он задан.
5. Допустимую длительность, если она задана и ограничение применимо.

Текстовые значения сравниваются без учёта регистра и крайних пробелов.
Бюджет запроса может быть нулевым, длительность — только положительной.
Подрядчик, не прошедший фильтр, не может вернуться в выдачу за счёт высокого score.

Для подходящих кандидатов:

```text
score = 0.60 × semantic_similarity
      + 0.25 × budget_fit
      + 0.15 × format_relevance
```

- `semantic_similarity` — косинусная близость TF-IDF описания к запросу.
  Если передан непустой `description`, используется он; иначе — `event_type`.
  В текущей форме свободного описания нет, поэтому используется тип мероприятия.
- `budget_fit = 1 − price_from_kzt / budget`. При нулевом бюджете для бесплатного
  подходящего подрядчика компонент равен 1.
- `format_relevance = 1 / число уникальных поддерживаемых форматов`.

TF-IDF строится по описаниям прошедших кандидатов. Это лексическое сопоставление,
без обучения нейросети и без внешних эмбеддингов.

Порядок: score по убыванию, затем цена по возрастанию, затем строковый `id`.
Возвращаются первые три кандидата. Тот же запрос на неизменном каталоге даёт тот же
порядок. Флаги synthetic/imputed сами по себе на ranking не влияют.

## Объяснения, diagnostics и подсказки

Core формирует explanation из конкретных фактов: свободная дата, цена и бюджет,
формат, язык и длительность. Дополняет его фрагментом описания с наибольшей
TF-IDF-близостью к запросу. Если описания нет, это указывается явно.

`ui/presentation.py` делает технические формулировки понятнее: форматирует дату
и деньги, заменяет сообщение о `max_hours` обычным текстом. Факты и выбранная
цитата из описания сохраняются; LLM не используется.

| Статус core | Сообщение в интерфейсе |
| --- | --- |
| `matched` | «Подобрано: …» и до трёх карточек |
| `category_absent` | «В этом городе нет такой категории» |
| `no_eligible` | «Никто не подходит под все условия» |

`diagnostics` содержит `candidates`, `busy`, `format`, `budget`, `language`,
`duration`, `remaining`. Профиль учитывается **на первом проваленном фильтре**.
`remaining` — число прошедших кандидатов до ограничения top-3.

UI строит воронку из этих счётчиков:

```text
Кандидаты → свободны на дату → подходят по формату → проходят бюджет
          → проходят язык/длительность → рекомендованы
```

Последовательно вычитаются причины отсева, предпоследний этап равен `remaining`,
последний — длине `recommendations`. Причины показываются также обычным текстом.

Для `no_eligible` сервис проверяет альтернативы, меняя **одно условие за раз**:

- Если есть отсев по бюджету, перебирает более высокие цены каталога по возрастанию
  и находит минимальный бюджет, при котором core возвращает хотя бы один вариант.
- Если есть занятые кандидаты, проверяет следующие дни до конца календаря
  и предлагает ближайшую последующую дату с подходящим вариантом.

Другие условия сохраняются. Непроверенные подсказки не показываются; основной
запрос и его результаты не подменяются альтернативами. Для вычисления подсказок
может потребоваться несколько дополнительных вызовов core.

## Контракт core

Пример вызова из папки `project`:

```python
from src.recommender import recommend

response = recommend({
    "city": "Алматы",
    "date": "2026-09-30",
    "event_type": "корпоратив",
    "category": "Ведущий",
    "budget": 1_200_000,
    "duration": 6,          # None, если не задана
    "language": "русский", # None, если не задан
})
```

Ответ содержит `status`, `recommendations`, `diagnostics`. Рекомендация включает
поля профиля, `score`, `score_components`, `explanation`. UI-адаптер добавляет копию
`request` и словарь проверенных `suggestions`.

## Частые проблемы

| Симптом | Что делать |
| --- | --- |
| `python` не распознаётся | Полностью перезапустите VS Code после настройки PATH. Если доступен `py`, используйте `py -V:3.14 -m streamlit run app.py` |
| `pip` или `streamlit` не распознаётся | Используйте `python -m pip ...` и `python -m streamlit ...` |
| `ModuleNotFoundError: No module named 'src'` | Запускайте тесты и приложение из `project`, а не из корня репозитория |
| Каталог не найден | Проверьте `project/data/contractors.csv`: в имени не должно быть опечатки `constractors.csv` |
| Loader требует старые `name`, `category`, `event_type` | У вас старая версия core; согласованно обновите код и каталог из репозитория |
| `Email:` при первом запуске | Оставьте пустым и нажмите Enter |
| Порт 8501 занят | Остановите предыдущий сервер через Ctrl + C или добавьте `--server.port 8502` |
