# Firebird — умный подбор event-подрядчиков

**До трёх подходящих подрядчиков вместо длинного каталога — с понятным объяснением каждого выбора.**

Проект команды **Aya & Dilya** для кейса Firebird на HackAlem AI. Он помогает заказчику мероприятия выбрать подрядчика из уже имеющегося каталога: учитывает город, дату, формат, категорию и бюджет, а затем объясняет, почему показанные варианты подходят.

Основной сценарий полностью работает **без API-ключей**. OpenAI можно подключить дополнительно для формулировки объяснений; он не определяет состав и порядок выдачи.

## Что реализовано

- Подбор по всем обязательным условиям: город, дата, формат мероприятия, категория и бюджет в тенге за одного подрядчика на событие. Дополнительно можно указать язык и длительность.
- От нуля до трёх уникальных карточек с ценой «от», объяснением и статусом занятости по данным каталога. Если найдено только один или два варианта, сервис объясняет причину и не дополняет список искусственно.
- Пожелания до 500 символов: распознаваемые темы сопоставляются с описаниями профилей и влияют на порядок подходящих кандидатов. Совпадения сопровождаются дословными цитатами.
- Необязательные AI-объяснения с маркировкой и раскрываемыми фактами-источниками. При отсутствии ключа или проблемах с моделью используются объяснения по правилам.
- **«План Б»** при отсутствии совпадений: ближайшие подходящие даты или изменение бюджета. Новые условия применяются только после нажатия пользователя.
- Сравнение двух или трёх результатов в таблице: цена, объяснения, подтверждения пожеланий, календарь и происхождение данных.
- Раздельные состояния для отсутствующей категории, отсутствия подходящих кандидатов, ошибок ввода и технических ошибок.
- Маркировка синтетических профилей, предположенного города и оценочной цены.
- Адаптивный русскоязычный интерфейс, быстрые примеры, сохранение условий показанного результата и защита от устаревших ответов при повторном подборе.

## Как работает решение

1. Пользователь заполняет условия мероприятия или выбирает пример. Пример только заполняет форму — подбор запускается кнопкой **«Подобрать подрядчиков»**.
2. Сервис проверяет запрос и применяет обязательные фильтры к каталогу. Занятые на выбранную дату профили исключаются. Если `max_hours = null`, ограничение длительности присутствия неприменимо и профиль по нему не исключается.
3. Среди прошедших фильтры кандидатов первыми идут профили с большим количеством подтверждённых тем пожеланий, затем — с меньшей начальной ценой. Равенство разрешается по `id`. Без пожеланий порядок определяется ценой и `id`.
4. Сервис возвращает до трёх карточек и объяснение общего результата. У каждой карточки есть обоснование по данным профиля. При настроенном ключе сервер может заменить его проверенным AI-текстом, сохраняя кандидатов и их порядок.
5. Пользователь изучает цитаты, сравнивает карточки или применяет предложенную альтернативу и запускает подбор с новыми условиями.

### Как устроен «План Б»

Каждая альтернатива меняет **ровно одно условие**:

- Поиск даты охватывает весь поддерживаемый календарь **23.09.2026–31.12.2026**. Показываются до двух ближайших подходящих дат; при равном расстоянии сначала будущая.
- На выбранную дату вычисляется минимальный бюджет, при котором появляется кандидат. Повышение до 20% может показываться вместе с датами. Более существенное повышение предлагается, только если подходящих дат с исходным бюджетом нет, и явно помечается. При нулевом бюджете процент не вычисляется.

Город, категория, формат, язык, длительность и пожелания сохраняются. Если изменение только даты или только бюджета не помогает, готовой альтернативы нет. При отсутствующей категории «План Б» не предлагается.

## Технологии

| Компонент | Реализация |
| --- | --- |
| Язык | TypeScript 6.0.3 |
| Интерфейс | React / React DOM 19.2.4, CSS |
| Разработка и сборка | Vite 7.3.6 |
| Сервер | Node.js, встроенный `node:http`, запуск TypeScript через `tsx` |
| Подготовка данных | `csv-parse` 7.0.2, локальные CSV и JSON |
| AI, необязательно | OpenAI Responses API через серверный `fetch`; модель по умолчанию `gpt-4.1-mini` |
| Проверки | Встроенный тестовый раннер Node.js, `node:assert`, TypeScript и проверка браузерной сборки |

Отдельная база данных не требуется. Подключений к CRM, платёжным системам и внешним календарям в текущей версии нет.

## Архитектура

```text
CSV → нормализация → catalog.json + audit.json
                            ↓
Форма React → HTTP-адаптер → POST /api/recommend
                            ↓
                 Валидация → фильтры → ранжирование
                            ↓
                 Карточки, объяснения и «План Б»
                            ↓
                 Необязательный редактор OpenAI
                            ↓
                 Результат и сравнение в интерфейсе
```

При недоступности HTTP API адаптер выполняет тот же подбор локально в браузере и показывает объяснения по правилам. Серверные секреты в браузерный код не передаются.

| Путь | Назначение |
| --- | --- |
| `src/pages/RecommendationPage.tsx` | Форма, состояния результатов, применение альтернатив |
| `src/pages/recommendationServiceAdapter.ts` | Обращение к API, резервный локальный подбор, защита от устаревших ответов |
| `src/components/` | Карточки и таблица сравнения |
| `src/shared/contracts.ts` | Общий контракт запросов, ответов и ошибок |
| `src/core/` | Валидация, фильтры, ранжирование, пожелания, объяснения и «План Б» |
| `src/data/` | Исходный CSV, нормализованный каталог, аудит и демозапросы |
| `server/api.ts` | HTTP API и ограничения запросов |
| `server/ai-explanations.ts` | Обращение к OpenAI, проверка ответа, кеш и резервные объяснения |
| `server/index.ts` | Раздача собранного интерфейса, API и `/healthz` |
| `scripts/`, `tests/` | Подготовка данных, воспроизводимые сценарии и проверки |

Единый интерфейс сервиса: `getCatalogOptions()` возвращает справочники и диапазон дат, `recommend(request)` — `Promise<RecommendationResponse>`. Бизнес-статусы: `matched`, `category_absent`, `no_match`. Ошибки валидации и технические ошибки обрабатываются отдельно; HTTP API возвращает для них 400 и 500 соответственно.

## Установка и запуск

### 1. Получить проект и установить зависимости

Нужны Git, npm и **Node.js 20.x от 20.19.0 либо Node.js от 22.12.0** согласно `package.json`. Для закрытого репозитория потребуется доступ GitHub.

```sh
git clone https://github.com/BAITC-Hacks/hack-34cd10d9-aya-dilya.git
cd hack-34cd10d9-aya-dilya
```

На момент подготовки README совместная версия находится в ветке `codex/smart-integration-check`:

```sh
git switch codex/smart-integration-check
npm ci
```

Если проект уже скачан, выполните команды из корня этой версии. Для первой установки зависимостей нужен доступ к npm registry.

### 2. Запустить без внешнего AI

Для основного сценария `.env` не нужен:

```sh
npm run dev
```

Откройте адрес, который напечатает Vite, обычно [http://localhost:5173](http://localhost:5173). Если порт занят, Vite выберет следующий. Dev-сервер обслуживает и интерфейс, и `/api/recommend`.

### 3. При необходимости подключить OpenAI

Если `.env` ещё нет, создайте его из примера:

```sh
cp .env.example .env
```

Заполните локально:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Перезапустите сервер. Ключ должен находиться только в серверном окружении: не используйте префикс `VITE_`, не добавляйте ключ в Git. `.env` исключён через `.gitignore`. С настроенным ключом запрос пользователя и факты выбранных профилей отправляются OpenAI; вызовы API могут тарифицироваться.

### 4. Запустить собранное приложение

```sh
npm run build
npm run start
```

По умолчанию приложение доступно на [http://127.0.0.1:4173](http://127.0.0.1:4173). `HOST` и `PORT` задаются окружением или `.env`. Сервер раздаёт `dist`, обслуживает API и предоставляет `GET /healthz`.

Для этого запуска нужны исходные серверные файлы и установленные devDependencies, поскольку `tsx` находится в них. **`npm run preview` обслуживает только статику, без API**; для проверки полной версии используйте `npm run start`.

Идентификаторы приведены для сверки API и автоматических проверок; в интерфейсе показаны имена. Состав и порядок результатов не зависят от наличия AI-ключа, формулировка AI-текста может отличаться.

### Автоматические проверки

```sh
npm run check
npm run build
npm run demo
```

`npm run check` проверяет актуальность данных, типы, **51 тест** ядра, сервера и UI-адаптера, а также браузерную сборку ядра. Среди проверок — 6 600 запросов по всем 100 датам календаря, неизменность исходных данных, границы фильтров, ранжирование, альтернативы и обработка ошибок. `npm run demo` воспроизводит восемь базовых сценариев, проверяет ожидаемые id и печатает замеры локального сервиса без UI и внешнего API.

Для проверки собранного приложения оставьте `npm run start` запущенным и выполните в другом терминале:

```sh
npm run smoke:release -- http://127.0.0.1:4173
```

Проверяются health endpoint, HTML, IT-подбор, «План Б», применение бюджета и ошибка даты. При настроенном ключе эта команда может вызвать OpenAI.

Отдельная проверка реального AI-вызова:

```sh
npm run check:ai
```

Нужен настроенный ключ. Успех — `ai.mode: openai` и код завершения 0. Код 2 означает отсутствие ключа, код 1 — переход на резервное объяснение. Обычные автоматические тесты используют подмену ответов OpenAI и не требуют ключа.

## Данные и интеграции

Источник — предоставленный для кейса анонимизированный CSV, сохранённый в [src/data/raw/contractors.csv](src/data/raw/contractors.csv). Продукт использует подготовленный [каталог](src/data/catalog.json); статистика и контрольная сумма источника находятся в [audit.json](src/data/audit.json).

- **66 профилей:** Алматы — 50, Астана — 15, значение «Зарубежье» — 1.
- 13 профилей помечены как синтетические, у 8 предположен город, у 18 оценочная цена. Эти группы могут пересекаться.
- У 9 профилей ограничение длительности присутствия неприменимо.
- Календарь фиксирован: с 23 сентября по 31 декабря 2026 года включительно.

Нормализация сохраняет флаги происхождения данных. Команда `npm run data:check` проверяет соответствие подготовленных файлов исходнику; `npm run data:prepare` пересоздаёт их. Демо использует настоящий каталог, а не заранее зашитые ответы.

Единственная внешняя интеграция приложения — необязательный **OpenAI Responses API**. Сервер отправляет выбранные факты, требует структурированный ответ, проверяет id, ссылки на факты, числа и некоторые неподтверждённые утверждения. Успешные ответы кешируются на 15 минут, таймаут обращения — 6,5 секунды. При ошибке или отклонении текста возвращаются объяснения по правилам.

## Ограничения текущей версии

- Цена «от» не гарантирует итоговую стоимость. Отсутствие занятой даты в CSV не подтверждает реальную доступность подрядчика; внешнего календаря и актуализации занятости нет.
- Подбор работает только по данному каталогу и фиксированному диапазону дат. Синтетические и оценочные данные не выдаются за проверенные сведения.
- Пожелания распознаются словарём из десяти тем, а не универсальным семантическим поиском. Неизвестные темы не влияют на порядок; отрицания и сложные формулировки могут распознаваться неполностью. Цитаты взяты из описаний профилей, а не из отзывов клиентов.
- AI помогает только с формулировками. Проверки ответа снижают риск неподтверждённых утверждений, но не доказывают смысловую достоверность каждого предложения. При отклонении ответа AI-маркировка не показывается.
- «План Б» не меняет несколько условий одновременно и не гарантирует альтернативу для любого запроса.
- Нет регистрации, личного кабинета подрядчика, редактирования каталога, бронирования, оплаты и отправки заявок.
- API ограничен 30 запросами в минуту на адрес соединения. За прокси пользователи могут делить этот лимит; отдельной авторизации и распределённого контроля расходов нет.
- Автоматические проверки подтверждают поведение на имеющихся данных, но не измеряют пользовательскую пользу и нагрузочную устойчивость публичного сервиса.

## Развёрнутая версия

**Публичная deployed-версия не опубликована.** Репозиторий содержит рабочие варианты локального запуска с сервером. Адреса `localhost` и `127.0.0.1` доступны только на машине, где запущен проект, и не являются публичной ссылкой.

Настройки для возможного размещения описаны в [docs/release.md](docs/release.md).
