# OnlyFriends: прогноз мощности ВЭС

Воспроизводимый почасовой прогноз нормализованной активной мощности двух турбин на 48 часов. Для каждого исторического запуска используется отдельный архивный выпуск ECMWF IFS, доступность которого оценивается до момента расчёта. Числовой прогноз выполняет обученная модель; кодовый оркестратор запускает загрузку, проверки, расчёт, анализ и запись происхождения результата.

Веб-интерфейс React + TypeScript + Vite находится в [`frontend/`](frontend/README.md). Он получает погоду и прогноз обученной модели через `windpower.api`; порядок запуска API и интерфейса описан в документации фронтенда.

## Состояние

Реализованы загрузка истории, обучение с помесячной проверкой, архив погоды, прогноз одного выпуска, последовательный ретропрогноз и API для визуализации. История организаторов **не публикуется** в Git; положите свои копии двух CSV в `raw/`. Февральских значений мощности в исходных файлах нет, поэтому февральский MAE/RMSE нельзя вычислить до получения факта.

Отдельный агент на LangGraph выполняет ограниченный прогнозный цикл, LangChain предоставляет погодные и поисковые инструменты, а LangSmith поддерживает необязательную трассировку.

## Данные и временные правила

- `raw/*turbine 1.csv` и `raw/*turbine 2.csv`: исходные 10-минутные данные с колонками `Статистическое время`, `Средняя скорость ветра(m/s)`, `Нормализованная активная мощность`, `Средняя температура окружающей среды(°C)`.
- Часовая цель — средняя мощность из минимум четырёх корректных записей. Недостаточно покрытые часы не используются. 12 неоднозначных 10-минутных меток при смене часового пояса Казахстана исключены с учётом в отчёте.
- Рабочее предположение: исходные метки заданы в `Asia/Almaty`; ежедневный запуск происходит в 00:00 этого пояса. Для обучения разрешены цели только до 2026-02-01 00:00 локального времени. Метки внутри кода хранятся в UTC.
- Метеоисточник: [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api), `models=ecmwf_ifs`, координаты `43.645150,78.535604` и `43.643198,78.538828`. Оба пункта попадают в одну модельную ячейку около `43.620384,78.47891`; различие турбин модель изучает по идентификатору и их мощности.
- Источник не отдаёт точное историческое время публикации в ответе. Мы допускаем запуск ECMWF не раньше чем через 7 часов после инициализации. Это **явное допущение**, а не доказанный timestamp публикации. Его правило и время выбранного запуска сохраняются с прогнозом. [Open-Meteo называет архив Single Runs hindcasts](https://open-meteo.com/en/docs/single-runs-api); неизменность ответа со времени исходного выпуска не доказана. Поэтому строгую историческую доступность погоды нельзя подтвердить одним этим API — для эксплуатации нужен архив оригинальных файлов с временем получения либо подтверждёнными журналами публикации.
- Скорость ветра запрашивается в м/с. В прогнозе используются только переменные архивного выпуска: ветер на 10 и 100 м, направление на 100 м, температура на 2 м, давление, календарное время и горизонт. Дополнительные признаки — компоненты ветра, сдвиг между высотами, возраст выпуска, соседние прогнозные часы того же выпуска и оценка плотности воздуха. Измеренный в будущем ветер не является входом прогнозной модели.

Сведения об API, доступности запусков и лицензии: [Single Runs](https://open-meteo.com/en/docs/single-runs-api), [условия Open-Meteo](https://open-meteo.com/en/terms). Данные Open-Meteo распространяются по CC BY 4.0 с указанием источника; открытый API предназначен для некоммерческого использования.

## Установка

Нужны Python 3.10+ и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```bash
uv sync
uv run pytest -q
```

Первое обучение скачивает около 688 ежедневных архивных выпусков и кэширует ответы в `artifacts/weather/`. Если архив временно недоступен, пропущенные даты фиксируются в `training_manifest.json`; фактическая погода их не заменяет. Файлы `raw/`, `artifacts/` и `.venv/` по умолчанию игнорируются Git. Для проверки результата в репозитории отдельно сохранены выбранные модели, метрики, 29 актуальных выпусков и итоговые CSV; исходные SCADA и полный погодный кэш не публикуются.

## Обучение и прогноз

### API и визуализация

```powershell
uv run python -m windpower.api
# во втором терминале:
cd frontend
npm ci
npm run dev
```

API слушает только `127.0.0.1:8000` и по умолчанию использует `artifacts/model/model.joblib`. Для архива интерфейс переводит локальную дату выпуска `00:00 Asia/Almaty` в UTC: выпуск 31 января соответствует `2026-01-30T19:00:00Z`. API подбирает раннюю версию модели для этого выпуска и проверяет, что её обучение закончилось до момента запуска. Режим `live` получает актуальный прогноз ECMWF и может начать 48-часовое окно с будущей даты в пределах десятидневного окна API. Ответ содержит по 48 погодных и модельных точек для каждой из двух координат, версию модели, погодный выпуск или время получения, хеш и предупреждения. Прогнозы API сохраняются отдельно в `artifacts/dashboard_runs/`.

Экран **Operations** превращает почасовой прогноз в краткую сводку для оператора: показывает ожидаемые 3-часовые изменения средней нормализованной мощности двух турбин от 25 п.п., низкую выработку не выше 15% не менее трёх часов, разницу с предыдущим сопоставимым прогнозом и этапы LangGraph. Пороги служат сигналами для проверки, а не подтверждёнными пределами безопасности. При открытой вкладке live-прогноз пересчитывается каждые 15 минут; сравнение использует только общие прогнозные часы. Исторический выпуск сравнивается только с более ранним выпуском.

Для автономного контроля при закрытом браузере запустите в отдельном терминале `uv run python -m windpower.watch --interval-minutes 15`. Он проверяет погоду сразу после старта и затем каждые 15 минут; модель вызывается только если для того же часа выпуска изменились погодные значения или версия модели. `--once` делает одну проверку. Процесс должен оставаться запущенным; в промышленной среде его запуск и перезапуск следует поручить менеджеру процессов.

Вопросы ассистенту отправляются через `POST /api/ask` вместе с ID сохранённого прогноза, выбранным часом, турбиной и горизонтом. Сервер читает именно этот прогноз. Пик нормализованной мощности рассчитывается напрямую по почасовым значениям; для других вопросов используется `OPENAI_API_KEY` из `.env` или окружения, и ключ в браузер не передаётся. На вопросы с объяснением ассистент отвечает несколькими предложениями с конкретными значениями прогноза и оговоркой о неопределённости; простые численные ответы остаются короткими. Для объяснения причин ветра сервер дополнительно получает прогноз давления на уровне моря в пяти соседних точках ECMWF. Для исторического режима используется тот же архивный выпуск, а для live контекст запрашивается отдельно и совпадение погодного выпуска не утверждается. Градиент давления помогает объяснить возможный механизм, но не доказывает конкретный фронт или циклон.

Примеры: `/api/forecast?mode=historical&issue=2026-01-30T19%3A00%3A00Z` и `/api/forecast?mode=live`. Если модель или погода недоступны, API выдаёт структурированную ошибку, без подстановки чисел. Историческое время публикации погодного выпуска по-прежнему оценивается правилом `+7 часов`; это ограничение показано в UI и не считается доказательством фактической доступности.

```bash
uv run python -m windpower train
uv run python -m windpower forecast --issue 2026-01-31
uv run python -m windpower backtest --from 2026-01-31 --to 2026-02-28
uv run python -m windpower run --issue 2026-02-01
uv run python scripts/verify_outputs.py
uv run python scripts/run_model_search.py
uv run python scripts/run_turbine_control.py
```

`ForecastAgent` принимает `predictor(features) -> DataFrame` с полями `turbine_id`, `valid_time_utc`, `lead_hour` и `predicted_power` для 48 часов по каждой турбине. `ForecastAgent(...).run(issue_utc)` принимает точный час UTC, возвращает `AgentResult` и при успехе сохраняет JSON с прогнозом, сводкой по двум 24-часовым окнам, временем и хешем погодного выпуска и версией модели. Исходный ответ погоды хранится отдельно в кеше. Контракт проверяется синтетическим предиктором из `tests/test_agent.py`; его значения не являются прогнозом ВЭС.

`run_daily(first_issue_utc, last_issue_utc)` последовательно запускает граф по дням и прекращает прогон при первой ошибке. Лимит — 29 запусков: 31 января и 1–28 февраля; для всех дат используется один час UTC.

`research_sources(query)` вызывает отдельный инструмент `search_web`, который возвращает до пяти ссылок и кратких фрагментов текущей выдачи. Поиск предназначен для исследования документации и не вызывается во время ретропрогноза. Его результаты не подтверждают историческую доступность сведений и не попадают в признаки модели. При недоступности сервиса поиск завершается ошибкой, не подменяя погодные данные.

Для необязательной трассировки задайте `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY` и при необходимости `LANGSMITH_PROJECT`. Ключ задаётся через переменную окружения. Агент отправляет в LangSmith шаги и их статус, скрывая входы и выходы; без ключа работает локально. Для ретропрогноза требуется отдельно подтвердить фактическое время публикации погодных выпусков: текущая проверка использует оценку `run_time_utc + 7h <= issue_time_utc`.

`train` строит монотонную кривую мощности от прогнозного ветра, прямые CatBoost-модели с базовыми и расширенными погодными признаками, двухэтапную коррекцию ветра с кривой мощности и фиксированные смеси 50/50. Глубина 4/6, регуляризация 3/10, 500 деревьев и seed 42 заданы заранее. Основной победитель выбирается по средней MAE на октябре 2025 — январе 2026 при условии улучшения в большинстве месяцев: погодная модель сравнивается с лучшей базовой прямой моделью, смесь — с лучшей прямой. Для первого выпуска 31 января модель выбирается только по октябрю — декабрю 2025. Проверочный месяц определяется **датой выпуска**, поэтому его известные целевые часы следующего месяца тоже оцениваются. Каждый месяц должен иметь не менее 80% ежедневных погодных выпусков; фактическое покрытие указано в CSV метрик. Затем создаются две версии модели: с метками строго до 31 января 00:00 и строго до 1 февраля 00:00 по местному времени. Прогноз отвергается, если последняя обучающая метка не раньше времени выпуска. Февраль не участвует в подборе.

`forecast` сохраняет 48 значений для каждой турбины и 48 суммарных значений станции. Сумма двух нормализованных мощностей имеет диапазон `[0, 2]`; трактовка как эквивалента номинала одной турбины предполагает одинаковую паспортную мощность обеих машин. `backtest` повторяет 29 запусков с 31 января по 28 февраля включительно и сохраняет каждый выпуск отдельно. `run` для 31 января читает обучающие метки и погодные выпуски только до момента выпуска; 1 февраля обучает новую версию после поступления данных за 31 января. Он проверяет хеш исходных CSV, погодного архива для обучения и версию алгоритма; при изменении переобучает модель и создаёт прогноз. Если часть архивных выпусков ранее не загрузилась, агент повторяет попытку и проверяет, появился ли новый допустимый вход. Бинарные модели сохраняются по неизменяемым версиям. Повтор запуска с теми же моделью и погодным выпуском возвращает тот же файл; новый выпуск получает отдельный `run_id`.

Оркестратор `run` отвечает только за полный цикл одного выпуска. Его допустимые операции: проверка истории и кэша, обучение при изменении допустимых входов, запрос архивной погоды, прогноз и запись результатов. Он не меняет исходные CSV, не заменяет недостающую погоду фактической и не строит численный прогноз свободным текстом. Выход — путь к CSV либо явная ошибка с JSON-журналом. Цикл завершается после одного успешного выпуска или конечной ошибки; передача задач другим агентам не предусмотрена. Для него не нужен LLM: выбор и проверки детерминированы, а численный прогноз делает CatBoost.

## Качество на месяцах подбора модели

На четырёх последовательных месяцах (октябрь 2025 — январь 2026) оценено 11 528 прогнозов «турбина × час × выпуск» для выбранной модели. Таблица показывает **среднее по месячным метрикам**, поэтому повторяющиеся целевые часы учитываются как отдельные прогнозы разных выпусков. Эти месяцы использованы для выбора кандидата; таблица не является независимой оценкой будущей ошибки. Покрытие ежедневных погодных выпусков — 100% в каждом из четырёх месяцев. Из 123 выпусков у 112 есть все 96 целевых меток по двум турбинам; 11 имеют неполные метки и учтены в [отчёте покрытия](artifacts/model/validation_issue_coverage.csv).

| Модель | MAE | RMSE |
| --- | ---: | ---: |
| Базовая кривая мощности | 0,18296 | 0,23788 |
| Прямая CatBoost, базовые признаки | 0,15955 | 0,23618 |
| Прежняя смесь 50/50 | 0,15907 | 0,23322 |
| **CatBoost, погодные признаки (выбрана)** | **0,15351** | **0,23121** |
| Смесь с погодными признаками | 0,15470 | 0,22845 |

Выбранная модель снизила MAE относительно базовой кривой на **16,1%**, относительно прежней смеси — на **3,5%**. Она лучше базовой прямой CatBoost в октябре, ноябре и декабре; в январе немного уступает. На 123 парных днях выпуска её MAE ниже прежней смеси в 78 днях. Парная разность средней месячной MAE равна −0,00555, а 95% интервал бутстрэпа по дням внутри месяцев — [−0,00815; −0,00295]. Интервал **исследовательский**: модель выбиралась на этих же месяцах, а соседние дни могут зависеть друг от друга. MAE по горизонтам 1–24 и 25–48: 0,14489 и 0,16223. Самый сложный месяц — декабрь (0,18846). Эти значения **не являются метриками февраля**.

### Девять моделей и подбор гиперпараметров

Дополнительный `GridSearchCV` использует только временные folds июля–сентября 2025 года. После заморозки параметров каждая модель обучается заново перед октябрём, ноябрём, декабрём и январём и оценивается на одинаковых известных часах архивных выпусков. Часы после 31 января без факта исключены. Исходный погодный архив содержит 682 выпуска; шесть дней 5–10 августа 2025 года отсутствуют в кэше. Таблица даёт **среднее четырёх месячных метрик**, а не ошибку февраля.

Новый CatBoost выиграл у рабочей модели только октябрь: 0,121957 против 0,122753; в ноябре–январе проиграл. Его средняя MAE выше на 0,001074. Остальные восемь моделей также не улучшили среднюю MAE. Правило выбора требует выигрыш как минимум в 3 из 4 месяцев и меньшую среднюю MAE; для версии 31 января — в 2 из первых 3. Рабочие версии и февральский прогноз оставлены прежними. Полные сетки, метрики по месяцам, двум турбинам и дням выпуска, парные разности и допущения находятся в [`artifacts/model_search/`](artifacts/model_search/) и [протоколе оценки](docs/EVALS.md). [Разбор версий, скачков и различий турбин](docs/FORECAST_DIAGNOSTICS.md) включает отдельную контрольную модель каждой турбины.

MAE и RMSE выражены в долях нормализованной мощности, а не в МВт·ч. Для расчёта физической выработки нужны паспортные мощности и подтверждённая база нормализации. Ошибки февраля рассчитываются отдельно при появлении фактических февральских значений; их нельзя выдавать за результаты проверки на исторических месяцах.
