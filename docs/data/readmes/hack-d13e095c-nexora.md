# Протокол · Nexora

### Совещание → протокол → поручения → контроль исполнения

Рабочее пространство для конференций по LAN и подготовки протоколов с локальным ИИ. Участники общаются в браузере, организатор включает запись, Whisper распознаёт речь, а Ollama формирует сводку и поручения для проверки человеком.

**Текущий статус: MVP.** Frontend подключён к FastAPI и PostgreSQL. Деморежим и генераторы примерных данных удалены. Для распознавания и анализа необходимы доступные self-hosted Whisper и Ollama.

## Быстрый старт

### 1. Что установить

- **На ПК с сайтом:** Git и Docker Desktop (Windows/macOS) либо Docker Engine с Compose v2 (Linux). Запустите Docker. Node.js, Python и PostgreSQL отдельно устанавливать не нужно.
- **На ПК с моделями:** Ollama. Это может быть тот же компьютер, где запущен сайт, или отдельный компьютер в той же LAN.

### 2. Скачать модель на ПК с Ollama

```sh
ollama pull qwen3:8b
```

Если Ollama расположен на отдельном ПК, задайте для процесса Ollama переменную окружения `OLLAMA_HOST=0.0.0.0:11434`, перезапустите Ollama и разрешите доступ к TCP 11434 из вашей LAN. Если Ollama запущен на том же ПК, внешний порт `11434` открывать не нужно.

### 3. Скачать проект и настроить адреса на ПК с сайтом

```sh
git clone https://github.com/BAITC-Hacks/hack-d13e095c-nexora.git
cd hack-d13e095c-nexora
cp .env.conference.example .env
```

Если проект уже скачан — выполните `git pull origin main`. Существующий `.env` сохраните. В PowerShell для копирования можно использовать `Copy-Item`.

Откройте `.env` и замените адреса на свои:

```dotenv
SITE_HOST=192.168.1.100
OLLAMA_URL=http://192.168.1.101:11434
OLLAMA_MODEL=qwen3:8b
SPEECH_URL=http://speech:8001
```

Здесь `.100` — ПК с сайтом, `.101` — ПК с Ollama. Для существующей базы сохраните прежний `POSTGRES_PASSWORD`.

Если Ollama и Docker работают на одном ПК, используйте `OLLAMA_URL=http://host.docker.internal:11434`.

#### PowerShell: настройка `.env`

Не вставляйте URL как Markdown-ссылку: значение должно быть обычным текстом `http://...`. Пример для IP `10.19.16.77` и Ollama на этом же ПК:

```powershell
Copy-Item .env.conference.example .env -Force
$config = Get-Content .env
$config = $config -replace 'SITE_HOST=.*', 'SITE_HOST=10.19.16.77'
$config = $config -replace 'OLLAMA_URL=.*', 'OLLAMA_URL=http://host.docker.internal:11434'
$config | Set-Content .env
```

### 4. Запустить всё

```sh
docker compose --profile speech up -d --build
```

Команда запускает сайт, API, базу, обработчик, HTTPS и Whisper. При первом запуске Whisper автоматически скачает `large-v3` — несколько ГБ; дождитесь завершения. HF-токен не нужен. Ollama продолжает работать на другом ПК. Whisper по умолчанию использует CPU и может не успевать за разговором.

**Если Whisper тоже нужен на другом ПК:** настройте его по [инструкции](CONFERENCES.md#3b-whisper-на-другом-пк-рядом-с-ollama), задайте `SPEECH_URL` и одинаковый `SPEECH_API_KEY` на обоих ПК; сайт запускайте командой `docker compose up -d --build` без профиля speech. Там же описан запуск с NVIDIA GPU.

### 5. Открыть сайт и начать встречу

Для камеры и микрофона по LAN установите сертификат сервера на каждом компьютере участника. Получить его:

```sh
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt ./conference-root.crt
```

Импортируйте `conference-root.crt` в доверенные корневые сертификаты ([как установить](CONFERENCES.md#4-https-для-всех-участников)), разрешите TCP 8443 на ПК с сайтом и откройте **`https://192.168.1.100:8443`**, заменив IP на свой.

**Начать совещание → создать → войти → пригласить коллег → включить «Запись и ИИ».** Кнопка «Проверить ИИ» покажет доступность Whisper и Ollama.

Проверка контейнеров: `docker compose ps`. Остановка с сохранением данных: `docker compose down`.

**Подробности и проверка двумя участниками: [CONFERENCES.md](CONFERENCES.md).**

## Диагностика Docker и LAN

### Проверить запуск

```powershell
docker compose ps
docker compose logs --tail=100
```

Нормальный результат: `api` и `db` имеют статус `healthy`; `gateway`, `frontend`, `live-worker` и `speech` имеют статус `Up`.

PostgreSQL работает в Docker на ПК с сайтом. База не опубликована в LAN: к ней обращается только API через внутреннюю сеть Compose. Данные сохраняются после `docker compose down`; команда `docker compose down -v` удаляет том базы.

### Сайт не открывается у коллег

Проверьте, что все устройства в одной сети, Docker Desktop запущен, а TCP-порт `8443` разрешён в брандмауэре Windows. На ПК с сайтом порт можно проверить командой:

```powershell
netstat -ano | findstr :8443
```

Для быстрой проверки интерфейса без сертификата используйте `http://ВАШ_IP:8080`. Этот адрес не подходит для микрофона, камеры и демонстрации экрана: браузеры разрешают их в LAN только по доверенному HTTPS.

### `ERR_SSL_PROTOCOL_ERROR` при `https://ВАШ_IP:8443`

Для LAN-IP Caddy должен иметь `default_sni`; он уже добавлен в `deploy/Caddyfile`. После обновления репозитория перезапустите gateway:

```powershell
git pull origin main
docker compose up -d --build gateway
docker compose logs gateway --tail=100
```

В `SITE_HOST` указывайте только IP или DNS-имя: без `http://`, `https://`, номера порта, квадратных скобок и Markdown-разметки.

### Микрофон и камера недоступны

Экспортируйте корневой сертификат Caddy:

```powershell
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt .\conference-root.crt
```

Импортируйте `conference-root.crt` в доверенные корневые центры сертификации ОС на каждом устройстве, полностью перезапустите браузер и откройте `https://ВАШ_IP:8443`. Затем разрешите браузеру доступ к микрофону и камере.

### ИИ недоступен

```powershell
ollama list
Invoke-WebRequest http://127.0.0.1:11434/api/tags
docker compose logs live-worker --tail=100
```

Для Ollama на том же ПК используйте `OLLAMA_URL=http://host.docker.internal:11434`; для отдельного ПК — его LAN-IP, например `OLLAMA_URL=http://192.168.1.101:11434`.

## Возможности

| Область | Реализация MVP |
| :--- | :--- |
| Конференции | Создание, планирование, приглашения, до 8 одновременных участников |
| Общение | WebRTC-аудио и видео, демонстрация экрана, чат |
| Запись | Явное включение организатором, уведомление участников, очередь аудиофрагментов |
| Расшифровка | Self-hosted Whisper, RU/KK, имена по отдельным потокам участников |
| Анализ | Удалённая локальная Ollama: промежуточная сводка, поручения и итоговый анализ |
| Поручения | Исполнитель, срок, цитата-основание, редактирование и статусы |
| Документы | Экспорт PDF, DOCX и аудиозаписи WAV |
| Напоминания | Сроки и просрочка в приложении; уведомления браузера при открытом сайте |
| Хранение | PostgreSQL и Docker-том записей; локальная очередь неотправленного аудио в браузере |

Начальные списки пустые. Встречи создаются пользователями, а реплики и результаты появляются после реальной обработки. Недоступность ИИ отображается в интерфейсе без подстановки примерного текста.

## Архитектура

- **Frontend:** React 19, TypeScript, Vinext / Vite.
- **Backend:** FastAPI, SQLAlchemy, PostgreSQL, Alembic.
- **Медиа:** WebRTC mesh; FastAPI предоставляет WebSocket-сигналинг.
- **ИИ:** отдельный сервис faster-whisper и Ollama на вашем сервере.
- **Развёртывание:** Docker Compose, Caddy HTTPS, один API-процесс и один live-worker.

Старый API обработки загруженных файлов с pyannote остаётся отдельным сценарием: [backend/README.md](backend/README.md). Его worker не запускается в корневом стеке живых конференций.

## Разработка

Node.js 22.13 или новее:

```sh
npm ci
npm run dev
```

Backend запускается отдельно или через Docker. Dev-сервер проксирует запросы конференций к локальному API.

## Проверки

```sh
npx tsc --noEmit
node scripts/test-live-audio.mjs
npm run build
```

Серверные тесты находятся в `backend/tests`.

При реализации проверены Docker-сборка и запуск, миграция PostgreSQL, HTTPS, 85 серверных тестов и 2 теста аудиокодирования/завершения записи. Тесты ИИ используют контролируемые ответы и проверяют обработку данных, а не качество моделей.

Реальный звонок между двумя физическими ПК, скорость обработки и качество русской, казахской и смешанной речи требуют проверки на вашем оборудовании. Сценарий приёмки включён в [CONFERENCES.md](CONFERENCES.md).

## Ограничения и дальнейшее развитие

- Каждый участник использует свой микрофон: подпись по имени не является биометрическим распознаванием личности.
- Скорость зависит от оборудования и моделей; CPU может не успевать за разговором.
- Доступ осуществляется по приглашению и персональному токену браузера; корпоративный SSO не реализован.
- Напоминания требуют открытого приложения. Email/Telegram и внешняя СЭД пока не подключены.
- В сетях без прямой связности участников необходим собственный TURN-сервер.

Разработано командой **Nexora**.
