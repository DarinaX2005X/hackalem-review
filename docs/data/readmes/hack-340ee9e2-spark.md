# Spark — локальное протоколирование совещаний

Проект команды **Spark** для **HackAlem AI**. Веб-приложение превращает MP3-запись совещания в транскрипт с временными метками и обозначениями говорящих, формирует краткое содержание и таблицу поручений, позволяет скачать протокол в DOCX.

Обработка выполняется на компьютере, где запущен сервер. Для распознавания речи используется многоязычная **Whisper small через faster-whisper**, для разделения говорящих — **pyannote Community-1**. Саммари и поручения формируются **локальными правилами**, а не LLM. Ollama и Qwen из первоначального плана в текущую интеграцию не подключены.

## Статус проекта

Реализован и проверен сквозной сценарий: загрузка настоящей MP3 через браузер → локальная транскрибация → диаризация → анализ текста → отображение результатов → скачивание DOCX.

В интеграционной проверке от **23 сентября 2026 года** обработаны первые **60 секунд русской записи**. Это не подтверждает качество распознавания всей записи, казахской или смешанной речи. Подробности и ограничения приведены ниже и в [отчёте интеграции](backend/INTEGRATION_CHECK.md).

`PROJECT_BRIEF.md` содержит первоначальные требования и план. Фактически реализованные возможности описаны в этом README; часть функций исходного плана ещё не выполнена.

## Возможности

- Загрузка одной MP3-записи за раз; API также принимает расширение `.mpeg` для MPEG-аудио.
- Обработка первых 60 секунд для быстрой демонстрации или всей записи длительностью до 10 минут.
- Локальное распознавание речи на CPU в режиме INT8.
- Автоматическое определение языка; через API и CLI можно явно выбрать `ru` или `kk`.
- Транскрипт с началом и концом каждого сегмента в секундах.
- Локальная диаризация: технические метки `SPEAKER_00`, `SPEAKER_01` и далее.
- Сохранение `speaker: null`, если говорящего нельзя однозначно сопоставить с сегментом.
- Краткое содержание и извлечение поручений с ответственным, сроком и фрагментом-основанием по локальным правилам.
- Экспорт протокола в DOCX.
- Отображение состояния обработки, предупреждений и ошибок; блокировка повторной отправки во время запроса.
- Сохранение транскрипта при недоступности диаризации.

Разделение голосов не определяет реальные имена участников. Техническая метка говорящего сама по себе не означает, что этот человек отвечает за поручение.

## Архитектура

```text
Браузер: HTML / CSS / JavaScript
    │ POST /analyze-audio, multipart file
    ▼
FastAPI: проверка файла и временное хранение
    │
    ├─ transcribe_mp3 → faster-whisper small → текст и временные метки
    ├─ add_diarization → отдельный процесс Community-1 → метки говорящих
    └─ build_protocol → локальные правила → саммари и поручения
    │
    ▼
JSON → отображение в браузере
    │ POST /export-docx с объектом protocol
    ▼
python-docx → документ Word
```

FastAPI обслуживает и API, и файлы интерфейса на одном адресе. Отдельный сервер frontend не требуется. Аудиозапрос синхронный: браузер ожидает итоговый результат, фоновой очереди и маршрутов опроса `/api/meetings/...` нет. Тяжёлая обработка вызывается через пул потоков, диаризация — в отдельном Python-процессе.

## Требования

Проверенное окружение: **macOS, Apple Silicon arm64, Python 3.13.2, CPU**. Команды ниже рассчитаны на macOS/Linux с путями `bin/python`. Работа на других ОС и архитектурах отдельно не подтверждена; доступность готовых пакетов нужно проверять для выбранной платформы.

Для первоначальной установки нужен интернет: Python-пакеты загружаются из PyPI, модели — из Hugging Face. Для обработки используются локальные модели. Размер загруженных файлов Whisper small в проверенной сборке — около **486,2 МБ**, выбранных файлов Community-1 — около **32,8 МБ**. Зависимости, окружения и кэши занимают дополнительное место.

Окружения разделены:

| Каталог | Назначение |
|---|---|
| `.venv-integration` | Сервер, анализ текста, экспорт и транскрибация при обработке через веб-интерфейс |
| `audio_module/.venv` | Самостоятельные команды аудиомодуля и его тесты |
| `audio_module/.venv-diarization` | Отдельный процесс pyannote/PyTorch |

В этом пути MP3 декодируется через PyAV, а диаризация получает готовый waveform. Отдельная установка системного FFmpeg для описанного сценария не требуется.

## Быстрый запуск на уже подготовленном компьютере

Выполняйте команды из корня репозитория. Если модели и три окружения уже установлены, повторять установку не нужно.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 \
PYANNOTE_METRICS_ENABLED=0 OTEL_SDK_DISABLED=true \
.venv-integration/bin/python -m uvicorn backend.main:app \
  --host 127.0.0.1 --port 8000 --no-access-log
```

- Приложение: http://127.0.0.1:8000/
- Интерактивное описание API: http://127.0.0.1:8000/docs
- Проверка живости сервера: http://127.0.0.1:8000/health

Для обычной демонстрации используйте главную страницу. Страница `/docs` — вспомогательный инструмент FastAPI, её оформление может требовать внешних ресурсов.

Запускайте **один процесс Uvicorn**, без `--workers`: защита от одновременной обработки записей действует внутри процесса. Для остановки нажмите `Ctrl+C` в терминале сервера. Если сервер уже запущен на порту 8000, второй экземпляр запускать не нужно.

## Установка с нуля

### 1. Получить код

Репозиторий команды требует предоставленного доступа GitHub. Пока общая сборка находится в `integration`:

```bash
git clone --branch integration https://github.com/BAITC-Hacks/hack-340ee9e2-spark.git
cd hack-340ee9e2-spark
```

После принятия интеграции в `main` можно использовать основную ветку. Если репозиторий уже есть на компьютере, повторное клонирование не требуется.

### 2. Подготовить окружения

Проверьте, что установлен Python 3.13:

```bash
python3.13 --version
python3.13 -m venv audio_module/.venv
audio_module/.venv/bin/python -m pip install --only-binary=:all: -r audio_module/requirements.txt

python3.13 -m venv audio_module/.venv-diarization
audio_module/.venv-diarization/bin/python -m pip install --only-binary=:all: -r audio_module/requirements-diarization.txt

python3.13 -m venv .venv-integration
.venv-integration/bin/python -m pip install --only-binary=:all: -r requirements.txt
```

Флаг `--only-binary=:all:` требует готовые пакеты. Если для платформы или версии Python их нет, установка завершится ошибкой; проверенная конфигурация указана выше. Зависимости аудио зафиксированы в отдельных файлах, часть backend-зависимостей задаётся диапазонами версий — новая установка может отличаться от проверенной.

### 3. Скачать Whisper small

```bash
audio_module/.venv/bin/python -m audio_module.cli download
```

Модель сохраняется в `audio_module/models/faster-whisper-small`. Команда проверяет размер перед загрузкой. При обычной транскрибации автоматического скачивания нет.

### 4. Подготовить Community-1

Откройте [страницу Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), войдите в Hugging Face и оформите доступ по условиям модели. Создайте токен чтения в [настройках Hugging Face](https://huggingface.co/settings/tokens), затем выполните:

```bash
audio_module/.venv/bin/python -m audio_module.download_diarization
```

Скрипт использует существующую локальную авторизацию или запрашивает токен скрытым вводом в терминале. Введённый токен этой командой не сохраняется. Не вставляйте токен в исходники, чат или аргументы команды. Модель сохраняется в `audio_module/models/community-1`; при последующей обработке токен не требуется.

Для интеграции используйте эти команды аудиомодуля. Старый `backend/scripts/download_model.py` не нужен.

### 5. Проверить зависимости и запустить сервер

```bash
.venv-integration/bin/python -m pip check
audio_module/.venv/bin/python -m pip check
audio_module/.venv-diarization/bin/python -m pip check
```

Затем выполните команду из раздела «Быстрый запуск».

## Как пользоваться

1. Откройте главную страницу приложения.
2. Выберите MP3 до **32 МиБ**.
3. Для первой проверки оставьте обработку первых **60 секунд**. Для полного протокола выберите всю запись до **10 минут**.
4. Нажмите кнопку обработки и дождитесь результата. Во время обработки повторная отправка блокируется.
5. Просмотрите транскрипт, временные метки, говорящих, саммари и поручения. Учитывайте предупреждение о частичной обработке.
6. Сверьте важные имена, числа, ответственных и сроки с записью.
7. Скачайте DOCX и откройте его в Word или совместимом редакторе.

Отсутствие найденных поручений означает, что текущие правила их не обнаружили в обработанном тексте. Это не доказывает отсутствия поручений в совещании. Встроенного редактирования и сохранения исправлений в этой версии нет; скачанный DOCX можно проверить и исправить отдельно.

## API

| Метод и маршрут | Вход | Результат |
|---|---|---|
| `GET /health` | — | `{"status":"ok"}`; живость сервера, не готовность моделей |
| `POST /transcribe` | Multipart-поле `file`; query `language`, `max_seconds` | Текст, сегменты, диаризация, параметры обработки и предупреждения |
| `POST /analyze-audio` | Multipart-поле `file`; query `language`, `max_seconds`, `title` | Транскрипт и сформированный протокол |
| `POST /analyze` | JSON с `text` или `transcript`, необязательный `title` | Анализ уже готового текста без запуска аудиомоделей |
| `POST /export-docx` | JSON объекта `MeetingProtocol` | Документ `meeting_protocol.docx` |

`language` можно не передавать для автоопределения или указать `ru`/`kk`. `max_seconds` принимает целое число от 1 до 600; без параметра обрабатывается полная запись с ограничением длительности 10 минут. Даже короткий отрывок требует загрузки файла целиком и соблюдения лимита 32 МиБ.

Пример проверки сервера:

```bash
curl http://127.0.0.1:8000/health
```

Пример реальной обработки. Замените путь на свою запись; JSON останется в игнорируемой папке:

```bash
mkdir -p audio_module/results
curl --fail-with-body \
  -F 'file=@/absolute/path/meeting.mp3' \
  'http://127.0.0.1:8000/analyze-audio?max_seconds=60' \
  -o audio_module/results/api-result.json
```

Основные поля ответа `/analyze-audio`:

| Поле | Значение |
|---|---|
| `text` | Полный текст обработанного интервала |
| `protocol.title` | Заголовок или `null` |
| `protocol.summary` | Саммари в виде строки |
| `protocol.transcript` | Список сегментов: `start`, `end`, `text`, `speaker` |
| `protocol.action_items` | Поручения: `text`, `responsible`, `deadline`, `source_fragment`, `confidence` |
| `language` | Определённый язык |
| `processing` | Обработанный интервал, режим и признак частичной записи |
| `diarization` | Статус, причины и данные диаризации |
| `diarization_available` | `true` только при `diarization.status == "ok"` |
| `warnings` | Предупреждения для пользователя |

Для экспорта отправляется **только объект `protocol`**, а не весь ответ `/analyze-audio`. Frontend выполняет это автоматически.

CLI сохраняет сегменты в поле `segments`; backend возвращает их в `transcript`, а в ответе анализа — в `protocol.transcript`. Временные метки измеряются в секундах от начала записи. `speaker: null` допустим даже при успешной диаризации, например при смене говорящего внутри одного сегмента.

Основные HTTP-ошибки: `413` — превышен размер, `415` — неподдерживаемое расширение, `422` — некорректные данные/аудио или речь не обнаружена, `503` — сервер занят либо Whisper/зависимости недоступны, `500` — внутренняя ошибка. Недоступность Community-1 отдельно обрабатывается с сохранением транскрипта и предупреждением.

## Отдельный запуск аудиомодуля

Из корня репозитория, с заменой пути к записи:

```bash
audio_module/.venv/bin/python -m audio_module.cli transcribe \
  '/absolute/path/meeting.mp3' --max-seconds 60 \
  --output audio_module/results/transcript.json

audio_module/.venv/bin/python -m audio_module.cli diarize \
  '/absolute/path/meeting.mp3' \
  --transcript audio_module/results/transcript.json \
  --output audio_module/results/diarized.json
```

Вторая команда использует интервал из первого JSON и не запускает Whisper повторно. Исходный и выходной JSON должны иметь разные пути. Полная инструкция: [audio_module/CHECK.md](audio_module/CHECK.md).

## Локальная обработка и данные

- Рабочая цепочка приложения не использует внешние облачные API для аудио и текста.
- Пакеты и модели скачиваются отдельными подготовительными командами; при обработке используется локальная папка модели.
- Backend сохраняет загрузку во временный каталог на время запроса; каталог удаляется после выхода из обработки. Постоянной истории совещаний и базы данных нет.
- JSON самостоятельного CLI сохраняется по указанному пути. Скачанный DOCX сохраняется средствами браузера.
- Окружения, модели, записи, результаты, `.env` и `.vscode` исключаются правилами Git. Произвольный файл вне предусмотренных каталогов нужно дополнительно проверить перед коммитом.
- Сервер по инструкции слушает только `127.0.0.1`. Аутентификация и промышленное многопользовательское размещение не реализованы.
- В проверках использовались локальные модели, офлайн-настройки и блокировка внешних запросов страницы. Полный браузерный проход с физически отключённым интернетом ещё не подтверждён.

## Ограничения и дальнейшая работа

1. **Анализ текста основан на правилах.** Полнота извлечения задач из настоящего совещания не подтверждена; результаты требуют проверки человеком.
2. **Языки.** Модель многоязычная, но подтверждённый интеграционный тест выполнен только на русском отрывке.
3. **Говорящие.** Перебивания и смена голоса внутри сегмента могут приводить к `null`. Автоматическое установление личности не выполняется.
4. **Редактирование.** Встроенное исправление транскрипта, переименование говорящих и сохранение правок не реализованы.
5. **Дата совещания.** Относительные сроки вроде «завтра» сохраняются текстом; календарная дата автоматически не рассчитывается.
6. **Обработка.** Одна запись за раз, запрос синхронный. Отмена в браузере не гарантирует остановку вычислений на сервере. Детальный прогресс этапов не передаётся.
7. **Экспорт.** Нужна отдельная визуальная проверка DOCX в Word; программная проверка не заменяет её.
8. **Переносимость.** Установка и производительность на других платформах требуют отдельной проверки.

Следующие этапы: контрольные русская/казахская/смешанная записи с известными поручениями, улучшение локального анализа, редактирование и сохранение результатов, работа с датой совещания, проверка после перезапуска без интернета.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Страница не открывается | Сервер запущен, терминал не закрыт, адрес `http://127.0.0.1:8000/` |
| Порт 8000 занят | Возможно, приложение уже работает; откройте страницу перед запуском второго экземпляра |
| `/health` работает, аудио возвращает 503 | Наличие Whisper, зависимости и пути моделей; `/health` не загружает модель |
| Диаризация `unavailable` | Каталог Community-1, окружение pyannote и `DIARIZATION_PYTHON` |
| `speaker: null` при статусе `ok` | Причины в `diarization.assignments`; сегмент может содержать несколько говорящих |
| Получен только фрагмент совещания | По умолчанию UI обрабатывает первые 60 секунд; проверьте `processing` |
| Поручения не найдены | Прослушайте обработанный интервал: правила могли пропустить формулировки или поручения находятся дальше |
| Ошибки импортов в редакторе | Выберите интерпретатор соответствующего окружения; для сервера используется `.venv-integration/bin/python` |
| После клонирования нет моделей | Модели и окружения не хранятся в Git; выполните первоначальную подготовку |
