# Qor — заказы поставщикам для ekt.kz

**Qor** (қаз. *қор* — запас). Сервис для менеджера закупа ТОО «Электрокомплект»: по выгрузке из 1С считает, что пополнить на складе, в каком количестве и насколько срочно.

Сейчас это делают вручную в Excel и редко. Из-за этого по одним позициям копится лишний запас, по другим возникает дефицит, а разовая крупная отгрузка искажает регулярную потребность. Qor собирает рекомендацию по каждому артикулу и не отправляет заказ поставщику сам: человек проверяет количество и отдельным шагом утверждает.

Два клиента, один расчёт:

- **Сайт** — рабочее место закупщика: загрузка выгрузки, таблица заказов, правка количества, карточка артикула с шагами расчёта. В правом нижнем углу чат: он отвечает только цифрами этого расчёта.
- **Телефон** — согласование. Руководитель видит тот же заказ, график продаж за 12 месяцев, спрашивает «почему столько» и нажимает «Утвердить» или «Вернуть». Поставщику ничего не уходит: после утверждения менеджер выгружает заказ в 1С на сайте.

## Как считается заказ

Рабочий расчёт — `backend/qor/pipeline.py`. Он читает Excel, строит признаки скриптом `scripts/prepare_dataset_v2.py` и прогоняет модель `ml/models/demand_model_v2.cbm` (CatBoost, цель — продажи следующего месяца).

На каждый артикул:

```
рекомендация = прогноз + 0,5 × σ за 6 месяцев − остаток − в пути
```

Результат округляется вверх до минимальной партии (MOQ). Срочность — покрытие остатком и товаром в пути: меньше 0,5 месяца спроса — «Критично», меньше 1 — «Скоро», иначе «Норма». У каждой строки есть шаги: прогноз, страховой запас, остаток, в пути, округление.

Признаки модели: лаги очищенного спроса 1/2/3/6/12, скользящие среднее и σ, рост за 3 месяца, остаток, календарь (`month_sin` / `month_cos`), индекс сезонности, а также лаги выброса, пустого склада и упущенного спроса. Клиентов в расчёте нет: в выгрузке нет персонального идентификатора, крупную отгрузку можно увидеть только по номеру документа.

Та же модель обучена с поправкой на выбросы и пустые месяцы (`scripts/prepare_dataset_v2.py`, `scripts/train_model_v2.py`):

- **Разовая крупная продажа.** По каждому артикулу порог = скользящая медиана за 6 месяцев + 6 × MAD. Если MAD равен нулю, порог = max(4 × медиана, медиана + 10). Месяц выше порога заменяется медианой и не входит в регулярный спрос.
- **Упущенный спрос.** Месяц без остатка не считается нулевым спросом: оценка потерянных продаж добавляется к очищенному ряду (`demand_adjusted`).

Сайт и телефон берут заказ из `run_workspace.py`: он вызывает этот же расчёт и пишет `backend/data/workspace.json`.

## Технологии

| Часть | Стек |
|---|---|
| Сайт | Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS |
| API согласования | Python, FastAPI, uvicorn. Папка `backend/` |
| Модель | CatBoost, pandas. Файл `ml/models/demand_model_v2.cbm`, сервис `ml` |
| Телефон | Flutter, riverpod, dio. Тот же REST |
| Данные | Шесть Excel из 1С. Схема полей — `docs/06-datasets.md` |

Роли: `aigerim` / `buyer` — менеджер закупа, `daniyar` / `director` — руководитель. Пароль для демо совпадает с ролью. Утверждать и возвращать заказ может только руководитель.

## Запуск

Модель `ml/models/demand_model_v2.cbm` уже в репозитории.

```bash
docker compose up --build
```

Три контейнера: сайт, API и CatBoost. Считать заказ умеет только `ml`. API сохраняет результат и отдаёт его сайту и телефону.

| | |
|---|---|
| Сайт | http://localhost:3000 |
| API | http://localhost:8000/docs |
| Вход | `aigerim` / `buyer`, `daniyar` / `director` |

Модель наружу не публикуется: API ходит к ней по `http://ml:8002`. Готовый заказ лежит в volume `qor-data`. Свою выгрузку 1С можно примонтировать в сервис `ml` как `/data/iek`.

Чат в углу сайта — четвёртый процесс, нужен `OPENAI_API_KEY` в `.env`:

```bash
uvicorn api.main:app --host 127.0.0.1 --port 8001
```

Сайт зовёт его через `POST /api/chat` (`QOR_AI_API`, по умолчанию `http://127.0.0.1:8001`). Без этого процесса кнопка чата пишет, что ассистент не запущен.

### Без Docker

Нужны Python 3.11+ и Node.js 20+.

```bash
pip install -r backend/requirements.txt
cd frontend && npm install
```

1. Посчитать заказ. Excel — в `IEK_DATA_DIR` (по умолчанию `/Users/azamatomirtaj/Documents/IEK`): динамика продаж, ежемесячные продажи, ежемесячные остатки, путь, MOQ, сезонность.

```bash
cd backend && python3 run_workspace.py
```

Появится `backend/data/workspace.json`. В git он не коммитится.

2. API для сайта и телефона: `cd backend && uvicorn main:app --host 0.0.0.0 --port 8000`.

3. Сайт: `cd frontend && npm run dev` — http://localhost:3000 (`/import`, `/orders`, `/sku/[артикул]`, `/anomalies`, `/suppliers`).

Телефон: `cd mobile && flutter pub get && flutter run`. Симулятор iOS ходит на `http://127.0.0.1:8000`, эмулятор Android — на `http://10.0.2.2:8000`. Реальный телефон в той же сети: `flutter run --dart-define=QOR_API=http://<IP компьютера>:8000`. Сценарий проверки — `mobile/README.md`.

## Как проверить

1. `python3 backend/run_workspace.py` завершается без ошибки и пишет число SKU к заказу.
2. `curl -s http://127.0.0.1:8000/health` возвращает `"ready": true` и `"model": "demand_model_v2.cbm"`.
3. На сайте `/orders` есть строки с артикулом, остатком, «в пути», рекомендуемым количеством и бейджем срочности. Раскрытие строки показывает шаги расчёта.
4. Измените количество в файле «Путь» и пересчитайте: рекомендуемое количество по этому артикулу изменится. Так же на результат влияют остаток и история продаж.
5. Войдите в API как `daniyar` и откройте `GET /v1/bundle` — тот же JSON, что на сайте. `POST /v1/orders/iek-current/approve` переводит заказ в `approved`. Повторное утверждение — 409. Тем же методом под `aigerim` — 403.
6. На телефоне тот же заказ: «Утвердить» или «Вернуть» с комментарием меняет статус, который читает `GET /v1/orders/current`. Поставщику запрос не уходит.
7. Выбросы: `scripts/prepare_dataset_v2.py` помечает `outlier_flag` и заменяет всплеск медианой. Компенсация пустого склада — колонка `demand_adjusted` в том же скрипте. Эти колонки входят в признаки `demand_model_v2.cbm`.
