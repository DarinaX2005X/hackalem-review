# Аким на 5 часов

**AI-симулятор городских решений: распределите бюджет, выберите пять инициатив и узнайте, как они изменят качество жизни районов Астаны.**

Городскому управленцу нужно одновременно развивать транспорт, озеленение, социальную инфраструктуру, безопасность и сервисы — при ограниченных ресурсах. Наш симулятор помогает управленцам, аналитикам и участникам игры сравнить последствия решений: кому станет лучше, какие проблемы останутся и чем придётся пожертвовать.

## Как это работает

1. Пользователь выбирает инициативы и районы. Интерфейс сразу показывает расход и предварительные изменения.
2. Сервер проверяет выбор и заново вычисляет результат единым TypeScript-движком — стоимость и Score из браузера не принимаются на доверии.
3. По запросу пользователя AI исследует внешний контекст и объясняет серверный отчёт. Числовые основания выводятся из расчёта; мировой опыт не меняет коэффициенты модели.
4. Сценарий и готовое объяснение сохраняются для повторного просмотра без новой генерации.

Горизонт модели — **восемь кварталов**. Эффекты учитывают срок реализации, синергии и ограничения показателей:

```text
Эффект меры = полный эффект × (8 − срок реализации в кварталах) / 8
Score = 0.7 × средний индекс с учётом населения
      + 0.3 × индекс слабейшего района
      − число показателей ниже 40
```

Так итог учитывает и общий прогресс, и положение слабейшего района. Подробные правила — в [датасете](docs/data/dataset-source.md), реализация — [src/engine](src/engine/README.md). Движок отделён от AI: отказ модели не блокирует расчёт.

## Локальный запуск

Нужны **Node.js 22.20+** и npm; используемый менеджер — **npm 11.20.0**.

```bash
git clone https://github.com/BAITC-Hacks/hack-4078ad52-mama-papa-and-me.git
cd hack-4078ad52-mama-papa-and-me
npx --yes npm@11.20.0 ci
npm run dev
```

Откройте [127.0.0.1:3000](http://127.0.0.1:3000). Без ключа работают симуляция, отчёт и SQLite; вместо AI показывается явно обозначенное шаблонное объяснение. Для production-режима остановите dev-сервер и выполните `npm run build`, затем `npm start`.

**Чтобы включить настоящий AI:** создайте `.env` по [.env.example](.env.example), если файла ещё нет, заполните `OPENAI_API_KEY` и перезапустите сервер. Локально оставьте `DEPLOY_TARGET=local` и пустой `DATABASE_URL`. Нужны интернет и доступ к указанной модели. `AI_ENABLED=false` отключает платные вызовы.

Ключ хранится только на сервере. AI запускается по вопросу или кнопке разбора; подбор мер не расходует API-баланс. На настроенном облачном сайте посетителю собственный ключ не нужен — используется серверный ключ команды. Настройка Netlify, Neon, фонового обработчика и квоты описана [отдельно](docs/deployment.md).

Настройки сборки берутся из netlify.toml: Node 22, npm 11.20.0, команда `npm run build`, каталог `.next`, функции `netlify/functions`. Next.js требует адаптер Netlify OpenNext и серверные функции. ## 3. Переменные окружения

Задайте через Netlify UI. Они должны быть доступны функциям во время выполнения; переменные из раздела build.environment в netlify.toml для этого недостаточны. Если доступны scopes, выберите Builds и Functions. Изменение переменных требует нового деплоя.

| Имя | Значение |
| --- | --- |
| DEPLOY_TARGET | `netlify` |
| DATABASE_URL | Строка подключения из Neon, секрет |
| APP_ORIGIN | Точный адрес `https://hackalem.netlify.app`, без `/` в конце |
| WORKER_SECRET | Случайный секрет не менее 32 символов |
| OPENAI_API_KEY | Ваш собственный ключ OpenAI, секрет |
| OPENAI_MODEL | `gpt-6-astra`, проектный default сохранён |
| AI_ENABLED | Сначала `false`, после проверки расчёта и БД — `true` |
| AI_MAX_ANALYSIS_MINUTES | `12` |
| AI_DAILY_ANALYSIS_LIMIT | Сначала `10`, затем нужное число; default кода `50` |

WORKER_SECRET можно сгенерировать локально: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Не публикуйте его. Не используйте префикс NEXT_PUBLIC_ для секретов. Используйте свой ключ OpenAI, чтобы запросы расходовались из вашего API-проекта, а не через неявную интеграцию платформы.

Квота — число допущенных анализов за сутки UTC для всего сайта, не денежный лимит. Каждый анализ может содержать два платных этапа и веб-поиск. Неудачная или одновременная повторная заявка может израсходовать одно место в квоте; автоматического возврата нет. В актуальном интерфейсе анализ вызывается по запросу пользователя; каждый запуск учитывается в квоте. Симуляция остаётся доступной при исчерпании квоты.

Не включайте production-секреты для непроверенных preview-веток. Эта версия нацелена на один основной адрес; preview не должен вызывать worker production-сайта.

## 6. Проверить публикацию

Для бесплатной проверки расчёта и HTTP-защиты без вызова AI:

```powershell
node scripts/judge-smoke.mjs https://hackalem.netlify.app
```

Скрипт проверяет статус, контрольный Score, бюджет, отклонение подмены Score и чужого Origin. Он не проверяет базу или генерацию AI. При 401 сначала исправьте доступ из раздела 5.

1. При AI_ENABLED=false открыть сайт с двух устройств, рассчитать пример: Score `56,54`.
2. Сохранить сценарий, перезагрузить страницу и открыть его. После повторного деплоя сценарий должен сохраниться в Neon.
3. Включить AI и повторно опубликовать. Запустить один анализ, закрыть вкладку. Через несколько минут проверить статус и ответ в таблице analyses в Neon. Закрытие вкладки может удалить sessionStorage: автоматическое восстановление панели AI в новой вкладке этой версией не гарантируется. При простой перезагрузке той же вкладки сохранённый ID обычно остаётся.
4. Убедиться, что в Netlify видны Next.js server function и `analysis-background`. Проверить логи без вывода секретов.
5. Проверить отмену и повторную доставку одной задачи: уже завершённая задача не должна создавать новые AI-запросы.
6. Проверить запрос к внутреннему маршруту без WORKER_SECRET: HTTP 403. Проверить межсайтовую запись: HTTP 403.

Успешная публикация файлов уже подтверждена; до этих проверок нельзя считать приложение полностью готовым для судьи. Локальные тесты используют имитацию AI и PostgreSQL в PGlite; реальная доступность модели и связь с Neon требуют отдельной проверки.

## Выполнение и ограничения

POST /api/analyses создаёт запись и запускает исследование OpenAI, затем получает подтверждение приёма фоновой функции Netlify. Worker каждые четыре секунды вызывает защищённый внутренний API. API проверяет статус провайдера, запускает второй этап и сохраняет ответ. GET из браузера только читает состояние. Закрытие вкладки не останавливает worker; сознательная отмена или новый ход останавливают старую задачу.

Повторные доставки используют одну запись и блокировку этапа. Переход сохраняется до запуска второго платного этапа. Если процесс прервался между созданием ответа OpenAI и сохранением его ID, система помечает задачу как прерванную, а не автоматически оплачивает повтор. Это защита от дублей, не гарантия бесшовного восстановления любого сбоя.

Общий срок анализа — до 12 минут; цикл worker ограничен 14 минутами при лимите Netlify 15 минут. Отдельный вызов API остаётся коротким относительно полного анализа. При недоступности базы или платформы задача может завершиться ошибкой; бесплатный тариф не даёт гарантии бесперебойности. Долгое ожидание в worker, опросы, сборки и трафик расходуют кредиты Netlify; AI оплачивается отдельно.

Источники: [Next.js на Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/), [Background Functions](https://docs.netlify.com/build/functions/background-functions/), [переменные функций](https://docs.netlify.com/build/functions/environment-variables/), [тарифы](https://www.netlify.com/pricing/).

## Сохранение кода в исходный репозиторий

GitHub и Netlify обновляются отдельно. Git push сохраняет код; CLI deploy обновляет сайт. Работа ведётся только в исходном репозитории, без fork. Для сохранения уже созданного локального коммита в main, как согласовано владельцем:

```powershell
$gitExe = Join-Path $env:USERPROFILE ".cache\codex-runtimes\codex-primary-runtime\dependencies\native\git\cmd\git.exe"
$env:GIT_SSH = "C:\Windows\System32\OpenSSH\ssh.exe"
& $gitExe --no-pager log -1 --oneline
& $gitExe push origin HEAD:main
```

Команды выполняются из рабочей копии с нужным коммитом. Push обычный, без `--force`: при новых изменениях команды или защите main Git должен отказать, после чего нужно обновить код и разрешить расхождения. Команды здесь являются инструкцией, а не подтверждением выполненного push.

## Ошибки установки на Windows

**node-gyp / Python при установке better-sqlite3.** Для текущего package-lock проверена установка `npx.cmd --yes npm@11.20.0 ci --ignore-scripts`; готовый SQLite-модуль работает на Node 24.21.0. Этот драйвер нужен локальному режиму, а в облаке используется PostgreSQL. При обновлении зависимостей повторите проверку пригодности установки без скриптов.

**git не найден / переменная gitExe пуста.** Сначала выполните две строки определения gitExe и GIT_SSH из раздела сохранения кода. Переменная действует только в текущем PowerShell.

**cannot spawn less.** Это ошибка просмотра истории, не скачивания репозитория. Используйте `& $gitExe --no-pager log -1 --oneline`.

**spawn EPERM в окружении агента.** Повторите команду сборки из обычного PowerShell пользователя; не отключайте TypeScript. Именно там уже получен успешный production deploy.
