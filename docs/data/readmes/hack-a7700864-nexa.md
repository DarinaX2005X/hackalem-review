# NEXA

**BUSINESS × TALENT**

> Хорошо поставленная задача находит свою команду.

NEXA помогает бизнесу превратить первоначальное, часто неполное описание потребности в структурированную бизнес-задачу, оценить её готовность и разместить в открытом каталоге. Студенческие команды самостоятельно изучают каталог, выбирают интересные задачи и отправляют предложения. Финальное решение о выборе команды принимает бизнес.

Ключевой сценарий:

```text
слабое описание → 3 AI-вопроса → структурированная карточка
→ рейтинг 0–100 → объяснение потерянных баллов → улучшение
→ публикация → Marketplace → предложение команды → решение бизнеса
```

## Краткое описание

Бизнес может понимать свою проблему, но сформулировать её слишком кратко:

> Хотим автоматизировать техподдержку.

Такого описания недостаточно, чтобы команда быстро поняла контекст, пользователей, доступные данные, ограничения, ожидаемый результат и критерии успеха. NEXA сокращает разрыв между бизнес-потребностью и постановкой задачи, пригодной для оценки и начала работы.

NEXA — marketplace практических бизнес-задач, а не биржа вакансий:

| Участник | Путь |
| --- | --- |
| **Бизнес** | идея → структурированная задача → рейтинг → публикация → предложения |
| **Студент** | каталог → задача → предложение решения |
| **NEXA** | OpenAI + прозрачный Rating Engine + D1 + Marketplace |

## Что реализовано

- Home Page с выбором сценария **«Бизнес»** или **«Студент»**;
- ввод задачи свободным текстом;
- server-side интеграция OpenAI;
- ровно три контекстных уточняющих вопроса;
- структурированная Task Card без добавления неизвестных фактов;
- редактирование карточки человеком;
- детерминированный рейтинг готовности 0–100;
- breakdown по критериям, потерянные баллы и недостающая информация;
- конкретные рекомендации и пересчёт рейтинга после редактирования;
- отдельное подтверждение и публикация задачи;
- Marketplace опубликованных задач с сортировкой по рейтингу;
- фильтры по категории и уровню готовности;
- предложение решения от студенческой команды;
- ручные решения бизнеса `ACCEPTED` и `REJECTED`;
- хранение задач, команд и предложений в Cloudflare D1;
- детерминированный fallback при недоступности OpenAI;
- синтетические demo-данные для быстрого показа проекта.

## Как работает решение

1. Бизнес нажимает **«Разместить задачу»** и описывает потребность обычными словами.
2. OpenAI анализирует описание и задаёт ровно три релевантных вопроса.
3. Бизнес отвечает, после чего AI формирует структурированную Task Card только из предоставленной информации.
4. Пользователь проверяет и редактирует карточку.
5. Rating Engine рассчитывает score 0–100 и показывает, что уже засчитано, чего не хватает и сколько баллов потеряно.
6. После дополнения карточки рейтинг пересчитывается.
7. Бизнес подтверждает и публикует задачу.
8. Опубликованная задача появляется в Marketplace; более высокий score поднимает её выше в каталоге.
9. Студент выбирает задачу и отправляет предложение с идеей, планом и сроком.
10. Бизнес вручную принимает или отклоняет предложение.

AI не назначает команду и не принимает финальное решение.

### Как устроен рейтинг

AI отвечает за понимание естественного языка и структурирование ввода. Итоговый score рассчитывает отдельный детерминированный Rating Engine. Поэтому одинаковая карточка получает одинаковую оценку, а происхождение каждого балла можно объяснить.

| Критерий | Максимум |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Итого** | **100** |

| Баллы | Уровень |
| --- | --- |
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Каждый критерий получает состояние `EMPTY`, `PARTIAL` или `COMPLETE`. Для неполного критерия интерфейс показывает:

- что уже засчитано;
- чего не хватает;
- сколько баллов потеряно;
- что можно дополнить.

Пример работы механики, закреплённый тестами:

```text
85 / 100 — ГОТОВАЯ

Данные и материалы   10 / 20   −10
Ограничения            5 / 10    −5

После дополнения:
85 → 100
+15 баллов
```

Конкретный score зависит от содержания карточки. Низкий рейтинг не скрывает опубликованную задачу, но Marketplace сортирует опубликованные задачи по score по убыванию.

## Архитектура проекта

NEXA реализована как full-stack modular monolith:

```text
React / Vinext Web UI
          ↓
Server-side API routes
          ├── AI Service ─────────────→ OpenAI API
          ├── Rating Service
          ├── Task Service
          ├── Marketplace Service
          └── Proposal Service
                       ↓
               Drizzle ORM
                       ↓
                Cloudflare D1
```

Разделение ответственности:

- **AI Service** понимает свободное описание, формирует три вопроса и структурирует предоставленную информацию. Системная инструкция требует не добавлять неизвестные сроки, данные, технологии, контакты или ограничения.
- **Rating Service** детерминированно рассчитывает score, breakdown, недостающую информацию, рекомендации и уровень готовности. AI не выставляет баллы.
- **Task Service** создаёт, обновляет, подтверждает и публикует задачи; score пересчитывается server-side.
- **Marketplace Service** выбирает только опубликованные задачи и сортирует их по score.
- **Proposal Service** связывает задачу с командой и обрабатывает ручное решение бизнеса.
- **D1** хранит состояние задач, команд и предложений.

При отсутствии API key, сетевой ошибке или временной недоступности OpenAI включается более простой детерминированный fallback. Он сохраняет основной demo flow, а Rating Engine продолжает работать независимо от AI.

## Установка и запуск

Требования:

- Node.js `>=22.13.0`;
- Git;
- OpenAI API key — опционально, без него работает fallback.

Проверенная последовательность для чистого клона:

```powershell
git clone https://github.com/BAITC-Hacks/hack-a7700864-nexa.git
Set-Location hack-a7700864-nexa/web
npm ci
Copy-Item .dev.vars.example .dev.vars
npm run db:migrate:local
npm run dev
```

Для macOS/Linux используйте:

```bash
git clone https://github.com/BAITC-Hacks/hack-a7700864-nexa.git
cd hack-a7700864-nexa/web
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm run dev
```

`npm run db:migrate:local` применяет ожидающие SQL-миграции из `web/drizzle/` к локальной D1 в `web/.wrangler/state`. При первом открытии приложения запрос `/api/bootstrap` автоматически добавляет demo-данные, если база пуста.

### Настройка OpenAI

Tracked-шаблон `web/.dev.vars.example` содержит:

```dotenv
OPENAI_API_KEY=
```

После копирования укажите собственный ключ в локальном `web/.dev.vars`:

```dotenv
OPENAI_API_KEY=<your_key>
```

Не добавляйте кавычки, пробелы или префикс `Bearer`. Файл `web/.dev.vars` игнорируется Git и не хранится в репозитории. После изменения переменной полностью перезапустите dev server.

Откройте Local URL, который выведет `npm run dev`. Типичный адрес при свободном стандартном порте — `http://localhost:5173`, но фактический порт может отличаться.

## Как проверить решение за 3–5 минут

1. Запустите приложение и откройте Home.
2. Нажмите **«Разместить задачу»**.
3. Введите: **«Хотим автоматизировать первую линию технической поддержки.»**
4. Получите ровно три уточняющих вопроса и ответьте на них.
5. Проверьте сформированную Task Card.
6. Посмотрите рейтинг, breakdown и объяснение потерянных баллов.
7. Дополните слабые поля и нажмите **«Сохранить и пересчитать»**.
8. Убедитесь, что рейтинг изменился в соответствии с введёнными данными.
9. Подтвердите карточку и опубликуйте задачу.
10. Нажмите логотип **NEXA**, чтобы вернуться на Home.
11. Нажмите **«Найти задачу»** и откройте опубликованную задачу в Marketplace.
12. Отправьте предложение от команды.
13. Переключитесь на роль **«Бизнес»**.
14. Откройте предложения и нажмите **«Выбрать»** или **«Отклонить»**.
15. Проверьте итоговый статус `ACCEPTED` или `REJECTED`.

Конкретное значение рейтинга зависит от ответов и последующего редактирования.

## Данные и интеграции

Внешняя интеграция проекта — OpenAI Chat Completions API. Запрос выполняется только server-side, а ответ проходит JSON Schema и Zod validation.

Cloudflare D1 хранит три связанные сущности:

- **Task** — описание, структурированные поля, score и статусы подтверждения/публикации;
- **Team** — название, интересы, навыки и технологии;
- **Proposal** — связь Task и Team, идея решения, план, срок, прототип и статус.

При первом запуске пустая база получает отслеживаемый в репозитории синтетический набор: **5 задач, 5 команд и 5 предложений**. Это demo-данные, а не реальные компании или пользователи.

## Ограничения текущей версии

В рамках 5-часового MVP сознательно ограничен scope:

- переключатель demo-ролей используется вместо полноценной authentication и RBAC;
- не реализованы realtime-чат, уведомления, загрузка файлов и полноценный project tracker;
- интерфейс оптимизирован прежде всего для ноутбука;
- fallback проще OpenAI и предназначен для сохранения демонстрационного сценария;
- команды выбирают задачи самостоятельно — автоматического подбора команд нет;
- vector database и RAG для рейтинговых рекомендаций не используются;
- production hardening, расширенная модерация и аудит доступа находятся за пределами MVP.
