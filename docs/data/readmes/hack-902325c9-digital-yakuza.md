# Digital Yakuza — агент тарифных кампаний Beeline

### [Открыть демо →](https://hackalem-frontend.vercel.app/)

[API / Swagger](https://hackalem-backend-5a3d74f6419c.herokuapp.com/docs) · [Результаты](#результаты-и-качество) · [Запуск](#установка-и-запуск) · [Проверка ТЗ](#как-проверить-решение)

**Помогаем маркетинговому аналитику выбрать, кому, какой тариф и через какой канал предложить.** Агент проверяет гипотезы пилотами, оценивает эффект и неопределённость, формирует план кампаний и объясняет основания решений.

Проект команды Digital Yakuza для кейса Beeline на **HackAlem AI**. На выходе — план в CSV, результаты пилотов и отчёт для аналитика.

**Файлы сдачи кейса:** [`beeline_agent/agent.py`](beeline_agent/agent.py) (класс `Agent`, метод `act(env)`) и [`beeline_agent/submission.csv`](beeline_agent/submission.csv) (из `make_submission.py`, seed 42).

## Бизнес-задача и ценность решения

Выгодный по истории переход на другой тариф может оказаться убыточным на текущей аудитории: часть клиентов начнёт платить меньше, а коммуникация дополнительно потратит бюджет. История описывает другую выборку абонентов, поэтому её выводы нужно проверять. Пилот помогает получить новые данные, но сам расходует ресурсы и даёт шумный результат.

| Задача аналитика | Что делает система | Практическая ценность |
|---|---|---|
| Выбрать гипотезы для проверки | Строит кандидатов по истории и профилю аудитории | Переводит данные в конкретные варианты кампаний |
| Решить, каким результатам доверять | Обновляет оценку после пилота с учётом его размера и шума | Показывает неопределённость и основания выбора |
| Уложиться в ограничения | Учитывает бюджет, контакты, число и размер кампаний | Возвращает план в формате и лимитах кейса |
| Обосновать решение | Сохраняет журнал, связывает кампании с пилотами, формирует объяснение | Позволяет проверить рекомендацию перед запуском |

**Цель кейса — чистый прирост ARPU после затрат на коммуникацию:**

```text
net_arpu_gain = прирост ARPU по уникальным абонентам − стоимость контактов
```

Пилоты входят и в эффект, и в затраты. Повторные контакты расходуют бюджет, но эффект абонента засчитывается по лучшей для него кампании. Полное расходование бюджета само по себе не является целью.

> Все данные синтетические. Результаты — условные единицы симулятора, не измеренная выручка Beeline. Экономия времени аналитика отдельно не измерялась.

## Пользовательский сценарий

1. **Запустить расчёт.** Аналитик открывает дашборд и запускает агента на предоставленной аудитории.
2. **Проверить разведку.** Агент проводит пилоты; аналитик видит их результаты и затраты.
3. **Изучить план.** Для финальных кампаний доступны аудитории, целевые тарифы, каналы и показатели результата.
4. **Проверить основания.** Отчёт связывает кампании с пилотами и содержит объяснение и предупреждения.
5. **Скачать CSV.** Аналитик получает воспроизводимый план для дальнейшего решения о запуске.

**AI рекомендует — решает человек.** Интеграции с реальной рассылкой абонентам нет. ИИ-объяснение показывается в дашборде в блоке «Почему такой план» с пометкой источника: «ИИ (luna)» или шаблон.

## Что реализовано и как работает агент

```text
История переходов + профиль аудитории
                  ↓
        Гипотезы и начальные оценки
                  ↓
      Выбор пилота → наблюдение результата
                  ↑             ↓
                  └── обновление оценки и погрешности
                                ↓
                  План с учётом риска и лимитов
                                ↓
                   CSV + факты + журнал решений
                                ↓
                     ИИ-объяснение → аналитик
```

- **Исторические оценки.** Начальный эффект и ошибка по связкам «текущий тариф × ARPU-сегмент → цель», с поправкой на неопределённость переноса.
- **Последовательная разведка.** Пилоты выбираются по предыдущим результатам. Байесовское обновление учитывает их размер и шум. Размер пока зависит от численности аудитории — 100 или 200; выбор размера по ожидаемой пользе не реализован.
- **Планирование.** Кампании ранжируются по консервативной оценке с учётом пересечений и ресурсов. Канал выбирается экономически: кампания начинает с бесплатного push и переходит на SMS, интернет-рекламу или звонок, только если доплата окупается по нижней границе оценки и помещается в остаток бюджета. Если ни одна кампания не прошла порог, используется небольшая запасная push-кампания с причиной в журнале. Прибыль не гарантируется.
- **Проверяемый результат.** `Agent.act(env)` возвращает 1–10 кампаний; пилоты, обновления оценок и решения записываются в `trace`.
- **Приложение.** Фоновый запуск, сохранение в PostgreSQL, показ кампаний и пилотов, скачивание CSV.

**Пример из seed 42:** кампания C1 для MID → `tariff_8` связана с пилотами P5 и P6. Наблюдаемые эффекты SMS-пилотов — около 11,07% и 13,61%; финальная кампания содержит 4 108 контактов. Связь и значения можно проверить в `report.json`, а не принимать объяснение на веру.

## Результаты и качество

**Официальная mock-среда, seed 42:**

| Показатель | Результат |
|---|---:|
| Чистый прирост ARPU после коммуникаций | **+5 165 453 у.е.** |
| Финальные кампании / пилоты | **5 / 20** |
| Затраты, включая пилоты | **95 094 из 100 000 у.е.** |
| Каналы финальных кампаний | **SMS × 3, интернет-реклама × 2** |
| Контакты, включая пилоты | **13 320 из 15 000** |

**Проверка переноса на другие эффекты:** 135 контрольных миров, 9 сценариев × 15 seed (10 000–10 014). Все стратегии запускались на одинаковых мирах и seed. Контрольный набор использовался только для итоговых проверок, без настройки на нём: сначала для версии `a631a16`, затем для сдаваемой версии, чей выбор каналов уже был принят по 180 тренировочным мирам.

| Стратегия | Медиана net, млн у.е. | 10-й перцентиль | Худший | Миров в минусе | Миров с нарушениями ТЗ |
|---|---:|---:|---:|---:|---:|
| Шаблон организаторов | −0,13 | −0,96 | −1,38 | 76,3% | 6 / 135 |
| Только история, без пилотов | 2,98 | 0,57 | −1,67 | 3,7% | 135 / 135 |
| Наш агент без выбора каналов (`a631a16`) | 2,60 | 0,33 | −0,92 | 2,2% | 0 / 135 |
| **Наш агент, сдаваемая версия** | **2,77** | **0,35** | **−0,90** | **1,5%** | **0 / 135** |

**Как интерпретировать:** агент улучшил результат относительно шаблона и выполнил проверяемые условия ТЗ во всех 135 мирах. У стратегии «только история» медиана выше, но нет обязательных пилотов и хуже минимальный результат. Сдаваемая версия превосходит её в 30% миров; в сценарии плохого переноса истории `random` медиана агента — 1,58 млн против 0,44 млн. Это показывает пользу проверки истории и одновременно цену осторожности.

Сдаваемая версия отличается от `a631a16` только экономическим выбором каналов (`dfcccc4`). Он принят по 180 тренировочным мирам (медиана парной разницы **+68 тыс. у.е.**, лучше в **71%** миров) и затем один раз проверен на тех же 135 контрольных мирах: медиана парной разницы **+127 тыс. у.е.**, лучше в **81%** миров, хуже в 12%, медиана выше во всех 9 сценариях. Повторный пилот «только при неясном решении» (−16 тыс., лучше в 39%) и разведка тарифов без истории (−595 тыс., лучше в 18%) реализованы за переключателями и **отклонены**. Скрытая среда судейства неизвестна; отдельные контрольные миры остаются убыточными.

Методика и отклонённые варианты, включая совместную модель ячеек: [EXPERIMENTS.md](beeline_agent/eval/EXPERIMENTS.md).

## Роль ИИ, надёжность и стоимость

Модель **`gpt-5.6-luna`** через OpenAI API объясняет уже готовый план: связывает кампании с доказательствами, формулирует предупреждения и следующие действия аналитика. Статистический код выбирает пилоты и кампании; модель не меняет их и не редактирует CSV.

| Механизм | Зачем он нужен |
|---|---|
| Компактные факты вместо всего клиентского датасета | Ограничивает объём запроса и делает основания ответа проверяемыми |
| Структурированный ответ со ссылками | Каждая кампания объясняется один раз; проверяются существование фактов и связь с её пилотами и тарифами |
| Числа подставляет код: `{C1.contacts}` | Ответ с числовыми значениями вне разрешённых ссылок отклоняется |
| План сохраняется до вызова модели | Таймаут или ошибка объяснения не теряют результат расчёта |
| Шаблон с указанной причиной | Workflow работает без ключа, при сбое API или отклонённом ответе |

Тестовый вызов команды: **2 909 входных / 1 188 выходных токенов, 12,2 с, около $0,00201** по использованным ценам. Токены, задержка и оплаченные попытки записываются в отчёт. Бюджет проверяется до запроса, но предварительная оценка токенов приблизительная: строгий финансовый потолок не гарантируется. USD API и у.е. кампаний — разные бюджеты.

Проверка ссылок и чисел не доказывает правильность каждой смысловой формулировки. Содержательную полезность объяснений для аналитика ещё предстоит измерить. [Подробности workflow](beeline_agent/WORKFLOW.md).

## Архитектура и технологии

```text
React / TypeScript → FastAPI → отдельный worker → Agent.act(env)
                        ↑              ↓
                        └────── PostgreSQL: план, пилоты, журнал
                                       ↓
                           explain_result: факты → LLM / шаблон
                                       ↓
                           объяснение того же сохранённого run_id
```

`explain_result` объясняет сохранённый запуск без повторных пилотов. Агент использует публичный интерфейс среды; истинные эффекты доступны оценщику. Mock-метрики отчёта рассчитываются после запуска.

| Компонент | Технологии | Код |
|---|---|---|
| Агент и расчёты | Python, NumPy `2.2.4`, pandas `2.2.3` | [agent.py](beeline_agent/agent.py) |
| ИИ и отчёты | OpenAI API, SDK `openai==2.54.0` | [workflow.py](beeline_agent/workflow.py) |
| Оценки и симулятор | Python, статистическая обработка данных | [prior/](beeline_agent/prior/README.md), [sim/](beeline_agent/sim), [eval/](beeline_agent/eval) |
| API и хранение | FastAPI, SQLAlchemy, PostgreSQL, Alembic | [backend/](backend) |
| Дашборд | React 19, TypeScript, Vite | [frontend/](frontend) |
| Запуск и тесты | Docker Compose, pytest | [Инструкция](frontend/docs/local-start.md), [тесты](beeline_agent/tests) |

## Установка и запуск

### Агент и отчёт без внешних сервисов

Нужен **Python 3.12**. Начните из корня репозитория:

```bash
python -m venv .venv
```

Активируйте созданное окружение: PowerShell — `.\.venv\Scripts\Activate.ps1`, Linux/macOS — `source .venv/bin/activate`.

```bash
cd beeline_agent
python -m pip install -r requirements-workflow.txt
python workflow.py --no-llm
```

Для сдаваемой версии ожидается **5 кампаний, net 5 165 453, объяснение `template`**. В `outputs/` появятся:

| Файл | Содержимое |
|---|---|
| `submission.csv` | Финальный план кампаний |
| `report.json` | План, метрики mock, пилоты, журнал, факты, связи, объяснение и расход модели |
| `explanation.md` | Читаемое объяснение с указанием источника |

По умолчанию: таймаут попытки 30 с, ответ до 2 000 токенов, до 2 попыток на ключ. `AGENT_LLM=0` или `--no-llm` отключает модель. Полные настройки и переопределение цен — в [WORKFLOW.md](beeline_agent/WORKFLOW.md).

## Как проверить решение

Для демонстрации: откройте сайт по ссылке в начале, запустите агента с seed 42, изучите кампании и пилоты, скачайте CSV. Ожидается «seed 42 · агент 59547e1d», 5 кампаний, чистый эффект 5 165 452,81 у.е. и блок «Почему такой план» с пометкой «ИИ (luna)»; CSV совпадает с `beeline_agent/submission.csv`. Версию агента на хостинге можно сверить: `GET /api/case/summary` возвращает `agent_sha256`, у сдаваемой версии — `59547e1d…`. Воспроизводимая локальная проверка выполняется из `beeline_agent`:

```bash
python local_eval.py
python make_submission.py
python -m eval.checks
```

Ожидаются `PASS`, 5 финальных кампаний и проверки без FAIL для зафиксированной версии. Официальный оценщик выводит **25 кампаний суммарно**: 20 пилотов + 5 финальных. T4 в тренажёре — диагностика генератора, не прибыль агента.

```bash
python -m pip install pytest
python -m pytest -q tests
python local_eval.py --runs 10
```

Проходят **47 тестов** (агент, workflow, выбор каналов) и **11 из 11** проверок тренажёра. `local_eval.py --runs 10`: **10 из 10 положительных**, медиана +4,82 млн, минимум +3,01 млн у.е. Тесты API используют подмену и не требуют платных запросов.

## Ограничения и следующий этап

| Ограничение текущей версии | Следующий шаг |
|---|---|
| Пилот проверяет смесь тарифов, оценка переносится на остаток после удаления пересечений; среднее по людям отличается от ценности по ARPU | Согласовать модель наблюдения и фактическую аудиторию кампании |
| Тарифы без истории не разведываются: 20 пилотов не хватает, в сравнении это ухудшило результат | Больше пилотов или отбор новых тарифов по сходству с известными |
| Пилоты и финальный план могут принести убыток при других эффектах | Проверить новую финальную стратегию на заранее зафиксированном свежем контрольном наборе |
| ИИ объясняет готовый план, его вклад в качество решений аналитика не измерен | Оценить полезность объяснений и ложные предупреждения на примерах |
| В тексте ИИ-объяснения встречаются англоязычные термины (lift, observed, LCB) и неудачные формулировки ограничений охвата | Упростить язык инструкции модели и проверить формулировки на примерах аналитиков |

Для реального внедрения потребуются контролируемые эксперименты на реальных данных: исторические зависимости и синтетические миры не доказывают причинный бизнес-эффект кампаний.
